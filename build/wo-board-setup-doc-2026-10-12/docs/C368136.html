Setup: The clear-shifts question shows on Board and Tech View only

Test case: C368136, WO Board and Tech View. Part 1 is for the manual QA tester. Part 2 is for a Claude session that prepares the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in square brackets, such as [Tech-A], stands for a person or record you create or pick; it is defined in the list below and used the same way in the test case. Write down the real value you used for each name, because the test steps refer to it.

What must be true before you start

  1. Needs: 1 user · 1 browser · Schedule access · about 15 minutes.
  2. Build: the Work Orders QA build (sv10043, v26.40.8-7a95011).
  3. User: [User-A] = you: an Owner/Admin user (on a QA branch the Admin quick-login user, shown as "Admin ShopView"). The Admin role holds Work orders > View and Work orders > Create & Edit.
  4. Browser: desktop browser window at least 1024 px wide. Narrower windows show only the List, without the display switcher.
  5. Location: one location for the whole case, shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); everything below is created in this location.
  6. People: two eligible technicians at this location: [Tech-A] "Esther Howard" and [Tech-B] (e.g. "Ralph Edwards"). A person only counts as a technician here when the staff member is active (not deactivated), Time Clock is on, the Role is neither Office User nor Time Clock User, and this location is picked in their Location field.
  7. Data: customer "ZZAUTOTEST F1 Prompt Where" (used by this case only) with one Approved work order [WO-1] led by [Tech-A].
  8. Data: a shift for [Tech-A] on [WO-1] tomorrow 8:00–12:00 (entire work order).
  9. Note: Esther Howard is named in the expected results and stays as written; the other name and the number are examples.

Part 1. Setup for manual QA tester

Do these steps in order.

  1. Sign in as an Owner/Admin user (on a QA branch: the Admin quick-login button on the sign-in page; you appear as "Admin ShopView").
    • The Admin role holds Work orders > View and Work orders > Create & Edit (to check: your initials at the top right > Settings > Roles & Permissions > Admin > Work orders).
  2. Use one location for the whole case: it is shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919")
    • To change it click your initials at the top right > Change Location.
  3. Settings (your initials at the top right > Settings) > Staff: reuse a technician only after checking it is active, has Time Clock on, a Role other than Office User or Time Clock User and this location in Location
    • Otherwise add one: New Staff Member > First Name and Last Name, an Email, Role "Technician", at least one Department (required), Location = this location, Time Clock on > Save & Close.
    • Record them as [Tech-A] = "Esther Howard" (use exactly this name: the expected results name it), [Tech-B] (e.g. Ralph Edwards).
  4. Create the customer used only by this case: top menu Customers > New Customer > Name "ZZAUTOTEST F1 Prompt Where" > Save.
    • On the customer page click the Contacts tab > New Contact > First Name and Last Name > Save (a new asset needs a contact).
    • Then click the Assets tab > New Asset > pick the Contact, then Year, Make, Model and Unit (e.g. 2022, Freightliner, M2, unit "TRK-118") > Save.
    • Make is required
    • Unit can be left empty.
  5. Create these work orders for "ZZAUTOTEST F1 Prompt Where": Work Orders > Create Work Order > in the New Work Order window pick the Customer and its Asset > Save.
    • The new work order opens with the New Line form (otherwise click New Line on the Lines tab): in "What Are You Doing?" pick a ready-made line (e.g. "Replace - Brake pot"; typed free text finds no results), turn on Line Approved so the work order status reads Approved, and click Save & Close.
    • Write down the number the build gives the work order (on a QA branch they look like "S10043-17581").
    • Then pick the lead in the Lead Technician dropdown on the work order page
    • It saves at once. (While a work order is an Estimate its Lead technician is read-only on the work order page; give an Estimate its lead from Board View instead: the card's More actions (…) > Reassign lead technician > pick the technician > Reassign.) Leave Lead Technician empty on the ones that should sit in Unassigned.
    • [WO-1] (e.g. S1-702): Lead Technician = [Tech-A].
  6. On the Schedule, give [Tech-A] a shift on the work order tomorrow 8:00–12:00: Schedule > go to that day > drag the work order from the work order list onto [Tech-A]'s row at the start time > in the picker choose Entire work order > set the end time > save.
  7. Check the setup worked: on the Schedule for tomorrow, [Tech-A]'s row has the 8:00–12:00 shift on [WO-1], and [WO-1] shows Lead Technician [Tech-A].
    • If not, fix it before starting.

Part 2. Setup for Claude session

Prepare the same starting state by carrying out Part 1 in a browser with Playwright. Record the real values you used, the build marker and screenshots in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only.

Environment

  • Work Orders QA site: app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com (the build named in the test case's Preconditions).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium through Playwright. Do not run "playwright install".

Access

  • Sign in with the QA site's quick login: node build/testing-tools/qa-branch-boot.mjs (see build/APP-ACTIONS-PLAYBOOK.md section A). Carry the sv_sso_session cookie only, scoped to the host.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Change location through the profile icon (your initials, top right) > Change Location.

Test data

Name anything you create with ZZAUTOTEST at the start. Leave all test data in place; nothing is deleted afterwards.
