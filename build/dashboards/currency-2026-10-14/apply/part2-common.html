How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md) and the Dashboard project state (build/dashboards/PROJECT-STATE.md).

Environment

  • Dashboard QA site (epic SV-490): app https://sv490.qa.shopview.com, API https://sv490api.qa.shopview.com. The specification's header names this site. Use the site named in the test run if it differs.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, desktop window at least 1024 px wide unless the case says otherwise. Do not run "playwright install".
  • Known location with history on the QA site: Staging Heavy Duty - 9919 (used by earlier Dashboard cases). Whether it holds the exact history a case needs is UNVERIFIED until Part 1's check is run.

Access

  • Sign in with the sign-in page's DEV MODE quick login, Admin (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Carry the sv_sso_session cookie only, scoped to the host.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.
  • Invoices and clocked time cannot be back-dated by hand. Where a case needs history from earlier days or months, use a location that already holds it and prove it with Part 1's check before the steps.

Cleanup

Name everything you create with ZZAUTOTEST at the start. Leave ZZAUTOTEST records in place; they are marked as test data.
