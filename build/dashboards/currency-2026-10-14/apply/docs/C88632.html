Setup: Sales and Advisor Analysis reports drop a voided invoice and keep its re-invoice

Test case: C88632, Dashboard v1. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as {User-A} (for example Admin ShopView), whose role has the Reports permission and can create and invoice work orders.

• Location {Location-A} (for example ZZAUTOTEST Quiet 14 Oct A) is a fresh location made for this run: nothing else is invoiced, credited or clocked there, so on the Dashboard the Revenue tile on This Week reads $0.00 with 0 Invoices.

• Labor rate {Rate-A} (for example ZZAUTOTEST Rate 100) charges $100.00 an hour at {Location-A}.

• Customer {Customer-A} (for example ZZAUTOTEST C88632 Void Reinvoice) has one contact and one asset (for example unit ZZ-101).

• {User-A} has Time Clock on and is the technician on the work.

• Work order {Work-order-1} (for example S490-1201) for {Customer-A} is invoiced, not sent and not paid, and its Service Advisor is {User-A}.

• {Work-order-1} has one labor line, {Line-1} (for example "ZZAUTOTEST Line 1"), with technician {User-A}, labor rate {Rate-A}, Estimated Time 2.00 and Tech Time 2.00, and exactly 2.00 hours clocked on it.

• You have written down the invoice's Subtotal (for example $200.00).

• You run the whole case on one day, and not on the last evening of the week, so every record stays inside This Week.

• You can open the release notes page on Confluence (https://shopview.atlassian.net/wiki/pages/viewpage.action?pageId=931069964).

Part 1. Setup for manual QA tester

1. Sign in as an Admin user: on the QA site's sign-in page, in the DEV MODE - QUICK LOGIN panel, click Admin (you appear as Admin ShopView). This is {User-A}. To use another role instead, check it has Reports: your initials (top right) > Settings > Roles & Permissions > edit icon on the role > Reports is switched on.

2. Create a fresh location for this run, with a new name each time (for example ZZAUTOTEST Quiet 14 Oct A): your initials (top right) > Settings > Locations > New Location: Name, Address 1, City, State/Province, ZIP/Postal Code, Timezone, Telephone, Shop Supplies Charge 0 > Save & Close. Switch to it: your initials > Change Location > pick it. This is {Location-A}. Nothing else is invoiced or clocked there.

3. While in {Location-A}, add a labor rate (rates belong to each location): your initials > Settings > Labor Rates > New Labor Rate: Name (for example ZZAUTOTEST Rate 100), Rate 100 > Save & Close. This is {Rate-A}.

4. Customers > New Customer > Name (for example "ZZAUTOTEST C88632 Void Reinvoice") > Save. On its Contacts tab click New Contact, enter a First Name and Last Name > Save. On its Assets tab click New Asset, pick the contact and fill Year, Make and Unit (for example 2022, Freightliner, ZZ-101) > Save. This is {Customer-A}; use it for this case only.

5. Check that {User-A} has Time Clock on: your initials > Settings > Staff > your own row > edit > Time Clock is on. In a fresh location you are the technician offered in Add Technician, and you clock time yourself.

6. Work Orders > Create Work Order > pick {Customer-A} and its asset > Save. In the left panel set Service Advisor to {User-A} (your own name, usually already shown). In the New Line window: What Are You Doing? (for example "ZZAUTOTEST Line 1"), Add Technician {User-A}, Labor Rate {Rate-A}, Estimated Time 2, Tech Time 2, tick Line Approved > Save & Close. This is {Work-order-1} with {Line-1}; write down its number.

7. On {Line-1}'s Labor row click Start, then Stop > Clock Out. Make the clocked time exactly 2.00 hours: three dots at the top right of the Lines tab > Timesheets (1) > edit the record (if it cannot be edited there or in Reports > Timesheet Activities, keep the real time and use the hours Timesheet Activities shows in every sum).

8. On {Line-1} click Story > type a short story > Update. Click Complete (if a Missing Details window asks for Mileage, enter one > Complete All Lines), then Mark Reviewed.

9. Finance tab > Create Invoice. Close the New Customer Payment window without paying; do not send or pay the invoice. Write down the Subtotal shown on the Finance tab.

10. Check the setup worked: on the Dashboard the Revenue tile on This Week reads the Subtotal you wrote down (for example $200.00), and Reports > Sales (Date: This week) lists exactly one invoice, {Work-order-1}'s. Run the steps on the same day.

Part 2. Setup for Claude session

• Goal: a fresh location {Location-A} holding exactly one invoiced, unpaid, unsent work order {Work-order-1} with 2.00 hours clocked and billed at $100.00 an hour; then the void (adding a line to that unpaid, unsent invoice), the re-invoice and the release-note check.

• Prepare the data on screen exactly as Part 1. No API recipe for this case's data has been proven on the Dashboard QA site (UNVERIFIED); if you try one, confirm the result on screen with Part 1's check before step 1.

• Trap (tech plan section 7): Reverse on an invoice deletes it rather than voiding it. Do not use Reverse; the void comes from adding a line while the invoice is unpaid and unsent (step 7).

• Step 15: open https://shopview.atlassian.net/wiki/pages/viewpage.action?pageId=931069964 (Release Notes (Combined)), find the Dashboard section's "Worth knowing" list and compare the note with the expected result word for word. The pre-release and release-day email copy on the same page still says totals will be "lower"; step 15 does not check the email copy.

• UNVERIFIED on the Dashboard QA site: whether Part Sales lets a sale be invoiced with no customer (step 14). Record what the screen does.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md) and the Dashboard project state (build/dashboards/PROJECT-STATE.md).

Environment

  • Dashboard QA site (epic SV-490): app https://sv490.qa.shopview.com, API https://sv490api.qa.shopview.com. The specification's header names this site. Use the site named in the test run if it differs.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, desktop window at least 1024 px wide unless the case says otherwise. Do not run "playwright install".
  • Known location with history on the QA site: Staging Heavy Duty - 9919 (used by earlier Dashboard cases). Whether it holds the exact history a case needs is UNVERIFIED until Part 1's check is run.

Access

  • Sign in with the sign-in page's DEV MODE quick login, Admin (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Carry the sv_sso_session cookie only, scoped to the host.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.
  • Invoices and clocked time cannot be back-dated by hand. Where a case needs history from earlier days or months, use a location that already holds it and prove it with Part 1's check before the steps.
