Setup: This Month's figure and trend line both include today's sales

Test case: C351716, Dashboard v1. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as {User-A} (for example Admin ShopView), whose role has the Reports permission, at location {Location-A} (for example ZZAUTOTEST Today Sales 14 Oct A).

• Your browser window is at least 1024 pixels wide at 100% zoom (a maximised laptop or desktop window).

• {Location-A} is a fresh location made for this run: before today nothing was invoiced or credited there.

• Today is not the 1st of the month.

• Work order {Work-order-1} (for example S490-1310) for customer {Customer-A} (for example ZZAUTOTEST Today Sales Fleet) was invoiced today at {Location-A}, with no discount and a Subtotal of (for example) $250.00 (2.50 hours at $100.00 an hour).

Part 1. Setup for manual QA tester

1. Sign in as an Admin user: on the QA site's sign-in page, in the DEV MODE - QUICK LOGIN panel, click Admin (you appear as Admin ShopView). This is {User-A}. To use another role instead, check it has Reports: your initials (top right) > Settings > Roles & Permissions > edit icon on the role > Reports is switched on.

2. Create a fresh location for this run, with a new name each time (for example ZZAUTOTEST Today Sales 14 Oct A): your initials (top right) > Settings > Locations > New Location: Name, Address 1, City, State/Province, ZIP/Postal Code, Timezone, Telephone, Shop Supplies Charge 0 > Save & Close. Switch to it: your initials > Change Location > pick it. This is {Location-A}. Nothing else is invoiced or clocked there.

3. While in {Location-A}, add a labor rate (rates belong to each location): your initials > Settings > Labor Rates > New Labor Rate: Name (for example ZZAUTOTEST Rate 100), Rate 100 > Save & Close.

4. Customers > New Customer > Name (for example "ZZAUTOTEST Today Sales Fleet") > Save. On its Contacts tab click New Contact, enter a First Name and Last Name > Save. On its Assets tab click New Asset, pick the contact and fill Year, Make and Unit (for example 2022, Freightliner, ZZ-101) > Save. This is {Customer-A}; use it for this case only.

5. Use a desktop browser window at least 1024 pixels wide at 100% zoom.

6. Today, create and invoice one work order for {Customer-A}: Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation says the customer is over their credit limit, click Create). In the New Line window: What Are You Doing? (for example "ZZAUTOTEST Line 1"), Add Technician (yourself), Labor Rate (the $100 rate of this location), Estimated Time 2.50 and Tech Time 2.50, tick Line Approved > Save & Close. On the line's Labor row click Start, wait a minute, then Stop > Clock Out. On the line click Story > type a short story > Update. Click Complete (if a Missing Details window asks for Mileage, enter one > Complete All Lines), then Mark Reviewed. Finance tab > Create Invoice, and close the New Customer Payment window without paying. This is {Work-order-1}; write down its number and the Subtotal (for example $250.00).

7. Check the setup worked: Reports > Sales, Date This month, at {Location-A} lists only {Work-order-1}'s invoice, dated today.

Part 2. Setup for Claude session

• Goal: a fresh location whose only invoice this month is today's.

• Prepare the data on screen exactly as Part 1. No API recipe for this case's data has been proven on the Dashboard QA site (UNVERIFIED); if you try one, confirm the result on screen with Part 1's check before step 1.

• Step 3: record the trend line's drawn points; every point before today must sit at the bottom edge and today's at the top edge (the line is drawn between its own lowest and highest point).

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md) and the Dashboard project state (build/dashboards/PROJECT-STATE.md).

Environment

  • Dashboard QA site (epic SV-490): app https://sv490.qa.shopview.com, API https://sv490api.qa.shopview.com. The specification's header names this site. Use the site named in the test run if it differs.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, desktop window at least 1024 px wide unless the case says otherwise. Do not run "playwright install".
  • Known location with history on the QA site: Staging Heavy Duty - 9919 (used by earlier Dashboard cases). Whether it holds the exact history a case needs is UNVERIFIED until Part 1's check is run.

Access

  • Sign in with the sign-in page's DEV MODE quick login, Admin (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Carry the sv_sso_session cookie only, scoped to the host.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.
  • Invoices and clocked time cannot be back-dated by hand. Where a case needs history from earlier days or months, use a location that already holds it and prove it with Part 1's check before the steps.

Cleanup

Name everything you create with ZZAUTOTEST at the start. Leave ZZAUTOTEST records in place; they are marked as test data.
