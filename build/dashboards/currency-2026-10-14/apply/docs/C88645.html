Setup: At Risk trend line has twelve monthly points and the last equals the count

Test case: C88645, Dashboard v1. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as {User-A} (for example Admin ShopView), whose role has the Reports permission and can reverse an invoice, at location {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 pixels wide at 100% zoom (a maximised laptop or desktop window).

• {Location-A} has invoices going back more than a year, with many customers.

• The At Risk Customers tile's window pill reads 120 Days.

• Customer {Customer-A} (for example ZZAUTOTEST Lapsed Fleet) is at risk on 120 days: its newest invoice, on work order {Work-order-1} (for example S490-1180), is 2 to 6 months old, and it also has an older invoice.

• {Work-order-1}'s invoice has no payment, so it can be reversed.

Part 1. Setup for manual QA tester

1. Sign in as an Admin user: on the QA site's sign-in page, in the DEV MODE - QUICK LOGIN panel, click Admin (you appear as Admin ShopView). This is {User-A}. To use another role instead, check it has Reports: your initials (top right) > Settings > Roles & Permissions > edit icon on the role > Reports is switched on.

2. Pick the location: click your initials (top right, beside the current location name) > under Change Location click the orange button showing the current location > pick the location. On the QA site start with Staging Heavy Duty - 9919. This is {Location-A}; use it for the whole case.

3. Use a desktop browser window at least 1024 pixels wide at 100% zoom.

4. Find the customer: on the Dashboard set the At Risk Customers pill to 120 Days and click View details. Pick a customer whose Last Invoice Date is 2 to 6 months ago and whose Lifetime Invoices is 2 or more; write it down as {Customer-A}. Customers > {Customer-A} > Invoices tab (turn Open only off): its newest invoice's work order is {Work-order-1}; write down both invoice dates. Prefer a ZZAUTOTEST customer; this case reverses its newest invoice. At-risk customers need months-old invoices, which cannot be created by hand.

5. If {Work-order-1}'s invoice has a payment, reverse the payment first: Customers > {Customer-A} > Payments > the payment's three dots > Reverse.

6. Check the setup worked: {Customer-A} is listed in the At Risk Customers table on 120 Days, and {Work-order-1}'s Finance tab offers Reverse in the invoice's three dots.

Part 2. Setup for Claude session

• Goal: an at-risk customer on 120 days whose newest invoice (2 to 6 months old, unpaid) can be reversed, plus an older invoice.

• This case reads history (earlier days or months). Invoices and clocked time cannot be back-dated by hand, so use a location that already holds it, prove it with Part 1's check and record the location and the real values in the case's verification folder.

• Steps 4 and 7: read each point's month and value from its hover tooltip; record all twelve both times and compare month by month.

• Trap (tech plan section 7): Reverse deletes the invoice rather than voiding it. Either way the point values must be worked out again from today's data (S5-R13); record which months changed.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.
