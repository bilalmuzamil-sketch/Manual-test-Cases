Setup: A tile's date picker offers Today and a custom range of up to 366 days

Test case: C581901, Dashboard v1. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as {User-A} (for example Admin ShopView), whose role has the Reports permission, at location {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 pixels wide at 100% zoom (a maximised laptop or desktop window).

• You use the same browser throughout, not a private window (the dashboard keeps these choices in this browser only).

• Work order {Work-order-1} (for example S490-1301) for customer {Customer-A} (for example ZZAUTOTEST Today Picker) was invoiced today at {Location-A}.

Part 1. Setup for manual QA tester

1. Sign in as an Admin user: on the QA site's sign-in page, in the DEV MODE - QUICK LOGIN panel, click Admin (you appear as Admin ShopView). This is {User-A}. To use another role instead, check it has Reports: your initials (top right) > Settings > Roles & Permissions > edit icon on the role > Reports is switched on.

2. Pick the location: click your initials (top right, beside the current location name) > under Change Location click the orange button showing the current location > pick the location. On the QA site start with Staging Heavy Duty - 9919. This is {Location-A}; use it for the whole case.

3. Use a desktop browser window at least 1024 pixels wide at 100% zoom.

4. Customers > New Customer > Name (for example "ZZAUTOTEST Today Picker") > Save. On its Contacts tab click New Contact, enter a First Name and Last Name > Save. On its Assets tab click New Asset, pick the contact and fill Year, Make and Unit (for example 2022, Freightliner, ZZ-101) > Save. This is {Customer-A}; use it for this case only.

5. Today, create and invoice one work order for {Customer-A}: Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation says the customer is over their credit limit, click Create). In the New Line window: What Are You Doing? (for example "ZZAUTOTEST Line 1"), Add Technician (yourself), Labor Rate (any labor rate of this location), Estimated Time and Tech Time (for example 1.00), tick Line Approved > Save & Close. On the line's Labor row click Start, wait a minute, then Stop > Clock Out. On the line click Story > type a short story > Update. Click Complete (if a Missing Details window asks for Mileage, enter one > Complete All Lines), then Mark Reviewed. Finance tab > Create Invoice, and close the New Customer Payment window without paying. This is {Work-order-1}; write down its number.

6. Check the setup worked: Reports > Sales, Date Today (or a custom range of today only): {Work-order-1}'s invoice is listed.

Part 2. Setup for Claude session

• Goal: one invoice today at the location, so today's Revenue is above $0.00.

• Prepare the data on screen exactly as Part 1. No API recipe for this case's data has been proven on the Dashboard QA site (UNVERIFIED); if you try one, confirm the result on screen with Part 1's check before step 1.

• Step 8: record exactly how the picker refuses the 367th day (the day cannot be picked, Apply stays unavailable, or a message appears); any of these is a pass as long as the tile never shows a 367-day range.

• Steps 9 to 11: close the page and open a new page in the SAME browser context.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md) and the Dashboard project state (build/dashboards/PROJECT-STATE.md).

Environment

  • Dashboard QA site (epic SV-490): app https://sv490.qa.shopview.com, API https://sv490api.qa.shopview.com. The specification's header names this site. Use the site named in the test run if it differs.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, desktop window at least 1024 px wide unless the case says otherwise. Do not run "playwright install".
  • Known location with history on the QA site: Staging Heavy Duty - 9919 (used by earlier Dashboard cases). Whether it holds the exact history a case needs is UNVERIFIED until Part 1's check is run.

Access

  • Sign in with the sign-in page's DEV MODE quick login, Admin (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Carry the sv_sso_session cookie only, scoped to the host.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.
  • Invoices and clocked time cannot be back-dated by hand. Where a case needs history from earlier days or months, use a location that already holds it and prove it with Part 1's check before the steps.
