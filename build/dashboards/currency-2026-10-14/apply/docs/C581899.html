Setup: Revenue trend line drops to $0 on days with no sales between two sales days

Test case: C581899, Dashboard v1. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as {User-A} (for example Admin ShopView), whose role has the Reports permission, at location {Location-A} (for example ZZAUTOTEST Gap Days 14 Oct A).

• Your browser window is at least 1024 pixels wide at 100% zoom (a maximised laptop or desktop window).

• This month {Location-A} has invoices on exactly two days, {Day-A} and {Day-B} (for example the 3rd and the 9th), at least two days apart, and no invoice on any day between them.

• Today is {Day-B} or a later day of the same month.

Part 1. Setup for manual QA tester

1. Sign in as an Admin user: on the QA site's sign-in page, in the DEV MODE - QUICK LOGIN panel, click Admin (you appear as Admin ShopView). This is {User-A}. To use another role instead, check it has Reports: your initials (top right) > Settings > Roles & Permissions > edit icon on the role > Reports is switched on.

2. Create a fresh location for this run, with a new name each time (for example ZZAUTOTEST Gap Days 14 Oct A): your initials (top right) > Settings > Locations > New Location: Name, Address 1, City, State/Province, ZIP/Postal Code, Timezone, Telephone, Shop Supplies Charge 0 > Save & Close. Switch to it: your initials > Change Location > pick it. This is {Location-A}. Nothing else is invoiced or clocked there.

3. While in {Location-A}, add a labor rate (rates belong to each location): your initials > Settings > Labor Rates > New Labor Rate: Name (for example ZZAUTOTEST Rate 100), Rate 100 > Save & Close.

4. Customers > New Customer > Name (for example "ZZAUTOTEST Gap Days Fleet") > Save. On its Contacts tab click New Contact, enter a First Name and Last Name > Save. On its Assets tab click New Asset, pick the contact and fill Year, Make and Unit (for example 2022, Freightliner, ZZ-101) > Save. This is {Customer-A}; use it for this case only.

5. Use a desktop browser window at least 1024 pixels wide at 100% zoom.

6. On the first day, {Day-A}, create and invoice one work order for {Customer-A}: Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation says the customer is over their credit limit, click Create). In the New Line window: What Are You Doing? (for example "ZZAUTOTEST Line 1"), Add Technician (yourself), Labor Rate (the $100 rate of this location), Estimated Time and Tech Time (for example 1.00), tick Line Approved > Save & Close. On the line's Labor row click Start, wait a minute, then Stop > Clock Out. On the line click Story > type a short story > Update. Click Complete (if a Missing Details window asks for Mileage, enter one > Complete All Lines), then Mark Reviewed. Finance tab > Create Invoice, and close the New Customer Payment window without paying.

7. Wait at least two days without invoicing anything at {Location-A}. Then, on {Day-B} (same month), create and invoice a second work order the same way.

8. Instead of a fresh location you may use an existing one only if Reports > Sales (Date: This month) shows invoices on exactly two days with nothing between them; write those days down as {Day-A} and {Day-B}.

9. Check the setup worked: Reports > Sales, Date This month at {Location-A}: invoices on {Day-A} and {Day-B} only, and none on the days between.

Part 2. Setup for Claude session

• Goal: a location whose invoices this month fall on exactly two days at least two days apart.

• This setup spans several days (invoices cannot be back-dated). Record {Day-A}, {Day-B} and the location; run the steps on {Day-B} or later in the same month.

• Prepare the data on screen exactly as Part 1. No API recipe for this case's data has been proven on the Dashboard QA site (UNVERIFIED); if you try one, confirm the result on screen with Part 1's check before step 1.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only.
