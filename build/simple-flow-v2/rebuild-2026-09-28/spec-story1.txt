Story 1**Work Order settings pageAs an admin, I want the settings that drive this flow to read the same way, so that turning one on always means more work rather than less. | **Design**[Shopview App](https://claude.ai/design/p/0c2ed95b-ce68-4b7f-a86d-0e3de1af5a28?file=Shopview+App.dc.html)**Prerequisite** - **Settings › App Settings** (`settingsApp`). The settings route already carries this guard and the new toggle inherits it. No new permission **Requirements** - **One setting is renamed.** *Automatically pick inventory parts* becomes **Require picking inventory parts**     - The new wording means the opposite of the value behind it: auto-pick *off* is picking *required*. So this is a deliberate inversion, not a text change. Changing only the words would leave every shop looking at a toggle that says the opposite of what it does     - The page already does this once: *Require Approval for New Lines* is rendered from `!autoApproveLines` in the same file. Whether the inversion sits at the read and write boundary the same way, or the column is renamed and its values flipped once, is an implementation choice. Either way every shop keeps the behaviour it has today - **One setting is new.** **Require ordering parts** does not exist in the product in any form, so the toggle and the behaviour behind it are both built here. This is the only setting this release adds - **Two settings on the page are already correct and are not touched.** *Require Approval for New Lines* and *Require Receiving Parts Before Completion* already carry those exact names and behave as described. Only the description of the second one changes     - **Trap for whoever builds this:** the toggle labelled *Require Receiving Parts Before Completion* is stored as `requireVendorInvoiceNumber`. The label and the field name say different things. Do not add a second field - **Every default reproduces today's behaviour**, so a shop that upgrades sees no change at all     - **Require ordering parts** — on. Nothing orders parts automatically today     - **Require picking inventory parts** — on. Auto-pick is off by default today, which is the same thing     - **Require receiving parts before completion** — on, which is its default today     - **Require approval for new lines** — on, unchanged - What each of the four does     - **Require ordering parts.***When on, you click Order on each part to record that you've ordered it. When off, parts are marked as ordered automatically.* On: an Order action appears on each qualifying part and in the bulk bar. Off: parts are recorded as ordered automatically and no Order action appears anywhere     - *What *marked as ordered* means when ordering is off. Adding a vendor part places it on a purchase order immediately and the part lands in Awaiting. A purchase order for that vendor is created where none is open, and the part is added to the open one where there is. The part never passes through Auth to order, and no Order action appears anywhere — not on the row, not in the bulk bar, not in the … menu. This is a real purchase order, identical to one created by pressing Order, and it reaches the accounting system the same way. A vendorless part is placed too, on a purchase order marked *Vendor missing\*. It is created silently, with no confirmation. Confirmed by Fabijan, 31 Aug     - **Require picking inventory parts.** *When on, you click Pick on each inventory and found part to record that it's been pulled. When off, these parts are ready as soon as the line is approved.* On: a Pick action appears on each inventory and found part and in the bulk bar. Off: those parts are marked as picked automatically and no Pick action appears     - **Require receiving parts before completion.** *When on, each part must be recorded as received before the work order can be invoiced. When off, you can finish the work order and receive later.* On: outstanding parts block the work order from being invoiced, and a Receive button sits on each part row. Off: outstanding parts do not block invoicing, and Receive moves into the part's … menu     - **Require approval for new lines.** On: a new line is created as Needs Approval. Off: a new line is created as Approved. **The setting governs new lines only and never changes a line that already exists.** This is existing behaviour, stated here so the rule lives in one place — see *Settings apply to every work order* - Switching **Require picking inventory parts** off marks the affected parts as picked. It does not only hide the button, because invoicing checks that inventory parts are picked and a hidden button over unpicked parts would leave the work order un-invoiceable - **Require receiving parts before completion** controls two behaviours, both wanted: whether outstanding parts block the work order from being invoiced, and whether the Receive button sits on the part row or in the part's … menu - The description under that setting currently ends with *complete now and receive later*. That phrase now names a separate feature and is replaced by the description above - The page is grouped into **Workflow**, **Line requirements** and **Parts**, with dividers **Negative cases** - Switching Require ordering on later does not un-order anything. Parts already recorded as ordered stay ordered, and only parts added afterwards need the press - Switching Require picking on later does not un-pick anything. Parts already picked stay picked - No shop's behaviour changes at the moment this ships. The rename preserves its value and the new setting defaults to what the product does today - A role with App Settings but only **Work Orders: View**, such as Office, can configure this page but cannot operate the flow it configures |
