The bulk action bar carries no delete action while this is deferred.**Design**PendingBulk deletion already exists and is stricter than removing a row. Today one ineligible line refuses the whole selection, and that is the only thing this story would change.**Prerequisite** - **WO Lines: Create & Edit**, the same gate as deleting one line. Deletion rules and roles are unchanged from V1 - Lines are selected and the work order is not Complete **Requirements** - Delete the lines that qualify and report the ones that do not. No deletion rule changes - The count on the button is the number of lines that will actually be deleted - A line's contents must be moved to another line on the same work order before it can be deleted, when it holds labour a technician recorded time against, parts, part requests that are still open, or returns still in progress - **A part request counts as finished only once it has been received or returned.** Anything earlier still counts as open and still forces the move - **A line holding received parts cannot be deleted at all until they are dealt with.** The user either moves them to another line or returns them. Returning and then deleting works, and the part stays in returns rather than disappearing with the line. Once the line is gone the part cannot be put back on the work order; it would have to be returned to inventory and added again - The confirmation separates the selection into groups, each hidden when empty     - **Will be deleted**: line numbers only, no controls     - **Choose where the contents go**: one row per line, with a plain summary of what it holds and a dropdown listing every line not being deleted. Rows share a default destination so the common case is one press, and each row can be changed on its own     - **Can't be deleted**: line number and reason in plain words. These lines stay on the work order and are never silently dropped from the selection - The primary button states what will actually happen, for example *Delete 4 lines*, which is usually fewer than the number in the title - Moving and deleting happen together. If anything fails, nothing is deleted and nothing is moved - Deleting a **part** takes it off its purchase order, deletes the purchase order if that was its last item, and marks the purchase order fulfilled if what remains is all received - Deleting a **part** that is partially received does not remove it. The unreceived remainder is cancelled and the part stays, and the result says so, for example *3 of 5 already received; the remaining 2 were cancelled* **Negative cases** - Delete is disabled with the reason when the work order is Complete, rather than hidden - A Complete line inside the selection is excluded and named.
