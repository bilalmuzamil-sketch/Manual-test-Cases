Story 17**The completion wizardAs a user, I want to be asked for what is missing in one place, so that finishing a work order is a short list rather than a hunt across the page. | **Design**[Shopview App](https://claude.ai/design/p/0c2ed95b-ce68-4b7f-a86d-0e3de1af5a28?file=Shopview+App.dc.html)The wizard already exists. This is a redesign and a reordering, not a rebuild.**Prerequisite** - The wizard has opened - Each step carries the permission of the action it performs: tech stories, missing details and core decisions need **WO Lines: Create & Edit**, pick needs **Pick Parts**, receive needs **Order Parts** **Requirements** - The step list is built from the settings and from what is actually outstanding, so a step whose work is already done never appears and a second pass never asks twice - Step order is **Tech stories, Pick parts, Resolve cores, Receive parts, Missing details** - **Only two things change about the sequence.** *Missing details* moves from first to last, and *Tech stories* is folded in as a step instead of being asked just before the wizard opens. Pick, Resolve cores and Receive keep the positions they have today - **Missing details is last**, because mileage and engine hours are work-order information and asking for them first changes the subject - Missing details covers mileage and engine hours, each only when its setting is on and the value is missing. It is asked once per work order, and only when the run is closing every remaining line - **Resolve cores is unchanged.** It appears only when a part in the run carries an unresolved core, and it keeps what it has today: the grouped rows, the resolved count against the total, and the effect on the invoice shown before it is confirmed - Steps appear as pills across the top, each carrying a count where more than one item is outstanding, so tech stories, pick parts and cores all show how many are left - A finished step shows a tick and becomes read-only. Unfinished steps stay clickable, so a user without the mileage to hand can skip ahead and come back - The modal title names the current step, not the flow - **There is no Continue button.** Each step's button is its own action: Save, Pick all, Receive parts. Performing the action saves it and advances in one press - **The receive step's only action is Receive parts.** There is no second action offering to leave the step without receiving. With receiving required there is nothing else that step can do, and a button that does nothing when pressed is exactly what this release removes elsewhere - The action button sits with the content it acts on, not in a footer - Closing the wizard keeps everything already done. Reopening it shows only what is left - The receive step states the outstanding count plainly, for example *3 parts not received* - The receive step opens the same modal as *Receiving from the work order*, so it carries the same required fields and **the same per-part Received later choice**. A user who has a bill for some parts and not others resolves both in one pass. In V1 this step navigated to a full page and lost the user's place - **The wizard never mentions ordering**, even when ordering is required. Anyone who opened it is finishing the job, so a part never marked as ordered is included anyway and the ordering happens without user action when the parts are received - Closing the receive modal returns the user to the wizard at the next step - Where a run ends depends on what opened it     - Complete on a line, or Complete lines: those lines complete, a toast, work order untouched     - Complete all lines: every open line complete, a toast, still on the work order. With review required, this is the moment **Mark as reviewed** appears in the header     - Create invoice: the invoice created, the Finance tab, the payment screen **Negative cases** - A step for work that is not required does not exist. It is not disabled and not skippable - If someone else finishes the outstanding work mid-run, the wizard closes to the outcome rather than showing an empty step - A server error mid-step leaves the step open with the entered values intact |
