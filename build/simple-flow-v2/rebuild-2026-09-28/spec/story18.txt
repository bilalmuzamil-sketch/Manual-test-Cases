Story 18**Create invoice as the finish actionAs an advisor, I want the header to offer what is actually next, so that the biggest button on the screen is never one I cannot use yet. | **Design**[Shopview App](https://claude.ai/design/p/0c2ed95b-ce68-4b7f-a86d-0e3de1af5a28?file=Shopview+App.dc.html)**Prerequisite** - **Create invoice** requires **Invoicing & Payments: Create & Edit** plus **See Financial Data**. Both already exist and Simple Flow only routes to them. A user can hold them through a standard profile or through a custom role with those atoms enabled - **Mark as reviewed** requires **Review Work Orders** (`woReviewWorkOrders`) - Neither is a new permission. Nothing on this story adds an atom **Requirements** - **Mark as reviewed acts on the work order, not on its lines.** It becomes available only once every line is already complete, and pressing it marks the work order reviewed. This is how V1 behaves and none of it changes; the only reason it is written out here is that the header no longer shows a finish action the user cannot yet use - The header offers what is genuinely next, and it depends on whether review is required     - **Review off, any line still open**: New Line, Send, and a … menu holding **Create invoice**     - **Review off, every line complete**: **Create invoice** promoted to a primary button beside New Line, then Send and …     - **Review on, any line still open**: New Line, Send, … and **no finish action at all**. Reviewing needs every line complete and invoicing needs the review, so the next real action is completing the lines, which lives on the line and in the bulk action bar     - **Review on, every line complete, not yet reviewed**: **Mark as reviewed** promoted to a primary button beside New Line     - **Review on, already reviewed**: **Create invoice** promoted in its place     - **Lines selected**: the bulk action bar, whatever the review setting - Only one finish action is ever on screen, and it is only ever one the user can actually press - **Create invoice is refused while any line is still in Needs Approval.** Approving a line is a commitment to the customer and invoicing it is a larger one, so the approval is asked for first — on the line or in the bulk action bar. The action is shown **disabled with the reason** *All lines must be approved before invoicing*, not hidden - **A declined line never blocks it.** Declining is terminal: the work is not performed, the line is not invoiced, and it is skipped entirely - Where every line is approved, Create invoice runs the wizard first if anything required is outstanding, and otherwise proceeds directly - If lines are still open, its confirmation states the invoice total and **how many Approved lines will be completed**. Declined lines are named as excluded rather than counted - On completion the invoice is created, every open Approved line completes, and the Finance tab opens with the payment screen - Where a deposit already covers the whole amount the payment screen is skipped, the work order reads Paid, and the user is told the deposit settled the invoice - Everything that happens today when an invoice is created must keep happening from every entry point: a deposit applying itself, an over-payment becoming a credit, the customer being locked, the accounting sync and the snapshot - *Complete Work Order* is retired as a label everywhere **Negative cases** - **Mark as reviewed never completes a line**, never opens the completion wizard and never asks for a confirmation, because by the time it exists there is nothing outstanding for it to collect - **Closing the payment screen rolls nothing back.** The invoice stands, the lines stay complete, and the work order stays invoiced with a balance owing. This is a standalone statement of how the app already behaves, not a new rollback rule and not conditional on anything else. It is written here because the payment screen is now reached from more places than before - Creating an invoice locks the work order, so no new lines, parts, labour, fees or discounts can be added - With review required, Create invoice is not offered at all until the work order is reviewed - Where every line is declined there is no finish action, because there is nothing to review or invoice - Once an invoice exists, both actions are gone from the header and the … menu - A user who may review but not invoice sees Mark as reviewed and then nothing further. A user who may only complete lines sees nothing in the header - A user without **See Financial Data** does not see Create invoice at all, since it requires that atom - **Nothing approves a line as a side effect of invoicing.** A work order whose lines are all in Needs Approval offers no finish action at all |
