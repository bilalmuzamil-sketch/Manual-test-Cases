Story 21**Permissions on the new surfacesAs an admin, I want the new screens to respect the permissions we already have, so that nobody sees money or takes an action their role does not allow. | **Design**[Shopview App](https://claude.ai/design/p/0c2ed95b-ce68-4b7f-a86d-0e3de1af5a28?file=Shopview+App.dc.html)[SV-8183](https://shopview.atlassian.net/browse/SV-8183) already maps every Simple Flow action to an existing atom. This story adds the one atom that map does not cover and applies the map to the new surfaces.**Requirements** - **One new permission, Received later**, which allows deferring a receive that would otherwise block completion     - It appears in the Work Orders section of the permissions page, as a yes or no toggle rather than a CRUD row     - It is **off by default in every role** and is granted per role     - It is the only atom this release adds - Everything else reuses an existing atom, and the spec names it on each story rather than describing a job title     - Settings page: **Settings › App Settings**     - Completing a line or a work order: **Work Orders: Create & Edit**     - Approving, declining, reordering parts, tech story, mileage, engine hours, core decisions: **WO Lines: Create & Edit** plus **Full View**     - Picking: **Pick Parts**     - Ordering and receiving on a work order: **Order Parts**, which requires **See Financial Data**     - The purchase order pages and assigning a vendor: **Vendor & Order Mgmt: Create & Edit**     - Fixing a part number into the catalogue: **Catalog & Inventory: Create & Edit**     - Marking reviewed: **Review Work Orders**     - Creating the invoice: **Invoicing & Payments: Create & Edit** plus **See Financial Data** - **The bulk version of an action is governed by exactly the same atom as the single version.** This is the whole permission story for the bulk bar: no bulk action introduces a gate of its own - **See Financial Data governs money. View mode governs work.** They answer different questions, so they never compete on the same row: cost, tax, subtotals, totals and sell price follow See Financial Data, while Tech View and Full View decide which actions and which columns of work a user sees - **No money field is ever both hidden and required.** Receiving needs a cost and a tax, and both always arrive prefilled, so a user without See Financial Data receives with those fields removed from the screen and the existing values standing. This is the rule that stops the two permissions deadlocking each other - Where a user cannot see money, those fields are removed rather than masked, and no text that reveals a price by implication is rendered either, such as a warning comparing cost to sell price - Receiving itself is not being changed. The vendor bill is produced as it is today, at the moment it is today, with the vendor and the invoice number both required **Negative cases** - A user without an atom does not see the action at all, in the bulk action bar or on the row. Nothing is shown and then refused - The values behind a hidden field are not sent to a screen that is not allowed to show them - Creating a new vendor keeps the existing vendor-management permission wherever it is offered - Several of these atoms collapse to the same pair on the back end, so a front-end distinction between them is a convenience and not a boundary anyone should rely on.
