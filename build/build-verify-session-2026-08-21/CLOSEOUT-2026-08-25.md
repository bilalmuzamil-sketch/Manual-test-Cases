**A sibling touched Invoice Refresh three minutes before I checked.** Rule 83's 6-hour staleness
threshold is about *abandonment*; **age is a proxy for abandonment, and here the proxy is simply
wrong** — the file is 99 hours old and the work behind it is minutes old. **Clearing it would have
removed a live worker's only signal to everyone else.**

**⇒ TRANSFERABLE, AND WORTH A RULE PROPOSAL:** **judge a lock by the project's COMMIT ACTIVITY, never
by the lock file's timestamp.** A lane that keeps working without re-claiming leaves an
old-looking-but-live claim, which is exactly the case that the staleness rule mishandles. **Proposed
addition to skill 13 §2** (drafted, not recorded — Rule 72): *before clearing any stale claim, check
`git log -- build/<project>/` and the branch tip; if either shows activity inside the staleness
window, the claim is LIVE regardless of its own timestamp — report it and leave it.*
