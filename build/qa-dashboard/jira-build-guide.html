QA Team Dashboard — Jira Build Guide

A copy-paste recipe to assemble the management QA dashboard directly in Jira, using only built-in gadgets. About 15 minutes end to end.

Site shopview.atlassian.net Prepared 13 Jul 2026 Owner Bilal Muzamil QA field QA Assignee (customfield_10385)

Before you start — what this guide builds, and its one honest limit

Jira dashboards are assembled from gadgets, and every gadget reads from a saved filter. So the build is always: create the filters first, then drop gadgets on top of them. Everything here uses stock Jira Cloud gadgets — no paid apps.

Most of the live HTML dashboard reproduces cleanly. A few visual pieces — the ranked bug-hunting leaderboard, the coverage / story % bars, and "since when" / yesterday-vs-today — have no native gadget; the same data is still reachable as a list or a count, just not as that exact visual. Those are flagged throughout.

Create the saved filters

Filters → View all filters → Create filter

Paste each JQL below, run it, then Save as with the name shown. Share every filter with your management group + the QA team — a dashboard renders filters using the viewer's permissions, so an unshared filter shows up as an error for your managers.

Core filters (F1–F13)

F1QA Queue (pending) Tickets waiting in the QA queue — nobody testing yet.
project = SV AND status = "Ready for QA" ORDER BY created ASC
F2Pending staging verification Passed QA-env, now waiting on the staging check.
project = SV AND status = "Merged to Staging" ORDER BY updated ASC
F3In testing now Actively being tested (QA env + staging).
project = SV AND status in ("TESTING QA", "TESTING STAGE")
F3bIn progress — held by a QA engineer A ticket is "in progress" for a QA engineer when its QA Assignee is that person and its status is TESTING STAGE. No label needed — the field + status defines it.
project = SV AND "QA Assignee" is not EMPTY AND status = "TESTING STAGE"
F4QA completed — this month Left the TESTING statuses into Ready for Production / Done = QA passed it.
project = SV AND "QA Assignee" is not EMPTY AND status CHANGED FROM ("TESTING QA", "TESTING STAGE") TO ("Ready for Production", "Done") AFTER startOfMonth()
F5QA completed — TODAY Same as F4 with a daily window.
project = SV AND "QA Assignee" is not EMPTY AND status CHANGED FROM ("TESTING QA", "TESTING STAGE") TO ("Ready for Production", "Done") AFTER startOfDay()
F6QA completed — THIS WEEK Same as F4 with a weekly window.
project = SV AND "QA Assignee" is not EMPTY AND status CHANGED FROM ("TESTING QA", "TESTING STAGE") TO ("Ready for Production", "Done") AFTER startOfWeek()
F7Rejected — this week Tickets QA bounced back to dev. The team's "defects caught" headline.
project = SV AND status CHANGED TO "REJECTED FROM TESTING" AFTER startOfWeek()
F8Stuck in queue > 3 days Aging red-flag list for the pending queue.
project = SV AND status = "Ready for QA" AND NOT status CHANGED AFTER -3d
F9Bugs raised by QA — this month Each tester's find-rate. Group by Reporter for the leaderboard's data.
project = SV AND issuetype in (Bug, "Story Defect") AND reporter in ("Bilal Muzamil", "Ayesha Khan", "Mudassir Qamar", "Viktoria Videnovic", "Nebojsa Glavinic", "Ahtasham Amjad") AND created >= startOfMonth()
F10Open bugs by priority Pie source — "how many criticals are open".
project = SV AND issuetype in (Bug, "Story Defect") AND statusCategory != Done ORDER BY priority DESC
F11Blocked Blockers management can actually clear for you.
project = SV AND status = Blocked
F12Pending with no QA Assignee Catches tickets nobody has picked up. Keeps the whole board honest.
project = SV AND status = "Ready for QA" AND "QA Assignee" is EMPTY
F13QA needs to respond Not-Done tickets whose Assignee is a QA member — a query is waiting on QA. (The HTML "🙋" table.)
project = SV AND assignee in ("Bilal Muzamil", "Ayesha Khan", "Mudassir Qamar", "Viktoria Videnovic", "Nebojsa Glavinic", "Ahtasham Amjad") AND statusCategory != Done ORDER BY updated DESC
F14In a QA member's queue Not-Done tickets whose QA Assignee is a QA member — open testing workload. (The HTML "🧾" table.)
project = SV AND "QA Assignee" is not EMPTY AND statusCategory != Done ORDER BY updated DESC

Only needed if the Two-Dimensional gadget can't group by QA Assignee. For each member X, make an "In testing" and a "Done this week" filter:

F3xIn testing — X
project = SV AND status in ("TESTING QA", "TESTING STAGE") AND "QA Assignee" = "Bilal Muzamil"

Swap the name for each of the six members. Jira autocompletes display names to account IDs as you type — accept the suggestion.

2

Create the dashboard

  1. Open Dashboards → Create dashboard
    Top nav Dashboards → Create dashboard.
  2. Name it
    Call it QA Team Dashboard. Add a short description so managers know what they're looking at.
  3. Share it
    Under Viewers, add your management group and the QA team (or the whole SV project). Editors: just you. Save.
  4. Pick a two-column layout
    ⋯ → Edit layout → the two-column option matches the layout in Step 4.

5

Finish & the one team rule

  1. Test the Two-Dimensional gadget first
    Set its axis to QA Assignee. If that field is missing from the dropdown (Jira Cloud sometimes can't group by a multi-user picker), switch rows 2–3 to Plan B: a row of six Filter Counter gadgets using the per-member F3x / F6x filters. Six small counters read just as well.
  2. Set refresh
    On each chart gadget, set auto-refresh to 15 minutes.
  3. Re-check sharing
    Open the dashboard in an incognito window as a manager would — any gadget showing a filter error means that filter isn't shared. Fix in Filters → the filter → Details → Edit permissions.
  4. Brief the team on the keystone rule
    Every ticket a QA picks up must have that person in the QA Assignee field. The whole dashboard keys off it — and F12 catches anyone who forgets.
