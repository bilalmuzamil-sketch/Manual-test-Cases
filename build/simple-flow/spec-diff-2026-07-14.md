### Δ5 (NEW) — Story 16 R12 auto-complete trigger + R13 clock-out exception — **NET-NEW, UNAPPLIED**
Quoted from the `_3` extract (baseline `requirements.md` §16 has only R1–R11 — R12/R13 absent):

> **R12 — Auto-complete trigger (last open line resolved, any path).** When the WO's last
> remaining open line becomes resolved, the outcome depends on **Require review**: **OFF →
> the WO is auto-marked Complete** (invoice-ready; no extra manual step); **ON → the WO goes
> to Ready for Review** and must be signed off before Complete (unchanged from today).
> Applies regardless of how the last line resolves: **(a) a single line; (b) bulk (several
> at once); (c) split** — if the original and/or newly created WO ends fully resolved, it
> auto-completes; **(d) delete a line** — if the remaining lines end resolved, the WO
> auto-completes.
>
> **R13 — Clock-out exception (intentional).** A clock-out that finishes the last line
> routes the WO to **Ready for Review even when review is OFF** — left as-is on purpose (a
> technician may not be allowed to complete a WO). The one path that does **not**
> auto-Complete when review is OFF.

Plus **new acceptance-criteria lines** (Review OFF single/bulk → Complete; split → Complete;
delete-line → Complete; Review ON → Ready for Review; clock-out → Ready for Review) and the
**new change-log row (2026-07-14, @Milos Vasic)** citing "Dipesh's findings".

**This is the Jira SV-8303 change Ayesha flagged on SF-SET-10.** No existing case covers the
auto-complete-on-last-line matrix or the clock-out exception.
Affected (proposal): sanity **SF-COMP-09** (add-line reopen), **SF-REV-01 / SF-REV-05 /
SF-REV-08 / SF-REV-11** (review-ON path → Ready for Review); **NEW cases required** for the
