# TestRail Case 26344 — Amendment (Reset to Template behavior)

Case URL: https://shopview.testrail.io/index.php?/cases/view/26344

Correction confirmed by product owner: "Reset to Template" resets a custom role's
permissions to its template defaults. The Save button becomes enabled ONLY if the
role had been changed from the template's default options; if the role still
matches the template defaults, clicking Reset to Template makes no change and the
Save button stays disabled (nothing to save).

The prior version of this case only covered the "settings were modified" path and
tied the expected result to a specific Foreman permission matrix; this amendment
corrects it to the confirmed two-path behavior above, in the approved layman
format.

Updated via `update_case/26344` — HTTP 200, verified via `get_case/26344`.

## AFTER

**Title:**
Reset to Template resets a custom role to template defaults; Save is enabled only if the role was changed

**Preconditions (custom_preconds):**
```
1. Log in as a user who can edit roles (e.g. Admin).
2. At least one custom role exists (created from a template).
```

**Steps (custom_steps):**
```
1. Go to Settings > Roles and Permissions.
2. Open the custom role in editable form by clicking the pencil (Edit) icon.
3. Click Reset to Template.
4. Click Save.
```

**Expected (custom_expected):**
```
1. If the role's permissions HAVE been changed from the template's default options: clicking Reset to Template resets the permissions back to the template defaults AND enables the Save button; clicking Save persists the reset.
2. If the role's permissions were NOT changed (they still match the template defaults): clicking Reset to Template makes no change and the Save button stays disabled — you cannot click Save (there is nothing to save).
```
