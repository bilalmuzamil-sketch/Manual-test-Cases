## 1. Where the cases live (storage) — KEY FINDING
- **There is NO local editable case source for Custom Roles.** Unlike Fees &
  Discounts and Simple Flow (which have `cases/*.json` with full bodies), the
  Custom Roles repo holds only:
  - `build/custom-roles-run/run331-tests.json` — a 160-row **test↔case-id map**
    with only `test_id / case_id / title / section_id / section_path` (NO
    preconditions/steps/expected).
  - `run-plan.json`, results logs, workbooks — no editable case bodies either.
- **Consequence:** the wording rewrite CANNOT be done against a local file. It must
  be a **TestRail get_case → edit → update_case** flow (Standing Rule: TestRail is
  the only real system; **explicit write authorization required first**).
- **Cached TestRail pull exists** in `/tmp/testrail/` (Jul 8-9 pull):
  `all_sections.jsonl` (449 sections), `all_cases.jsonl` (3173 cases),
  `run331_cases_full.json`. These let us size scope with **zero new TestRail calls**;
  they are the basis for the counts below (re-pull fresh before editing — cache is
  ~5 days old).

**Recommended storage approach:** before rewriting, **pull the in-scope cases into a
new local `build/custom-roles-run/cases/*.json`** (one file per case, mirroring the
other projects) via `get_case`. Edit locally (resume-safe checkpoint =
committed JSON + `viu_status`/`fresh_run`), then push each area via `update_case`.
This gives the area-by-area resume safety the process requires.
