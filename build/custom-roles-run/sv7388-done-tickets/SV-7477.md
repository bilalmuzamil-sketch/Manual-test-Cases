## Summary

Rewrite `FEPermissionMappings.php` so each new bundle grants the correct atom set. Purify View bundles (remove write atoms) and re-home mis-placed atoms. Apply the **silent cross-area grant** rule (locked decision 4): an area bundle carries the cross-area atoms its flows need (e.g. `WORK_ORDERS_EDIT` carries `ROLE_CUSTOMER::CREATE/CHANGE`).

## Atoms that must move

* `ROLE_WORK_ORDER::CREATE/CHANGE`, `ROLE_VEHICLE::CHANGE`, `ROLE_INVOICE::CHANGE`, `ROLE_WORK_ORDER_LINE::CHANGE` — out of `WorkOrdersPageView` (a _view_ bundle, verified `FEPermissionMappings.php:447-463`) into the matching `*_EDIT` bundles.
* `ROLE_CUSTOMER_TRANSACTION::DELETE` — Customers → `INVOICING_DELETE` (payments are invoicing).
* `ROLE_PO::DELETE` — orphan (`PermissionEnum.php:203`) → `VENDOR_ORDER_DELETE`.

## Open-question atoms (per user: do NOT add net-new unless they already exist)

* `ROLE_SCHEDULE::DELETE` and a part-sale "reverse" atom: if not already defined, **fold into the nearest existing atom** rather than inventing one. Confirm during implementation.
