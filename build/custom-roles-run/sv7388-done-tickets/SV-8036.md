# SV-8036 — Editing Inventory Category Fails with Application Error

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-06-30  **Updated:** 2026-07-07T04:56
- **Link:** https://shopview.atlassian.net/browse/SV-8036

## Description

**Environment :** Staging

‌

**Affected Role:**  
Administrator, or any role with permission to edit Inventory Parts

**Description:**  
Editing an existing inventory item fails when the user changes the **Category** from the dropdown and clicks **Save**.

After the error is triggered once, the edit inventory modal appears to stay in an error state. Any further attempt to update other fields in the same modal, such as **Vendor**, **Manufacturer**, or **Price**, continues to throw the same error.

If the user closes the modal and opens it again, other fields can be updated successfully unless the **Category** field is changed again.

**Steps to Reproduce (STRs):**

1. Navigate to **Parts → Inventory**.
2. Locate any listed inventory item.
3. Open the **Edit Inventory** modal.
4. Change the **Category** from the dropdown.
5. Click **Save**.
6. Observe the application error.
7. Without closing the modal, update another field such as **Vendor**, **Manufacturer**, or **Price**.
8. Click **Save** again.
9. Observe that the same error continues to appear.
10. Close the modal and open it again.
11. Update any field other than **Category** and save.
12. Observe that the update works unless **Category** is changed again.

**Actual Result:**  
The inventory item is not updated when the **Category** is changed, and the following error is displayed:

`Ooooops! An error occurred For more information, please contact support. Include your request ID: [69fd214d-b700-4fc4-8845-c674ea329530] when reaching out for faster assistance.`

After this error occurs, any further save attempt in the same modal also fails, even when changing unrelated fields like **Vendor**, **Manufacturer**, or **Price**.

**Expected Result:**  
The inventory item should update successfully when the **Category** is changed.

After saving, the modal should either close or show a successful update state, and the Inventory list should reflect the updated category. Other fields should continue to save normally and should not be blocked by a previous category update failure.

**Impact:**  
Users are unable to update the category for existing inventory items. Once the issue occurs, the edit modal must be closed and reopened before other inventory fields can be updated, which disrupts inventory management workflows.
