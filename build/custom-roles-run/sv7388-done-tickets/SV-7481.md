## Summary

Implement the API contract agreed in CRP-00 so the FE editor can read/write the full role shape.

## Scope

* Keep the wire format as a flat `fePermissions: string[]` (FE composes grid→codes; cascade is FE-side). Add scalar `viewMode` + `templateId` to `CreateRoleRequestDto`/`ChangeRoleRequestDto`, the Create/Change Commands + handlers, and `Role::create()/change()` signatures.
* Extend `RoleViewOutputDto` (via `ViewController`) to derive + emit `templateId`, `viewMode`, `crossToggles`, and toggle/woSettings/settings booleans (editor renders from one GET).
* Add the `me/fe-permissions` wrapper `{ fePermissions[], viewMode, crossToggles }`.
* Emit `templateId` (+ template name) on the role list DTO for the FE Template column.
* Implement the **admin-capability signal** decided in CRP-00 (replaces the FE `has('Locations')` isAdmin proxy).

## Dependencies

Blocked by **CRP-00** + **CRP-BE-04** (Role model). Once merged, unblocks the FE tickets that need real BE (they can mock until then).

## Acceptance criteria

* \[ \] POST/PUT `/api/roles` round-trips `viewMode`+`templateId`+bundle codes
* \[ \] GET `/api/roles/{id}` returns structured crossToggles/viewMode/templateId
* \[ \] `me/fe-permissions` returns the wrapper with viewMode + crossToggles
* \[ \] Admin-capability flag present in payload
* \[ \] Functional tests for all of the above
