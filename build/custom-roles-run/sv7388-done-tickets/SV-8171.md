# SV-8171 — Timesheets: View role — login hangs indefinitely (spinner) and freezes the browser (Chrome and Firefox); recovery requires clearing cache, closing the browser, and restarting the device. Occurs with Timesheets: View alone or with other permissions

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-07-06  **Updated:** 2026-07-10T07:24
- **Link:** https://shopview.atlassian.net/browse/SV-8171

## Description

**Issue Type:** Bug  
**Suggested Priority:** High (cross-browser login freeze; requires cache clear + device restart to recover)  
**Epic:** SV-7388 (Custom Roles and Permissions)

**Environment:** Staging; reproduced on **Google Chrome and Firefox**

**Affected Area:** Timesheets: View role — login / app load

**Preconditions:**

* Custom role with **Timesheets: View ON**
* Reproduces with Timesheets: View alone, and combined with other permissions (Customers, Schedule, Work Orders: View)
* User is assigned to that custom role

**Steps to Reproduce:**

1. Assign the Timesheets: View role to a user
2. Open the login page (loads normally; credentials can be entered)
3. Enter the custom role user's credentials and click **Log in**
4. Observe the result (repeat on Chrome and Firefox)

**Expected Result:**  
The user should log in and land in a usable state.

**Actual Result:**

* After clicking Log in, the **login button shows a circular spinner and hangs indefinitely** — nothing else happens.
* No other tabs/navigation are usable; the **browser freezes** (reproduced on both **Chrome** and **Firefox**).
* **Recovery requires clearing the browser cache/data, closing the browser, AND restarting the device.** Clearing cache alone is not enough — after clearing cache only, the app shows a **blank white page with a loading indicator** (the ShopView tab shows a spinner) and stays stuck until the browser is closed and the device restarted.

**Scope / Notes:**

* Severe: a hard freeze at login, not a graceful error — takes down the browser tab and requires a device restart to recover.
* **Cross-browser** (Chrome + Firefox), which points to an app-side issue on the Timesheets post-login load path (e.g., an infinite loop / unresolved request) rather than a browser-specific quirk.
* Reproduces with **Timesheets: View alone** and when combined with other permissions (Customers, Schedule, Work Orders: View) — appears tied to Timesheets: View being present.
* Possibly a regression/escalation of **SV-8051** (same Timesheets: View config): SV-8051 reported "Access restricted" on login (recoverable via the ShopView logo), whereas this now presents as a full browser freeze/crash requiring cache clear + device restart. Behavior may have worsened since SV-8051 was filed.
