# SV-7977 — Custom Role Without Reports Permission Shows "Access Restricted" Error on Login Regardless of Other Permissions Enabled

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-06-27  **Updated:** 2026-06-30T15:32
- **Link:** https://shopview.atlassian.net/browse/SV-7977

## Description

**Issue Type:** Bug

**Priority:** Critical

**Environment:** Staging

**Affected Area:** Custom Roles & Permissions — Reports / Access Control

**Preconditions:**

* Custom role is being configured with various permission combinations.
* Reports permission is toggled on/off to observe behavior.

**Steps to Reproduce:**

1. Create a custom role with **all permissions enabled except Reports**.
2. Assign this role to a user and log in.
3. Observe that the **Access Restricted** error appears on login despite all other permissions being enabled.
4. Go back to the role settings and enable **Reports** in addition to all other permissions.
5. Log in again as the same user.
6. Observe that the Access Restricted error is gone and the user is correctly redirected to the Work Orders list.
7. Now create a role with only **Work Orders: View** and **Reports** enabled (All other permissions are disabled)
8. Log in as that user.
9. Observe that the user lands on the Work Orders list without any Access Restricted error.

**Expected Result:**  
The Reports permission should not be a dependency for a user to successfully log in and access the areas they are permitted to. A custom role with any valid permission set should be able to log in without encountering an Access Restricted error, regardless of whether Reports is enabled.

**Actual Result:**  
Without the Reports permission enabled, the user consistently sees an **Access Restricted** error immediately after logging in — even when all other permissions are enabled. Enabling the Reports permission resolves the login error and correctly redirects the user to the Work Orders list. This means Reports is acting as an unintended login dependency.

**Notes:**

* The Access Restricted error for Work Orders View-only roles was previously reported in **SV-7975**.
* This ticket extends that finding — the root cause appears to be that the Reports permission is required for a successful login redirect, regardless of what other permissions are configured.
* A role with only **Work Orders: View + Reports** enabled successfully logs in and lands on the Work Orders list without any errors.
* Reports should not be a required permission for basic platform access or login routing.
* This is a **critical data exposure issue** and the Reports permission needs to be properly scoped to prevent financial information from leaking to unauthorized roles.
