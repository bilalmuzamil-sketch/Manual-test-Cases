# SV-8141 — Clarification: Is the "Time Clock" Staff Toggle Intended to Control All Clock In/Out Functionality for Time Clock Users?

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-03  **Updated:** 2026-07-06T16:15
- **Link:** https://shopview.atlassian.net/browse/SV-8141

## Description

During validation of the **Time Clock** role, it was observed that a user cannot clock in or out unless the **Time Clock** toggle is enabled in the **Edit Staff** modal.

Disabling the **Time Clock** toggle has the following effects:

* The **Clock In/Out widget** in the top-right corner disappears.
* The **Start** and **Stop** CTAs disappear from Work Order Lines and Department clock-in.
* The user is effectively unable to clock in or out anywhere in the application.

This behavior appears to indicate that the **Time Clock** toggle in **Staff → Edit Staff** is a master switch controlling all time clock functionality, regardless of the user's assigned role.

**Steps to Reproduce (STRs):**

1. Create or use a user with the **Time Clock** role.
2. Navigate to **Settings → Staff**.
3. Edit the staff member.
4. Toggle **Time Clock** **OFF**.
5. Log in as that user (or refresh the session).
6. Observe the available clock-in functionality.

**Actual Result:**

* The **Clock In/Out widget** disappears.
* The **Start** and **Stop** buttons are no longer available.
* The user cannot clock in or out for a **Work Order Line** or a **Department**.

**Expected Result / Clarification Needed:**  
Please confirm whether this is the intended behavior.

* Is the **Time Clock** toggle in **Edit Staff** designed to be a prerequisite for all clock-in/clock-out functionality?
* Should users with the **Time Clock** role always require this toggle to be enabled in order to use the Time Clock widget and Start/Stop actions?

If this is the intended design, the current behavior can be considered **Working as Designed**. Otherwise, the implementation or documentation should be updated accordingly.

### Sasha Grosman — 2026-07-06T16:08

We did not modify this functionality. 

TL;DR the staff Time Clock setting enables users to Clock in and out of everything.  
  
Quick claude digest:

Staff "Time Clock" toggle = staff.clockable

It's a functional permission that gates whether a staff member can use the time clock. Specifically, when ON it enables/controls:

* Clock in / clock out — the check-in and check-out endpoints hard-reject the action if the staff member isn't clockable (CheckInCommand.php:80 → "You are not allowed to clock in"; CheckOutController.php:43 → "Staff is not clockable").
* Time-clock UI visibility — clockable is carried in the auth/session payload (LoginUserService.php:124, UserProvider.php), so the app knows whether to surface time-clock features for that user.
* Appearing in time-clock / work-order listings that filter s.clockable = 1 (e.g. the WO snapshot provider, staff listings).
* Eligibility for the "Lead technician" dropdown on work orders — that list requires s.clockable = 1 (which is why we saw it earlier as a filter).
