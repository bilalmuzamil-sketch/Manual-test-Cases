# SV-8107 — Custom Roles: Tech view exposes WO-line labor rate when See Financial is ON

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-02  **Updated:** 2026-07-03T23:28
- **Link:** https://shopview.atlassian.net/browse/SV-8107

## Description

## User-facing

When a role is set to **Tech** view mode, technicians should not see labor rates. But if that role also has **See Financial Data ON**, the **labor rate appears anyway** on the work order's Lines tab — breaking the promise of Tech view and leaking confidential rate info to restricted users.

## Steps to reproduce

1. Create a custom role: View Mode = **Tech**, **See Financial Data = ON** (plus Work Orders View, WO Lines Create/Edit, Catalog & Inventory View, Invoicing View).
2. Assign to a user; log in; open any work order → **Lines** tab.
3. The lines table shows a **"Rate"** column with the dollar labor rate.

## Expected

In Tech view, labor rates stay hidden on WO lines **regardless of** See Financial Data. Other pricing (parts cost/totals) may still show; only the labor rate must be suppressed (spec §4 "Tech view — Cannot view labor rates").

## Actual

The "Rate" (labor-rate) column renders. Also affects mobile line cards and the new-line dialog labor-rate field.

## Root cause (FE)

The labor-rate column is gated on `seeFinancialData` alone, with no view-mode check:

* `app/src/components/ts/work-orders/work-order-lines/WorkOrderLineRow.vue:185` → `<q-td v-if="seeFinancialData" key="labour_type">` (computed at :548, no `isTechView`/`woTechViewMode`).
* `WorkOrderLines.vue:1086-1092` `getColumns()` strips `labour_type`/`cost`/`margin` only when `!seeFinancialData()`.
* Same in `WorkOrderLineCard.vue:171` and `LineDialog.vue:106-118` (new-line path).

## Suggested fix

Gate the labor-rate column/field on `seeFinancialData && !isTechView` (spec §4 is a view-mode rule, so the FE guard is the right home).

## Evidence

E2E `C27558` (`e2e/tests/permissions/custom/sv7388-adversarial-enforcement.spec.ts`) asserts the Rate column `toHaveCount(0)` under this role — **fails on stage** (received 1). Kept as an intentional red bug-guard; flips green when fixed.
