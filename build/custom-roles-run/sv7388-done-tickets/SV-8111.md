# SV-8111 — FE - Canceling "Move Part" Displays Lines from a Different Work Order While URL and Work Order Number Remain Unchanged

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-07-03  **Updated:** 2026-07-08T10:01
- **Link:** https://shopview.atlassian.net/browse/SV-8111

## Description

**Affected Role:**  
Any Role

**Description:**  
When using the **Move Part** feature, selecting a different Work Order immediately loads the lines from the selected Work Order into the current screen.

If the user then **cancels** the move operation, the application does not restore the original Work Order state. Instead, it continues displaying the lines from the previously selected Work Order, while the **URL** and **Work Order number** still belong to the original Work Order.

This results in the Work Order details and the displayed lines becoming out of sync.

**Steps to Reproduce (STRs):**

1. Open any **Work Order** containing a part.
2. Open the part and select the **Move** action.
3. Select a different **Work Order** from the Work Order dropdown.
4. Observe that the destination Work Order's lines are displayed.
5. Click **Cancel** to cancel the move operation.

**Actual Result:**

* The **URL** remains that of the original Work Order.
* The **Work Order number** remains that of the original Work Order.
* However, the page displays the **lines from the destination Work Order** that was selected during the move operation.

**Expected Result:**  
Canceling the move operation should completely restore the original Work Order. The displayed lines, URL, and Work Order number should all remain synchronized and represent the same Work Order.
