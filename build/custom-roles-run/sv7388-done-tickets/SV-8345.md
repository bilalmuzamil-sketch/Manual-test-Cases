# SV-8345 — Implement hard-coded rule: Office users cannot create invoices BUT they can make payments.

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-14  **Updated:** 2026-07-15T01:22
- **Link:** https://shopview.atlassian.net/browse/SV-8345

## Description

Per the Custom Roles spec (page 565116952, added in the 7/7 change), Office users **must be able to make payments** but must **not** be able to **create invoices**. This requires a hard-coded rule that overrides the standard Invoicing & Payments CRUD.

**Requirement:**

* A hard-coded rule for Office users disables the **Create Invoice** button on both **Work Orders** and **Part Sales**.
* This rule **overrides** the Invoicing & Payments CRUD (i.e. even if Invoicing CRUD would otherwise allow it, Office cannot create invoices).
* Office users can still make/process payments.

**Acceptance Criteria:**

1. An Office user does not see a usable Create Invoice button on Work Orders.
2. An Office user does not see a usable Create Invoice button on Part Sales.
3. The rule applies regardless of the Office role's Invoicing & Payments CRUD configuration.
4. Office users can still process payments (verify the payment path remains available).

**Spec reference:** https://shopview.atlassian.net/wiki/spaces/PM/pages/565116952 (v49) — "Office Users Cannot Create Invoices" (Migration Plan subsection + Key Decisions row); change log 7/7.
