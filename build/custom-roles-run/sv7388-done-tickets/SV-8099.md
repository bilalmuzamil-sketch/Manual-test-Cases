# SV-8099 — Billing Portal role: "Return to ShopView" from the Billing Portal shows "Access restricted" — user can reach and use the portal (via avatar → Settings) after the login Access restricted, but cannot return to the app

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-07-02  **Updated:** 2026-07-07T09:16
- **Link:** https://shopview.atlassian.net/browse/SV-8099

## Description

**Issue Type:** Bug  
**Epic:** SV-7388 (Custom Roles and Permissions)

**Environment:** Staging 

**Affected Area:** Billing Portal — "Return to ShopView" path

**Preconditions:**

* Custom role with **Billing Portal access ON** only
* No other permissions enabled
* User is assigned to that custom role

**Steps to Reproduce:**

1. Log in as the custom role user → "Access restricted" appears **(already reported SV-8076)**
2. Open the **Billing Portal** via the top-right avatar → Billing
3. Perform Billing Portal actions (works)
4. Click **Return to ShopView** on the Billing Portal
5. Observe the result

**Expected Result:**  
Clicking "Return to ShopView" should return the user to a usable state in the app. (And a Billing-Portal-only role should ideally not land on "Access restricted" on login in the first place.)

**Actual Result:**

* On login, "Access restricted" appears.
* The user can reach and use the **Billing Portal** via the avatar → Billing.
* Clicking **Return to ShopView** shows **"Access restricted"** — the user cannot return to the app.

**Scope / Notes:**

* The **"Access restricted" on login** is the same systemic single-area landing pattern reported separately (Billing Portal is another affected area).
* The **distinct/new issue** is the broken **Return to ShopView** path from the Billing Portal → "Access restricted." Similar in shape to the Send-to-Terminal return-path issue (SV-8087), where an external portal is reachable but the return-to-app path fails.
