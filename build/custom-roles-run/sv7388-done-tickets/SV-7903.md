# SV-7903 —  Clarify intended behavior — Parts Technician has Invoicing: Create and Edit, but invoicing depends on line approve/complete/review steps the role cannot perform

- **Type:** Task
- **Status:** OBSOLETE

## Description

Per spec, Parts Technician has **Invoicing and Payments: Create and Edit**, so the role is intended to be able to create invoices.

However, in the build, creating an invoice on a work order is only possible once the work order line has been **approved, completed, and reviewed** first. Those upstream actions require permissions the Parts Technician does NOT have:

* Approve/authorize a line and edit line status → requires **Work Order Lines: Create and Edit** (Parts Technician = View only).
* Review a work order → requires **Review Work Orders** (Parts Technician = OFF).

So in practice a Parts Technician can only create the invoice if someone else has already approved/completed/reviewed the line — the role holds the final step but not the prerequisites.

**Question for the product owner:** Is this intended? The spec grants Invoicing: Create and Edit to Parts Technician but does not describe a required approve → complete → review → invoice sequence. Should Parts Technician be able to create invoices given they cannot perform the prerequisite line steps, or should the role's invoicing/line permissions be reconciled?

**Spec references:**

| Setting | What the spec says |
| --- | --- |
| Permission Matrix → Invoicing | Parts Technician = View / Create and Edit |
| Permission Matrix → Work Order Lines | Parts Technician = View only (cannot approve/edit lines) |
| Permission Matrix → Review Work Orders | Parts Technician = OFF |
| Invoicing → Create and Edit "Controls" | "Create invoices, process payments directly from work orders and part sales, manage invoice fields, collect deposits, send payments to terminal." |

**Note:** The approve → complete → review → invoice sequence is observed build/workflow behavior; the spec defines these permissions independently and does not document this dependency chain.
