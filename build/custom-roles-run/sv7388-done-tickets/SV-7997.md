# SV-7997 — "Failed to Load Work Order Lines" Error Persists Even After Enabling Work Order Lines Create & Edit — Resolved Only When Customers Permission is Enabled

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-06-28  **Updated:** 2026-07-03T05:32
- **Link:** https://shopview.atlassian.net/browse/SV-7997

## Description

**Issue Type:** Bug

**Environment:** Staging

**Affected Area:** Custom Roles & Permissions — Work Order Lines / Customers Permission Dependency

**Preconditions:**

* Custom role has **Work Orders: View Checked**
* **Work Order Lines: Create & Edit** **Checked**
* All other permissions are disabled.
* A similar issue for Work Orders View-only roles was previously reported in **SV-7976**.

**Steps to Reproduce:**

1. Create a custom role with **Work Orders: View** and **Work Order Lines: Create & Edit** enabled. All other permissions off.
2. Assign this role to a user and log in.
3. Navigate to the Work Orders list and open any Work Order.
4. Observe the error that appears.
5. Go back to the role settings and enable the **Customers** permission.
6. Log in again and open a Work Order.
7. Observe that the error no longer appears and Work Order Lines load correctly.

**Expected Result:**  
A custom role with Work Orders: View and Work Order Lines: Create & Edit enabled should be able to open a work order and load its lines without any errors. The Customers permission should have no bearing on the ability to load Work Order Lines.

**Actual Result:**  
Even with Work Order Lines: Create & Edit enabled, opening a work order still triggers the error:

> _"Failed to load work order lines. Error fetching work order lines."_

The error only disappears and Work Order Lines load correctly after the **Customers** permission is also enabled — indicating an unintended dependency between Work Order Lines and the Customers permission.

**Notes:**

* A similar "Failed to load work order lines" error for Work Orders View-only roles was previously reported in **SV-7976** — this ticket extends that finding by showing the error persists even after enabling Work Order Lines Create & Edit.
* The Customers permission should not be a dependency for loading Work Order Lines. This appears to be an unintended permission coupling.
* Enabling Customers as a workaround is not acceptable as it grants the user unintended access to customer data.
