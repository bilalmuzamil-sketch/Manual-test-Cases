# SV-7871 — Vendor transaction reverse / payment delete blocked when Manage AP/AR is OFF — action is trapped behind the AP/AR-gated Payments tab

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-06-24  **Updated:** 2026-07-10T12:39
- **Link:** https://shopview.atlassian.net/browse/SV-7871

## Description

Per spec, reversing vendor transactions is granted by **Vendor and Order Management: Delete** (and invoice/payment reverse/delete by **Invoicing and Payments: Delete**).

* In the build, these reverse/delete actions live **inside the Unpaid Invoices / Payments tabs** (Parts → Vendors → a vendor). Those tabs only appear when **Manage Accounts Payable and Receivable** is ON.
* Result: a role with the Delete permission but Manage AP/AR OFF (e.g. **Parts Technician** — Vendor & Order = View/Create and Edit/Delete, Manage AP/AR = OFF) **cannot reach the reverse action**, even though the spec grants it.

**Spec references:**

| Permission | What the spec says it controls |
| --- | --- |
| Vendor and Order Management → Delete | "Delete vendors, delete purchase orders, reverse vendor transactions." |
| Invoicing and Payments → Delete/Reverse | "Reverse invoices, delete payments (including customer payments), void transactions." |
| Manage Accounts Payable and Receivable (`seeApArData`) | Visibility of "the Unpaid Invoices, Payments, and Credits tabs on Customer and Vendor detail pages." (Visibility only — spec does not say it gates the reverse/delete action.) |

If **Vendor and Order Management → Delete** is intended to be accessible through the **Vendor Payments** section, and access to the Vendor Payments section itself depends on **Manage AP/AR Data → View and Manage AP/AR Data** being enabled, then enabling **Vendor and Order Management → Delete** should prompt the user to also enable **Manage AP/AR Data → View and Manage AP/AR Data**.

Otherwise, users may grant the Delete permission but still be unable to access the Vendor Payments section required to perform the deletion, making the permission configuration confusing and difficult to understand.

Permission dependencies should be clearly surfaced to users during configuration to ensure the intended functionality is actually accessible.
