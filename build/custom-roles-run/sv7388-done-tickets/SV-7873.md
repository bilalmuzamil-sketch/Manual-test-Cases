# SV-7873 — No Permission Dependency Warning When Delete/Reverse Permissions Require AP/AR Visibility to Be Usable

## Description

**Duplicate of** <custom data-type="smartlink" data-id="id-0">https://shopview.atlassian.net/browse/SV-7871</custom> 

---

* Per spec, reversing vendor transactions is granted by **Vendor and Order Management: Delete** (and invoice/payment reverse/delete by **Invoicing and Payments: Delete**).

But placing the check mark for  **Vendor and Order Management: Delete  does not help**

‌

Because:

* In the build, these reverse/delete actions live **inside the Unpaid Invoices / Payments tabs** (Parts → Vendors → a vendor). Those tabs only appear when **Manage Accounts Payable and Receivable** is ON.

---

### **Example Scenario:**

A role is configured with:

* **Vendor & Order Management → Delete = ON**
* **Manage Accounts Payable & Receivable = OFF**

Per the specification, the Delete permission grants:

> "Delete vendors, delete purchase orders, reverse vendor transactions."

However, the reverse transaction actions are currently located inside:

* Vendor → **Payments**
* Vendor → **Unpaid Invoices**

These tabs are hidden when **Manage Accounts Payable & Receivable** is OFF.

Therefore, the user cannot access the reverse action despite having the permission that supposedly grants it.

---

### **Actual Result:**

* Admin can enable **Delete/Reverse** permissions.
* No warning or dependency information is shown.
* End users cannot access the corresponding actions because the required AP/AR tabs are hidden.
* The permission appears enabled but is not practically usable.

---

### **Expected Result:**

When enabling permissions such as:

* Vendor & Order Management → Delete
* Invoicing & Payments → Delete/Reverse

the system should clearly inform the administrator of any additional permissions required to access those actions.

Examples:

> **This permission grants the ability to reverse vendor transactions. To access these actions, "Manage Accounts Payable & Receivable" must also be enabled.**

or

> **The selected permission depends on AP/AR visibility settings. Users will not be able to access the associated actions unless AP/AR access is granted.**

Alternatively, the system could automatically surface the dependency and offer to enable the required permission.
