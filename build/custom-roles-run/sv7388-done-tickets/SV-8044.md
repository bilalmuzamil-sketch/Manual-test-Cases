# SV-8044 — Digital Inspections — inspection filler is editable & submittable for roles WITHOUT Work Order Lines: Create & Edit (should be read-only)

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-06-30  **Updated:** 2026-07-07T09:24
- **Link:** https://shopview.atlassian.net/browse/SV-8044

## Description

**Summary**
A user whose role does NOT grant **Work Order Lines: Create & Edit** can still open an in-progress inspection and see a **fully editable filler with an active "Submit & Generate Report" button**. Per the Digital Inspections spec the inspection should open **read-only** for these roles (view access only). The filler does not enforce the user's edit permission — its read-only state is derived only from the _inspection's own state_ (e.g. line completed / already submitted), never from the viewing user's Work Order Lines permission.

**Affected roles (system roles that have Work Orders: View but Work Order Lines: View only — no Create & Edit):**

* Parts Technician
* Office

(Verified on staging that neither role's `fe_permissions` include `workOrderLinesCreateAndEdit`.)

**Preconditions**

* A Work Order with an in-progress inspection on a line.
* A user assigned to **Parts Technician** or **Office** (or any role with Work Order Lines = View, no Create & Edit).

**Steps to Reproduce**

1. Log in as Parts Technician (or Office).
2. Open the Work Order and expand the line that has the in-progress inspection.
3. Click the inspection's **Open** control.

**Expected (per spec)**

* The inspection opens **read-only**: items cannot be filled/edited, and there is **no** active "Submit & Generate Report" button (the role lacks Work Order Lines: Create & Edit).

**Actual (staging)**

* The filler opens in **editable** mode: inspection items are editable, the progress/save UI is shown ("All changes saved"), and the **"Submit & Generate Report" button is active**. The read-only filler state (`filler_read_only_status`) is not shown.

**Impact**
View-only roles can fill out and submit/complete inspections (and generate reports) that they should only be able to view. Note: this is the _inverse_ of SV-7985 (which covers a role _with_ Create & Edit performing delete/reopen). This ticket is specifically about roles _without_ Create & Edit being able to fill/submit.

**Likely root cause (FE)**
`DesktopFiller` gates editability/submit on the inspection's `isReadOnly` (inspection/line state) only. There is no per-user permission check (`workOrderLinesCreateAndEdit`) on the filler's edit controls or the Submit button. By contrast, the WO line-level affordances (Add / bin) ARE correctly gated by `workOrderLinesCreateAndEdit`, so the gap is specific to the inspection filler. BE enforcement of the save/submit endpoints for these roles should also be confirmed (guardChange → ROLE_WORK_ORDER::CREATE_AND_EDIT).

**Test coverage**
Caught by the E2E DVI per-role matrix (TestRail §3629): C27353, C27354 (Parts Technician D/E) and C27364, C27365 (Office D/E). These cases assert the spec (read-only) and currently fail against staging, flagging this bug.
