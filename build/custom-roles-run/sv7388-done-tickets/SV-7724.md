# SV-7724 — BE - Customer Portal and Billing portal fail to open — CORS error on sso-login

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-06-17  **Updated:** 2026-07-03T11:43
- **Link:** https://shopview.atlassian.net/browse/SV-7724

## Description

Both external portals launched from the top-right user (avatar) menu are inaccessible. The "Customer Portal" item (tagged "New") and the "Billing" item each trigger an SSO handoff to open the portal in a new tab. During that handoff the `sso-login` request is blocked by a CORS error, so the SSO flow never completes and neither portal loads. This reproduces consistently on both launch points, pointing to a single shared root cause in the SSO/cross-origin configuration rather than an issue with either portal individually. Observed on SV4235 QA (<custom data-type="smartlink" data-id="id-0">http://sv4235.qa.shopview.com</custom> ) while signed in as an admin (mudassir.qamar+admin@…, Lethbridge-4310).

**Steps:**

1. Sign in to SV4235 QA as an admin.
2. Open the top-right avatar (MQ) menu.
3. Click Customer Portal (or Billing).
4. Observe the new-tab/SSO handoff and the Network panel.

**Priority:** High — both customer-facing portals are completely unreachable, blocking any portal testing.

**Expected Result:** The SSO handoff completes successfully and the selected portal (Customer Portal or Billing) opens in a new tab, fully loaded and authenticated.

**Actual Result:** The `sso-login` XHR (initiator `index.ts:20`, \~397 ms) is blocked by a CORS error. The SSO flow fails, the new tab does not load the portal, and the action dead-ends. Reproduces identically on both the Customer Portal and Billing launch points. Likely a backend CORS allowlist missing the portal origin; confirm whether it also reproduces outside QA.
