# SV-8080 — [Clarification] Part Sales: Create & Edit lets user pick, order, receive, and authorize part requests within a part sale while WO Pick Parts / Order Parts sub-settings are OFF — confirm whether these parts-sourcing actions are intended to be included

## Description

**Issue Type:** Question / Clarification (Task or Story — per your process)  
  
**Epic:** SV-7388 (Custom Roles and Permissions)

**Environment:** Staging

**Affected Area:** Part Sales — parts-sourcing actions (pick / order / receive / authorize) vs. Work Orders Pick/Order Parts sub-settings

**Preconditions:**

* Custom role with **Parts Department ON**, **Part Sales: View + Create & Edit ON**
* **See Financial Data ON** (required by the Part Sales financial gate)
* **Work Orders: Pick Parts and Order Parts sub-settings: OFF** (and Work Orders area not enabled)
* No other permissions enabled

**Steps to Reproduce:**

1. Log in as the custom role user
2. Go to Parts → add a new **Part Sale** (or a special-order part sale)
3. Within the part sale, attempt to: **pick** a part, **order** a part, **receive** a part, and **authorize/approve** the part request

**Observed Behavior:**  
With only Part Sales: View + Create & Edit enabled, the user can **pick, order, receive, and authorize** parts within a part sale — even though the Work Orders **Pick Parts** and **Order Parts** sub-settings are OFF in the role editor.

**Question for PM (spec is silent on this intersection):**  
The spec defines **Pick Parts / Order Parts** only in the **Work Orders** sub-settings context (§4) — governing picking/ordering onto a **work order line**. It defines **Part Sales: Create & Edit** (§1e) as "create part sales, create part returns, process part transactions," but does **not** explicitly enumerate whether parts-sourcing actions (pick / order / receive / authorize) _within a part sale_ are included.

Please confirm the intended behavior:

1. Are the parts-sourcing actions (pick / order / receive / authorize) inside a Part Sale **intended to be included** in Part Sales: Create & Edit — i.e., independent of the Work Orders Pick/Order Parts sub-settings (which govern the WO context only)?
2. Or should these actions in the Part Sales context be **gated separately** (e.g., by the Pick/Order Parts sub-settings or another permission)?

**Context / Rationale:**

* A plausible reading is that Part Sales: Create & Edit inherently includes sourcing parts for the sale (a special-order part sale cannot be processed without ordering/receiving the part), and that the WO Pick/Order Parts sub-settings apply only to the work order context — in which case the observed behavior is expected.
* Flagging so the intended scope of Part Sales: Create & Edit (with respect to parts sourcing) is documented in the spec, rather than assumed by QA/dev.

**Spec references:**

| # | Section | Verbatim quote |
| --- | --- | --- |
| 1 | §1e Part Sales, Create and Edit row | "Create part sales, create part returns, process part transactions." |
| 2 | §4 WO Sub-Settings, Pick Parts | "Pick parts from inventory onto a work order line. Move parts between work orders." |
| 3 | §4 WO Sub-Settings, Order Parts | "Place a purchase order for parts needed on a work order… Also controls receiving parts deliveries onto a work order." |
| 4 | §4 WO Sub-Settings (gate) |  |
