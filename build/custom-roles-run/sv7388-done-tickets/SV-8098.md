# SV-8098 — Custom role with Settings + Parts sub-setting lands on “Access restricted” + “Unable to check QuickBooks” on login, and the Parts settings section is never reachable (loads briefly, then “Access restricted” repeatedly on each Settings click)

## Description

**Issue Type:** Bug  
  
**Epic:** SV-7388

**Environment:** Staging

**Preconditions:**

* Custom role with **Settings ON** and **Parts sub-setting ON**
* No other permissions enabled
* User is assigned to that custom role

**Steps to Reproduce:**

1. Log in as the custom role user → "Access restricted" with "Unable to check QuickBooks" error appears
2. Click the **Settings** tab (top-right avatar)
3. Observe the Parts sub-setting section and any error toasts

**Expected Result:**  
With Settings + Parts sub-setting enabled, the user should be able to open the Parts settings section.

**Actual Result:**

* On login, "Access restricted" appears, along with an **"Unable to check QuickBooks"** error toast in the bottom-right.
* Clicking the **Settings** tab still shows "Access restricted"; the **Parts** sub-setting loads for a moment (≈a nanosecond) and then shows "Access restricted" again.
* This repeats every time the Settings tab is clicked — the Parts settings section is **never reachable.**

**Scope / Notes:**

* **Distinct from the systemic "Access restricted" on login issue:** in that case, clicking the tab lets the user open the section. Here, the Parts settings section never becomes reachable — it loads briefly then reverts to "Access restricted" repeatedly.
* The brief load-then-"Access restricted" suggests the page starts rendering before an access check resolves and fails.
* The **"Unable to check QuickBooks"** error on login suggests a background QuickBooks/integration check firing for a role that has no such access.
* **Spec update suggestion (Parts sub-setting contents):** During the brief load, the Parts settings section shows **pricing matrices, Bin Locations, and categories**. The spec's Parts sub-setting description (§3) lists "pricing matrices, categories, parts-specific configuration" but does not name **Bin Locations**. Please update the spec to include Bin Locations, or confirm it is intended to fall under "parts-specific configuration."

**Spec update for PM:**

1. The build shows **Bin Locations** under Parts settings, not named in the spec's Parts sub-setting description — please update the spec to include Bin Locations, or confirm it falls under "parts-specific configuration."

**Spec references:**
