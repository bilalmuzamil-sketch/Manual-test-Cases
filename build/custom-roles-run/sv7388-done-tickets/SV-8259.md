## Description

**Description:**  
On the QuickBooks Unexported Items report, clicking **Export** in the "Export Manually" column does nothing — no download, no success toast, no error. The row stays in the list. Feature looks non-functional.

**Steps to Reproduce:**

1. Open Reports › QuickBooks Unexported Items
2. On any tab (Customers / Vendors / Journal Entries), pick a row
3. Click **Export**

**Expected:** The item exports to QuickBooks (or a clear result/error shows), and the row updates.

**Actual:** Nothing happens — no result, no message, row unchanged.

Hi <custom data-type="mention" data-id="id-0">@Mudassir Qamar</custom> <custom data-type="mention" data-id="id-1">@Bilal Muzamil</custom>,

I checked this, and the **Retry** action is actually working as expected.

When **Retry** is clicked, the system sends the retry API request (you can see it in the **Network** tab), and the API returns **200 OK**.

As part of the retry process, the old unexported record is deleted. Then one of two things happens:

* if the export succeeds, no new unexported record is created;
* if the same export error occurs again, a new unexported record is created with the same error message and the same data.

In this case, the export failed again, so the original record was removed and a new one was created with the same error. Since the report only shows the **date** (not the time) when the record was created, both the old and the new record appear to have the same date, making it look like nothing changed.

This is how the system has worked since this feature was introduced. If we want to make this behavior clearer (for example, by storing/displaying the time or providing additional UI feedback), we should create an improvement ticket with the expected behavior specified. <custom data-type="mention" data-id="id-2">@Sasha Grosman</custom>
