# SV-8205 —  Cannot Re-Enable Time Clock for the existing Time clock users After Migration Due to Incorrect Toggle State

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-07-08  **Updated:** 2026-07-13T09:37
- **Link:** https://shopview.atlassian.net/browse/SV-8205

## Description

**Affected Role:**  
Technician (existing users after migration)

**Description:**  
After deploying the latest fixes to **Staging**, existing user with the **Technician** role  automatically got the Time clock toggled-off and now the Admin cannot re-enable the time clock toggle for the technician.

Although the **Time Clock** toggle is already **OFF**, attempting to enable it is blocked because the application incorrectly displays the tooltip:

> **"Cannot turn time clock off with the role Technician."**

‌

**Steps to Reproduce (STRs):**

1. Log in as an Admin on the Staging account
2. Navigate to Settings → Staff
3. Edit the Technician user.
4. Attempt to **enable** the **Time Clock** toggle.

**Actual Result:**

* The toggle cannot be enabled.
* The following tooltip is displayed:

> **"Cannot turn time clock off with the role Technician."**

even though the toggle is already **OFF** and the user is attempting to turn it **ON**.

V-8205 — FE Handoff: Time Clock toggle locked for Technician

Area: Frontend (app/) · Type: Bug · Epic: SV-7388 Custom Roles & Permissions

Summary

On the Staff dialog, the Time Clock toggle is locked for users whose role is Technician, Foreman, or Service Advisor Technician. When such a user has Time Clock off (e.g. after the Staging migration), the admin cannot turn it back on, and an incorrect tooltip shows: "Cannot turn time clock off with the role Technician" — even though it's already off and the admin is trying to turn it on.

Root cause

app/src/components/office/ts/StaffDialog.vue hardcodes three role labels as "always clockable" and uses that to disable + force the toggle. This is a legacy holdover that contradicts the current spec.

Offending pieces (line numbers approximate — match on the code):

* \~L442–449 — the hardcoded lock:  
  const roleHasTimeClockFunc = computed(() => {  
  const validRoles = new Set(\['Technician', 'Foreman', 'Service Advisor Technician'\]);  
  return validRoles.has(role.value?.label ?? '');  
  });
* \~L186 — :disable="roleHasTimeClockFunc" on the toggle_time_clock q-toggle
* \~L192–194 — <q-tooltip v-if="roleHasTimeClockFunc"> with the Cannot turn timeclock off with the role '...' text
* \~L670 — inside onRoleInput: staff.value.clockable = roleHasTimeClockFunc.value; (force-sets clockable from role)

What the spec says (authoritative)

"Custom Roles and Permissions" (PM space, page 565116952, epic SV-7388):

* Key Decision — "Job clocking = staff record, not permission": whether a user can clock into WO line tasks is controlled by the Time Clock setting on their staff record.
* Cross-cutting behaviors: "Any user with Time Clock enabled can clock into WO line tasks regardless of role."

→ Time Clock is a free per-staff toggle, independent of role. There is no rule that any role forces it ON or forbids turning it off.

Required change

Remove the role-based locking entirely so the Time Clock toggle is freely editable for every role:

1. Delete the roleHasTimeClockFunc computed.
2. Remove :disable="roleHasTimeClockFunc" from the toggle (toggle is always enabled).
3. Remove the <q-tooltip v-if="roleHasTimeClockFunc">…</q-tooltip> block.
4. In onRoleInput, remove the staff.value.clockable = roleHasTimeClockFunc.value line — do not overwrite clockable on role change. Preserve the user's current value; the toggle stays whatever it was.
5. Check for any now-unused imports/vars after the deletions.

BE needs no change — the Change/Create commands already accept clockable as a plain boolean.

Acceptance criteria

* Editing a Technician (or Foreman / SA-Technician) staff record: the Time Clock toggle is enabled and interactive.
* Admin can turn Time Clock on and off for any role; the value persists after save and reload.
* No "Cannot turn time clock off…" tooltip anywhere.
* Changing a user's role in the dialog does not silently flip their Time Clock value.

Testing

* Update/covering unit test: app/src/components/office/tests/StaffDialog.spec.ts — assert the toggle_time_clock toggle is not disabled for a Technician role, and that selecting a role does not mutate clockable.
* Keep the data-test-id="toggle_time_clock" attribute (E2E depends on it).
* Run scoped gates before done: npx eslint --max-warnings=0 <file>, npx vitest run StaffDialog.spec.ts, npx vue-tsc --noEmit.
* Browser-walk: Settings → Staff → edit a Technician → toggle Time Clock on → save → reopen and confirm it stuck.

Out of scope (separate follow-up — do NOT fix here)

Why existing technicians came out with clockable = false after the Staging migration is a BE/data question. The FE fix above unblocks the admin to set it manually and closes this ticket's STR. If those users legitimately had job-clocking in legacy and the migration stripped it, that needs a BE/ops data-correction ticket — flag it, don't fold it in here.
