# SV-7972 — Technician Can See "Receive" Button for Special Order Parts Despite "Order Parts" Permission Being Disabled

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-06-27  **Updated:** 2026-07-07T07:44
- **Link:** https://shopview.atlassian.net/browse/SV-7972

## Description

**Affected Role:**  
Technician (configured with all permissions/CRUD as per the specification)

**Description:**  
A Technician is able to see the **Receive** button for a **Special Order Part (SPO)** after the part has been ordered by an Administrator.

Clicking **Receive** correctly results in an access error, indicating that the backend permission check is working. However, the **Receive** action itself should not be visible to a user who is not permitted to order or receive Special Order Parts.

**Steps to Reproduce (STRs):**

1. Log in as and Admin
2. Create a Work Order as an admin
3. Request a **Special Order Part (SPO)**.
4. Order the requested Special Order Part.
5. Log back in as the Technician and refresh the Work Order.
6. Observe the **Receive** button.

**Actual Result:**

* The **Receive** button is displayed.
* Clicking it results in an access error. (Correct backend behavior with Order part permission being disabled)

**Expected Result:**

* The **Receive** button should not be displayed to Technicians when **Order Parts** is disabled.
* Users should only see actions they are authorized to perform.

**Impact:**

* Inconsistent frontend/backend permission enforcement.
* Exposes unavailable functionality and confuses users.
