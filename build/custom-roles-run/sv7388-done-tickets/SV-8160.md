# SV-8160 — Custom Roles: "Add Customer" button visible in New WO flow for a role without Customers Edit (permission leak)

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-06  **Updated:** 2026-07-06T16:17
- **Link:** https://shopview.atlassian.net/browse/SV-8160

## Description

**Area:** Custom Roles & Permissions (SV-7388) — §1d / Key Decisions (Data Access)

**Custom role under test (C27580 / CR-BRK-025):** Work Orders View+Edit, **Customers OFF**, View Mode: Full.

**Steps to reproduce**

1. Create a custom role with Work Orders V/E ON and **Customers OFF** (no Customers View/Edit). Assign to a test user and log in.
2. Start the New Work Order flow and open the customer selection.

**Expected**

* Customers top nav hidden (correct today).
* In the New WO flow the user can still **select** an existing customer.
* The **"Add Customer"** button (in-dialog, `button_add_customer` — WorkOrderDialog.vue:37) must be **hidden**, because the role has no Customers Edit.

**Actual**

* The in-dialog **"Add Customer" button is visible** despite the role having no Customers Edit permission → a role that cannot create customers can create one via the New WO flow. This is a permission-enforcement leak.

**Evidence**

* E2E enforcement test `C27580` (customer-management-enforcement.spec.ts) fails on exactly this assertion: `getByTestId('button_add_customer')` expected count 0, received 1. The test is left as a bug-guard (will go green once the button is gated on `canEdit('customers')`).

**Suggested fix**

* Gate the in-dialog Add Customer button on `canEdit('customers')` (Customers Edit), mirroring the standalone Customers page (`button_new_customer` is already `v-if="canEdit('customers')"`).

Filed from the SV-7388 custom-roles E2E automation pass.
