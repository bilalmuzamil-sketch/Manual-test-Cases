# SV-8104 — AP/AR OFF Leaks Credit Term and Credit Limit on Customer Detail Page Despite Being Hidden on Edit Customer Modal

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-02  **Updated:** 2026-07-03T03:45
- **Link:** https://shopview.atlassian.net/browse/SV-8104

## Description

**Affected Configuration:**  
Role with **Manage Accounts Payable & Receivable (AP/AR) = OFF**

**Description:**  
According to the **Custom Roles specification**, disabling **Manage Accounts Payable & Receivable (AP/AR)** should hide sensitive customer financial fields throughout the application.

While the current build correctly hides these fields on the **Edit Customer** modal, the **Customer Detail/Overview** page still displays **Credit Term** and **Credit Limit**. Additionally, the Credit Limit field renders **$NaN** instead of being hidden.

This results in inconsistent permission enforcement and exposes sensitive financial information to users who should not have access to it.

**Steps to Reproduce (STRs):**

1. Configure a role with **Manage Accounts Payable & Receivable (AP/AR) = OFF**.
2. Log in as a user with that role.
3. Navigate to **Customers**.
4. Open any customer.
5. Observe the **Customer Overview/Detail** page.
6. Click **Edit Customer** and compare the visible fields.

**Actual Result:**

* The **Edit Customer** modal correctly hides the sensitive financial fields.
* The **Customer Detail/Overview** page still displays:

    * **Credit Term**
    * **Credit Limit**
    
* The **Credit Limit** field additionally renders **$NaN**.

**Expected Result:**  
As defined in the **7/1 specification**, **Credit Term** and **Credit Limit** should be hidden everywhere when **Manage AP/AR = OFF**, including both:

* Edit Customer modal
* Customer Detail/Overview page
