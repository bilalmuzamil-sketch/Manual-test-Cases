# SV-8118 — Custom Roles: New WO flow shows "Add Customer" without Customers Edit permission

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-03  **Updated:** 2026-07-06T04:49
- **Link:** https://shopview.atlassian.net/browse/SV-8118

## Description

## User-facing

A user whose role has **Work Orders Create & Edit but no Customers permission** can still **create a brand-new customer** from inside the New Work Order dialog. The Customers area is correctly hidden from them (no Customers nav), yet the New WO flow exposes an **"Add Customer"** button — letting them create customer records they otherwise have no permission to manage.

## Steps to reproduce

1. Create a custom role: **Work Orders View + Create & Edit**, **Customers OFF**, everything else off.
2. Assign to a user; log in.
3. Confirm the **Customers** top-nav is hidden (correct).
4. Open the Work Orders list → **New Work Order** → the create dialog.
5. Observe the customer field.

## Expected

The user can **pick an existing customer** for the WO (that's ungated, intended), but the **"Add Customer"** (create-inline) button must be **hidden** — creating a customer requires Customers: Create & Edit (spec CR-BRK-025 / §Key Decision).

## Actual

The **"Add Customer"** button is present and usable in the New WO dialog despite the role having no Customers permission.

## Root cause (FE)

`app/src/components/work-orders/ts/WorkOrderDialog.vue:34` gates the button `v-if="permissionService.canEdit('customers')"` (test-id `button_add_customer`, suffix at :38) — but it renders for a role that has neither Customers View nor Edit (its Customers nav is hidden, confirming zero customers permission). The gate is not effective at runtime for this permission combination (deployed since 2026-06-04, so not a staging-lag).

## Evidence

E2E `C27580` (CR-BRK-025, `combo-wo-lines`/`customer-management-enforcement`): with Customers OFF + WO Create&Edit, assertions (a) Customers nav hidden and (b) existing-customer select works both PASS; (c) `button_add_customer` toHaveCount(0) FAILS (received 1). Kept as an intentional red bug-guard; flips green when the gate is fixed.

**Note:** please confirm whether `permissionService.canEdit('customers')` is returning true here (permission-eval bug) or the button has a second/looser gate path — the E2E confirms the button renders, but the exact false-positive source in the permission service is worth a quick dev check.
