# SV-7975 — Custom Role with Only Work Orders View Permission Gets "Access Restricted" Error on Login

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-06-27  **Updated:** 2026-06-29T20:07
- **Link:** https://shopview.atlassian.net/browse/SV-7975

## Description

**Issue Type:** Bug

**Environment:** Staging

**Affected Area:** Custom Roles & Permissions — Work Orders / Access Control

**Preconditions:**

* Custom role has only **Work Orders: View** enabled.
* All other permissions are disabled.
* View Mode - Tech view and Full view

**Steps to Reproduce:**

1. Create a custom role with only **Work Orders: View** enabled and all other permissions off.
2. Assign this role to a user.
3. Log in as that user.
4. Observe the landing page shows ‘Access Restricted’ right after logging in
5. Observe the URL shows ‘access-denied’
6. Click the **Work Orders** tab from the navigation.
7. Observe that the Work Orders tab loads.
8. Refresh the page.
9. Observe that the error appears again

**Expected Result:**  
A user with Work Orders View permission should land on the Work Orders page successfully upon login and after a refresh, with no access restrictions.

**Actual Result:**  
Upon login, the user is immediately shown an **Access Restricted** error and the URL reflects an `access-denied` state. Clicking the Work Orders tab from the navigation does load the page correctly, however refreshing the page causes the Access Restricted error to reappear.

**Notes:**

* The issue occurs both on initial login and after a page refresh on the Work Orders tab.
* Navigating to Work Orders via the tab works as a temporary workaround, but is not a reliable fix since a refresh reintroduces the error.
* Only Work Orders: View is enabled — all other permissions are off.
* The system appears to be routing the user to an incorrect default landing page that they do not have access to, rather than landing them on the Work Orders page.
