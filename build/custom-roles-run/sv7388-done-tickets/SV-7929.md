**Background / operational need:**

**Parts Technician** — is intended to be:

* **View-only** on Work Orders.
* **View Only** on Work Order Lines,

  
But operationally still need to perform a few specific data-entry actions on the shop floor:

**The problem:**

* The only way to unblock the operational actions is to grant full **Create and Edit on Work Orders and Work Order Lines.**
* That grants many other edit capabilities the role should not have 
* So there is no way, under the current permission model, to give a role _just_ these operational edits.

**How to reproduce / see it today:**

1. Log in as a **Parts Technician** (or any role configured with **Work Orders = View only** and **Work Order Lines = View only**).
2. Open a work order.
3. Try to set mileage → blocked (requires Create and Edit).
4. Open a work order line and try to add tech story → blocked (requires Create and Edit).
5. Confirm there is no permission that allows steps 3–4 without enabling full Create and Edit.

**Spec references** (Custom Roles and Permissions, <custom data-type="smartlink" data-id="id-3">https://shopview.atlassian.net/wiki/spaces/PM/pages/565116952</custom> ):

* Work Orders → Create and Edit "Controls": _"Edit work order fields (customer, asset, service advisor, lead technician, status)."_ (asset data such as mileage / engine hours / license plate falls under editing the asset)
* Work Order Lines → Create and Edit "Controls": _"Add new lines, edit line details, move parts between lines, authorize lines, manage part requests on lines."_ (tech time / tech story is a line-detail edit)
* Permission Matrix: Parts Technician → Work Orders = View; Work Order Lines = View.
