# SV-7995 — Access Restricted Error Reappears When Clicking Start/Stop on a Work Order Line for Roles Without Reports Permission

- **Type:** Bug
- **Status:** Done
- **Resolution:** Done
- **Created:** 2026-06-28  **Updated:** 2026-06-30T19:12
- **Link:** https://shopview.atlassian.net/browse/SV-7995

## Description

**Issue Type:** Bug

**Environment:** Staging

**Affected Area:** Custom Roles & Permissions — Reports / Time Clock / Work Order Lines

**Preconditions:**

* Custom role has all permissions enabled **except Reports**.
* Staff Profile > Time Clock Enabled and Disabled
* The Access Restricted login issue for roles without Reports has been previously reported in **SV-7977**.

**Steps to Reproduce:**

1. Configure a custom role with all permissions enabled except **Reports**.
2. Assign this role to a user and log in.
3. Observe the Access Restricted error appears on login (known issue — SV-7977).
4. Navigate to a Work Order and open a WO line.
5. Click the **Start** button on a work order line to begin clocking in.
6. Observe the screen after clicking Start.
7. Repeat with the **Stop** button to clock out.
8. Observe the screen after clicking Stop.

**Expected Result:**  
Clicking Start or Stop on a work order line should clock the user in/out without triggering any access restriction errors. The Reports permission should have no bearing on the ability to interact with work order line time clock actions.

**Actual Result:**  
Clicking **Start** or **Stop** on a work order line triggers the **Access Restricted** error again, interrupting the user's workflow. The user is unable to continue until they navigate away. The user appears as clocked in on the admin side despite the error. This issue occurs consistently for any role that does not have the Reports permission enabled.

**Notes:**

* The Access Restricted error on login for roles without Reports is a known issue tracked in **SV-7977** — this ticket captures the additional occurrence of the same error being triggered by Start/Stop actions on WO lines.
* Even with all other permissions fully enabled, the absence of Reports permission causes Access Restricted to surface during WO line interactions.
* The error appears to be triggered by any navigation or state change action that routes through a Reports-dependent check.
* This significantly impacts technician workflows as they cannot clock in/out on work order lines without interruption.
