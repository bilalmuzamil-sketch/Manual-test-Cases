## Summary

Add `templateId` and `viewMode` to the `Role` aggregate and enforce the PRD dependency invariants in the domain.

## Scope

* Add **two columns** to `Role` (`api/src/Auth/Domain/Model/Role.php`) + `Role.orm.xml` + one Doctrine migration on `v2_role`: `template_id` (nullable string), `view_mode` (string `tech|full`, default `full`). Everything else stays a bundle FK row (preserves the single `getRoles()` resolution chain); `viewMode` is the sole column exception (no atom).
* Domain invariants in `Role::create()/change()` (mirror existing `assertOfficePermissionsDelta`): cascade integrity (Delete⇒Edit⇒View), `PART_SALES_*`/`INVOICING_*` require `SEE_FINANCIAL_DATA`, parts areas require `PARTS_DEPARTMENT`, `viewMode` choice, Office/TimeClock uneditable. **Re-validate the FE-composed bundle list server-side — never trust it.**
