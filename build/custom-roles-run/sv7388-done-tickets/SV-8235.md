# SV-8235 — 403 error accessing AP/AR reports with Reports ON and Manage AP/AR OFF (reports should follow the Reports permission per 7/3 spec change)

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-09  **Updated:** 2026-07-10T13:06
- **Link:** https://shopview.atlassian.net/browse/SV-8235

## Description

**Expected (per spec v42):**  
With Reports ON, all AP/AR reports are accessible — Manage AP/AR OFF does not block them (it now only affects the Unpaid Invoices / Payments / Credits tabs and sensitive fields, not the reports).

**Actual (build):** Opening any AP/AR report with Reports ON and Manage AP/AR OFF throws a 403 error.

**Steps to Reproduce:**

1. Configure a role with Reports = ON, Manage AP/AR = OFF (All other permissions/Cruds → OFF)
2. Log in as that role.
3. Go to Reports and open each AP/AR report (A/R Aging Summary, A/R Aging Details, A/R Aging Collection, A/P Aging Summary, A/P Aging Details, A/P Unpaid Invoices).

**Actual Result:** Each AP/AR report throws a 403 error.

**Expected Result:** Each AP/AR report opens, because AP/AR reports now follow the Reports permission (Reports ON).

**Spec reference:** <custom data-type="smartlink" data-id="id-0">https://shopview.atlassian.net/wiki/spaces/PM/pages/565116952</custom>  (v42) — 7/3 change log: "Manage AP & AR no longer gates the AR & AP aging reports; those now follow the Reports permission (all-or-nothing)."
