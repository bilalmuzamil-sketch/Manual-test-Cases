# SV-8093 — Service Manager Template Incorrectly Grants Work Orders Delete Permission Instead of Matching Custom Roles Specification

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-02  **Updated:** 2026-07-13T09:21
- **Link:** https://shopview.atlassian.net/browse/SV-8093

## Description

While validating the **Service Manager** template against the **Custom Roles and Permissions** specification (v33), it was observed that the template grants the **Delete** permission for **Work Orders**, which does not match the specification.

According to the specification, the Service Manager should **not** have **Work Orders → Delete** or **Invoicing & Payments → Delete**. However, the Service Manager template in the application has **Work Orders → Delete** enabled.

This results in a mismatch between the implemented template and the documented permission matrix.

**Specification (Service Manager):**

| Permission | Expected per Spec | Actual |
| --- | --- | --- |
| **Work Orders** | View / Create & Edit (**Delete OFF**) | **Delete ON** ❌ |
| **Part Sales** | View / Create & Edit / Delete | Matches ✅ |
| **Invoicing & Payments** | View / Create & Edit (**Delete OFF**) | Matches (Delete OFF) ✅ |

**Steps to Reproduce (STRs):**

1. Navigate to **Settings → Roles & Permissions**.
2. Edit the **Service Manager** role (or reset it to the Service Manager template).
3. Locate the **Work Orders** permission group.
4. Observe the CRUD permissions.

**Actual Result:**  
**Work Orders → Delete** is enabled for the Service Manager template.

**Expected Result:**  
The Service Manager template should match the specification:

* **Work Orders** = View / Create & Edit (**Delete OFF**)
* **Part Sales** = View / Create & Edit / Delete
* **Invoicing & Payments** = View / Create & Edit (**Delete OFF**)
