# SV-8123 — Custom Roles: WO Finance tab disappears when Customers View is added to an Invoicing-View role

- **Type:** Bug
- **Status:** OBSOLETE
- **Resolution:** Done
- **Created:** 2026-07-03  **Updated:** 2026-07-06T04:07
- **Link:** https://shopview.atlassian.net/browse/SV-8123

## Description

## User-facing

A role that grants **Work Orders View + Invoicing/Payments View + See Financial Data** correctly shows the **Finance** tab on a work order. But if you _also_ grant that same role **Customers: View**, the **Finance tab disappears** — even though nothing about the invoicing permission changed. Adding an unrelated permission removes access the user should still have.

## Steps to reproduce

1. Create custom role **A**: Work Orders View, Invoicing & Payments View, See Financial ON. Open any WO → **Finance tab present** ✅ (this is the existing, passing case C26420).
2. Create custom role **B**: same as A **plus Customers: View**. Open any WO → **Finance tab is gone** ❌.

## Expected

Adding Customers View is orthogonal to invoicing; the Finance tab must remain (its gate is `canView('invoicingPayments')` = Invoicing View + See Financial, both still granted).

## Actual

The Finance tab (`link_finance_tab`, `WorkOrderTabs.vue:105` `v-if="permissionService.canView('invoicingPayments')"`) is absent for role B. Reproduced on a **seeded WO that has a contact** (so it's not the `:disable="!customer_id"` empty-WO path) and across repeated runs.

## Evidence it's not a provisioning artifact

Raw `GET /api/roles/{id}` for role B confirms it stores exactly: `workOrdersView, invoicingPaymentsView, customersView, seeFinancialData, woFullViewMode` and `cross_toggles.seeFinancialData = true`. So `canView('invoicingPayments')` _should_ be true, yet the tab doesn't render.

## Likely area (needs dev confirmation)

Either `permissionService.canView('invoicingPayments')` mis-evaluates when `customersView` is also present, or the runtime `/auth/me/fe-permissions` wrapper for this combination drops `seeFinancialData`/`invoicingPaymentsView`. The E2E confirms the _behavior_; the exact false-negative source (FE canView vs BE fe-permissions computation for this combo) is worth a quick dev check.

## Evidence

E2E `C27521` (`invoicing-payments-enforcement.spec.ts`): role B, seeded contact WO via `createCompleteWoWithContact`, `openWoFinance` → Finance tab absent. Sibling `C26420` (role A) passes. Kept as an intentional red bug-guard; flips green when fixed.

### Vladimir Tomovic — 2026-07-06T04:07

Thanks <custom data-type="mention" data-id="id-0">@parth fadadu</custom>  for double-checking.   
I re-verified this and can confirm the behavior is correct: for a role with Work Orders: View + Invoicing/Payments: View + See Financial Data + Customers: View, the Customers navigation and the WO Finance tab are both present, exactly as expected. Adding Customers: View does not remove the Finance tab.

The original report was a false alarm on automation side. In the initial check, the role being tested didn't actually have Invoicing/Payments: View effectively applied — so the Finance tab was correctly hidden (a role without Invoicing/Payments View shouldn't see it). That absence was mistakenly read as "adding Customers View removed the Finance tab," when in fact the invoicing permission simply wasn't in effect for that role. Once the role genuinely has Invoicing/Payments: View, the Finance tab shows as it should.

No product change is needed — the permissions compose correctly and each gate is independent. Proposing we close this as Obsolete (<custom data-type="mention" data-id="id-1">@Milos Vasic</custom>).
