## Description

**Issue Type:** Bug  
  
**Epic:** SV-7388 (Custom Roles and Permissions)

**Environment:** Staging - Tested on Production to compare the results

**Affected Area:** Settings → App Settings — Integrations visibility

**Preconditions:**

* Custom role with **Settings ON** and **App Settings sub-setting ON**
* No other permissions enabled
* User is assigned to that custom role

**Steps to Reproduce:**

1. Log in as the custom role user mentioned above
2. Open Settings
3. Observe the available sections

**Expected Result:**  
Per spec (§3), App Settings includes Integrations. The user should see Settings, Staff, Roles & Permissions, Locations, Departments, **and Integrations**. In Production, Integrations is present with three sections: **QuickBooks, IBS, and OpenAPI**.

**Actual Result:**

* The user can see Settings, Staff, Roles & Permissions, Locations, and Departments.
* **Integrations is not shown** — despite the spec listing it under App Settings, and despite Production showing Integrations (QuickBooks, IBS, OpenAPI).

**Scope / Notes:**

* Staging-vs-Production discrepancy: Integrations (QuickBooks, IBS, OpenAPI) present in Production, absent on Staging for a Settings + App Settings custom role.
* Related to **SV-7806** (Service Manager: Integrations not visible) — same symptom for a system role; likely shared root cause. This ticket covers the **custom role (Settings + App Settings)** path.
* Related to **SV-7809** (OpenAPI missing from Integrations) — narrower (one section); here the entire Integrations section is absent.

**Spec references:**
