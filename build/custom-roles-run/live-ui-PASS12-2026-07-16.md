## RESIDUAL 2 — Send to Terminal (prod) — CLOSED as a FULLY-CHARACTERIZED org-device gate

**Core answer (stated crisply):** **Send-to-Terminal is ORG-DEVICE gated, NOT role/migration gated.**
Staging (whose org has a terminal device) shows it for invoicing roles; prod (whose org has no
terminal device) hides it for **all** roles; **migrating roles does NOT change Send-to-Terminal access.**

**Prod live check (this pass):** self-login as admin, drove the SPA:
- **Administration → Settings full nav** and **Payment Methods** page (`_terminal/settings_landing.png`,
  `_terminal/payment_methods.png`) show **NO Terminals / Card-Readers / Payment-Devices section
  anywhere** in the entire admin settings surface.
- **Payment Methods** only lists named methods (Amex/Cash/Check/Debit/Mastercard/Visa/Charge Account…);
  **"New Payment Method" creates a NAMED method, not a hardware terminal device.**
- All terminal APIs probed = **404**: `/api/terminals`, `/api/payment-terminals`,
  `/api/organizations/terminals`, `/api/card-readers`, `/api/payments/terminals`, `/api/stripe/terminals`.
- Admin holds **no** terminal/payment-device `fe_permission`.

**Verdict:** there is **no UI path to provision a terminal on prod** — a real card-reader/terminal
must be registered externally with the payment processor (hardware), which is not a ShopView UI action.
The prod Send-to-Terminal cell is therefore recorded as **"org-device gated; prod org has no terminal
device; no UI provisioning path — not a role/permission difference"** (a fully-characterized org-config
verdict, NOT an unexplained NOT-VERIFIED). The staging side (org has a terminal → SHOWN for invoicing
roles) was live-observed in earlier passes.
