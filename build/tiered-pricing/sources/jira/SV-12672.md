# SV-12672 Verify: categories API, category moves, category delete and category audit entries (Phase 9)

## Description

**Covers:** TP-S7-R1, R2, R4, R6, R9, R11–R13, R15, N1; TP-S8-R1, R3, R4, R8, R10, N3, E1, E2; TP-S18-R1, R3–R6, N1, N2; TP-S19-R20; NFR-002; decisions D5, D26, D31, D35

**Checklist**

1. No reserved category name (TP-S8-N3, TP-S18-R4, page 37): "Credits not tied to a part" saves like any other category name through `add-category`, `change-category`, the Open API `POST /api/v1/part-categories` and the inventory import, and the Open API is otherwise unchanged.
2. Categories list (TP-S7-R1, TP-S7-R2, TP-S7-R4, TP-S16-R11, D31): `GET /api/pricing/categories` gives Uncategorized first, then A to Z, with each row's `matrixId` and one short label per Default and tier cell. With 'Settings — Parts' but not 'See Financial Data', the pricing fields are absent, not empty. A page is served by one summary query for its matrices, not a query per row.
3. Moving a category (TP-S7-R9, TP-S19-E2, TP-S8-R4): `PUT /api/pricing/categories/{id}/matrix` moves it at once; a stale `expectedCurrentMatrixId` gives 409 naming the category and changes nothing; Uncategorized refuses any move. `add-category` with a `pricingMatrixId` from a user without 'See Financial Data' gives 403; without that field the new category uses the General Matrix.
4. Delete (TP-S8-R8, TP-S8-E1, TP-S8-E2): deleting a category that parts use is no longer blocked. Its catalog parts, work order and Part Sale lines (invoiced ones included), canned line parts, order items, delivery items and `invoice_part_line` rows move to Uncategorized; no price changes; its QuickBooks mapping is removed; its matrix stays in the library. Deleting Uncategorized gives 409.
5. Integrations (TP-S18-R3, TP-S18-R5, TP-S18-R6): the delete sends AccountingHub the same category event as today; invoices already sent to QuickBooks or AccountingHub are not sent again; an invoice re-synced later books those parts to Uncategorized's QuickBooks item.
6. Category audit (TP-S19-R20, TP-S19-R23, D35): "Category Created", "Category Renamed", "Tax Exempt Changed" and "QuickBooks Mapping Changed" land on the category's log; a delete makes one entry on the Categories list's log, recording the category's name, matrix and QuickBooks mapping and the number of parts and lines moved to Uncategorized (TP-S19-R8). Every category move writes the same three entries whatever path made it (a matrix's Categories line, New Matrix with categories, the category's own page): "Category Matrix Changed" on the category, and "Categories Changed" on the matrix it left and on the one it joined ("Matrix Created" for New Matrix), one entry per log per save.
7. Open API (D26, TP-S18-R4): creating a category through the Open API still works with no location header: its audit entry uses the API user's home location, or is skipped with a WARNING in the log when there is none. Its output `pricing_matrix_id` is unchanged.
8. Renaming a category keeps it on its matrix (TP-S8-R1), and names stay unique ignoring capitals ("A category called <name> already exists") with at least 3 characters. Another client's category id gives 404 (NFR-002). `bin/smoke-test.sh` shows no 500s, and the backend log is clean.
