# SV-12668 Verify: lines record what priced them, and the API withholds it without See Financial Data (Phase 5)

## Description

**Covers:** TP-S10-N2; TP-S12-R1–R10, R12, R15, R17–R19, N2, N3, E1; NFR-002, NFR-003; decisions D15, D20, D21

**Checklist**

1. As `admin`, the Parts tab, Lines tab and Part Sale part rows in the API carry `pricedBy: {source, label}`, with `source` one of tier, default, fixedPrice, fixedLineTotal, manual or beforeTiers, and `label` the tier's current name (Default's current name for Default). A line saved before release reads `beforeTiers` (TP-S12-R6). The work order and Part Sale payloads carry `pricingTier {id, number, name}`, or null.
2. Masking (NFR-003, TP-S10-N2, D20): as a user without 'See Financial Data', the same payloads have no `pricedBy` key at all (absent, not null or zero), and `GET /api/work-orders/{workOrderId}/part-requests/{partRequestId}/price-details` is refused with 403 ("Access restricted").
3. Ownership (NFR-002): price details for a work order of another client or location, or for a part request that isn't on that work order, are refused (404) and never returned.
4. Content (TP-S12-R2, TP-S12-R4, TP-S12-R7): a tier-priced line's details carry the pricing source; the tier name; the matrix, its side (Work Order Matrix or Part Sale Matrix) and the rule (cost range and calculation); the cost used; the sell price; when it was priced; the customer it was priced for; for % Off or $ Off, the Default price; and where the part came from (inventory with its bin, or vendor with its bill number, or nothing when neither applies). A Manual line adds who typed the price. No part status such as "Received" appears.
5. Names after a rename (TP-S12-R5, TP-S12-R18, TP-S12-R19): rename a tier used on lines. `pricedBy.label` shows the new name, and the details give the name when priced and the current one. For Default, `tierIsDefault` is true, so only the current name is shown. A Same as previous tier line gives the work order's tier as its source, plus `sameAsPreviousTierName` and that tier's current name.
6. Special cases (TP-S12-R12, TP-S12-R17, TP-S12-N2): a fixed-total line gives the total and its parts amount; a canned line's saved price on a Default work order names the canned line (with `pendingCost` for a part with no cost); a line whose customer has since moved gives that customer's tier now; a line kept through Change Customer names the customer it was priced for; a part with no cost gives details for the work order's tier at $0.00 and is never Manual.
7. `bin/smoke-test.sh` shows no 500s, and the backend log is clean after these calls.
