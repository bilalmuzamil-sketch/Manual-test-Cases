# SV-7857 Add flat-rate/dollar-value parts markup option

## Summary

Add an option to apply flat-rate (fixed dollar value) parts markup instead of percent-only markup.

## Problem Statement

Currently, parts markup is likely configured as a percentage. Some shops need to apply a fixed dollar markup per part or per item to match pricing strategy, vendor rules, or established pricing sheets.

## Proposed Solution

* Add a new parts markup mode: **Flat-rate / fixed dollar value**.
* Allow users to select markup type at the point markup is configured (e.g., percent vs fixed amount).
* Support entering a fixed dollar amount (e.g., $X) that is applied to the part price using the shop’s existing pricing logic.
* Ensure the UI clearly labels the markup type and the entered value (e.g., “$ Markup” when flat-rate is selected).
* Update any downstream calculations (pricing, totals, invoices/quotes where applicable) so fixed-dollar markup is reflected consistently.
* Add validations (e.g., fixed dollar markup cannot be negative unless explicitly supported; handle rounding/display behavior).

## User Impact

* Shop operators and pricing admins benefit by being able to implement fixed pricing rules without needing manual workarounds.
* Customers benefit indirectly through more accurate quotes/invoices that align with the shop’s intended pricing method.

## Acceptance Criteria

* [ ] The system supports selecting markup type **percent** and **flat-rate (fixed dollar)** for parts pricing/markup configuration.
* [ ] When **flat-rate (fixed dollar)** is selected, the user can input a fixed markup amount (e.g., $X) and the system applies it to the part price according to the defined pricing formula.
* [ ] Quote/invoice/any displayed “marked up” part price reflects the flat-rate markup value and updates totals accordingly.
* [ ] The UI clearly distinguishes markup type and labeled input (e.g., “Fixed markup ($)” vs “Percent markup (%)”).
* [ ] Fixed-dollar markup value has validation and cannot produce invalid pricing states (e.g., disallowed negative values if negatives are not supported).
* [ ] Existing percent markup behavior remains unchanged and backwards compatible for previously configured parts/pricing rules.
* [ ] Rounding/display behavior is consistent and deterministic when flat-rate markup interacts with tax or currency formatting (documented via implementation).
