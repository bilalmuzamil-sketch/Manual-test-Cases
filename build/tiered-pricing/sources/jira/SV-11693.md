# SV-11693 Tiered Pricing - Story 1 - Release day

## Description

## Summary

On release day the client's default matrix becomes the General Matrix, every category matrix moves into the matrix library unchanged, and every customer is on the Default tier, so no price changes until the client sets something up. There is no feature flag.

## Context

* Applies to every client automatically at release; no user action and no permission. Settings screens are desktop only.
* What must be true first: the client's existing default matrix and category matrices, which carry over as they are.
* CS contacts the clients who use customer-named categories (about 20) and the 3 clients who use Fees & Discounts as a tier before release.

## Requirements

* S1-R1: The existing default matrix is renamed the General Matrix, with its rules unchanged, and prices every category without a matrix of its own, as today.
* S1-R9: Each existing category matrix becomes a matrix in the library with the same name, rules and categories; no category moves. A client with no category matrices has only the General Matrix. A category matrix with no rules gets a copy of its client's General Matrix rules on release day, so no price changes; afterwards it keeps its own rules.
* S1-R10: Apart from the rename and the name suffixes (S1-E9, S1-E13), no matrix, rule or price changes. No matrix has a tier column other than Default, no Part Sale side is on, and the client has one tier, Default. The below-cost warning only informs.
* S1-R11: Uncategorized already uses the default matrix and can't be renamed, so the rename changes nothing for it.
* S1-R2: Every existing customer is on Default for work orders and for Part Sales.
* S1-R3: For a client who changes nothing, no sell price changes. Parts already on work orders and Part Sales keep their prices, never show the Manual icon, and their details read "Priced before tiers". A part added afterwards prices exactly as the day before, receiving and canned lines included, except for the rare half-cent ties that now round up (S10-R5). Parts already received are repriced only when split onto a new work order or Part Sale, or when their category changes. A work order or Part Sale open on release day keeps Default for parts added later, whatever tier its customer is put on.
* S1-R6: Fixed rules are unchanged and work as today.
* S1-R7: No feature flag: everything ships to every client on release day.
* S1-R8: Before release, the What's New entry and the client email explain, in plain words, the 12 changes listed in the PRD: the new Pricing tabs and General Matrix name; category pricing on the Categories page; tier columns, Part Sale tab, new rules, simulator, below-cost warning and Audit Logs; Priced by and price details; the customer card's Pricing section and tier fields; receiving reprices tier-priced lines by their recorded tier; canned lines priced by the customer's tier; Change Customer keeps prices; the two new reports; moving off customer-named categories with CS; Fees & Discounts still applying on top of tiers; and tier moves never changing existing work orders and Part Sales.
* S1-N1: None: nothing in this story is a user action, so there is nothing to refuse.
* S1-E1: Clients using customer-named categories keep working as before until they move. Deleting one moves its parts and past lines to Uncategorized; nothing recategorizes them.
* S1-E2: ShopView doesn't detect customer-named categories and blocks nothing in their matrices; Set Rule reaches them when their matrices are checked, so % Off or $ Off there can discount a part twice (a $160 Fleet category price at 20% off gives $128). CS tells clients to delete these categories before using Set Rule.
* S1-E3: Moving a part out of a customer-named category changes its tax where the tax-exempt settings differ, and moves its QuickBooks revenue to the part's own category.
* S1-E9: Two existing matrices whose names match, ignoring capitals, are both kept; the second is named "<name> (2)".
* S1-E11: No existing matrix has a gap or overlap between ranges.
* S1-E12: An existing matrix whose first range starts above $0.00 shows its real start and prices as today (a lower cost uses the first range). Once that side is saved, its first range starts at $0.00, which changes no price.
* S1-E13: An existing category matrix named "General Matrix", in any capitals, gets " (old)" added to its name; its rules and categories don't change.

## Out of Scope

* Detecting or migrating customer-named categories. CS helps each client move onto tiers and delete them (S1-E1, S1-E2).

## Acceptance Criteria

- [ ] Given a client with a default matrix and category matrices Brakes and Tires, when the release runs, then the default matrix is named General Matrix with the same rules, and Brakes and Tires are in the matrix library with the same names, rules and categories, with no category moved.
- [ ] Given a client with no category matrices, when the release runs, then the library holds only the General Matrix.
- [ ] Given any client after release, then the client has one tier, Default; every matrix shows only the Default column; and no matrix has its Part Sale side on.
- [ ] Given Uncategorized after release, then it uses the General Matrix and still can't be renamed.
- [ ] Given any existing customer, then their Work Order Tier and Part Sales Tier are Default.
- [ ] Given a client who changes nothing, when a part is added to a work order or Part Sale the day after release (an inventory part, a canned line, and a special-order part received at a cost), then its sell price matches what it would have been the day before.
- [ ] Given parts on work orders and Part Sales before release, then their prices are unchanged, no Manual icon shows, and their price details read "Priced before tiers".
- [ ] Given a work order open on release day whose customer is then put on Fleet, when a part is added to it, then Default prices it; when its lines are split onto a new work order, then the moved parts are priced by Fleet.
- [ ] Given a fixed rule on a part, then after release it prices the part as today.
- [ ] Given any client, then every feature in this PRD is available without a feature flag.
- [ ] Given the What's New entry and the client email, when reviewed before release, then they cover each of the 12 points in S1-R8.
- [ ] Given existing matrices "Fleet" and "fleet", when the release runs, then both are kept and the second is named "fleet (2)".
- [ ] Given an existing category matrix named "general matrix", when the release runs, then it is named "general matrix (old)", keeps its rules and categories, and the default matrix is the General Matrix.
- [ ] Given an existing matrix whose first range starts at $5.00, when a part costing $3.00 is priced, then the first range prices it; when that matrix side is saved, then its first range starts at $0.00 and the part's price doesn't change.
- [ ] Given any existing matrix, when it is opened after release, then its ranges have no gap or overlap.
- [ ] Given a customer-named category with parts and past lines, when it is deleted, then its parts and past lines move to Uncategorized and nothing moves them anywhere else.
- [ ] Given a customer-named Fleet category priced at $160 where Default is $200, when Set Rule gives Fleet 20% off in that matrix, then the part prices at $128 and nothing is blocked.
- [ ] Given a part moved out of a customer-named category whose tax-exempt setting differs from the part's own category, then the line's tax follows the new category.
