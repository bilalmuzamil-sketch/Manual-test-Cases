# SV-12746 Verify: part-line backfill, tie-out audit and the signed-off list of invoices that don't add up (Phase 2)

## Description

**Covers:** RPT-S1-R3, R7, R9, E4, E6; RPT-S5-E3, E5; NFR-R3, NFR-R4; decisions R-D9, R-D10, R-D11, R-D17, R-D18, R-D22, R-D26, R-D30, R-D34

**Checklist**

1. Dry run and timing: on staging restored from a fresh prod dump, `app:invoicing:backfill-part-lines --created-before=<the Tiered Pricing deploy instant> --dry-run` prints counts per client and location and writes nothing. A timed run with `--limit=2000` gives the per-invoice time used to book the prod window (about 308k invoices and 1.2M part rows fleet-wide).
2. Full backfill (NFR-R4, R-D11): every non-void invoice created before the Tiered Pricing deploy gets its `invoice_part_line` rows, void invoices get none, and `invoice.parts_sell` and `invoice.parts_cost` don't change. A second run writes nothing, and a stopped run resumes where it left off. A failing invoice is skipped, recorded, and shows in the audit as missing rows. Pending invoices run last, in a quiet window.
3. Historical attribution (RPT-S1-R3, RPT-S1-R9, RPT-S1-E6, R-D9, R-D26): backfilled rows carry each line's recorded pricing, so pre-release lines report as Before tiers. A pre-release core, environmental charge, and fee or discount on a single part carry the part's category and Before tiers; whole work order and Part Sale fees are not in the rows. A part-line discount comes from the invoice's frozen adjustments only when they are fully identified, otherwise none, as Sales by Customer counts it.
4. Pre-release fixed line totals (RPT-S1-E4, RPT-S5-E3, R-D22): a pre-release fixed line total spanning two categories lands in Before tiers, split by the Tiered Pricing fixed-line-total routine: by each part's cost at invoicing (by quantity when every part costs $0.00), with the leftover cent on a part with a quantity of 1, or on the line's labor when there is none. The shares add up to the line's parts amount.
5. Imported historical invoices (R-D18): check whether any live in `invoice` with no part rows. If so, each reports as one Before tiers row carrying its `parts_sell` and `parts_cost`, so the Totals still tie out.
6. Audit (NFR-R3, R-D30): `app:invoicing:audit-part-line-tie-out --output=<csv>` is read-only on the replica and lists every non-void invoice that fails `SELL_MISMATCH`, `COST_MISMATCH`, `MISSING_ROWS`, `SNAPSHOT_NULL`, `FIXED_LINE_TOTAL` (a line with no quantity-1 part, or with no stored labor and parts portions) or `CREDIT_LINE_UNATTRIBUTED` (informational), with expected, actual and delta cents, plus a summary per check (count, share of invoices, total of the deltas).
7. The RPT-S1-R7 list (R-D34): the staging run's invoice-level rows and summary are pasted into the plan's Appendix C, grouped by cause, and the owning PM and the report standard's owner have signed off every cause class, or each invoice the class doesn't explain, before the PR merges. No release while a row is unsigned. The PR description and Jira carry no copy of the list.
8. After release (R-D34): the backfill runs on prod, then the audit against the prod replica; any invoice not already in Appendix C is added and signed off before the reports are announced.
9. Golden Rule (R-D17): both commands enumerate every client and run each one under `runAs()`, and the PR's "Golden Rule Exemptions" block records it.
