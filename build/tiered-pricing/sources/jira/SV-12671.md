# SV-12671 Verify: tiers and matrices API, including grid saves, Set Rule, Undo, tier delete and audit entries (Phase 8)

## Description

**Covers:** TP-S1-E11; TP-S2-R1, R3, R5–R8, R12–R15, R17, R18, R20, R22–R30, N7, N8, E2, E5; TP-S3-R5, R6, R8, R9, R12, R13, R16, R18, R20, R21, R23, R25–R28, R30–R32, N3, N4, E3, E4; TP-S4-R1, R3–R5, R7, R10, R12, R15, R16, R18–R20, R22, R26–R32, N1, E3; TP-S6-R1–R3, R6–R11; TP-S16-R2, R4–R6, R8, R11, N1, N4, N5, E1; TP-S19-R1, R3, R5–R10, R12–R15, R18–R23, E2; NFR-002, NFR-004, NFR-008, NFR-010; decisions D7, D8, D17, D18, D23, D30, D33, D35, D36

**Checklist**

1. Permissions (NFR-004, TP-S16-R5): every `/api/pricing/tiers…` and `/api/pricing/matrices…` endpoint answers `admin`, and refuses with 403 ("Access restricted") both a role with 'Settings — Parts' but not 'See Financial Data' and a role with 'See Financial Data' but not 'Settings — Parts', when called directly. The one exception is `GET /api/pricing/tiers/options`, which also answers 'Customers — Create & Edit'.
2. Tenant isolation (NFR-002): a tier or matrix id from another client gives 404 on every read and write, and no list ever shows another client's rows.
3. Tier names (TP-S2-R3): 50 characters after trimming are accepted and 51 give 422 `tooLong`; a taken name in any case gives `taken`; an archived tier's name gives `takenByArchived`; "fixed PRICE" or any other reserved name gives `reserved`; a blank name gives `required`.
4. Grid save (TP-S3-R6, TP-S19-E2): `PUT /api/pricing/matrices/{id}/sides/{side}/rules` with a stale `expectedRulesRevision` gives 409 `matrixChanged` with "<matrix> was changed by someone else. Reload to see their changes." and saves nothing. Invalid cells give 422 with a code per cell (`endNotAboveStart`, `valueRequired`, `tooManyDecimals`, `marginOutOfRange`, `percentOffOutOfRange`, `amountOffNegative`, `gapOrOverlap`). No value may be negative, while 0% markup or margin, + $0.00, 0% off and $0.00 off are accepted; ranges from before release with a gap or overlap are refused until fixed (TP-S3-R5, TP-S1-E11). A success returns the new `rulesRevision`, and saving one side doesn't make the other side's next save stale.
5. Archived tiers keep their rules (D36): give an archived tier its own rules, then save from the active view with no range change (its cells don't change), with a range removed (the range above keeps its value and takes the end), with an end moved (values stay) and with a range added (it copies the range above). An archived-view save leaves Default and the active tiers alone. Reactivating the tier brings its columns back as saved, last, with the next number (TP-S2-R6).
6. Set Rule and Undo (TP-S2-R22–R24, TP-S2-R27, TP-S2-E5, NFR-010): a select-all with exceptions covers matrices that aren't loaded and Inactive ones; the preview returns `{changing, changingInactive}`; applying it writes the Work Order side and each Part Sale side that is on, all or nothing (a forced failure changes nothing). Undo puts back exactly what the tier had; once any changed matrix is saved again it gives 409 `savedAfter` naming the matrix and changes nothing.
7. Archive and delete (TP-S2-R7, TP-S2-R8, TP-S2-R13, D33): a tier with customers gives 409 `hasCustomers`; a tier that priced saved lines, or that an open work order, estimate or Part Sale keeps, gives 409 `deleteBlocked`, by the same rule the usage endpoint reports. A tier kept only by an invoiced work order deletes, and that work order's kept tier becomes NULL; reversing that invoice returns the work order to Complete, and a part added then prices at Default. These don't block a delete: a customer who was on the tier and was taken off before any part was priced, and lines it priced that were later deleted. The Default tier can't be archived or deleted, and deleting a tier removes its column from every matrix. A direct SQL delete of a tier that an open work order keeps still fails on the foreign key.
8. Lists (TP-S6-R6, TP-S2-R14, D30): the Matrices list gives 50 a page, General Matrix first, then A to Z, and `sortBy=categoryCount` puts the most categories first. `GET /api/pricing/matrices/{id}?view=archived` returns the archived tiers after Default in the order they were archived, earliest first. The Tiers list gives active tiers by number, then archived tiers A to Z.
9. Audit entries (TP-S19-R8, TP-S19-R20, TP-S19-R23, D35): each entry records what changed (each value before and after), who made it and when, and each save makes one entry on the log of what was saved, with a summary such as "1 range added; rules set for Default and 5 tiers": "Rule Changed" for a grid save that changes a rule or range; for each category a save moves (Categories line, or New Matrix with categories), "Category Matrix Changed" on the category and "Categories Changed" on the matrix it left (the General Matrix for one removed from the line) and on the saved matrix ("Matrix Created" for New Matrix), one entry per log; "Matrix Changed" for the Part Sale switch; and "Tier Rule Set" or "Tier Rule Undone" on the tier ("Rule set in 7 matrices") and on each matrix it changed. A save that changes nothing writes no entry. A settings write sent without a location is refused (409) before anything is written (D7).
10. `bin/smoke-test.sh` shows no 500s, and the backend log is clean.
