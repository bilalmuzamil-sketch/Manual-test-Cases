# SV-12677 Verify: Tiers list, tier page, archive, delete, reactivate and Set Rule with Undo (Phase 14)

## Description

**Covers:** TP-S2-R1, R3, R5–R8, R12–R15, R17, R18, R20, R22–R30, N7, N8, E2, E5; TP-S16-E1; TP-S19-R6, R14, R19, R20; decisions D21, D33

**Checklist**

1. Tiers list on `/administration/pricing?tab=tiers` (TP-S2-R1, TP-S2-R14, TP-S2-R15, TP-S2-R25): # (a plain number), Name, Customers (distinct customers, with the work order and Part Sales split on hover), Matrices ("All" or "4/5", Work Order side only, Inactive matrices not counted, Default always "All") and Status. Active tiers by number, then archived ones A to Z; the Status filter opens on Active; 50 a page; "No archived tiers yet." when there are none; filter and page kept on return. Once Default is renamed, its new name carries the Default badge.
2. New Tier (TP-S2-R3, TP-S2-R17, TP-S2-R18, TP-S2-R29, TP-S19-R6, TP-S19-R14): a page opens with the name field focused, the hint "New tiers go last, as Tier <n>.", Cancel and Create Tier; Enter creates it; the toast reads "<tier> created" with "It prices the same as the tier before it until you set its rules." The field stops at 50 characters, paste included. A blank or taken name shows an inline error, an archived tier's name shows "An archived tier is called <name>. Rename it first.", and "fixed PRICE" shows "Fixed price is used by the reports. Choose another name." Cancel creates nothing. The new tier shows in every matrix as "Uses previous tier".
3. Tier page (TP-S2-R5, TP-S2-R20, TP-S2-R28, TP-S2-N8): breadcrumb Settings › Pricing › Tiers › <tier>, also from a bookmark; the title renames in place. The Pricing tab lists the General Matrix first, then A to Z, loading more as you scroll, with Work Order Matrix and Part Sale Matrix columns in the grid's words (one rule as "35% markup", "30% margin", "Cost + $5", "10% off" or "$5 off"; one type with different values as "% markup", "% margin", "Cost + $", "% off" or "$ off"; different types as "Mixed rules"; "Uses previous tier"; "Same as work orders" when there is no separate side); Edit on a row opens that matrix in edit with the tier's column in view. Default's page has no checkboxes and no Set Rule.
4. Set Rule (TP-S2-R22, TP-S2-R23, TP-S2-R24, TP-S2-N7): the header checkbox checks every matrix, Active and Inactive, loaded or not, and shows partly checked when only some are. The sticky bar shows "2 matrices", "Set <tier> to", a picker that starts on % Off with no Previous tier, the value, Set Rule and a clear button. An empty or bad value blocks with "Enter a % from 0 to 99.99", "Enter an amount of $0.00 or more", "Enter a margin from 0 to 99.99" or "Enter a value of 0 or more". The confirmation reads "Set <tier>'s Rule?" with "<tier> becomes <rule> in <n> matrices (<m> inactive), replacing what it had. Parts already on work orders keep their prices."; when nothing would change, "<tier> already uses <rule> in those matrices" shows instead.
5. Toast and Undo (TP-S2-R27, TP-S2-E5, D21): "<tier> set to <rule>" with "<n> matrices changed.", Undo and a close button. It stays 20 seconds, pauses while the pointer or focus is on it, and stays up when you move to another page. Undo shows "Undone" with "<tier>'s rules are back." After one of those matrices is saved again, Undo shows "Can't undo: <matrix> was saved after this rule was set." and changes nothing.
6. Archive and Delete with customers (TP-S2-R7, TP-S2-R12, TP-S2-R30, TP-S16-E1): both open a dialog listing the customers with their channels, a secondary Close and a "Remove Customers" link (only for users with 'Customers — Create & Edit') that opens Manage Customers on the Remove tab. Without 'Customers — View' the dialog reads "12 customers are on Fleet. Someone who can manage customers moves them first." With no customers, "Archive <tier>?" lists each following tier under "These tiers price the same as <tier> and will follow <tier before it> instead:" and ends with "Parts already on work orders keep their prices."
7. Delete grayed (TP-S2-R8, TP-S2-R13, D33): in the menu and on the page, Delete is grayed with "Can't delete <tier>. <n> open work orders, estimates or Part Sales use it." or "<tier> priced parts on <n> saved lines, so it can't be deleted. Archive it instead."; when both apply, the saved-lines reason shows. A tier kept only by an invoiced work order can be deleted. Archive is never grayed, and Default has neither.
8. Archived tiers (TP-S2-R6, TP-S2-R15, TP-S2-R26, TP-S2-E2): archiving moves the later tiers up one number, and a tier that followed it now follows the tier before it. An archived tier's menu has Reactivate and Delete; Reactivate applies at once and shows "<tier> is reactivated. It's now the last tier, Tier <n>.", with its columns back as they were. On an archived tier's page, Edit opens the archived grid view, and Set Rule and rename still work.
9. Audit Log (TP-S19-R19, TP-S19-R20): "Audit Log: <tier>" from the tier's page and its row, "Audit Log: Tiers" from the list, with Tier Created, Tier Renamed, Tier Archived, Tier Reactivated, Tier Deleted, Tier Rule Set ("Rule set in 7 matrices") and Tier Rule Undone entries.
