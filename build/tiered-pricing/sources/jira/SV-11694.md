# SV-11694 Tiered Pricing - Story 2 - Tiers

## Description

## Summary

Owners create numbered price levels, each opening on its own page, rename, archive, reactivate and delete them, and give a tier one rule across many matrices at once with Set Rule and Undo. Each kind of customer can get its own pricing.

## Context

* Role: user with 'Settings — Parts' and 'See Financial Data'. Desktop only (settings).
* Tiers are client-wide, shared by every location. Default is tier 1 and every customer starts on it.
* What must be true first: the matrix library from Story 1. A tier's column in each matrix is edited in the grid (Story 4); putting customers on a tier is Story 9.
* Dependency: tiers take over the Settings › Pricing page. SV-11258 (Settings Pricing and Categories Sorting) changes the same page. Matrices and Categories sorting are built here; Fixed Rules sorting stays on SV-11258 and ships separately.

## Requirements

* S2-R1: The Tiers list shows each tier's number, name, customers and status. Customers counts distinct customers on the tier for either channel, with the work order and Part Sales split on hover. Default is tier 1; once renamed, its new name carries the Default badge; the General Matrix and Uncategorized keep theirs; nothing else carries it.
* S2-R25: A Matrices column reads "All" when the tier has its own rules in every Active matrix, otherwise "4/5". Inactive matrices don't count; Default reads "All"; only the Work Order Matrix side counts.
* S2-R3: A tier name is required, trimmed, up to 50 characters (the field stops accepting more) and unique among active and archived tiers, ignoring case; a blank or taken name shows an inline error and nothing saves, and an archived tier's name shows "An archived tier is called <name>. Rename it first." "Manual", "Fixed price", "Fixed line total" and "Before tiers" are reserved: "<name> is used by the reports. Choose another name.", naming the reserved name as written whatever case was typed
* S2-R15: Default is 1 and other active tiers follow in creation order, with no gaps. Archiving or deleting a tier moves the later tiers up one number; order and names never change; tiers can't be reordered; archived tiers have no number. The number shows as plain text beside the name (no pill) on the Tiers list (under #), in grid headers and in tier pickers.
* S2-R17: New Tier opens a new tier's page, no dialog: an empty name field with the cursor in it, the hint "New tiers go last, as Tier <n>.", Cancel and Create Tier. Until created, its matrix list has no checkboxes and no Set Rule. Create Tier creates the tier and stays on its page. No limit on tiers. Cancelling, or leaving with no name, creates nothing.
* S2-R29: Creating a tier shows "<tier> created" with "It prices the same as the tier before it until you set its rules."
* S2-R18: A new tier appears as a column in every matrix, priced Same as previous tier.
* S2-R5: Any tier can be renamed, Default included. Edits to its columns price parts from then on; lines keep the name and price they recorded.
* S2-R6: A tier other than Default can be archived. It keeps its rules and stays in reports, can't take customers, prices only parts added to open work orders and Part Sales made while it was active, and has no column in any active grid or on the Categories page. It can be renamed and repriced from its page (Set Rule, archived grid view). Reactivated, it goes last with the next number and its columns come back as they were; a tier after it on Same as previous tier keeps following the tier it follows now.
* S2-R26: An archived tier's row menu has Reactivate and Delete. Delete works the same from the list and the tier's page. Reactivate applies at once, with no confirmation: "<tier> is reactivated. It's now the last tier, Tier <n>."
* S2-R30: Archive and Delete ask first: "Archive <tier>?" / "Delete <tier>?" lists, one per line, every tier that follows this one through Same as previous tier in any matrix or side ("These tiers price the same as <tier> and will follow <tier before it> instead:"), then "Parts already on work orders keep their prices.", with Cancel and Archive (or Delete). With no follower, just the question and the last line.
* S2-R7: A tier with customers on either channel can't be archived or deleted: Archive, and Delete unless grayed, open a dialog that says so and lists those customers with their channel(s). There is no move step in the dialog.
* S2-R12: In that dialog Close is a secondary button, as in every dialog that only informs; a "Remove Customers" link, shown only with 'Customers — Create & Edit', opens the tier's Manage Customers on the Remove tab.
* S2-R8: A tier can be deleted only when no customers are on it, no saved work order, estimate or Part Sale line, open or invoiced, was priced by it, and no open work order, estimate or Part Sale keeps it. A customer taken off before any part was priced, and lines later deleted, don't block. Default can't be archived or deleted. Deleting a tier removes its column from every matrix.
* S2-R13: Delete is grayed only when the tier priced saved lines or open ones still keep it, with the tooltip "Can't delete <tier>. <n> open work orders, estimates or Part Sales use it." or "<tier> priced parts on <n> saved lines, so it can't be deleted. Archive it instead." An estimate counts as its work order. Archive is never grayed.
* S2-R14: The list shows active tiers by number, then archived tiers A to Z. A Status filter (Active, Archived) opens on Active; 50 tiers a page; each user's filters and page are kept. Archived with none: "No archived tiers yet."
* S2-R28: Clicking a tier's row opens its page on the Pricing tab, never a dialog, with the breadcrumb Settings › Pricing › Tiers › <tier>, also from a link or bookmark. The name is the page title, renamed in place and saved at once. Coming back keeps the list's filter and page.
* S2-R20: A tier's page has Pricing and Customers tabs. Pricing lists every matrix with its categories and how each side prices the tier, in the grid's words ("Same as work orders" when there is no separate Part Sale side); Default's tab lists every matrix's Default rules. Edit on a row opens that matrix's page in edit with the tier's column in view (archived tiers: the archived grid view). The General Matrix is first, then A to Z, loading more as the user scrolls.
* S2-R22: The matrix list has a checkbox per row and a select-all that checks every matrix, Active and Inactive, loaded or not (partly checked when only some are). Checking a row doesn't open it. While any is checked, the design system's bulk action bar shows at the top and stays in view: the count ("2 matrices"), "Set <tier> to", a rule picker (Off default price: % Off, $ Off; From cost: + $, Markup %, Margin %) starting on % Off, its value, Set Rule and a clear button. No Previous tier option and no Set Rule For Entire Tier button.
* S2-R23: Set Rule asks "Set <tier>'s Rule?" with "<tier> becomes <rule> in <n> matrices (<m> inactive), replacing what it had. Parts already on work orders keep their prices." (Cancel / Set Rule). n counts checked matrices that would change; "(<m> inactive)" shows only when some are Inactive. When none would change, nothing is asked and "<tier> already uses <rule> in those matrices" shows ("in that matrix" for one).
* S2-R24: On confirm, the tier gets that rule in every range of every checked matrix, Active and Inactive, on the Work Order Matrix side and every Part Sale side that is on. It never asks Change All. Unchecked matrices don't change; the checks clear. A matrix created later starts the tier as Same as previous tier; a Part Sale side turned on later copies the work order side.
* S2-R27: The success message reads "<tier> set to <rule>" with "<n> matrices changed.", Undo and close; it stays 20 seconds and pauses on hover or focus. Undo puts back exactly what the tier had in every matrix it changed: "Undone" with "<tier>'s rules are back."
* S2-N7: Set Rule is blocked while its value is empty or invalid: "Enter a % from 0 to 99.99" (% Off), "Enter an amount of $0.00 or more" ($ Off), "Enter a margin from 0 to 99.99" (Margin %), "Enter a value of 0 or more" (+ $, Markup %). Cancel, or clearing the checks, changes nothing.
* S2-N8: Default's page has no checkboxes and no Set Rule.
* S2-E2: When a tier is archived or deleted, a tier after it on Same as previous tier follows the tier before it. Saved lines keep their prices; an archived tier still prices parts added to open work orders and Part Sales that keep it.
* S2-E5: Undo is refused once any matrix it would change is saved again: "Can't undo: <matrix> was saved after this rule was set." Nothing changes.
* Error: a failed tier save keeps the typed name and shows today's error toast. Set Rule and Undo are all or nothing: if any matrix fails, none changes and today's error toast shows.

## Acceptance Criteria

- [ ] Given Default and tiers Fleet and Wholesale, when the Tiers list opens, then it shows #, name, customers, status and Matrices, Default is 1, with the Default badge once it's renamed, and no other tier has the badge.
- [ ] Given Fleet with 3 customers for work orders and 2 for Part Sales, 1 of them on both, then Customers reads 4 and hover shows the work order and Part Sales split.
- [ ] Given 5 Active matrices and Fleet with its own rules in 4 of them, then Fleet's Matrices cell reads "4/5"; with its own rules in all 5, "All"; Default reads "All"; a Part Sale side doesn't change the count.
- [ ] Given a new tier name that is blank, " fleet " when Fleet exists, or the name of an archived tier, when Save is clicked, then the matching inline error shows and nothing is saved; given "manual" in any case, then "Manual is used by the reports. Choose another name." shows.
- [ ] Given New Tier, when it opens, then a page (not a dialog) shows an empty focused name field with "New tiers go last, as Tier <n>.", Cancel and Create Tier, and the matrix list has no checkboxes and no Set Rule.
- [ ] Given a named new tier, when Create Tier is clicked (or Enter in the name), then the tier is created, the page stays open, "<tier> created" with "It prices the same as the tier before it until you set its rules." shows, and every matrix has its column as "Uses previous tier".
- [ ] Given New Tier, when the user cancels or leaves with no name, then no tier is created.
- [ ] Given tiers 1–4, when tier 2 is archived, then tiers 3 and 4 become 2 and 3 with the same names and order, and the archived tier has no number; deleting a tier renumbers the same way.
- [ ] Given a tier's number, then it shows as plain text beside its name on the Tiers list, in grid headers and in the customer tier pickers.
- [ ] Given Default renamed "Retail", then every screen shows Retail and saved lines keep the name they recorded.
- [ ] Given Fleet followed by Wholesale on Same as previous tier in one matrix, when Fleet is archived, then the question lists Wholesale under "These tiers price the same as Fleet and will follow <tier before it> instead:", ends "Parts already on work orders keep their prices.", and after Archive Wholesale prices as the tier before Fleet.
- [ ] Given a tier no other tier follows, when Archive is clicked, then the question is "Archive <tier>?" with only the last line.
- [ ] Given Fleet with customers, when Archive or Delete is clicked, then a dialog lists the customers with their channels, Close is a secondary button, and the Remove Customers link opens Manage Customers on the Remove tab; without 'Customers — Create & Edit' the link doesn't show.
- [ ] Given an archived tier, then it has no column in any active grid or on the Categories page, can't be picked for a customer, can be renamed, and its Set Rule works from its page.
- [ ] Given an archived tier kept by an open work order, when a part is added to that work order, then the archived tier's rules price it.
- [ ] Given an archived tier, when Reactivate is clicked, then it applies with no confirmation, the tier goes last, "<tier> is reactivated. It's now the last tier, Tier <n>." shows, and its columns return with their rules.
- [ ] Given a tier that priced 3 saved lines, then Delete is grayed with "<tier> priced parts on 3 saved lines, so it can't be deleted. Archive it instead."; given 2 open work orders keep it, then "Can't delete <tier>. 2 open work orders, estimates or Part Sales use it."; an estimate and its work order count once.
- [ ] Given a tier with no customers, no priced lines and no open work order keeping it, when Delete is confirmed, then it is deleted and its column leaves every matrix; given a customer taken off it before any part was priced, then Delete is not blocked.
- [ ] Given Default, then it has no Archive or Delete.
- [ ] Given the Tiers list, then active tiers show by number, then archived A to Z; Status opens on Active; 50 a page; filter and page are kept on return; Archived with none shows "No archived tiers yet."
- [ ] Given a tier's row, when clicked or opened from a bookmark, then its page opens on the Pricing tab with the breadcrumb Settings › Pricing › Tiers › <tier>, and renaming the title saves at once.
- [ ] Given Fleet's Pricing tab, then every matrix is listed (General Matrix first, then A to Z) with its categories and its Work Order and Part Sale columns in the grid's words, and "Same as work orders" where there is no Part Sale side; Edit opens the matrix in edit with Fleet's column in view.
- [ ] Given two checked matrices, then the bulk action bar shows "2 matrices", "Set Fleet to", a picker starting on % Off with no Previous tier option, a value, Set Rule and clear; select-all checks every matrix, loaded or not.
- [ ] Given Fleet already 10% off in one of 3 checked matrices, when Set Rule 10% off is clicked, then "Set Fleet's Rule?" says 2 matrices; with one Inactive among them, "(1 inactive)" shows; given all 3 already 10% off, then no question and "Fleet already uses 10% off in those matrices".
- [ ] Given Set Rule confirmed, then Fleet is 10% off in every range of each checked matrix on the work order side and every Part Sale side that is on, Change All isn't asked, unchecked matrices are unchanged, and the checks clear.
- [ ] Given the success message, then it reads "Fleet set to 10% off" with "<n> matrices changed.", Undo and close, stays 20 seconds and pauses on hover or focus; Undo restores Fleet's previous rules in each matrix and shows "Undone" / "Fleet's rules are back."
- [ ] Given one of those matrices saved after Set Rule, when Undo is clicked, then "Can't undo: <matrix> was saved after this rule was set." shows and nothing changes.
- [ ] Given an empty value, 100 for % Off, -1 for $ Off, 100 for Margin % or -1 for Markup %, then Set Rule is blocked with the matching message.
- [ ] Given Default's page, then there are no checkboxes and no Set Rule.
- [ ] Given a matrix created after Set Rule, then Fleet starts as Same as previous tier in it; given a Part Sale side turned on afterwards, then Fleet's rule there copies the work order side.
- [ ] Given Set Rule where one matrix fails to save, then no matrix changes and today's error toast shows; given a tier save that fails, then the typed name is kept and the error toast shows.
