# SV-11709 Tiered Pricing - Story 19 - Shared behavior for every new page, dialog and list

## Description

## Summary

Every new page, dialog and list follows ShopView's existing rules for saving, closing, validation messages, loading, errors, keyboard and screen readers, and every change to a matrix, tier or category is recorded and shown in an Audit Log. Users meet nothing surprising on the new screens, and clients see who changed their pricing.

## Context

* Applies to every new screen in this feature: tier, matrix and category pages and lists, Manage Customers, the archive, delete and Set Rule dialogs, price details and the Audit Log.
* Form factor: settings pages desktop only; work order and Part Sale behavior works on a phone.
* Audit Log needs 'Settings — Parts' and 'See Financial Data'. ShopView records none of these changes today; the display reuses the existing history dialog.

## Requirements

* S19-R1: Saving, dialogs, field messages and session expiry work as today: the primary button spins and Save, Cancel and X are disabled while saving; dialogs close only with Cancel or X; required and number fields use today's messages; an expired session logs out with "Session expired, please log in again."
* S19-R13: Tiers, matrices and categories are created and edited on their own pages, never in dialogs. Dialogs are only for confirming, Manage Customers, the Audit Log and where today's screens use one.
* S19-R14: New Tier, New Matrix and New Category can be cancelled before saving, creating nothing.
* S19-R15: The new pages show no explanatory text or help banners; explanations sit in short info-icon tooltips (one or two sentences, never repeating the label). Tier names have no tooltip.
* S19-R3: Leaving a matrix page, the New Category page or a grid in edit with unsaved changes asks "Discard these changes?" (Keep Editing / Discard Changes); with no changes it leaves at once.
* S19-R5: The Manual icon and the grid's warning icons have screen reader names; Priced by and price details name the source in words, never by color alone.
* S19-R6: Every new control, every grid cell in edit included, is reachable by keyboard. Enter in the New Tier name saves it.
* S19-R7: Every new page, list, tab and grid shows a loading skeleton; price details show the popover spinner.
* S19-R10: A failed load shows "Ooooops! An error occurred" with Try again, keeping search, filters, sort and page.
* S19-R8: Every change to a matrix (created, renamed, deleted, rules on either side, categories, Part Sale switch), tier (created, renamed, archived, reactivated, deleted, Set Rule and Undo, customers added or moved off) or category (created, renamed, deleted, matrix, Tax Exempt, QuickBooks mapping; a delete records its name, matrix, mapping and parts and lines moved) is recorded with each value before and after, who, when and the client.
* S19-R12: The client's Audit Log keeps these changes for all time; ShopView's internal copy follows the existing cleanup (90 days). Engineering confirms what the existing change log captures.
* S19-R19: Audit Log is in the three-dot menu of each matrix page and the Matrices list, each tier page, its Tiers list row and the Tiers list, and each category page and the Categories list. It opens the existing history dialog titled "Audit Log: <name>" or "Audit Log: Matrices / Tiers / Categories" (deleted ones included, each detail starting with its name), with today's search and columns minus Line, newest first, details as "<label>: <old> → <new>", Close, 50 entries at a time with more on scroll, "No history here. Yet." when empty, and every change since release.
* S19-R20: Event names — matrix: Matrix Created, Matrix Renamed, Matrix Changed, Matrix Deleted, Rule Changed, Categories Changed, Tier Rule Set, Tier Rule Undone, Tier Deleted; tier: Tier Created, Tier Renamed, Tier Archived, Tier Reactivated, Tier Deleted, Tier Rule Set, Tier Rule Undone, Customer Added, Customer Changed, Customer Removed; category: Category Created, Category Renamed, Category Deleted, Category Matrix Changed, Tax Exempt Changed, QuickBooks Mapping Changed.
* S19-R21: Every Audit Log needs 'Settings — Parts' and 'See Financial Data'; a tier's and the Tiers list's show customer names.
* S19-R22: In every sortable list, the first click on a number column sorts highest first.
* S19-R23: Each save makes one entry summing up what it changed ("1 range added; rules set for Default and 5 tiers"); unsaved edits log nothing. Set Rule and Undo make one entry on the tier ("Rule set in 7 matrices") and one per matrix changed; a Manage Customers save makes one ("3 customers added, 1 removed"); a category delete one on the Categories list's log with the parts and lines moved.
* S19-R18: Every search matches a case-insensitive substring, ignores leading and trailing spaces and keeps the sort. In tier pickers a whole number matches that tier number first, then names containing it.
* S19-R9: Column titles, headers, page titles, tabs and buttons use Title Case ("Manage Customers on Fleet Platinum"); messages and tooltips use sentence case.
* S19-E2: If someone else saved first, the second save is refused and nothing saves; everything typed is kept. When the save is no longer valid (a name now taken, a category moved, a tier archived), the reason shows inline, naming the conflict. When someone else saved the same matrix, it shows "<matrix> was changed by someone else. Reload to see their changes."
* Error: a failed save shows "Ooooops! An error occurred" with "Contact support for more information" (or the server's message) in today's error toast; the page or dialog stays open with everything typed.
* S16-R2 applies: read-only pages show no Edit, Save or New.

## Acceptance Criteria

- [ ] Given any new Save, when clicked, then the button spins and Save, Cancel and X are disabled, so a double click saves once.
- [ ] Given a confirmation dialog, when the user clicks outside it, then it stays open; Cancel or X closes it.
- [ ] Given a required field left empty, then "{Field} is a required field" shows; given a number over its maximum or not a number, then today's messages show.
- [ ] Given an expired session, then the user is logged out with "Session expired, please log in again."
- [ ] Given a tier, matrix or category, then it is created and edited on its own page, never in a dialog; no matrix opens in a dialog anywhere.
- [ ] Given New Tier, New Matrix or New Category, when cancelled before saving, then nothing is created.
- [ ] Given the new pages, then they show no help banners, explanations are in info-icon tooltips, and tier names have no tooltip.
- [ ] Given a matrix page, New Category page or grid in edit with unsaved changes, when the user leaves, then "Discard these changes?" asks Keep Editing / Discard Changes; with no changes, they leave at once.
- [ ] Given a screen reader, then the Manual icon and warning icons are announced by name, and Priced by names the source in words.
- [ ] Given keyboard only, then every new control and every grid cell in edit can be reached, and Enter in the New Tier name saves it.
- [ ] Given a new page, list, tab or grid loading, then a skeleton shows; price details show the popover spinner.
- [ ] Given a list that fails to load, then "Ooooops! An error occurred" with Try again shows and search, filters, sort and page are kept.
- [ ] Given a matrix save that adds a range and sets rules for Default and 5 tiers, then the matrix's Audit Log gets one entry "1 range added; rules set for Default and 5 tiers" with each value before and after, who and when; an edit cancelled before Save logs nothing.
- [ ] Given Set Rule on Fleet across 7 matrices, then Fleet's log gets one "Tier Rule Set" entry "Rule set in 7 matrices" and each of the 7 matrices one entry; Undo does the same with "Tier Rule Undone".
- [ ] Given a Manage Customers save adding 3 and removing 1, then Fleet's log gets one entry "3 customers added, 1 removed" with customer names.
- [ ] Given a category deleted, then the Categories list's log gets one "Category Deleted" entry with its name, matrix, QuickBooks mapping and the parts and lines moved.
- [ ] Given a tier renamed, archived, reactivated or deleted, a category renamed or its matrix, Tax Exempt or QuickBooks mapping changed, or a matrix created, renamed, deleted, its categories or Part Sale switch changed, then the matching named event is logged.
- [ ] Given the three-dot menu of a matrix page, tier page, Tiers list row, category page, and the Matrices, Tiers and Categories lists, then each has Audit Log, titled "Audit Log: <name>" or "Audit Log: Matrices / Tiers / Categories".
- [ ] Given an Audit Log, then it has today's search and columns without Line, newest first, details "<label>: <old> → <new>", Close, 50 entries with more on scroll, and "No history here. Yet." when empty; the Matrices list log includes deleted matrices, each detail starting with its name.
- [ ] Given a user without 'See Financial Data', then no Audit Log opens.
- [ ] Given a change made at release plus 120 days, then the client's Audit Log still shows it.
- [ ] Given a sortable number column, when first clicked, then it sorts highest first.
- [ ] Given a search for "  BRAK ", then it matches "Brakes" and the list keeps its sort; given "4" in a tier picker, then tier 4 is listed first, then tiers whose names contain "4".
- [ ] Given titles, tabs and buttons, then they use Title Case; messages and tooltips use sentence case.
- [ ] Given two users editing, when the second saves a matrix name the first just took, then nothing saves, the conflict shows inline and everything typed is kept.
- [ ] Given a save that fails, then "Ooooops! An error occurred" with "Contact support for more information" (or the server's message) shows in the error toast and everything typed is kept.
