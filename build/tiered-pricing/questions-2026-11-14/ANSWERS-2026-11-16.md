## 1. Tiered Pricing: the page trail (breadcrumbs) at the top of a tier's page and a matrix's page

**Chosen: (b)**

> (b) Start at Pricing, as the design draws it: Pricing › Tiers › [tier name] and Pricing › Matrices › [matrix name]. A Settings crumb would need a page to return to. The Settings side panel is always visible, so no one needs to go back to a Settings page to start over. Clicking a Settings crumb would open the Settings section of Settings, which defaults to the Organization settings page, and we don't want that. PRD fix needed: remove "Settings ›" from S2-R28, S3-R26 and S7-R6.

## 14. Tiered Pricing: the change count in the grid's edit bar

**Chosen: (c)**

> (c) The rule-type change counts as 1, and each box whose value changes counts as 1 more. A 3-range column switched to % Off shows "1 change" (boxes start empty, question 13); after a value is typed in each box it shows "4 changes". After Save, the Audit Log records both: 1 rule type changed and 3 range values changed. Reason (Matt): every action must be recorded for audit, so a column quietly changed from 15% margin to a large % off is fully traceable. PRD fix needed: S4-R4 counting and the Audit Log wording (Story 4 / S19-R19) to state this example.

_Where we found it:_ PRD Story 4 (the edit bar); Tiered Pricing design canvas, picture 4.11

## 15. Tiered Pricing: the message after saving a matrix grid

**Chosen: (c)**

> (c) It depends on what changed, per tier: • One rule and value across every range of the tier: the PRD's form, "1 change: Tier 5 is 28% margin." • The same rule type with a different value in each range: "Tier 5 is" followed by a bullet list of each range's rule, for example "• $0.00 to $25.00: 35% margin • $25.01 to $100.00: 28% margin". • More than one rule type in the tier: "Tier 5 is multiple rules" followed by a bullet list of the types, for example "• + $ • Margin %". The toast's "up to three changes, then and <n> more" rule (S4-R12) still applies; each tier is one item. PRD fix needed: S4-R12 and the messages table get these three forms. ## 24. Tiered Pricing: parts added to a paid work order that is reopened

**Chosen: (a)**

> (a) The customer's tier as it is now, as the developers built it. Code check (Nov 16): adding a line to a work order whose invoice is Sent or Paid doesn't reopen it; it creates a new linked work order (new number, Approved) and the paid one and its invoice are untouched (CreateCommandHandler.php, PayedWorkOrderReopenedSubscriber.php). New work orders take the customer's current settings: labor rate (the new labor line defaults to the customer's current labor type), tax and shop supplies. PRD fix needed: Story 10 adds this case (a line added to a paid work order goes on a new work order, priced by the customer's current tier).
