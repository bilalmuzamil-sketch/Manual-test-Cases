*Where the expected result comes from*
Spec "Work Orders — Board View & Tech View Display Options", version 64:
{quote}S11-R1: Each view is a single Tab stop. Tab lands on one work order row (Tech View) or card (Board View), the one last focused, or, when none has been, the first work order shown in on-screen order: the first row or card in Unassigned, or the first technician's first row or card when Unassigned is collapsed or empty (never a group or column header while a work order is shown; when every group is collapsed, Tab lands on the first group header; after the user arrows onto a header and tabs out and back in, Tab returns to a work order row while any row is shown; on Board View, if the last-focused card has scrolled out of view in its column, Tab lands on the first card in view); the focused row or card shows a visible focus ring.{quote}
Chris Ward in this ticket (16 October): "The Tab stop must land on a work order row, never the Unassigned header while a row is shown." His later answer to Slavcho is written into the same rule.
The spec uses "shown" for the work orders listed in the view ("a count of the work orders currently shown in that group … so the count always matches the rows listed", S2-R12) and says "in view" when it means on the screen (the Board View case above). S2-16688 is listed, so it counts as shown.
