# SV-11533 — A/R and A/P Report Sorting - Story 3 - Export to PDF and CSV
Story · TESTING QA · assignee None · parent SV-11315 · QA branch https://sv11315.qa.shopview.com

## Description
h2. Summary

Give each of the six reports the native Export menu with PDF and CSV, exactly matching the rows, filters and sort on screen; A/P gains a PDF for the first time and A/R's Print button is replaced.

h2. Context

As a user, I want to download any of the six reports as a PDF or a CSV in the order on screen so that I can file, print, share or analyze it outside ShopView.

Prerequisites: User must have 'Reports → Page Access' setting enabled.

Form factor: Desktop only by rule: detailed reports.

h2. Requirements

* S3-R1: Each of the six reports has the native report Export menu (the ⋯ button at the right of the title row, labelled "Export report") with "Download (PDF)" and "Download (CSV)". A/R's former Print button is replaced by this menu. The A/P reports gain a PDF.
* S3-R2: The PDF downloads as a file.
* S3-R3: The PDF and the CSV contain exactly the rows on screen for the chosen as-of date, customer or vendor and locations, in the on-screen sort, including a sort changed after an earlier export, without refreshing the page.
* S3-R4: Each export states the as-of date the user picked: the PDF "As of Oct 15, 2026", the CSV "As of: Oct 15, 2026" (format: three-letter month, day, four-digit year).
* S3-R5: Each export states the locations under the as-of line: "Locations: All locations" when every location is ticked, otherwise "Locations: " followed by the ticked locations' names in the Location menu's order (A to Z), separated by a comma and a space, for example "Locations: Main Shop, North Bay". Under it, only when set: "Past due: " and the ticked ranges in menu order (for example "Past due: 31-60 days, 91+ days"), then, for one ticked customer or vendor, "Customer: " or "Vendor: " and the name, and for several, "Customers: " or "Vendors: " and the names in the order they were ticked.
* S3-R6: The Location column appears in the export under the same rule as on screen (Story 6).
* S3-R7: The A/R and A/P Summary PDF and CSV head the last bucket column "91 And Over", exactly as the screen shows it; in the PDF the heading stays on one line.
* S3-R8: The CSV starts with the lines of S3-R5, each in its own row, in this order: As of, Locations, then Past due and the customer or vendor line only when set. The column heading row follows directly, then one flat table: one row per customer or vendor (Summaries) or per document (Detail, Collection, Unpaid Invoices), with the aging bucket, customer or vendor in its own column; no group header or subtotal rows; one Totals row at the bottom. Money is a plain number with two decimals, and an empty bucket is a blank cell; dates are YYYY-MM-DD.
* S3-R8b: The CSV column headings are the on-screen headings, letter for letter (S2-R4a): "Customer Full Name" on A/R Detail, "Customer" on A/R Collection, "Vendor Name" on the A/P reports. The bucket column on A/R Detail and A/P Detail is headed "Aging Bucket", and its values are the bucket names shown on screen.
* S3-R8a: On A/R Collection, every CSV row also carries the customer's "Phone" and, for users with 'View and Manage AP/AR Data', "Credit term", in columns right after "Customer"; the PDF prints them on each customer's line (Story 9).
* S3-R9: The row count for the export limits is the number of customer or vendor rows (Summaries) or document rows (the other four), not counting headers, subtotals or the Totals row.
* S3-R10: A successful export shows the native "Success" message, "Data exported successfully." An export with no rows downloads nothing and shows the native warning "Empty export", "Export didn't yield any results".
* S3-N1: Over 2,000 rows, the PDF is refused before anything is generated: no download, and the message "This report is too large for PDF. Export it as CSV, or narrow the filters, then try again." Exactly 2,000 rows is allowed.
* S3-N2: Over 50,000 rows, the CSV is refused: no download, and the message "This report is too large to export. Choose an earlier as-of date, then try again." Exactly 50,000 rows is allowed.
* S3-N3: A refused export shows exactly one message (S3-N1 or S3-N2), never a second generic error.
* Error handling: If an export fails for any other reason (a server error or a lost connection), nothing downloads and one error message shows: "We couldn't export this report. Please try again." This message is on these six reports only; the other reports keep theirs.

h2. Acceptance Criteria

* Given any of the six reports, when the user opens the ⋯ menu right of the title, then it offers "Download (PDF)" and "Download (CSV)", and A/R no longer has a Print button (S3-R1).
* Given a report sorted and filtered on screen (including a sort changed after an earlier export), when the user downloads the PDF and the CSV, then both hold exactly the on-screen rows in the on-screen order, and the PDF downloads as a file (S3-R2, S3-R3).
* Given as-of date Oct 15, 2026, one location ticked, the 31-60 and 91+ day ranges ticked and two customers ticked, then the PDF reads "As of Oct 15, 2026", the CSV "As of: Oct 15, 2026", then "Locations: <name>" (two ticked locations read in Location menu order, A to Z, for example "Locations: Main Shop, North Bay"), "Past due: 31-60 days, 91+ days" and "Customers: <first>, <second>" in the order ticked; with one customer it reads "Customer: <name>"; the Past due and Customer lines appear only when set (S3-R4, S3-R5).
* Given A/R or A/P Summary, then the PDF and CSV head the last bucket "91 And Over", on one line in the PDF (S3-R7).
* Given any CSV, then it starts with the As of and Locations lines (and the Past due and customer or vendor lines when set), one per row, directly above the column headings; the headings match the screen letter for letter and the bucket column is "Aging Bucket"; then it is one flat table with the bucket, customer or vendor in its own column, no group or subtotal rows, one Totals row, money as plain two-decimal numbers, empty buckets blank, dates YYYY-MM-DD; on A/R Collection, Phone and (with 'View and Manage AP/AR Data') Credit term follow Customer (S3-R5, S3-R8, S3-R8a, S3-R8b).
* Given 2,001 rows, when PDF is chosen, then nothing downloads and exactly one message shows: "This report is too large for PDF. Export it as CSV, or narrow the filters, then try again."; 2,000 rows downloads (S3-N1, S3-N3, S3-R9).
* Given 50,001 rows, when CSV is chosen, then nothing downloads and exactly one message shows: "This report is too large to export. Choose an earlier as-of date, then try again."; 50,000 rows downloads (S3-N2, S3-N3).
* Given a successful export, then "Success", "Data exported successfully." shows; given no rows, then "Empty export", "Export didn't yield any results" and nothing downloads; given a server error or lost connection, then "We couldn't export this report. Please try again." shows once (S3-R10, Error Handling).

h3. CSV layout [S3-R8, S3-R8a, S3-R8b]

* [ ] Headings = the screen's headings, letter for letter ("Customer Full Name" on A/R Detail, "Customer" on A/R Collection, "Vendor Name" on A/P).
* [ ] One row per customer (Summaries) or per document (the other four); no group or subtotal rows; one Totals row.
* [ ] Detail: "Aging Bucket" is the first column, with the screen's bucket names; the Totals row is labelled in it.

* Detail: grouped by bucket in the fixed order, each bucket's lines then its subtotal, one Totals row. Only buckets that hold a document are printed.

h2. Known mismatches (not bugs)

* PDF negatives read "(-$11,111.00)"; the screen shows "$-11,111.00" (Product decision).
* Three date formats: screen "Nov 4, 2026", PDF "Nov 04 2026", CSV "2026-11-04" (Product decision).
* The CSV column is "Credit Term"; the PDF line keeps "Credit term:" (it is a label, not a heading — S9-R2).
* Bills not yet due show negative Past Due in the files too (Product decision).

h2. What is NOT impacted

* Other reports' exports (Sales By Customer, Inventory Value, Work In Progress, …). Only the six aging export addresses were added to the app's "show one message" list.
