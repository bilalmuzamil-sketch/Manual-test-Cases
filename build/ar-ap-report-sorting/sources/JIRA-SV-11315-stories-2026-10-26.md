# SV-7192 — A/R & A/P report: add option to alphabetize customer names for print/PDF output to match QuickBooks

## Reported By

**Customer:** Steph Sabo

**Company:**  Fast Truck and Trailer, Benton

**Email:** stephsabo@yahoo.com

**Number of Users:** 24

**Source:** [Intercom](https://app.intercom.com/a/apps/u6fon4u9/inbox/inbox/conversation/215474187340331)

## Summary

Add an option to alphabetize customer names in the A/R & A/P report for print/PDF output to match QuickBooks ordering.

## Problem Statement

When users print or export the Accounts Receivable (A/R) report, the generated PDF mirrors the current report view. However, the A/R report currently has no built-in sorting control (no clickable customer name header / arrows) to alphabetize customer names, making it difficult to match the customer order shown in QuickBooks.

## Proposed Solution

Enhance the A/R report to support customer-name sorting specifically for the on-screen report and for the resulting print/PDF output. Add a selectable option such as “Sort customers: Alphabetical (A-Z)” (and optionally “Default order” / “As shown”) within the A/R report controls.

When the user selects alphabetical sorting:

* The customer rows in the A/R report should be reordered by Customer Name (A-Z).
* The printed/PDF output should reflect this sorted order (not the previously unsorted/default order).
* Sorting should be deterministic and consistent between preview, print, and PDF export.

## User Impact

Customers who rely on QuickBooks-consistent formatting and ordering will be able to generate A/R PDFs/prints with customer names alphabetized, reducing manual effort and preventing reconciliation/recordkeeping confusion.

## Acceptance Criteria

* \[ \] A new A/R report control/option exists to sort customers alphabetically by Customer Name (A-Z), with a clear default behavior (e.g., “Default order”).
* \[ \] Selecting the alphabetical option reorders the customer rows in the A/R report preview by Customer Name (A-Z).
* \[ \] Printed and/or PDF-exported A/R reports reflect the selected alphabetical sort order exactly (preview and output match).
* \[ \] If a user switches the sorting option, subsequent print/PDF outputs use the latest selected sort order without requiring page refresh or additional steps.
* \[ \] Customer Name sorting handles ties deterministically (e.g., secondary sort by Customer ID if available) so results remain stable across exports.

# SV-11531 — A/R and A/P Report Sorting - Story 1 - Reports open in QuickBooks name order

## Summary

Open all six A/R and A/P aging reports in customer or vendor name order, A to Z, compared the way QuickBooks compares names, with stable paging, so shops can reconcile them line by line against QuickBooks.

## Context

As an office or accounting user, I want each report to open in customer or vendor name order so that I can reconcile it against QuickBooks line by line.

Prerequisites: User must have 'Reports → Page Access' setting enabled.

Form factor: Desktop only by rule: these are detailed reports.

## Requirements

* S1-R1: A/R Summary opens with customers in name order, A to Z; A/P Summary opens with vendors in name order, A to Z.
* S1-R2: Name order compares names ignoring capitals, in plain character order: digits and punctuation compare as characters, so "10 Trucking" comes before "2 Trucking" and "A-1 Towing" before "a1 towing". Names that start with a punctuation mark follow the same order: "#1 Diesel", "-1 Diesel", "10 Trucking", "@Home Towing".
* S1-R3: Accented letters sort with their base letter: "Émile's" sorts among the E names (é è ê ë sort as e, á à â ä ã å as a, ç as c, ñ as n, ö ó ò ô õ ø as o, ü ú ù û as u, í ì î ï as i, ý ÿ as y, ß as ss, æ as ae, œ as oe, in both cases).
* S1-R4: Two names that compare equal are ordered by the plain lower-cased name, then by the customer or vendor itself, so the same two customers always come out in the same order on screen, in the PDF and in the CSV. For example, "Emile's Towing" comes before "Émile's Towing": the accent folds for the name order (S1-R3), so the two tie, and in the plain lower-cased name the unaccented letter comes first.
* S1-R5: A/R Detail and A/P Detail keep their aging buckets in this fixed order: "91 or more days past due", "61-90 days past due", "31-60 days past due", "1-30 days past due", "Current". Inside each bucket, rows open in customer or vendor name order (S1-R2 to S1-R4), ties by document number (S2-R4).
* S1-R6: A/R Collection groups by customer and A/P Unpaid Invoices by vendor, groups in name order (S1-R2 to S1-R4); inside each group, rows open oldest date first; rows on the same date, whatever the time of day they were created, go in document-number order (S2-R4).
* S1-R7: The column the report opened on is marked as sorted: the name column on the Summaries and Detail reports, the Date column on Collection and Unpaid Invoices.
* S1-R8: A/R Summary, A/P Summary, A/R Collection and A/P Unpaid Invoices show 30 customers or vendors at a time, and the next 30 load as the user scrolls down, as today. There are no page buttons. A/R Detail and A/P Detail show each bucket's first 100 lines, then load more as the user scrolls (S4-R4). Paging never repeats or skips a customer, vendor or row, in any sort.
* S1-N1: If the user lacks 'Reports → Page Access', the reports are not available, as today.
* S1-E1: A customer with no open documents on the as-of date does not appear, as today.

## Acceptance Criteria

- [ ] Given A/R Summary with customers "2 Trucking", "10 Trucking", "a1 towing" and "A-1 Towing", when it opens, then the order is "10 Trucking", "2 Trucking", "A-1 Towing", "a1 towing" (S1-R1, S1-R2).
- [ ] Given a customer named "Émile's", when A/R Summary opens, then it sorts among the E names, and every accented letter in S1-R3 sorts with its base letter in both cases (S1-R3).
- [ ] Given two customers whose names compare equal, when the report, its PDF and its CSV are produced, then the two come out in the same order in all three; "Emile's Towing" comes before "Émile's Towing" (S1-R4).
- [ ] Given A/R Detail or A/P Detail, when it opens, then the buckets read "91 or more days past due", "61-90 days past due", "31-60 days past due", "1-30 days past due", "Current" in that order, and rows inside each bucket are in name order, ties by document number (S1-R5).
- [ ] Given A/R Collection or A/P Unpaid Invoices, when it opens, then groups are in name order and rows inside each group are oldest date first, ties by document number, and the Date column is marked sorted; on the other four the name column is marked sorted (S1-R6, S1-R7).
- [ ] Given a report with more than 30 customers, vendors or rows, when the user scrolls through it, the next 30 loading as they scroll (no page buttons), in any sort (with and without Past due ranges ticked), then no customer, vendor or row repeats or is skipped (S1-R8).
- [ ] Given a user without 'Reports → Page Access', then the reports are not available (S1-N1); given a customer with nothing open on the as-of date, then it is not listed (S1-E1).

# SV-11532 — A/R and A/P Report Sorting - Story 2 - Sort by clicking any column header

## Summary

Make every column on the six reports sortable from its header, with the first click giving the useful order for the data type, so users can work the aging in priority order.

## Context

As a user working the aging, I want to sort by any column in one click so that I can work the list in priority order.

Prerequisites: User must have 'Reports → Page Access' setting enabled.

Form factor: Desktop only by rule: detailed reports.

## Requirements

* S2-R1: Every column on all six reports sorts when its header is clicked, except A/P Unpaid Invoices' Vendor Name column (S2-N1). The columns are: • A/R Summary and A/P Summary: the name column, Location (when shown), Current, 1-30 Days, 31-60 Days, 61-90 Days, 91 And Over, Total. • A/R Detail: Date, Location (when shown), Transaction Type, ID, Customer Full Name, Due Date, Amount, Open Balance. • A/R Collection: Date, Location (when shown), Transaction Type, ID, Due Date, Past Due, Amount, Open Balance. • A/P Detail and A/P Unpaid Invoices: Date, Location (when shown), Transaction Type, No., Vendor Name, Due Date, Past Due, Amount, Open Balance.
* S2-R2: The first click gives the useful order for the kind of data: text (names, Location, Transaction Type) A to Z; money columns largest first; dates oldest first; Past Due largest first; ID and No. smallest number first (S2-R4). The second click reverses it. The third click repeats the first; there is no unsorted state.
* S2-R3: A header that is already the sorted column reverses on its first click.
* S2-R4: ID and No. sort by number value: S1-99 before S1-100 before S1-101. The first click puts the smallest number first and the second click the largest first. The same number-aware order breaks ties in every sort, always smallest document number first: reversing a sort reverses the sorted column only, so tied rows keep that order in both directions. A date column compares the day only, never the time of day, so two rows on the same date are a tie.
* S2-R4a: Column headings are in Title Case on all six reports, on screen, in the PDF and in the CSV, as on the other reports (Sales By Customer, Inventory Value, Parts Velocity): the A/R reports read "Transaction Type", "Customer Full Name", "Due Date", "Past Due" and "Open Balance", the same as the A/P reports.
* S2-R5: On the grouped reports, a header click sorts the rows inside each group; the groups themselves never move (S1-R5, S1-R6).
* S2-R6: A blank value (for example a vendor credit on A/P Unpaid Invoices, which has no due date and no Past Due) sorts to the bottom of its group in both directions. On A/P Detail a vendor credit shows its own date as its due date, as today, so it is not blank there.
* S2-R7: The sort is kept while the user stays on the report: changing the as-of date, loading more rows by scrolling, and changing the customer, vendor, Past due or Location filter keep it.
* S2-R8: The sort is not remembered between visits: opening the report again starts from Story 1's order.
* S2-R9: Re-sorting never changes which groups are expanded or collapsed (Story 4).
* S2-N1: On A/P Unpaid Invoices, the Vendor Name header is not clickable, because every group holds a single vendor and sorting by it could never change the order.
* S2-E1: A column where every row has the same value (for example Location when each customer has one location) shows no visible change; the tie-break (S2-R4) still applies.

## Acceptance Criteria

- [ ] Given any of the six reports, when the user clicks each header listed in S2-R1, then the rows re-sort by that column; on A/P Unpaid Invoices the Vendor Name header is not clickable (S2-R1, S2-N1).
- [ ] Given an unsorted text column (name, Location, Transaction Type), when clicked once, then A to Z; a money column, largest first; a date column, oldest first; Past Due, largest first; a second click reverses; a third click repeats the first (S2-R2).
- [ ] Given the column the report opened on, when its header is clicked, then it reverses on that first click (S2-R3).
- [ ] Given documents S1-99, S1-100 and S1-101, when ID or No. is clicked once, then they read S1-99, S1-100, S1-101, and a second click reads S1-101, S1-100, S1-99; two rows tied on the sorted column stay smallest document number first in both directions (S2-R4). The A/R headings read "Transaction Type", "Customer Full Name", "Due Date", "Past Due" and "Open Balance", in Title Case like the A/P reports, on screen, in the PDF and in the CSV (S2-R4a).
- [ ] Given a grouped report, when any header is clicked, then rows re-sort inside each group and the groups do not move, and expanded groups stay expanded (S2-R5, S2-R9).
- [ ] Given A/P Unpaid Invoices with a vendor credit, when Due Date or Past Due is sorted either way, then the credit sits at the bottom of its vendor group (S2-R6).
- [ ] Given a sorted report, when the user changes the as-of date, scrolls to load more rows, or changes the customer or vendor, Past due or Location filter, then the sort is kept; when the user opens the report again from the Reports menu, then it opens in Story 1's order (S2-R7, S2-R8).

# SV-11534 — A/R and A/P Report Sorting - Story 4 - Collapse all, Expand all and pinned group rows

## Summary

On the four grouped reports, add a Collapse all / Expand all chevron in the top-left header cell and keep the group row in view pinned under the column headings while scrolling.

As a user reading a grouped report, I want to open or close every group at once and always see which group I'm scrolling through so that I don't lose my place.
