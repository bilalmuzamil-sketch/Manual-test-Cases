Setup: Pinned technician columns after deactivation or removal from this location
Test case: C368131, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.
How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.
What the setup creates (the test case's Preconditions)
• You are signed in as {User-A}, an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).
• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.
• A second user {User-B} (for example "ZZAUTOTEST C368131 Viewer") has a role with Work orders > View only (Create & Edit off) at {Location-A} and is signed in in a second browser or a private window.
• Technician {Technician-A} (for example Esther Howard) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.
• Technician {Technician-B} (for example ZZAUTOTEST Jenny Pinned) is an active technician at {Location-A}, made for this case only, and leads no work order.
• Technician {Technician-C} (for example ZZAUTOTEST Theresa Pinned) is an active technician whose Location (Settings > Staff) is {Location-A}, made for this case only. {Location-B} is another location of the company (for example Staging Lethbridge - 4310).
• Customer {Customer-A} (for example "ZZAUTOTEST C368131 Pinned Gone") is used by this case only.
• Approved work order {Work-order-1} (for example S10043-17691) for {Customer-A} is led by {Technician-A}.
• Approved work order {Work-order-2} (for example S10043-17692) for {Customer-A} is led by {Technician-C}.
• Both {User-A} and {User-B} have {Technician-B} and {Technician-C} pinned in Board View.
• No technician has a shift on the Schedule for {Work-order-1} or {Work-order-2}.
• On the Work Orders page nothing is ticked in Status, Asset on Site shows no choice (if its chip shows Yes or No, click the x on the chip), Assigned to me is off and Search is empty.
Part 1. Setup for manual QA tester
1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.
2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.
3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).
4. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Esther Howard), an Email, Role Technician, Departments Service, Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}.
5. Your initials > Settings > Staff. Create a new staff member for this case only (do not reuse a shared one, because this case changes the record): click New Staff Member and enter First Name and Last Name (for example ZZAUTOTEST Jenny Pinned), an Email, Role Technician, Departments Service, Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-B}.
6. Your initials > Settings > Staff. Create a new staff member for this case only (do not reuse a shared one, because this case changes the record): click New Staff Member and enter First Name and Last Name (for example ZZAUTOTEST Theresa Pinned), an Email, Role Technician, Departments Service, Location {Location-A} (the Location field takes one location; in the test she is moved to {Location-B}, another location in that list, for example Staging Lethbridge - 4310), turn Time Clock on, then Save & Close. This is {Technician-C}.
7. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST C368131 Pinned Gone") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.
8. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17691). Repeat this once more. Number them {Work-order-1} and {Work-order-2}.
9. On the work order page pick the technician in the Lead Technician dropdown; it saves at once. Give {Work-order-1} the lead {Technician-A} and {Work-order-2} the lead {Technician-C}.
10. Your initials > Settings > Roles & Permissions > Create Custom Role > in the Choose a template window click Skip > Role Name (for example "ZZAUTOTEST C368131 View Role") > under Work orders turn on View and leave Create & Edit off > Create.
11. Your initials > Settings > Staff > New Staff Member with an email you can open (for example "ZZAUTOTEST C368131 Viewer"), Role = the new role, at least one Department, Location {Location-A} > Save & Close. Accept the invitation email and set a password. This is {User-B}; keep it signed in in a second browser or a private window.
12. As {User-A}, and again as {User-B}: Work Orders > All tab > Board View. If three technicians are already pinned, unpin one (click the filled pin in its column header), because only three pins are allowed. Click the pin icon in {Technician-B}'s and in {Technician-C}'s column headers (pins are per user).
13. Do not book any Schedule shift on {Work-order-1} or {Work-order-2}.
14. Check the setup worked: for both users, Board View shows {Technician-B} and {Technician-C} right after Unassigned with filled pins. Work Orders > All tab > Search with the name of {Customer-A} shows {Work-order-1} led by {Technician-A} and {Work-order-2} led by {Technician-C}. If anything differs, fix it before you start, then clear the search.
Part 2. Setup for Claude session
• Goal: two pinned technicians for both users; during the test one is deactivated ({Technician-B}, leading nothing) and one is removed from {Location-A} ({Technician-C}, still leading {Work-order-2}); then the board is read and three drags are made, and the board is read as a view-only user.
• GET /api/staff lists staff; each row has both id and staff_id, and the Schedule's staffId and the working-hours calls use staff_id.
• Create {Technician-B} and {Technician-C} new for this case (never deactivate or move a shared technician). Create {Customer-A}, its contact and asset, and {Work-order-1} and {Work-order-2} on screen as in Part 1. Record {Work-order-1 id} and {Work-order-2 id}.
• {User-B} needs a second browser context with its own sign-in (the invitation and password are set on screen). Quick login signs in only as Admin, so {User-B} must sign in with the email and password; keep the password in /tmp only.
• On staging (build v26.40.17-ddb9ba1, 14 Oct 2026) the Edit Staff Member Location field takes one location, so step 3 moves {Technician-C} from {Location-A} to {Location-B} (Save & Close).
• Steps 1 to 3 change the staff records during the test; do them on screen as written.
• Steps 9 to 12: Playwright drag-and-drop from each card to the target column. Read the message after step 10 exactly and compare it character for character with "This technician can't be assigned work orders." Record where each card ends up and whether any question opened.
• Steps 7, 8 and 15: record each column header's text and whether it shows a pin, an inactive marker and the empty-column text. UNVERIFIED: how the build shows the inactive marker (a label or a badge); record what you see.
• Context: this case follows PRD version 49 (14 Oct 2026). Nothing about how the build behaves today is assumed; judge only what you see.
• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.
How to work
Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only.
