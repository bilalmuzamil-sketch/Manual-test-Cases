## 2. Recipes (how to build each kind of record)

- **New staff member:** Settings → Staff → New Staff Member: first name, last name, email, Role, location enrollment, Billable, then the toggle row below Billable (Time Clock, Sales Representative, Technician) → Save & Close. A staff member who must sign in also needs a password set (record it in `/tmp` only). API alternative (playbook §ROLES / STAFF / ADMIN): `POST /api/iam/create`.
- **Technician on or off on an existing staff member:** Edit Staff Member → Technician → Save & Close. Turning it off for someone with open work shows Turn Off Technician; click Save there. Editing a staff record logs that user out today (playbook: "EDITING A STAFF RECORD KILLS THAT USER'S SESSION"), except a Technician-only change (S1-R8): finish all record changes before signing in as that user.
- **Custom role from a template:** Settings → Roles & Permissions → Create custom role → Choose a template (Technician, Foreman, Office User or Time Clock User) → Apply → Role name `ZZAUTOTEST <key> Role A` → Create. 'Settings → App Settings' off for S1-34.
- **Service work order in a status:** Work Orders → New Work Order (customer + asset) gives Estimate; add a line (New Line) and approve it to reach Approved; start work for In Progress; move to Ready for Review; complete for Complete; invoice for Invoiced; take payment for Paid; decline the work order for Declined, or decline a single line for a declined line. Playbook: create a fresh work order (existing ones can bounce).
- **Lead:** On the work order, Lead Technician dropdown → pick the person while they are still a technician.
- **Labor entry on a line:** Add Labor on the line, technician = the person (no time needed unless the case says so).
- **Add Technician on a line:** New Line or Edit Line → Add Technician → pick the person (no labor).
- **Line's own technician:** The technician set on the line itself, without labor and without Add Technician. **Confirm on the build how the screen sets it** (the PRD names it; the v9 tech plan maps it to the line's own technician field); record the click path here once proven.
- **On a line through a schedule shift:** Schedule → create a shift for the person on that line (the playbook notes the grid is click-to-create, so this is done by hand).
- **Time recorded on a line:** Sign in as the person → open the work order → Start on an approved line → Stop. For a time entry on a given past date, a time sheet editor adds a manual entry for the person on the work order's Time Sheets tab.
- **Former technician (on work, no longer a technician):** Make the person a technician, give them the lead or line, then switch Technician off and click Save in Turn Off Technician. Nothing is unassigned (S2-R5).
- **Pinned Board View column:** Board View → the person's column → pin it (while they are still a technician) → then switch their Technician off.
- **Location C (no technicians):** Create a location `ZZAUTOTEST <key> Location C` in the organization; enroll no technician there (any staff enrolled there has Technician off).
- **Computer clock for the pill and notice:** Set the operating system clock (not the app). The PRD reads the end date from the viewer's own clock (S1-R2). Until the release is scheduled the build carries 31 Dec 2026, 07:00 UTC (SV-12008).
- **Public API requests:** Read: `GET /api/v1/staff`, `GET /api/v1/staff/<id>`, `GET /api/v1/locations/<id>/staff`. Update: `PATCH /api/v1/staff/<id>` (`technician` is ignored, S5-N1). Names from the v9 tech plan's API table; confirm against the Public API documentation. A role change and a work order lead change through the Public API are not named in any saved source (API-12, API-13 held).
