## 5 · One honest side effect, reported not hidden

A TestRail **UI** save re-serialises **every** field on the form, not only the one edited. `custom_preconds`
and `custom_steps` held plain text with literal `1.` / `2.` / `3.` line prefixes; the editor loaded them,
recognised the numbering and stored them as a real ordered list:

```
before:  '1. You are signed in to the ShopView App on a desktop browser.\n2. ...'
after :  '<ol><li>You are signed in to the ShopView App on a desktop browser.</li><li>...'
```

**The words are byte-identical and the tester still reads a numbered list** — the numbers are now list
markers instead of typed characters, and both fields also moved from the escaping `markdown` container
to `markdown fr-view`. This is the same shape the rest of the estate's rich-text cases already use
(e.g. C26496, C30287). It is recorded here because Rule 12 does not allow a silent side effect.
