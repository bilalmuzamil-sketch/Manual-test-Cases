## The historical precedent nobody should have to rediscover

**[SV-7855](https://shopview.atlassian.net/browse/SV-7855)** — *"Sales Rep: report links clickable
despite View OFF (3 pages)"*, **filed 2026-06-23, Done 2026-07-13** — is this exact defect class on the
**legacy** reports, and its own words are the best statement of the rule Parth generalised:

> *"When a user with the Sales Rep role has view permissions turned OFF for areas like Customers, Work
> Orders, Vendors, or Invoices, any links to those pages inside reports should be plain text and
> completely non-clickable… Actual: A/R Aging, A/P Unpaid Invoices: Links are clickable and lead to 403
> or 'Access Denied' error pages. A/P Aging Detail: The Invoice link actually opens up a forbidden
> /parts/delivery page."*

**Three legacy reports shipped with exactly this fault, and on one of them the link actually let the user
through.** So the negative half is not a theoretical nicety — **it is a defect this product has already
had**, which is why authoring it matters even though we could not run it. **SV-8292 / SV-8293 / SV-8294**
(Work Orders Audit Log, all Done) are three more of the same class.

**Anticipated challenge, answered here:** *"you had a live session and still did not test the main
thing."* True, and the reason is in one line — **a live session as an administrator cannot show what a
user without permission sees**, and becoming that user was the part we could not do.
