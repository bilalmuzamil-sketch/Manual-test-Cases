# SV-8976 — Sales By Representative: a saved date range that is no longer valid leaves the report empty

1. What happens now
The report remembers your filters in the browser. If the saved date range is one the report no longer recognises, it does not fall back to the normal default.
Instead the date button reads "Select Date Range", no data is asked for at all, and the report sits there empty with the no-data message.
The user has no way of telling that anything went wrong - it simply looks as though there is no sales activity.
2. What should happen instead
A saved value that is no longer valid should quietly fall back to that setting default - here, This Month - and the report should load normally.

4. How bad is it
Low, but misleading: an empty report reads as "no sales", not as "your saved setting was dropped".
5. What we ruled out
We checked that every OTHER saved setting does fall back correctly: an unknown sort column, an unknown column list, an unknown product type and an unknown invoice status all quietly revert to their defaults and are rewritten in the browser. It is the date range alone that does not. Nothing errors, so the "never causes an error" half of the requirement is met.
6. Where this expected behaviour comes from
Where this expected behaviour comes from: the Sales By Representative report specification, version 17, requirement S23-R3, which says: "Restoration is defensive: a remembered value that is no longer valid (a location the user can no longer access, a range or sort column that no longer exists, a hidden-but-sorted column) falls back to that setting's default rather than being sent to the server.". That is source type 2: the specification (PRD) in Confluence. The version number given is the Confluence page version, not the version written inside the page.
