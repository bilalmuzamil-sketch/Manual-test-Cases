# SV-8989 — Work In Progress: Inv. Hrs shows two decimal places where the description asks for one

What happens now
Switch the Inv. Hrs column on in the Work In Progress report. Every value carries TWO decimal places - for example +0.50, +1.24, -0.81, -14.86 - and a zero reads 0.00.
The Totals row at the foot of each tab does the same: +246.84, +1434.65, +0.52, +173.50.
What should happen instead
Requirement S4-R23 asks for "a signed number with one decimal place (\"+2.0\", \"-14.0\", \"0.0\"). A zero value shows unsigned as \"0.0\" (never \"+0.0\" or blank)."
So the same values should read +0.5, +1.2, -0.8, -14.9 and 0.0.
How to see it
Open Reports, then Work In Progress. Set the date range to Last 12 Months. Open Column Selection and switch Inv. Hrs on. Read any value in that column, and the Totals row at the bottom.
What we tested it on
QA branch sv8582, build v3.5-f77875c, on 6 August 2026. Date range Last 12 Months, both locations (Staging Heavy Duty - 9919 and Staging Lethbridge - 4310). Checked on all four tabs.
How bad is it
Low. The sign is right, the zero is correctly unsigned, and the arithmetic is right - it is the number of decimal places that differs. The green and red colouring of the values is also correct.
Where this expectation comes from
The Work In Progress report specification on Confluence, version 9 - the numbered requirement is named in each section below. The owning story is the parent of this ticket, and that story sits under epic SV-8582.
