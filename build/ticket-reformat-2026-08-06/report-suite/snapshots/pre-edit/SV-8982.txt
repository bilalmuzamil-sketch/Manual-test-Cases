# SV-8982 — Sales By Representative download file names have a date-range word added to them

1. What happens now
All four downloads should have fixed, predictable file names. Each one instead has the chosen date range added to the end.
You get sales-by-representative-summary-this_month.csv rather than sales-by-representative-summary.csv, and the word changes with the range - this_year, last_week, or custom.
All four files behave the same way: both spreadsheets and both PDFs.
2. What should happen instead
The four names should be exactly sales-by-representative-summary.pdf, sales-by-representative-expanded.pdf, sales-by-representative-summary.csv and sales-by-representative-expanded.csv.

4. How bad is it
Low, but it defeats the point of a fixed name: anything that picks the file up automatically, or any saved-file rule, will not find it.
5. What we ruled out
We downloaded the same view three times with three different date ranges and read the name the browser was given each time, so the changing part is definitely the date range and not something else. The file contents were correct every time.
6. Where this expected behaviour comes from
Where this expected behaviour comes from: the Sales By Representative report specification, version 17, requirement S14-R11, which says: "PDF filenames are deterministic: sales-by-representative-summary.pdf and sales-by-representative-expanded.pdf.". That is source type 2: the specification (PRD) in Confluence. The version number given is the Confluence page version, not the version written inside the page.
