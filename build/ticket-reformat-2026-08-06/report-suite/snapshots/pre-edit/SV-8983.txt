# SV-8983 — Sales Rep Assignments spreadsheet does not start with the UTF-8 marker

1. What happens now
The Sales Rep Assignments download is missing the small UTF-8 marker that should sit at the very start of the file.
Without it, a spreadsheet application opening the file on a Windows machine can show accented letters in customer or representative names incorrectly.
2. What should happen instead
The file should start with the UTF-8 marker, the same way the report own two spreadsheets do.

Customers Aaborough Works, Aacastle Services, Aachester Partners, Aacrest Works, Beman Systems. Locations Staging Heavy Duty - 9919 and Staging Lethbridge - 4310.
4. How bad is it
Low. Every row in the file is correct; it only shows up on names with accented characters.
5. What we ruled out
We read the first three bytes of the file rather than opening it in a spreadsheet, so this is the real first line and not a display effect. We checked the report own Summary and Expanded spreadsheets in the same session and both DO start with the marker, so this one file is the odd one out. Everything else about it is right: the name is sales-rep-assignments.csv, the three headings are exactly Customer Name, Sales Rep, Rep is active?, there is one row per customer with a representative (4,724 of them), they are in customer-name order, and the success message appears.
6. Where this expected behaviour comes from
Where this expected behaviour comes from: the Sales By Representative report specification, version 17, requirement S15-R4, which says: "The CSV has a header row + one row per customer. Headers, in order: Customer Name, Sales Rep, Rep is active?. UTF-8 BOM prepended.". That is source type 2: the specification (PRD) in Confluence. The version number given is the Confluence page version, not the version written inside the page.
