# SV-8977 — Sales By Representative: the heading row and the Totals row both scroll away instead of staying put

1. What happens now
The written description asks for two rows to stay put while you scroll down a long report: the column heading row at the top, and the Totals row at the bottom.
Neither does. Both scroll away with the data, so on a long list you lose sight of which column you are reading and of the totals.
2. What should happen instead
The column heading row should stay stuck to the top while you scroll down, and the Totals row should stay stuck to the bottom of the scrolling area.

Low. Everything reads correctly; it is harder to use on a long report.
5. What we ruled out
We checked the Subtotal column separately and it IS correct - it stays stuck to the right-hand edge when you scroll sideways, and it is bold on the heading row, on every representative row and on the Totals row. So the pinning code works in one direction and not the other. The Totals row is also correct in content: it reads "Totals", merges the four name columns, and every figure is the total across the whole filtered result.
6. Where this expected behaviour comes from
Where this expected behaviour comes from: the Sales By Representative report specification, version 17, requirement S10-R6, which says: "On screen, the column-header row is sticky to the top during vertical scroll". That is source type 2: the specification (PRD) in Confluence. The version number given is the Confluence page version, not the version written inside the page.
