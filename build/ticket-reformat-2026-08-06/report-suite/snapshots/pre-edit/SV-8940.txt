# SV-8940 — Parts Velocity never shortens long Description, Category or Vendor text, so the table runs far wider than the window

### 1. What happens now
On the Parts Velocity report, long text in the Description, Category and Vendor columns is never shortened. Instead the column simply grows as wide as the longest value in it, which pushes the table far wider than the window and forces the user to scroll sideways to reach the numbers. There is also no tooltip: resting the pointer on a long value shows nothing, because the full value is already on display.
### 2. What should happen instead
Parts Velocity specification, version 5, requirement S3-R7 is covered by the test as: long Description, Category and Vendor text is shortened with an ellipsis on screen, and the full value is shown on hover. Part # is never shortened.
### 3. How to see it
1. Sign in as a user who can see reports and open Reports > Parts Velocity.
2. In the report's own search box type 179.YK5005.
3. Look at the Description cell in the row that comes back, and rest the pointer on it.
4. Notice the horizontal scrollbar under the table.
Exact test data this was seen with: part number 179.YK5005, description CLEVIS KIT MERITOR TYPE 5/8"Straight, 5/8in-18 Threads, 1/2in and 1/4in Pins, Pin C to C is 1-3/8in(E11430A, R810019) (117 characters), category HD-Air Brakes & Air Suspension (30 characters), locations Staging Heavy Duty - 9919 and Staging Lethbridge - 4310, date range This Year, browser window 1680 pixels wide.
### 4. What was actually shown
The Description cell was 744 pixels wide and held the whole 117-character value with nothing cut off, and it carried no tooltip text at all. The table itself came out 2,429 pixels wide inside a 1,372 pixel space, so roughly a thousand pixels of it sat off-screen.
### 5. What was ruled out
- It is not the window being too narrow. The cell is not clipped at all - it is sized to fit the whole value, so the text is complete and the table is simply too wide.
- It is not the Part # column. Part # is correctly left alone, which is what the written description asks for.
- It is not one long value. Category behaves the same way - a 30-character category is shown in full in a 217-pixel cell.
- Note for triage: the same behaviour was reported on Inventory Value as https://shopview.atlassian.net/browse/SV-8932#icft=SV-8932. This ticket is the Parts Velocity report.
### 6. How often
Every time, on every row looked at.
### 7. Where it was seen
Reports > Parts Velocity, on the QA branch, build v3.5-16cf83f, on 6 August 2026.
 
Where this expected behaviour comes from: the Parts Velocity report specification, version 5, requirement S3-R7, which says: "The Description, Category, and Vendor columns truncate long text with an ellipsis on screen; the full value is available on native hover (browser tooltip) and is written in full to the CSV export (S6). Part # is never truncated (on screen or in any export)."
