# SV-8871 — A saved Customer, Lead Technician or Service Advisor filter comes back without its name on the button

Snapshot taken before the 2026-08-06 reformat. Live `updated` at snapshot time: 2026-08-06T08:11:28.669-0500

---

### Environment

QA branch https://sv8785.qa.shopview.com/workorders — build v3.4.2-d00239b (index.html last modified Tue, 04 Aug 2026 22:51:02 GMT). Desktop browser, signed in as an Admin.

### Steps to Reproduce

- Open Work Orders on the All tab with no filters on.
- Click the Customer button and pick the customer named Iibay Landscaping. The button correctly reads "Customer: Iibay Landscaping" and the list narrows.
- Now leave the page and come back — any of these four does it: open a work order and click back; refresh the page; close the browser completely and sign in again; or open the same link in a new window.
- Look at the Customer button.
- Repeat the whole thing with the Lead Technician button (pick Admin ShopView) and with the Service Advisor button (pick Admin ShopView).

### Expected Result

The button should still read "Customer: Iibay Landscaping", the same as it did before you left the page. The user needs to see WHICH customer the list is filtered by without opening the button.

### Current Result

The button comes back blue (switched on) but reads only "Customer" — the customer's name is gone. The filter itself is still working: the list is still filtered by that customer, and if you open the button the name is there as a tag with a tick beside it. So the list is filtered by something the screen no longer names.

The same thing happens on the Lead Technician and Service Advisor buttons. It does NOT happen on the Status or Asset on Site buttons — those keep their value ("Status: Paid" comes back correctly), so a user sees one button naming its value and another not naming its value side by side.

### How often

Every time, on all four routes back to the page, on all three of those buttons. Reproduced twice from a clean start.

### Technical detail

The three affected filters are the ones whose choices are fetched from the server (/api/customers/list-options and the staff list); the two unaffected ones are fixed lists held in the page. On a restore the saved filter value is read back and applied to the request (filters[n][field]=company_id&filters[n][value]=00122246-ab6d-47ee-a885-3425c7bda754) but the button's label is rendered before the name for that id is available, and is not re-rendered once it arrives. Specification references: S7-R1, which says the chip "displays the selected value(s)", and S10-R1, which says filter selections are "restored exactly as they were left".

 

Where this expected behaviour comes from: the Filters specification, version 18, requirement S7-R1, which says: "When a filter has one or more values selected, the chip changes to an active/highlighted visual state (blue pill) and displays the selected value(s)". The last five words are the part that is missing.

And requirement S10-R1, which says: "When the user navigates away from the Work Orders page (e.g., to a Work Order detail, then back), the filter selections and collapsed/expanded state are restored exactly as they were left".
