# SV-8912 — On a phone there is no page search: the magnifier opens global search, which does not narrow the list (S13-R17/R18)

Snapshot taken before the 2026-08-06 reformat. Live `updated` at snapshot time: 2026-08-06T08:11:30.995-0500

---

### Type of Issue

Defect against the build — on a phone the page search control is absent, and the toolbar search button opens the global search instead, which does not narrow the list.

### Environment

QA branch — sv8785.qa.shopview.com/workorders. Build v3.4.2-d00239b (index.html last-modified Tue 04 Aug 2026 22:51:02 GMT). Mobile viewport 390 x 844, touch enabled, iPhone user agent. Signed in as Admin ShopView, Administrator, workplace Staging Heavy Duty - 9919.

### Steps to Reproduce

- Open the Work Orders page on a phone-sized viewport (390 x 844).
- Look at the action row. There is one search control, the magnifier button.
- Tap it.
- Type a customer name that exists in the list — use Bahampton Holdings.
- Watch the work order list and the address bar.

### Actual Result

- There is no page search control on mobile at all. The only search element in the action row is the magnifier button, and tapping it opens the GLOBAL search — the input that appears is the global search field, accompanied by a global-search close button.
- Typing Bahampton into it does not narrow the list. The list stays at 30 work orders, the address bar stays at /workorders?tab=all with no search parameter, and no list request carrying a search term is sent.
- The primary call to action, Create Work Order, keeps a width of 332px on a 390px-wide viewport. It does not fall back to its natural hug width, so there is no free space in the action row for a search field to expand into.

### Expected Result

S13-R17: "On mobile the expanded field fills the remaining width of the action row rather than taking the fixed 180px desktop width. On Work Orders that resolves to 162px. All other toolbar actions remain visible and in position throughout".

S13-R18: "To create that room, the primary CTA on mobile uses its natural hug width instead of stretching to fill the row: 'New Work Order' is 144px, the same width it has on desktop, not 211px."

So on a phone the page search should expand inline in the action row to roughly 162px and narrow the work order list as the user types, exactly as it does on desktop, while the primary call to action shrinks to its hug width to make room. The global search is a separate control and must not stand in for it — the specification keeps them distinct, and the global search does not filter a page list.

### Test Data

- Customer searched for: Bahampton Holdings — it has 6 work orders, so a working page search would visibly narrow the list to those 6.
- The same search term typed into the DESKTOP page search on the same build does narrow the list correctly to 7 rows showing only Bahampton Holdings, which is what makes the mobile behaviour a phone-specific gap rather than a broken search.
- Values tried and ruled out: the term is not the problem (it works on desktop); no page_search_toggle element exists anywhere in the mobile document, so this is not a matter of the control being collapsed or scrolled out of view.

### Technical Notes

- On desktop the control is the element carrying data-test-id page_search_toggle, which expands into page_search_input. Neither element is present in the document on a mobile viewport.
- The mobile magnifier button carries data-test-id button_open_mobile_search, and what it opens is the element carrying data-test-id select_global_search, together with button_global_search_close.
- Measured on the build: Create Work Order 332px against a 390px viewport.

 

Where this expected behaviour comes from: the Filters specification, version 18, and three requirements settle it together.

Requirement S13-R16: "Mobile uses the same inline expansion as desktop. There is no modal, no separate search screen, and no mobile-only state in the component. Tapping the collapsed control expands it in place within the action row, moves focus into the field and raises the keyboard".

Requirement S13-R17: "On mobile the expanded field fills the remaining width of the action row rather than taking the fixed 180px desktop width. On Work Orders that resolves to 162px. All other toolbar actions remain visible and in position throughout; nothing is hidden while searching".

Requirement S13-R18: "To create that room, the primary CTA on mobile uses its natural hug width instead of stretching to fill the row: “New Work Order” is 144px, the same width it has on desktop, not 211px."

The same specification also keeps the page search and the application-wide search apart, in requirement S13-R9: "Search is scoped strictly to the records in the current table. It never returns results from another table, another page, another module, or any content outside that table." So the global search cannot stand in for the page search.
