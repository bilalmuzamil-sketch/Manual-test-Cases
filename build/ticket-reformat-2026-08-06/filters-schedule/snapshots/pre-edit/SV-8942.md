# SV-8942 — Schedule: at 960px and below the whole page scrolls sideways and the work order panel never collapses

Snapshot taken before the 2026-08-06 reformat. Live `updated` at snapshot time: 2026-08-06T02:50:07.196-0500

---

### What happens now

The Schedule page is meant to cope with a narrow screen by letting the grid slide sideways while the left-hand panel folds away. Neither happens. Make the browser window narrower and the whole page starts sliding sideways instead - the top navigation, the toolbar and everything else go with it - while the left-hand work order panel stays exactly as wide as it was.

### Why this matters

A planner on a laptop or a small window ends up scrolling the entire page left and right just to see the end of the week, and the panel that should have got out of the way is still taking up a third of the screen. Nothing is lost or broken, but the page becomes awkward to work in.

### How to see it

- Sign in and open the Schedule page in Week view.
- Make the browser window 960 pixels wide - that is the narrowest width the Schedule is supposed to support.
- Look at the left-hand work order panel, and try scrolling the page sideways.
- Narrow it further, to 900 and then to 700 pixels, and look again.

### What you see

- The left-hand panel keeps the same width the whole way down - 275 pixels of content inside a 299 pixel column - at 1000, 960, 900 and 700 pixels alike. It never folds away.
- The page itself is what scrolls sideways. Its total width stays stuck at 1030 pixels no matter how narrow the window gets, so the sideways scrollbar belongs to the whole page and not to the grid.
- There is no sideways scroller on the grid at all. The only things that overflow are the page and its outer containers.
- At a full 1680 pixel window there is no sideways scrolling at all, so this only appears once the window is narrowed.

### What should happen

From the Schedule specification, section 11: "Minimum supported width is 960px (the grid scrolls horizontally below that), and the sidebar collapses on narrow viewports."

- The grid - not the page - should be the thing that scrolls sideways.
- The left-hand panel should collapse once the window is narrow.

### Exact test data used

- Location: Staging Heavy Duty - 9919.
- Schedule page, Week view, the week of 3 August 2026, with 22 technician rows and 55 shift blocks showing.
- Signed in as admin@shopview.com.
- Widths measured: 1680, 1000, 960, 900 and 700 pixels, window height 1000.

### Things checked and ruled out first

- Not a stray error - the page reports zero errors at every width tested.
- Not only a below-minimum problem. It happens at exactly 960 pixels, which the specification calls the narrowest supported width, so it is inside the supported range and not just an edge case.
- Not a missed element - every element on the page that overflows was listed, and the only ones are the page itself and its outer containers. No grid-level scroller exists to have been missed.
- Not the full-size layout - at 1680 pixels the page width matches the window exactly.

### Where this came from

Found while running the Schedule test case SCH-EDGE-01 (TestRail C30086) against build v3.5-7ec992f on 6 August 2026.

 

Where this expected behaviour comes from: the Schedule specification, version 23, section 11 (Non-functional requirements), which says under Responsiveness: "Minimum supported width is 960px (the grid scrolls horizontally below that), and the sidebar collapses on narrow viewports." Both halves are in that one sentence: it is the grid that scrolls sideways, and the sidebar collapses.
