# SV-8855 — The spread window has no start date, so a second technician's run of days cannot be made to follow the first

Snapshot taken before the 2026-08-06 reformat. Live `updated` at snapshot time: 2026-08-06T02:49:27.098-0500

---

### Description

When a big job is spread over several days, the spread window lets the planner choose how much to schedule and shows a preview - but it has no start date field. The run of days always begins on whichever day the job was dropped on, and there is no way to change it in the window. That removes the one way the planner was meant to have of making a second technician's run start AFTER the first one finishes instead of alongside it, which is how two technicians share a long job in sequence.

### Steps to reproduce

- Open the Schedule and pick the Week view.
- Type S-14527 into 'Search work orders' to find the Qispring Rentals work order (5 lines, 40.3h estimate).
- Drag the card onto technician Brittany Anderson's row on the Monday column and choose 'Schedule whole work order'.
- The spread window opens showing 'Brittany Anderson - Whole order - 40h 19m', a 'Schedule' choice reading 'Full estimate (40h 19m)', and a preview reading '4 shifts - 40h 19m / Aug 10 to Aug 13 - 12h/day, Mon-Thu'.
- Look for a start date field anywhere in the window.
- Try each of the other choices - 1 week, 2 weeks, 'Until a date...' and 'Specific hours...' - and look again.

### Expected behaviour

The spread window carries a start date that defaults to the earliest working day and can be changed, so a planner can push a second technician's run to begin after the first one ends.

### Current behaviour

There is no start date field in the window under any of the five choices. 'Until a date...' adds a 'Finish by' date and 'Specific hours...' adds an 'Hours per day' number, but neither lets the planner set where the run begins. The start is fixed by the cell the card was dropped on.

### Technical details for developers

Enumerated every input inside the spread dialog for all five selector values: Full estimate -> 1 text input (the selector itself); 'Until a date...' -> that plus one input[type=date] labelled 'Finish by'; 'Specific hours...' -> that plus one input[type=number] labelled 'Hours per day' pre-filled 12. No date input for the start exists in any state. The POST body confirms it: startDate is taken from the drop cell (startDate '2026-08-10'). Spec section 4.5: 'Start date. Defaults to the earliest working day. Adjusting it is how a second technician's series can be made sequential (starting after the first) rather than parallel.'

 

Where this expected behaviour comes from: the Schedule specification, version 23, section 4.5 (Multi-day spread scheduling), which says: "Start date. Defaults to the earliest working day. Adjusting it is how a second technician's series can be made sequential (starting after the first) rather than parallel." The second sentence names the exact thing that cannot be done today.
