# SV-8935 — Parts Velocity spreadsheet prints Last Sale as the words "54 days" instead of a plain number
# parent: SV-8646

1. What happens now
The Parts Velocity spreadsheet download prints the "Last Sale" column as a piece of text such as 54 days instead of the plain number 54.
Because the cell is text and not a number, somebody who opens the file in Excel cannot sort by it or use it in a calculation without cleaning the column first.
2. What should happen instead
The written description asks for the wording only in the PDF, and a plain number in the spreadsheet.
Parts Velocity specification, version 5, requirement S6-R8: "Last Sale renders as N days (e.g. 42 days) in the PDF; the CSV renders the raw integer."
3. How to see it
Sign in as a user who can see reports and open Reports > Parts Velocity.

In the report's own search box type BRAKECLEAN.

Open the three-dot menu at the top of the report and choose Download (CSV).

Open the downloaded file and look at the Last Sale column.

Exact test data this was seen with: part number BRAKECLEAN, description Brake & Parts Cleaner, locations Staging Heavy Duty - 9919 and Staging Lethbridge - 4310, date range This Year. The file is named velocity-report.csv.
4. What was actually in the file
{noquote}
Inventory,BRAKECLEAN,"Brake & Parts Cleaner",HD-Fluids,—,"Staging Heavy Duty - 9919",512.00,$4.79,$7.69,"$4,332.11","$1,634.06",37.7%,416,"54 days",618.00
{noquote}
The cell reads "54 days" where it should read 54.
5. What was ruled out
It is not the PDF. The PDF correctly prints 54 days, which is what the written description asks the PDF to do. Only the spreadsheet is wrong.

It is not one part. Every row in the file carries the same wording.

It is not an empty value. A part with no sale at all correctly prints an em dash in both files, so the empty case is handled properly.

6. How often
Every time. Four spreadsheet downloads out of four.
7. Where it was seen
Reports > Parts Velocity, on the QA branch, build v3.5-16cf83f, on 6 August 2026.
