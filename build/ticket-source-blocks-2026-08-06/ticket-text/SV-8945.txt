# SV-8945 — Sorting a Technician Utilization column reloads the report from the server instead of reordering the rows on screen
# parent: SV-8649

1. What happens now
Clicking a column heading on Technician Utilization sends a fresh request to the server and waits for new rows. The written description asks for the rows already on screen to be reordered without any reload.
2. What should happen instead
Technician Utilization specification, version 6, requirement S2-R13: "All six columns... are sortable by clicking the column header... Sorting is applied on screen to the loaded rows (no reload)."
3. How to see it
Open Reports > Technician Utilization and set the date range to This Year so there are plenty of rows.
Click the Total Hours heading once, then again.
Watch the table: it briefly clears and refills each time rather than simply reordering.
Exact test data this was seen with: organisation Staging Foothills Group Inc; signed-in user Admin ShopView; active location Staging Heavy Duty - 9919; the other accessible location Staging Lethbridge - 4310; date range This Year (1 January 2026 to 6 August 2026), which returns 29 technicians.
4. What was actually shown
Each click sent a new request to the report's own data address carrying the sort as part of the request - first with the sort marked not-descending, then with it marked descending. The rows came back from the server rather than being reordered in the page.
5. What was ruled out
It is not the sort being wrong. The order itself is correct: the first click on Technician sorts Z to A, the next A to Z, with no third state, and Est. Lost Labor sorts correctly both ways.
It is not a one-off. It happened on every column tried - Technician, Total Hours and Est. Lost Labor.
It is not the report reloading for another reason. The date range and the location selection were untouched between the clicks.
6. How often
Every time, on every column.
7. Where it was seen
Reports > Technician Utilization, on the QA branch, build v3.5-16cf83f, on 6 August 2026.
