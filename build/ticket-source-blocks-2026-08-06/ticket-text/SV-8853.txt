# SV-8853 — The Escape and Enter keys do not work on the delete and reassign confirmation windows
# parent: SV-8700

Description
Two of the Schedule's confirmation windows ignore the keyboard. The 'Delete from this series?' window and the 'Reassign shift' window cannot be dismissed with Escape, and cannot be confirmed with Enter - the only way in or out of them is the mouse. Every other pop-up on the page closes with Escape, so the behaviour is inconsistent as well as inaccessible: anyone working keyboard-only gets stuck in these two windows.

Steps to reproduce
Open the Schedule and pick the Day view for a day that holds a multi-day job (use S-14527 Qispring Rentals spread over four days from a Monday).

Click a shift in the middle of that series to open the shift window, then click the delete bin.

The 'Delete from this series?' window opens. Press Escape - nothing happens. Press it again - still nothing. Click inside the window first and press Escape again - still nothing. Only Cancel or the close X will shut it.

Now close everything and switch to the Week view.

Drag any shift block from one technician's row to another technician's row.

The 'Reassign shift' window opens asking 'Move this shift to <name> on <date>?'. Press Enter - nothing happens, the move is not confirmed. Press Escape - nothing happens either.

Expected behaviour
Escape closes whichever pop-up is on top, and Enter confirms the window that is asking for confirmation, so both windows can be driven entirely from the keyboard.
Current behaviour
Neither key does anything in either window. Escape does work on the shift window itself and on both toolbar menus, so it is specifically these two confirmation windows that ignore it.

Technical details for developers
Escape tested twice on the delete-scope dialog, the second time after moving focus to a button inside it: .q-dialog count stayed 1 both times. Enter on the reassign dialog left .q-dialog count at 1 and produced no .undo-toast, so no request was sent. Escape DOES close dialog_schedule_shift_detail, schedule_view_options_menu and schedule_filter_display_menu. Spec section 7 names both windows first in its stacking order: 'Escape closes the topmost open modal or popover, following a defined stacking order (delete scope, reassign, spread, ...)' and 'Enter confirms the active confirmable dialog (delete scope, reassign, spread, event create/edit).'
