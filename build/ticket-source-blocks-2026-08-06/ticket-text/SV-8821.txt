# SV-8821 — Creating an invoice from a completed work order fails with a server error
# parent: SV-8582

1. Description
When you create an invoice from a completed work order, it works — provided the work order has a contact person on it. If it does not, the invoice cannot be created.
This ticket was originally raised the wrong way round, and this description has been corrected. It first said that pressing Create Invoice on the work order's Finance tab fails with a server error. Re-testing on the same branch shows that is not what happens:
On a work order that has no contact, the product does not let you press the button at all. The Finance tab is greyed out, and hovering it shows the reason: "Please select a contact for the asset". There is no Create Invoice button on screen to press.

Once you pick a contact, the Finance tab becomes available, the Create Invoice button appears, and pressing it works — the invoice is created and the work order moves to Invoiced.

So there is nothing here that a person using the product, or a manual tester, can run into. The product already stops them and tells them what to do.
What is left is a back-end tidiness issue only. If the invoice request is sent straight to the back end for a work order with no contact — skipping the screen that would have stopped you — the back end answers with a general "something went wrong" server error instead of a clear message saying a contact is missing. Nobody can reach that by clicking the product.
The original ticket also blamed the wrong thing. It implied the pre-set job ("canned line") chosen for the work order mattered. It does not. Eleven different pre-set jobs, covering every way they can be priced, all behaved identically. The only thing that matters is whether a contact is set.

3. Steps to reproduce
Read this first: what is left of this issue cannot be reached from any screen in the product. The screen that would create the invoice is deliberately unavailable in exactly the situation that fails, so there are no clicking steps that end in the error. The steps below are therefore given in two parts: what a person does see, and (in section 7) the back-end call that produces the server error.
Part A — what a person sees on screen (this is the correct, working behaviour)
Go to Work Orders and press Create Work Order.

In the New Work Order dialog choose Customer = Aaborough Works and Asset = the 2020 Ford Transit with VIN/Serial 86J8FAC1VALJ43SJY, then press Save. (Note: this dialog has no Contact field, so the new work order starts with no contact.)

On the work order, press New Line and add the pre-set job named exactly HD CVIP air brake trailer single/tandem (a fixed-labour job priced at $350.00; any of the pre-set jobs behaves the same).

Fill in the work order's Mileage (for example 123,456) and type anything into the line's Story, then set the line to Complete, then set the work order to Complete. Its total will read $406.09 (labour $350.00 + shop supplies $36.75 + GST $19.34).

Look at the tabs across the top of the work order. Finance is greyed out. Hover over it: the product says "Please select a contact for the asset". Click it — nothing happens, and there is no Create Invoice button anywhere.

Now, on the customer card on the left, open the Contact dropdown and choose Jeffrey Burns. A confirmation appears — "Would you like to change to the new contact for this asset permanently?" — press YES.

The Finance tab is now available. Open it and press Create Invoice. It works — the invoice is created and the work order becomes Invoiced.

Part B — the situation that produces the server error
Do steps 1 to 5 above and stop there — leave the work order with no contact. Then have the invoice request sent to the back end directly, without going through the screen (see section 7). That is the only route to the error.

4. Expected behaviour
Two things, and only the second is outstanding.
On screen: the work order's Finance tab should be unavailable while no contact is set, and should say why. This already happens correctly and is what the original ticket missed.
In the back end: when an invoice is requested for a work order that has no contact, the answer should be a clear rejection naming the missing contact — the same shape of answer the product already gives for other missing prerequisites, for example "Work order is not complete." or "Line can`t be completed with unfulfilled part requests.". A general "something went wrong" server error is the wrong answer to a request that is simply missing a required piece of information.

5. Current behaviour
On screen: correct. With no contact the Finance tab is greyed out and reads "Please select a contact for the asset"; there is no Create Invoice button. After a contact is chosen the tab opens, the button appears, and pressing it creates the invoice.
In the back end: an invoice request for a work order with no contact returns a general server error ("An error occurred. We're sorry for this inconvenience, please try again a bit later later.") rather than a clear message about the missing contact. The work order is left untouched.

Why no user can reach it — the front end already guards it
On a work order with customer_id = null, the Finance tab carries aria-disabled="true", the disabled class and opacity: 0.6 while every sibling tab is enabled; its tooltip reads "Please select a contact for the asset"; clicking it leaves the active tab as Lines (1); and the count of Create Invoice buttons in the DOM is 0. With a contact set, the same tab reads aria-disabled: null, has no tooltip, activates on click, and yields exactly 1 Create Invoice button, which returns 201.
The product's Create Work Order dialog has only three inputs — Customer, Asset, Asset Here? — and no Contact field, so a work order created entirely through the product also starts with customer_id = null and hits the same guard. (This closes the gap the earlier version of this ticket flagged as unverified.) The contact is an attribute of the asset: the New Asset dialog makes Contact * a required field, which is why the tooltip says "for the asset"; assets created before that rule have none.
