# SV-8843 — Filter bar sits on the same row as the tabs, so collapsing it frees no space
# parent: SV-8785

Environment
QA branch https://sv8785.qa.shopview.com/workorders — API host sv8785api.qa.shopview.com — build marker <meta name="app-version"> = v3.4.2-4f8211c (index.html last-modified Mon, 03 Aug 2026 20:09:32 GMT) — observed 2026-08-04, org d55bc308-e61a-438d-b5f1-c7a73c89d49f, location "Staging Heavy Duty - 9919", signed in as an Administrator.
Steps to Reproduce
Open Work Orders on a desktop browser at a 1680x1050 window, on the All tab.

Look at where the five filter buttons (Status, Customer, Lead Technician, Service Advisor, Asset on Site) sit in relation to the tab row (All, Estimates, Completed, My Work Orders).

Click the filter icon to the left of the Status button to collapse the filter bar.

Watch whether the table moves up into the space the buttons were using.

Expected Result
The five filter buttons sit on their own row directly BELOW the tab row, and when the bar is collapsed the table moves up and uses the space that is freed.
Current Result
The filter buttons sit on the SAME row as the tabs, to the right of "My Work Orders". Because they share the tab row there is no separate row to give back: collapsing hides the buttons but the table does not move up at all. The table header stays in exactly the same place before and after collapsing.
How often
Every time, on desktop.
Technical detail
Measured from the DOM: the tab elements are at y=85 with height 40; the five buttons (CSS class "filter-chip") are at y=90 with height 30 and x from 452 to 1164, i.e. inside the same band, to the right of the tabs. The table head element stays at y=144 both before and after clicking the collapse toggle (data-test-id="toggle_filter_bar"). The approved design frame for the final desktop layout (Figma node 11854:24657) also draws the bar on its own row below the tabs.
