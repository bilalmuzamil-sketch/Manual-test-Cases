## The shape (every case of your suite)

```
Preconditions
- Scenario: <one short plain sentence: the situation this test needs, in the shop's and the screen's words>
- You are <role> working at {Location-A}.            For example: …
- <record 1 that must exist, with {placeholder}>      For example: …
- <record 2 …, in the order a tester would create it> For example: …
- <state the records must be in (default term, deactivated, invoiced …)>
- Starting screen: <where the tester starts>
- If any record above is missing, mark this test Blocked: "setup not done".
```

Worked example (Credit terms C723889, S1-25):
- Scenario: Your shop uses only two credit terms of its own and has switched off every other term it can.
- You are an Admin user working at {Location-A}. For example: {Location-A} is Staging Heavy Duty - 9919.

  month. It has no other terms of its own. For example: {Term-A} is ZZAUTOTEST S1-25 Fourteen and {Term-B} is ZZAUTOTEST S1-25 Tenth.

Rules for the rewrite:
1. Write the Scenario line yourself for every case, from what the case tests and its existing preconditions. Plain words a manual
   tester understands; no requirement codes, no internal names, no "Rule", no "QA lead", no "ask …". One sentence, ideally ≤ 25 words.
2. Keep every fact the existing preconditions hold (records, values, examples, placeholders, settings, starting screen). Reword into
   plain setup order; merge or split bullets only when that makes building the account easier. Never drop a needed fact; never add a
   fact that is not in the case or its sources. Placeholders and "For example:" lines keep the Rule 117 shape (seventh/eighth
   amendments).
3. Only what is needed: no generic lines, no who-to-ask, no "set aside for this suite".
4. Change NOTHING else in a case: title, steps, results, quotes, From lines, References from Design, notes, AUTOMATION line stay
   byte-identical. Implement the Scenario line as a per-case field the library renders first in Preconditions; add a gate to build.py:
   every case has exactly one Scenario line, first, ≤ 40 words, with no requirement code and no "QA lead"/"ask your".
5. Regenerate the suite's setup file and outputs; its recipes must still match the preconditions.
