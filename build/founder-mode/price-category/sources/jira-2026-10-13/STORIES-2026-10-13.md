## SV-10134 — Parts Alphabetical Sort - Story 1 - Categories, Sort By Name

- **Link:** https://shopview.atlassian.net/browse/SV-10134
- **Type:** Story · **Status:** Open · **Priority:** Medium
- **Parent:** SV-11258 · **Labels:** (none)

- **Created:** 2026-09-16T10:15:44.552-0500 · **Updated:** 2026-10-13T10:13:58.520-0500
- **Linked issues:**
  - relates to **SV-10394** — Verify: Categories sorting (Name, QuickBooks, pinned Default) (Board Backlog)

### Description (verbatim)

## Summary

Make the Name and QuickBooks Products and Services columns on Settings, Parts, Categories actually sort, load the whole list so the sort covers it, and keep the user's chosen sort through a reload and a search.

## Context

The Name header on Categories already looks sortable and already shows a sort arrow, but clicking it does nothing. The list also loads a page at a time, so any sort would only cover the rows already fetched. The Default category is pinned to the top of this list by the server today and stays pinned: that is production behaviour and this feature does not change it.

## Requirements

* S1-R1: The Name column header is sortable.
* S1-R2: When the page first opens, the list is sorted by name in ascending order, A to Z.
* S1-R3: The name sort ignores whether letters are upper case or lower case, and compares numbers inside a name as numbers, so "Tier 9" comes before "Tier 10".
* S1-R4: When the page first opens, the Name column header shows an ascending arrow.
* S1-R5: When the user clicks the Name header while the sort is ascending, the list re-sorts into descending order, Z to A.
* S1-R6: When the user clicks the Name header while the sort is descending, the list re-sorts into ascending order, A to Z.
* S1-R7: The Name column header arrow always shows the direction that is currently applied.
* S1-R8: The sort covers every category, not only the categories already visible on screen.
* S1-R9: The QuickBooks Products and Services column header is sortable.
* S1-R10: When the user clicks the QuickBooks Products and Services header while that column is not sorted, the list sorts by that column in ascending order, A to Z.
* S1-R11: When the user clicks that header again, the list re-sorts into descending order, Z to A.
* S1-R12: The QuickBooks Products and Services sort ignores whether letters are upper case or lower case, and compares numbers inside a value as numbers.
* S1-R13: Only one column is sorted at a time.
* S1-R14: While the QuickBooks Products and Services column is the column being sorted, the Name column header shows no arrow.
* S1-R15: When the list reloads in place, the sort the user chose stays applied, in the same direction, and the header arrow stays where it was.
* S1-R16: Opening the page afresh returns the list to name ascending, whatever sort was applied last time.
* S1-R17: Every category shows a value in the QuickBooks Products and Services column. A category that has never been mapped shows the word Parts there, which is what the page shows today and does not change. That column has no empty state and no row is moved to the bottom of it.
* S1-R18: Typing a search term keeps the sort. The rows that match the term are shown in the order the current sort produces.
* S1-R19: The Default category is always the first row in the list, under either sort, in both directions, and after a reload in place or a search. This is production behaviour and it does not change.
* S1-R20: Every category other than the Default category sorts beneath it. The Default category is not compared against the other rows; it is placed first and the remainder are sorted.
* S1-R21: The Default category keeps its Default badge in every sort.
* S1-N1: If the shop is not connected to QuickBooks, the QuickBooks Products and Services column is not shown and no sort is available for it.
* S1-N2: If no categories exist, the Name column header still renders as sortable and still shows the ascending arrow.
* S1-N3: If the user does not have the Settings - Parts permission, the user cannot open the Categories page.
* S1-N5: If the QuickBooks connection cannot be checked, the column is not shown and the user is told once: "Unable to check QuickBooks connection. Please try again." The list still loads and the Name column still sorts.

## Acceptance Criteria

- [ ] Given the Categories page opens, then the list is in name order A to Z and the Name header shows an ascending arrow.
- [ ] Given the Categories page opens, then the Default category is the first row, above every other row whatever its name.
- [ ] Given the Name header is clicked, then the order reverses to Z to A, the arrow flips, and the Default category is still the first row.
- [ ] Given a shop with more categories than one page, then the sort covers every category and not only the ones fetched so far.
- [ ] Given categories named "Tier 9" and "Tier 10", when sorted ascending by name, then "Tier 9" comes before "Tier 10".
- [ ] Given categories named "Zinc" and "alternator", when sorted ascending by name, then "alternator" comes before "Zinc".
- [ ] Given the QuickBooks Products and Services header is clicked, then the list sorts by that column, its arrow is shown, and the Name header shows no arrow.
- [ ] Given a category that has never been mapped, then its QuickBooks Products and Services cell reads "Parts" and it sorts under P with any category mapped to a service of that name.
- [ ] Given a sort is applied, when a category is created, edited or deleted and the dialog closes, then the list reloads and the same sort and arrow are still applied.
- [ ] Given a sort is applied, when a search term is typed, then the matching rows are shown in that same sort order.
- [ ] Given a sort was applied, when the user navigates away and returns, then the list is back to name ascending.
- [ ] Given the shop is not connected to QuickBooks, then that column and its sort are absent and the Name column still sorts.

## SV-10386 — categories-list endpoint has no authorization check

- **Link:** https://shopview.atlassian.net/browse/SV-10386
- **Type:** Bug · **Status:** Open · **Priority:** Medium
- **Parent:** SV-11258 · **Labels:** (none)
- **Reporter:** Milan Zivanovic · **Assignee:** (none)
- **Created:** 2026-09-23T03:42:59.582-0500 · **Updated:** 2026-10-13T10:14:05.043-0500
- **Linked issues:** none

### Description (verbatim)

`GET /api/parts-catalogue/categories-list` (`CategoryListController`) has no `#[IsGranted]`, so any logged-in user can read it, whatever their permissions. Every sibling endpoint is guarded: create/change use `ROLE_CATALOG_INVENTORY_CREATE_AND_EDIT`, remove uses `ROLE_CATALOG_INVENTORY_DELETE`, and the Pricing list endpoints use `ROLE_CATALOG_INVENTORY_VIEW`. No global `access_control` covers it.

**Fix:** add `#[IsGranted(PermissionEnum::ROLE_CATALOG_INVENTORY_VIEW)]`.

**Watch out:** it's a shared reference endpoint. It's used by the pricing-matrix dialog, part-request screens and `useDefaultCategory()` (the default category on work-order lines). Check which roles use those screens and confirm they all hold `ROLE_CATALOG_INVENTORY::VIEW` before tightening it, or technician flows will get 403s.

**Tests:** a functional test for 403 without the permission and 200 with it. There's no functional test for this endpoint today.

Found during tech planning for SV-10134. It's outside that feature's scope.

### Summary

List every fixed rule on the Fixed Rules tab, including a rule whose part has no category. Today those rules are left out of the list entirely.

### Context

Raised by Milan Zivanovic during tech planning for Parts Alphabetical Sort (Confluence comment 882475016). The Fixed Rules tab only lists rules whose part has a category, so a category-less rule never appears. Across every shop in production that is 3 rules. The Parts Alphabetical Sort PRD rules out changing what the server sends, so S3-R12b records the gap and this story fixes it separately, after that release.

* The tab label count N in "Fixed rules (N)" includes these rules (S3-R17).
* Fixed Rules search (S3-R18) matches these rules on Part number and Fixed price like any other rule.

- [ ] Given a fixed rule whose part has no category, when the user opens the Fixed Rules tab, then the rule is listed with an empty Category cell.
- [ ] Given the Category column is sorted ascending or descending, when the list includes a rule with no category, then that rule is last.
- [ ] Given 3 category-less rules exist at a location, when the tab opens, then the label count includes all 3.

### UI/UX

No new design. The row uses the existing Fixed Rules row; the Category cell is empty.

### PRD

[Settings "Pricing" And "Categories" Sorting](https://shopview.atlassian.net/wiki/spaces/~712020aa00b8d6a71f4259891982a304227c20/pages/578781186) (S3-R12b, S3-R13, S3-R17, S3-R18). Not in this release.
