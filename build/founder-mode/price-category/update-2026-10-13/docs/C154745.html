Setup: Fixed Price sorts by value: highest first, then lowest first on the next click

Test case: C154745, Founder Mode / Price/Category. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with the Settings - Parts permission.

• Category {Category-A} (for example ZZAUTOTEST-PC45 cat) exists.

• Fixed rule part {Part-A} (for example ZZAUTOTEST-PC45-1) is at {Location-A} in category {Category-A} with fixed price (for example 9000.00).

• Fixed rule part {Part-B} (for example ZZAUTOTEST-PC45-2) is at {Location-A} in category {Category-A} with fixed price (for example 100000.00).

• Fixed rule part {Part-C} (for example ZZAUTOTEST-PC45-3) is at {Location-A} in category {Category-A} with fixed price (for example 10000.00).

• Fixed rule part {Part-D} (for example ZZAUTOTEST-PC45-4) is at {Location-A} in category {Category-A} with fixed price (for example 90000.00).

• No other fixed rule at {Location-A} has a fixed price of 9,000 or more.

• You are on a page other than Pricing and the Pricing Search box is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and choose {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher at the top of the screen.

2. In Settings → Parts → Categories click New Category, type the name {Category-A} (for example ZZAUTOTEST-PC45 cat) exactly as written, including capitals, and save the dialog. Leave every other field as it is.

3. On Settings → Parts → Pricing, Fixed rules tab, click Add Fixed Rule and create a fixed rule for part {Part-A} (for example ZZAUTOTEST-PC45-1) in category {Category-A} with fixed price (for example 9000.00), then save. If the dialog only lets you pick an existing part, first create the part at {Location-A} under Parts → Inventory → New Inventory Part with that part number and category {Category-A}, then come back.

4. On Settings → Parts → Pricing, Fixed rules tab, click Add Fixed Rule and create a fixed rule for part {Part-B} (for example ZZAUTOTEST-PC45-2) in category {Category-A} with fixed price (for example 100000.00), then save. If the dialog only lets you pick an existing part, first create the part at {Location-A} under Parts → Inventory → New Inventory Part with that part number and category {Category-A}, then come back.

5. On Settings → Parts → Pricing, Fixed rules tab, click Add Fixed Rule and create a fixed rule for part {Part-C} (for example ZZAUTOTEST-PC45-3) in category {Category-A} with fixed price (for example 10000.00), then save. If the dialog only lets you pick an existing part, first create the part at {Location-A} under Parts → Inventory → New Inventory Part with that part number and category {Category-A}, then come back.

6. On Settings → Parts → Pricing, Fixed rules tab, click Add Fixed Rule and create a fixed rule for part {Part-D} (for example ZZAUTOTEST-PC45-4) in category {Category-A} with fixed price (for example 90000.00), then save. If the dialog only lets you pick an existing part, first create the part at {Location-A} under Parts → Inventory → New Inventory Part with that part number and category {Category-A}, then come back.

7. Click the Fixed Price header once on the Fixed rules tab (the highest price comes first) and check that no other rule is priced 9,000 or more. If one is, multiply your four prices by 100 and keep the same order.

8. Go to another page (for example Settings → Parts → Categories), so the test starts by opening Pricing afresh.

9. Check the setup worked: the four parts are listed with the four prices above (shown with or without two decimals).

Part 2. Setup for Claude session

• Screens: Settings → Parts → Pricing is the address /administration/pricing, with the Pricing matrices and Fixed rules tabs (playbook §H). Today the labels read Pricing Matrices(N) and Fixed Rules(N) with no space. It needs the Settings - Parts permission.

• Fixed rules list: GET /api/parts/list-fixed-price, scoped to the organization and the current location (tech plan §9). After this feature it is requested 1,000 rows at a time and looped (tech plan §5). Switch to {Location-A} in the top bar before you read or seed.

• A fixed rule is one inventory part with a fixed selling price (PRD §5). The tech plan's own test seeds inventory parts flagged as fixed price with a sell price. UNVERIFIED: the fields of the Add Fixed Rule dialog and whether it creates the part or picks an existing one; record them on first use.

• Inventory parts by request: POST /api/inventory/parts/create needs catalog_part_id, category_id, quantity, cost, tags and bins, and the catalog part comes first from POST /api/parts-catalogue/add-catalogue-part (playbook). UNVERIFIED: the field that sets the fixed price. Record each {Part-A id} and so on from the responses.

• Reading the screen: headers carry data-test-id header_fixed_rules_partNumber, header_fixed_rules_categoryName and header_fixed_rules_fixedPrice with aria-sort, and cells fixed_rule_<column>_<row id> (tech plan Phase 4). UNVERIFIED until a build exists.

• Trap: fixed prices print without two decimals today (for example $4.5); bug SV-10387 may change this to $4.50. Read prices as they are shown.

• Trap: the tab count reads (0) until every rule has loaded (tech plan D9), and hovering an unsorted sortable header fades its arrow in (tech plan D17).

• The page sorts on the number, not the shown text (tech plan Phase 4: the fixedPrice accessor reads the raw value). Trap: the tech plan of 13 Oct (FR-018, FR-020 and its end-to-end test) still says the first click puts the lowest price first; PRD version 21 (S3-R4, S3-R8, S3-R9) says highest first, and the case follows the PRD.

• Run: click Fixed Price once, read aria-sort (expect descending) and the first four rows; click again, read aria-sort (expect ascending), scroll to the end and read the last four rows.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
