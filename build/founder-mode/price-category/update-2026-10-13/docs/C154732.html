Setup: Unmapped categories show Parts in the QuickBooks column and sort under P

Test case: C154732, Founder Mode / Price/Category. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with the Settings - Parts permission.

• {Location-A} is connected to QuickBooks, so the Categories list shows the QuickBooks Products And Services column.

• Category {Category-A} (for example ZZAUTOTEST-PC32 never mapped) has never been mapped to a QuickBooks product or service.

• QuickBooks product or service {Qb-item-A}, named exactly Parts, exists in the connected QuickBooks company.

• Category {Category-B} (for example ZZAUTOTEST-PC32 mapped to Parts) is mapped to {Qb-item-A}.

• QuickBooks product or service {Qb-item-B} (for example Equipment) has a name starting with a letter before P.

• Category {Category-C} (for example ZZAUTOTEST-PC32 before P) is mapped to {Qb-item-B}.

• QuickBooks product or service {Qb-item-C} (for example Services) has a name starting with a letter after P.

• Category {Category-D} (for example ZZAUTOTEST-PC32 after P) is mapped to {Qb-item-C}.

• You are on a page other than Categories.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and choose {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher at the top of the screen.

2. Check that {Location-A} is connected to QuickBooks: Settings → Parts → Categories shows the QuickBooks Products And Services column.

3. In the connected QuickBooks company, check that a product or service named exactly Parts exists ({Qb-item-A}), one whose name starts with a letter before P (for example Equipment, {Qb-item-B}) and one whose name starts with a letter after P (for example Services, {Qb-item-C}). Create any that are missing in QuickBooks.

4. In Settings → Parts → Categories click New Category, type the name {Category-A} (for example ZZAUTOTEST-PC32 never mapped) exactly as written, including capitals, and save the dialog. Leave every other field as it is. Do not choose any QuickBooks value for it.

5. In Settings → Parts → Categories click New Category, type the name {Category-B} (for example ZZAUTOTEST-PC32 mapped to Parts) exactly as written, including capitals, and save the dialog. Leave every other field as it is.

6. In Settings → Parts → Categories click New Category, type the name {Category-C} (for example ZZAUTOTEST-PC32 before P) exactly as written, including capitals, and save the dialog. Leave every other field as it is.

7. In Settings → Parts → Categories click New Category, type the name {Category-D} (for example ZZAUTOTEST-PC32 after P) exactly as written, including capitals, and save the dialog. Leave every other field as it is.

8. Map {Category-B} to {Qb-item-A}, {Category-C} to {Qb-item-B} and {Category-D} to {Qb-item-C}, saving each.

9. Go to another page (for example Settings → Parts → Pricing), so the test starts by opening Categories afresh.

10. Check the setup worked: search for the tag (for example ZZAUTOTEST-PC32). Four rows show, and the QuickBooks cells read Parts, Parts, {Qb-item-B} and {Qb-item-C} for {Category-A} to {Category-D}. If no QuickBooks connection is available, write 'not checked by hand: no QuickBooks connection' in the result comment.

Part 2. Setup for Claude session

• Screens: Settings → Parts → Categories is the address /administration/categories on the app host. It needs the Settings - Parts permission (settingsParts in the app's permission list).

• The list comes from GET /api/parts-catalogue/categories-list (organization-wide). After this feature it is requested 1,000 rows at a time and looped until a short page (tech plan §5). Rows carry id, name, isDefault and productAndServiceName (tech plan Phase 2). UNVERIFIED: field names on the built page; record them.

• Create categories in the browser through New Category. UNVERIFIED: the request the dialog sends and its required fields (the tech plan says only that create and change sit under /api/parts-catalogue and need Part Library & Inventory → Create & Edit). Record the request on first use and repeat it for bulk data.

• Reading the screen: after the build ships, each header cell carries data-test-id header_categories_<column name> and aria-sort ascending, descending or none, and each name cell carries data-test-id category_name_<row id> (tech plan D12). UNVERIFIED until a build exists; if they are absent, read the arrow icon and the row text instead.

• Trap: hovering an unsorted sortable header fades its arrow in (tech plan D17). Move the pointer away from the headers before reading arrows.

• Trap: the categories list is cached on the server for 24 hours by query, and any create, change or delete made through the app clears it (tech plan §5). A category made another way may not show until then.

• QuickBooks: the page checks the connection with GET /api/bookkeeping/integration (playbook; tech plan D8). The QuickBooks Products And Services column shows only when the location is connected. UNVERIFIED: which field of the category dialog maps a category to a QuickBooks product or service; record it.

• QuickBooks values are the connected QuickBooks company's products and services. An unmapped category shows the word Parts (PRD S1-R17). The QuickBooks header carries data-test-id header_categories_quickbooks_product_and_service and each cell category_qb_<row id> (tech plan Phase 2), UNVERIFIED until built.

• The page sorts this column on the value it shows, the mapped name or the word Parts (tech plan D7), so unmapped rows sort with genuine Parts mappings.

• Seed the four tagged categories; leave {Category-A} unmapped. Record ids. Run: read {Category-A}'s cell, sort by QuickBooks twice, read the four rows' relative order each time.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
