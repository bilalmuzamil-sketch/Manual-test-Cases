Setup: Without the Settings - Parts permission the Pricing page does not open

Test case: C573693, Founder Mode / Price/Category. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as staff member {User-B} (for example ZZAUTOTEST-PCA06 User) at {Location-A} (for example Staging Heavy Duty - 9919).

• The role of {User-B}, {Role-A} (for example ZZAUTOTEST-PCA06 Role), does not have the Settings - Parts permission.

• The web address of the Pricing page, {Address-A} (for example the app address followed by /administration/pricing), was copied beforehand while signed in as an Admin.

Part 1. Setup for manual QA tester

1. Sign in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919).

2. Open Settings → Parts → Pricing and copy the page's web address from the browser's address bar. This is {Address-A}.

3. Open Settings → Roles & Permissions, click Create custom role, name it {Role-A} (for example ZZAUTOTEST-PCA06 Role) and leave the Settings - Parts permission off. Save it.

4. Open Settings → Staff and add a staff member {User-B} (for example ZZAUTOTEST-PCA06 User) at {Location-A} with role {Role-A}. Set a password you can use.

5. Sign out, then sign in as {User-B}.

6. Check the setup worked: {Role-A} shows Settings - Parts switched off and {User-B} can sign in.

Part 2. Setup for Claude session

• Screens: Roles at /administration/roles-permissions, staff at /administration/staff; POST /api/iam/create gives 201 with user_id (playbook). The Pricing page is /administration/pricing, guarded by settingsParts (tech plan FR-017 and FR-025, no change).

• Check the role with GET /api/auth/me/fe-permissions as {User-B}: settingsParts must be false.

• Run: open the address; also note whether the Settings menu shows Pricing (fact only). UNVERIFIED: the page you are sent to instead; record it.

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
