Setup: Categories search shows the Default category first only when it matches

Test case: C573688, Founder Mode / Price/Category. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with the Settings - Parts permission.

• The Default category {Default-category-A} (for example Uncategorized) shows the Default badge in the Categories list.

• Search term {Term-A} (for example categ) is part of the Default category's name.

• Category {Category-A} (for example AAA-ZZAUTOTEST-PCA02 categ) exists. Its name contains {Term-A} and comes before the Default category's name.

• Category {Category-B} (for example ZZAUTOTEST-PCA02 categ) exists. Its name contains {Term-A} and comes after the Default category's name.

• Search term {Term-B} (for example ZZAUTOTEST-PCA02) matches {Category-A} and {Category-B} but not the Default category.

• You are on a page other than Categories and the Categories Search box is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and choose {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher at the top of the screen.

2. Find the category that shows the Default badge (for example Uncategorized). This is {Default-category-A}. It cannot be edited. Do not delete it.

3. Pick a part of the Default category's name as {Term-A} (for example categ, if the Default category is called Uncategorized).

4. In Settings → Parts → Categories click New Category, type the name {Category-A} (for example AAA-ZZAUTOTEST-PCA02 categ) exactly as written, including capitals, and save the dialog. Leave every other field as it is.

5. In Settings → Parts → Categories click New Category, type the name {Category-B} (for example ZZAUTOTEST-PCA02 categ) exactly as written, including capitals, and save the dialog. Leave every other field as it is.

6. {Term-B} is the tag (for example ZZAUTOTEST-PCA02).

7. Go to another page (for example Settings → Parts → Pricing), so the test starts by opening Categories afresh.

8. Check the setup worked: searching for {Term-A} shows the Default category, {Category-A} and {Category-B} among the results, and searching for {Term-B} shows only {Category-A} and {Category-B}. Clear the Search box and leave the page.

Part 2. Setup for Claude session

• Screens: Settings → Parts → Categories is the address /administration/categories on the app host. It needs the Settings - Parts permission (settingsParts in the app's permission list).

• The list comes from GET /api/parts-catalogue/categories-list (organization-wide). After this feature it is requested 1,000 rows at a time and looped until a short page (tech plan §5). Rows carry id, name, isDefault and productAndServiceName (tech plan Phase 2). UNVERIFIED: field names on the built page; record them.

• Create categories in the browser through New Category. UNVERIFIED: the request the dialog sends and its required fields (the tech plan says only that create and change sit under /api/parts-catalogue and need Part Library & Inventory → Create & Edit). Record the request on first use and repeat it for bulk data.

• Reading the screen: after the build ships, each header cell carries data-test-id header_categories_<column name> and aria-sort ascending, descending or none, and each name cell carries data-test-id category_name_<row id> (tech plan D12). UNVERIFIED until a build exists; if they are absent, read the arrow icon and the row text instead.

• Trap: hovering an unsorted sortable header fades its arrow in (tech plan D17). Move the pointer away from the headers before reading arrows.

• Trap: the categories list is cached on the server for 24 hours by query, and any create, change or delete made through the app clears it (tech plan §5). A category made another way may not show until then.

• Search is answered by the server on the name (tech plan D5); the Default row is placed first only when the server returns it (tech plan FR-009). If {Term-A} is not part of the Default category's name on the environment, choose another fragment and rename the two seeded categories to contain it.

• Run: type each term, wait for the list to settle (about 300 ms debounce), read row 1 and the rows shown.

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
