Setup: Canned job warning names a typed vendor part by the inactive part's number

Test case: C425731, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), a role that has 'Part Library & Inventory → View', 'Create & Edit' and 'Delete'.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-CANVEND-01) is tracked at {Location-A} and is inactive.

• Inventory part {Part-C} (for example ZZAUTOTEST-PL-CANVEND-03) is tracked at {Location-A} and is active.

• Canned job {Canned-job-A} (for example "ZZAUTOTEST PL CANVENDSRC line") holds {Part-C} and a vendor part typed in by hand as {Number-A} (for example zzautotest.pl.canvend.01), which equals {Part-A} once upper and lower case, hyphens and periods are ignored.

• Work order {Work-order-1} (for example S2-15440) at {Location-A} is open and has no lines.

Part 1. Setup for manual QA tester

1. Sign in as an Admin (or Owner) and pick the location in the top-bar location switcher (for example Staging Heavy Duty - 9919). This location is {Location-A}; every step runs there unless it names another location.

2. Go to Parts → Vendors, click "New Vendor", type Name (for example "ZZAUTOTEST PL CANVEND Vendor") and click "Save & Close". This vendor is {Vendor-A}.

3. Go to Parts → Inventory and click "New Inventory Part". Type Description (for example ZZAUTOTEST PL CANVEND A) and Part Number (for example ZZAUTOTEST-PL-CANVEND-01). The part number you typed is {Part-A}.

4. Pick Category (for example Uncategorized), type Cost (for example 10.00) and Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 4 and click Save.

5. Go to Parts → Inventory and click "New Inventory Part". Type Description (for example ZZAUTOTEST PL CANVEND C) and Part Number (for example ZZAUTOTEST-PL-CANVEND-03). The part number you typed is {Part-C}.

6. Pick Category (for example Uncategorized), type Cost (for example 10.00) and Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 4 and click Save.

7. Go to Work Orders and click "New Work Order". In Customer click Add and create a customer (for example "ZZAUTOTEST PL CANVENDSRC Customer"); in Asset click Add and create a unit (for example "ZZAUTOTEST-PL-CANVENDSRC-UNIT"); click Create. The number shown at the top left (for example S2-15440) is {Work-order-2}.

8. On {Work-order-2} click "New Line", type Title (for example "ZZAUTOTEST PL CANVENDSRC line") and click "Save & Close". This line is {Line-2}. Click "Approve" on {Line-2}.

9. On {Line-2} open the ⋮ menu, click "Request part", type the number in lower case with periods (for example zzautotest.pl.canvend.01) and press Tab, pick Source "Vendor", Vendor {Vendor-A}, Category (for example Uncategorized), Cost 8.00 and Sell Price 16.00, and click "Save Part". The number you typed is {Number-A}.

10. On {Line-2} open the line's ⋮ menu, click "Request part", type {Part-C} in Part Number, pick the row that shows "Inventory Qty", set Quantity to 1 and click "Save Part".

11. On {Line-2} open the line's ⋮ menu, click "Save as canned line" and save it under the line's title. That canned job is {Canned-job-A}.

12. Go to Work Orders and click "New Work Order". In Customer click Add and create a customer (for example "ZZAUTOTEST PL CANVEND Customer"); in Asset click Add and create a unit (for example "ZZAUTOTEST-PL-CANVEND-UNIT"); click Create. The number shown at the top left (for example S2-15440) is {Work-order-1}.

13. Set {Part-A} inactive: on Parts → Inventory, Active tab, search {Part-A}, click its row, pick Part Status "Inactive", click Save, leave "Note (Optional)" empty and click "Deactivate" in the "Deactivate part?" confirmation.

14. Check the setup worked: the {Canned-job-A} suggestion on New Line shows "Total Parts: 2" (close the dialog without saving) and {Part-A} is on the Inactive tab.

Part 2. Setup for Claude session

• Fastest reliable route: drive Part 1 in the browser with Playwright, using the labels in Part 1; no request shape below has been observed on a Part Lifecycle build.

• UNVERIFIED: after release a new part is created with POST /api/inventory/parts/create carrying partNumber, description and isTracked instead of catalogPartId (tech plan §5). Record the request the dialog sends and reuse it for further parts.

• Part requests: POST /api/work-orders/part/make-request with line, work_order, quantity, part_source_type 'inventory', part_number, sell_price, cost and part_category_id (playbook §E); part_category_id is required. The UI route is the line's ⋮ → "Request part" dialog.

• UNVERIFIED: a status change is sent as PATCH /api/inventory/parts/status with partIds, status ("active" or "inactive") and note (tech plan §5), for the dialog and the bulk bar alike. Record what the confirmation sends.

• Work orders: the playbook (§D, Navigation Map) says a freshly created work order reliably opens its detail page while an existing one can bounce to /workorders, so create the work order fresh and stay on it; lines are made with the New Line dialog (POST /api/work-orders/lines/create needs a canned line).

• The vendor part must be saved while {Part-A} is still active, so it is not refused on the way in.

• Observe step 5 as the exact text of the toast; compare it character by character with {Part-A} as it shows on the Inactive tab. UNVERIFIED: the tech plan (written before this rule) builds the warning from the skipped part number and does not say which number it uses; this case checks it.

• Evidence: take a screenshot at every step that has an expected result, and record the build marker before you start.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
