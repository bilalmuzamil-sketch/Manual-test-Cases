Setup: With no sort chosen, tracked parts are listed before untracked parts

Test case: C425644, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919); the Admin role has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and 'Part Library & Inventory → Delete' and can see costs and prices.

• Parts → Inventory is open on the Active tab at {Location-A}.

• Bin {Bin-A} is the default bin of {Location-A} (for example General Storage), the bin New Inventory Part fills in.

• Four parts at {Location-A} have numbers starting {Prefix-A} (for example ZZAUTOTEST-PL-NOSORT-).

• Inventory parts {Part-A} (for example ZZAUTOTEST-PL-NOSORT-02, described ZZAUTOTEST PL NOSORT ALPHA) and {Part-B} (for example ZZAUTOTEST-PL-NOSORT-01, described ZZAUTOTEST PL NOSORT CHARLIE) are tracked.

• Inventory parts {Part-C} (for example ZZAUTOTEST-PL-NOSORT-04, described ZZAUTOTEST PL NOSORT AARDVARK) and {Part-D} (for example ZZAUTOTEST-PL-NOSORT-03, described ZZAUTOTEST PL NOSORT ZULU) are untracked.

• No column of the Inventory list is sorted: no header shows a sort arrow.

Part 1. Setup for manual QA tester

1. Sign in as an Admin, pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar, and open Parts → Inventory on the Active tab.

2. Click New Inventory Part and note the bin the Inventory section fills in (for example General Storage); this is {Bin-A}, the location's default bin. Click Cancel.

3. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL NOSORT CHARLIE) and a Part Number (for example ZZAUTOTEST-PL-NOSORT-01), pick any Category (for example Uncategorized) and type Cost 2.00. This part is {Part-B}.

4. Leave Track quantities and cost of goods on and leave Min and Max empty.

5. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 1.

6. Click Save. The dialog closes.

7. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL NOSORT ALPHA) and a Part Number (for example ZZAUTOTEST-PL-NOSORT-02), pick any Category (for example Uncategorized) and type Cost 2.00. This part is {Part-A}.

8. Leave Track quantities and cost of goods on and leave Min and Max empty.

9. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 8.

10. Click Save. The dialog closes.

11. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL NOSORT ZULU) and a Part Number (for example ZZAUTOTEST-PL-NOSORT-03), pick any Category (for example Uncategorized) and type Cost 2.00. This part is {Part-D}.

12. Click the Track quantities and cost of goods switch so it is off (grey); Min and Max disappear.

13. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 1.

14. Click Save. The dialog closes.

15. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL NOSORT AARDVARK) and a Part Number (for example ZZAUTOTEST-PL-NOSORT-04), pick any Category (for example Uncategorized) and type Cost 2.00. This part is {Part-C}.

16. Click the Track quantities and cost of goods switch so it is off (grey); Min and Max disappear.

17. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 1.

18. Click Save. The dialog closes.

19. The shared start of the four part numbers (for example ZZAUTOTEST-PL-NOSORT-) is {Prefix-A}.

20. If any column header shows a sort arrow, click that header until the arrow disappears, or sign out and in again.

21. Check the setup worked: no header shows a sort arrow, and searching {Prefix-A} lists four rows.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
