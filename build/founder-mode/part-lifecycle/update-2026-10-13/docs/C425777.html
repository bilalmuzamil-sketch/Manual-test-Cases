Setup: A core gets the same number and description history entries

Test case: C425777, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), a role that has 'Part Library & Inventory → View', 'Create & Edit' and 'Delete'.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-CORERN-01), with description {Description-A} (for example ZZAUTOTEST PL CORERN PART), is tracked at {Location-A} with a Core Charge (for example $25.00), so it has a core, {Core-A}, described "Core for {Description-A}".

• The new part number is {Number-A} (for example ZZAUTOTEST-PL-CORERN-01B) and the new description is {Description-B} (for example ZZAUTOTEST PL CORERN NEW).

Part 1. Setup for manual QA tester

1. Sign in as an Admin (or Owner) and pick the location in the top-bar location switcher (for example Staging Heavy Duty - 9919). This location is {Location-A}; every step runs there unless it names another location.

2. Go to Parts → Inventory and click "New Inventory Part". Type Description (for example ZZAUTOTEST PL CORERN PART) and Part Number (for example ZZAUTOTEST-PL-CORERN-01). The part number you typed is {Part-A} and the description is {Description-A}.

3. Pick Category (for example Uncategorized), type Cost (for example 10.00) and Sell Price (for example 20.00), type Core Charge (for example 25.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 4 and click Save.

4. The core the system makes for {Part-A} is {Core-A}; its description reads "Core for {Description-A}".

5. Decide the new number (for example ZZAUTOTEST-PL-CORERN-01B), which is {Number-A}, and the new description (for example ZZAUTOTEST PL CORERN NEW), which is {Description-B}.

6. Check the setup worked: {Part-A} is on the Active tab with its core charge in the "Core" column.

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
