Setup: A number over 50 characters is refused while on an open part request

Test case: C425718, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• Part {Part-A} (for example ZZAUTOTEST-PL-LONG-01) is stocked at {Location-A}.

• Work order {Work-order-1} (for example S2-15444) has a line, {Line-1} (for example "Replace - Brake pot"), with an open part request for {Part-A}: requested and not received.

• Part {Part-B} (for example ZZAUTOTEST-PL-LONG-02) is stocked at {Location-A} and is on no part request.

• {Number-A} (for example ZZAUTOTEST-PL-LONG-01-XXXXXXXXXXXXXXXXXXXXXXXXXXXXX) is exactly 51 characters long, and {Number-B} (for example ZZAUTOTEST-PL-LONG-02-YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY) is exactly 60 characters long. Neither is used by any part.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Long A) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-LONG-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save.

3. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Long B) and the Part Number {Part-B} (for example ZZAUTOTEST-PL-LONG-02). This part is {Part-B}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save.

4. Go to Customers → New Customer, name it (for example ZZAUTOTEST PL LONG Customer) and Save; this customer is {Customer-A}. Add an asset to it (for example unit ZZ1). Go to Work Orders → New Work Order, pick {Customer-A} and the asset, and click Create. The work order number shown is {Work-order-1} (for example S2-15444). On the work order click New Line, pick any job in the Title list (for example "Replace - Brake pot") and click Save & Close. This line is {Line-1}.

5. On {Line-1} click ⋮ → Request part, type {Part-A} and pick the result marked "Part Library", set Quantity 1 and click Save Part. It stays requested.

6. Write down {Number-A} (for example ZZAUTOTEST-PL-LONG-01-XXXXXXXXXXXXXXXXXXXXXXXXXXXXX, 51 characters) and {Number-B} (for example ZZAUTOTEST-PL-LONG-02-YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY, 60 characters). Count the characters before you start.

7. Check the setup worked: {Work-order-1} → Parts tab lists {Part-A} as Requested.

Part 2. Setup for Claude session

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• Work order and line: create them on screen as Part 1 says (a line created without a canned job answers 500 through POST /api/work-orders/lines/create, so use the New Line window). Request a part on the line with the line's ⋮ menu → Request part; record {Work-order-1 id} from the work order's address.

• Messages: take a screenshot while each message shows and copy its text exactly, including any second, smaller line. Error messages that fade go away after about 3 seconds, so capture them at once.

• Generate {Number-A} and {Number-B} in code and assert their lengths (51 and 60) before typing them.

• UNVERIFIED: the tech plan says part requests store at most 50 characters (work_order_part_request.part_number), which is why the rule exists; a build that truncates instead of refusing is a failure.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup
