Setup: The dashboard inventory figure keeps an untracked part's stock

Test case: C425659, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example ZZAUTOTEST PL DASHBOARD LOC), a location created for this case that holds only this case's part, so its figures come from that part alone.

• Bin {Bin-A} is the default bin of {Location-A} (for example General Storage), the bin New Inventory Part fills in.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-DASH-01) is active and tracked at {Location-A}, with 6 in {Bin-A} at a cost of $10.00 ($60.00 of stock).

• The Dashboard at {Location-A} shows an inventory figure {Dashboard-figure-A} of $60.00 before the steps start.

• The Dashboard refreshes its figures about once an hour, so the steps include a wait.

Part 1. Setup for manual QA tester

1. Sign in as an Admin, go to Settings → Locations and add a location (for example ZZAUTOTEST PL DASHBOARD LOC), filling the required fields with any values. This location is {Location-A}.

2. Pick {Location-A} in the location switcher in the top bar and open Parts → Inventory.

3. Click New Inventory Part and note the bin the Inventory section fills in (for example General Storage); this is {Bin-A}, the location's default bin. Click Cancel.

4. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL DASHBOARD STOCK) and a Part Number (for example ZZAUTOTEST-PL-DASH-01), pick any Category (for example Uncategorized) and type Cost 10.00. This part is {Part-A}.

5. Leave Track quantities and cost of goods on and leave Min and Max empty.

6. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 6.

7. Click Save. The dialog closes.

8. Wait about 70 minutes, then open the Dashboard (the page ShopView opens after sign-in) at {Location-A} and find its inventory figure; that figure is {Dashboard-figure-A}.

9. Check the setup worked: {Dashboard-figure-A} reads $60.00 (6 × $10.00). If the Dashboard shows no inventory figure, mark the case Blocked with the comment "no inventory figure on this build's Dashboard" and tell the QA lead.

Part 2. Setup for Claude session

• Create the location in Settings → Locations with Playwright; record {Location-A id} from GET /api/staff/my-workplaces and switch to it with POST /api/iam/change-location (workplace_id and its workplace_timezone).

• Create the parts through New Inventory Part with Playwright, exactly as Part 1 says. • Record {Part-A id} = the part_id in the create response, or the id of the row returned by GET /api/inventory/parts?search=<its part number>.

• The 70-minute wait: schedule the second half of the run rather than waiting in the session.

• UNVERIFIED: which Dashboard tile carries the inventory figure on this build (Dashboard v1 may ship first); record its label and value in the verification folder.

• Inventory Value data (playbook §N): GET /api/reporting/reports/inventory-value?range=custom&start_date=&end_date=&locations=<location id>&search=<prefix> returns rows (qty, unit_cost, total_cost) and totals; money is integer cents. Use it only to cross-check what the screen shows; the result is the screen.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
