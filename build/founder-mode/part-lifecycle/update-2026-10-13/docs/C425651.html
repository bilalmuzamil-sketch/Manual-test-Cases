Setup: Without Delete, a user can still rename a part stocked at two locations

Test case: C425651, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919); the Admin role has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and 'Part Library & Inventory → Delete' and can see costs and prices.

• Staff member {User-B} (for example ZZAUTOTEST PL-NODEL-RENAME) works at {Location-A} with the custom role {Role-B} (for example ZZAUTOTEST-PL-NODEL-RENAME-ROLE), which has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and See Financial Data but not 'Part Library & Inventory → Delete'.

• {User-B} is signed in in a second browser window (for example a private window), and the Admin stays signed in in the first window.

• Location {Location-B} (for example ZZAUTOTEST PL RENAME LOC 2) is a second location created for this case.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-NODEL-RENAME-01, described ZZAUTOTEST PL RENAME OLD) is stocked at both {Location-A} and {Location-B} on the same Part Library entry.

• The new description {Description-B} (for example ZZAUTOTEST PL RENAME NEW) is not used by any part.

• Parts → Inventory is open on the Active tab at {Location-A} in {User-B}'s window.

Part 1. Setup for manual QA tester

1. Sign in as an Admin, go to Settings → Locations and add a location (for example ZZAUTOTEST PL RENAME LOC 2), filling the required fields with any values. This location is {Location-B}.

2. Sign in as an Admin, pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar, and open Parts → Inventory on the Active tab.

3. Go to Settings → Roles & Permissions, click Create custom role, choose Skip (blank role) and type a Role name (for example ZZAUTOTEST-PL-NODEL-RENAME-ROLE). This role is {Role-B}.

4. In the Part Library and Inventory group tick View and Create & Edit and leave Delete unticked, also tick See Financial Data so costs and prices show, and click Create (the toast reads "Role created successfully.").

5. Go to Settings → Staff and add a staff member: First name ZZAUTOTEST, a Last name (for example PL-NODEL-RENAME), an email inbox you can open (for example your own address with +plnodelrename added before the @), Role {Role-B} and location {Location-A}; click Save. This staff member is {User-B}.

6. Open the invitation email in that inbox, accept it and set a password.

7. Open a second browser window (for example a private window) and sign in there as {User-B}, so the Admin stays signed in in the first window.

8. In the Admin window, at {Location-A}, open Parts → Inventory.

9. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL RENAME OLD) and a Part Number (for example ZZAUTOTEST-PL-NODEL-RENAME-01), pick any Category (for example Uncategorized), type Cost 5.00, keep tracking on and the filled-in bin with Quantity 2, and click Save. This part is {Part-A}.

10. Pick {Location-B} in the location switcher, open Parts → Inventory, click New Inventory Part and type exactly the same Description and Part Number as {Part-A}; pick any Category, type Cost 5.00 and click Save. Typing the number exactly links it to the same Part Library entry.

11. Choose the new description {Description-B} (for example ZZAUTOTEST PL RENAME NEW).

12. Check the setup worked: {Part-A} is listed at both {Location-A} and {Location-B} (switch location in the Admin window), and {User-B} finds it at {Location-A}.

How to work

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
