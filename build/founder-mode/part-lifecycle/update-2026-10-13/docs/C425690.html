Setup: Changing the description warns how many other locations it changes

Test case: C425690, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• You can switch to a second location, {Location-B} (for example Staging Lethbridge - 4310), in the location switcher in the top bar.

• You can also switch to a third location, {Location-C} (for example ZZAUTOTEST PL Loc 3), in the same location switcher.

• Part {Part-A} (for example ZZAUTOTEST-PL-DESCMSG-01), with the description {Description-A} (for example ZZAUTOTEST PL Desc Msg A), is stocked at {Location-A} and {Location-B}, active at both, and at {Location-C}, where it is inactive.

• Part {Part-B} (for example ZZAUTOTEST-PL-DESCMSG-02) is stocked at {Location-A} and {Location-B}.

• Part {Part-C} (for example ZZAUTOTEST-PL-DESCMSG-03) is stocked at {Location-A} only.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Open the location switcher in the top bar. If it lists no second location, go to Settings → Locations, add a location (for example ZZAUTOTEST PL Loc 2) and Save, then go to Settings → Staff, open your Admin user, give it access to the new location and Save. The second location is {Location-B} (for example Staging Lethbridge - 4310).

3. Make sure a third location exists the same way (for example ZZAUTOTEST PL Loc 3, added in Settings → Locations and given to your Admin user in Settings → Staff). The third location is {Location-C}.

4. Go to Parts → Inventory and click New Inventory Part. Type the Description {Description-A} (for example ZZAUTOTEST PL Desc Msg A) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-DESCMSG-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save.

5. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Desc Msg B) and the Part Number {Part-B} (for example ZZAUTOTEST-PL-DESCMSG-02). This part is {Part-B}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save.

6. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Desc Msg C) and the Part Number {Part-C} (for example ZZAUTOTEST-PL-DESCMSG-03). This part is {Part-C}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save.

7. Pick {Location-B} and create {Part-A} and {Part-B} there the same way, typing each number exactly.

8. Pick {Location-C}, create {Part-A} there the same way, then set it inactive there: on the Active tab type {Part-A} in the search, click its row, pick Inactive under Part Status, click Save, then click Deactivate in the "Deactivate part?" window.

9. Pick {Location-A} in the location switcher in the top bar.

10. Check the setup worked: Parts → Part Library, open {Part-A}: its page lists {Location-A}, {Location-B} and {Location-C}. Open {Part-B}: {Location-A} and {Location-B}. Open {Part-C}: {Location-A} only. At {Location-C}, {Part-A} is on the Inactive tab.

Part 2. Setup for Claude session

• Switch location in the top bar, or with POST /api/iam/change-location (workplace_id and workplace_timezone, taken from GET /api/staff/my-workplaces).

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• To set a part inactive quickly: UNVERIFIED, from the tech plan of 7 Oct 2026, PATCH /api/inventory/parts/status with partIds set to the part's id and status set to inactive; otherwise use the part window as Part 1 says.

• The Part Library list is Parts → Part Library (address /parts/parts-catalogue, unchanged by this release); click a row to open the entry's page, which lists each Workplace that stocks it and Total parts.

• Steps 3, 5, 9 and 13: read the text directly under the Description field. UNVERIFIED: the tech plan names it text_description_other_locations.

• S13-R13 was reworded 9 Oct 2026: inactive parts at other locations count; a build that counts only active ones shows "1 other location" at step 3, which is a failure.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
