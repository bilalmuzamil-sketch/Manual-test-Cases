Setup: Inventory Value location and category filters still scope the net figures

Test case: C425668, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919); the Admin role has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and 'Part Library & Inventory → Delete' and can see costs and prices.

• Location {Location-B} (for example ZZAUTOTEST PL IV NET LOC 2) is a second location created for this case.

• Category {Category-A} (for example ZZAUTOTEST PL IV NET CATEGORY) is used only by this case.

• Bin {Bin-A} is the default bin at each location (for example General Storage), and bin {Bin-B} is a second bin at {Location-B} (for example ZZAUTOTEST-PL-BIN-B).

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-IVNET-LOC-01) is at {Location-A} in {Category-A}, with -2 in its only bin {Bin-A}, at a cost of $10.00.

• Inventory part {Part-B} (for example ZZAUTOTEST-PL-IVNET-LOC-02) is at {Location-B} in another category, with 5 in {Bin-A} and -2 in {Bin-B}, at a cost of $10.00.

• Both part numbers start with {Prefix-A} (for example ZZAUTOTEST-PL-IVNET-LOC-).

• Line {Line-1} (for example "ZZAUTOTEST PL IV NET LOCATION ONE") of work order {Work-order-1} (for example S2-15440) took 2 of {Part-A} from {Bin-A} while {Bin-A} held 0, which put {Bin-A} at -2.

• Line {Line-2} (for example "ZZAUTOTEST PL IV NET LOCATION TWO") of work order {Work-order-2} (for example S2-15440) took 2 of {Part-B} from {Bin-B} while {Bin-B} held 0, which put {Bin-B} at -2.

Part 1. Setup for manual QA tester

1. Sign in as an Admin, go to Settings → Locations and add a location (for example ZZAUTOTEST PL IV NET LOC 2), filling the required fields with any values. This location is {Location-B}.

2. Go to Settings → Categories and add a category (for example ZZAUTOTEST PL IV NET CATEGORY). This category is {Category-A}.

3. Sign in as an Admin, pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar, and open Parts → Inventory on the Active tab.

4. Click New Inventory Part and note the bin the Inventory section fills in (for example General Storage); this is {Bin-A}, the location's default bin. Click Cancel.

5. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL IV NET LOCATION ONE) and a Part Number (for example ZZAUTOTEST-PL-IVNET-LOC-01), pick Category {Category-A} and type Cost 10.00. This part is {Part-A}.

6. Leave Track quantities and cost of goods on and leave Min and Max empty.

7. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 0.

8. Click Save. The dialog closes.

9. The shared start of the two part numbers (for example ZZAUTOTEST-PL-IVNET-LOC-) is {Prefix-A}.

10. Go to Work Orders and click New Work Order; pick any customer and one of its assets (for example a ZZAUTOTEST customer) and click Create. The new work order's number (for example S2-15440) is {Work-order-1}.

11. On the Lines tab click New Line, type a Title (for example ZZAUTOTEST PL IV NET LOCATION ONE) and click Save & Close. This line is {Line-1}.

12. On {Line-1} open the line's ⋮ menu and choose Request part.

13. In New Part Request type the part number of {Part-A} and pick its inventory result (it shows Inventory Qty).

14. Take 2 from {Bin-A}, which holds 0, and nothing from any other bin; click Save & Close.

15. Back in Parts → Inventory, search {Part-A} and check that {Bin-A} now reads -2 (QA lead, 9 Oct 2026: using an inventory part on a work order line while its bin holds 0 takes the bin below zero).

16. Pick {Location-B} in the location switcher and open Parts → Inventory; check that {Location-B} has a bin besides its default one (add one in Settings → Bin Locations if not, for example ZZAUTOTEST-PL-BIN-B); that second bin is {Bin-B}.

17. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL IV NET LOCATION TWO) and a Part Number (for example ZZAUTOTEST-PL-IVNET-LOC-02), pick any Category (for example Uncategorized) and type Cost 10.00. This part is {Part-B}.

18. Leave Track quantities and cost of goods on and leave Min and Max empty.

19. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 5.

20. Click Add Bin Location, pick {Bin-B} and set its Quantity to 0.

21. Click Save. The dialog closes.

22. Go to Work Orders and click New Work Order; pick any customer and one of its assets (for example a ZZAUTOTEST customer) and click Create. The new work order's number (for example S2-15440) is {Work-order-2}.

23. On the Lines tab click New Line, type a Title (for example ZZAUTOTEST PL IV NET LOCATION TWO) and click Save & Close. This line is {Line-2}.

24. On {Line-2} open the line's ⋮ menu and choose Request part.

25. In New Part Request type the part number of {Part-B} and pick its inventory result (it shows Inventory Qty).

26. Take 2 from {Bin-B}, which holds 0, and nothing from any other bin; click Save & Close.

27. Back in Parts → Inventory, search {Part-B} and check that {Bin-B} now reads -2 (QA lead, 9 Oct 2026: using an inventory part on a work order line while its bin holds 0 takes the bin below zero).

28. Check the setup worked: at {Location-A}, {Part-A} shows "{Bin-A} | -2"; at {Location-B}, {Part-B} shows "{Bin-A} | 5" and "{Bin-B} | -2".

Part 2. Setup for Claude session

• Record {Location-B id} from GET /api/staff/my-workplaces after creating it, and switch with POST /api/iam/change-location (workplace_id and workplace_timezone).

• Create the parts through New Inventory Part with Playwright, exactly as Part 1 says. • Record {Part-A id} and {Part-B id}; record {Category-A id} from GET /api/inventory/categories?limit=500 (the option's value is the id).

• Negative bins: follow the QA lead's route (a work order line takes stock from a bin at 0). Playbook §E: create the work order fresh (existing work orders bounce off their detail page), add the part with POST /api/work-orders/part/make-request (part_source_type inventory, part_category_id required) or through the line's ⋮ → Request part dialog, where the per-bin quantity inputs are input_bin_quantity_<bin id>. Record {Work-order-1 id} (at {Location-A}) and {Work-order-2 id} (at {Location-B}) from the create response (data.work_order_id) and {Line-1 id} and {Line-2 id} from GET /api/work-orders/lines/<work order id>.

• Inventory Value data (playbook §N): GET /api/reporting/reports/inventory-value?range=custom&start_date=&end_date=&locations=<location id>&search=<prefix> returns rows (qty, unit_cost, total_cost) and totals; money is integer cents. Use it only to cross-check what the screen shows; the result is the screen. The category filter is categories=<Category-A id>; a category name returns 400.

• Trap: keep the work order until the case is finished; deleting it (POST /api/work-orders/delete with the work_order_id) or removing the part request returns the stock and the bin is no longer below zero. Delete it only during cleanup.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
