Setup: A delivery opened before a rename is received under the new number

Test case: C425700, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• A second browser tab is open on the same site, signed in as the same Admin at {Location-A}.

• Part {Part-A} (for example ZZAUTOTEST-PL-RECV-01) is stocked at {Location-A} with 3 on hand.

• Vendor {Vendor-A} (for example ZZAUTOTEST PL RECV Vendor) exists.

• Purchase order {Purchase-order-A} (for example PO-1011) has a line for {Part-A}, picked from the lookup, with 2 ordered and none received.

• Purchase order {Purchase-order-B} (for example PO-1012) has a line where {Part-A} was typed by hand and added as typed, with 1 ordered and none received.

• The new number, {Number-A} (for example ZZAUTOTEST-PL-RECVNEW-02), is unused and does not contain {Part-A}.

• The invoice numbers you will type are {Invoice-A} (for example ZZ-RECV-INV-1) and {Invoice-B} (for example ZZ-RECV-INV-2).

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Receive) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-RECV-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with Quantity 3 and click Save.

3. Go to Parts → Vendors and add a vendor (for example ZZAUTOTEST PL RECV Vendor), then Save. This vendor is {Vendor-A}.

4. Go to Parts → Purchase Orders → New Purchase Order and pick {Vendor-A}. Add a line: type {Part-A} in Part Number and pick the result that shows an Inventory Qty, set Quantity 2 and save the order. The purchase order number shown is {Purchase-order-A} (for example PO-1011).

5. Go to Parts → Purchase Orders → New Purchase Order and pick {Vendor-A}. Add a line: type {Part-A} in full and choose the row that adds the number as typed (not the result with an Inventory Qty), set Quantity 1 and save the order. The purchase order number shown is {Purchase-order-B} (for example PO-1012).

6. Open a second tab of the same site, signed in as the same Admin at {Location-A}. Call the first tab tab 1 and the second tab 2.

7. Write down {Number-A}, {Invoice-A} (for example ZZ-RECV-INV-1) and {Invoice-B} (for example ZZ-RECV-INV-2).

8. Check the setup worked: {Purchase-order-A} and {Purchase-order-B} are listed as not received, both lines reading {Part-A}.

Part 2. Setup for Claude session

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• Purchase orders: create them on screen and record each id from its address; GET /api/inventory/orders/<id> lists each item's part_number. Receiving goes through the Receive screen (Receive on the purchase order), which sends POST /api/inventory/orders/accept; the Receive button stays disabled until vendor, invoice number, part number, cost and a sell price above 0 are filled. Cost and invoice edits there are not kept if the screen is reloaded.

• Two tabs: use two pages of one browser context so both share the session. Open the Receive screen in tab 1 and keep it unsubmitted while the rename is saved in tab 2.

• Step 12: read the delivery's line from GET /api/inventory/deliveries as well as on screen; record its part number.

• Trap: step 11 must run before step 16, because receiving the hand-typed line under {Part-A} may itself create a Part Library entry for {Part-A}.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
