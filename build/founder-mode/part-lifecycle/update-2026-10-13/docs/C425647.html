Setup: A custom role can change part status only once Delete is granted

Test case: C425647, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919); the Admin role has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and 'Part Library & Inventory → Delete' and can see costs and prices.

• Staff member {User-B} (for example ZZAUTOTEST PL-GRANT) works at {Location-A} with the custom role {Role-B} (for example ZZAUTOTEST-PL-GRANT-ROLE), which has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and See Financial Data but not 'Part Library & Inventory → Delete'.

• {User-B} is signed in in a second browser window (for example a private window), and the Admin stays signed in in the first window.

• Bin {Bin-A} is the default bin of {Location-A} (for example General Storage), the bin New Inventory Part fills in.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-GRANT-01) is active and tracked at {Location-A}, with 2 in {Bin-A}.

• Parts → Inventory is open on the Active tab in {User-B}'s window.

Part 1. Setup for manual QA tester

1. Sign in as an Admin, pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar, and open Parts → Inventory on the Active tab.

2. Go to Settings → Roles & Permissions, click Create custom role, choose Skip (blank role) and type a Role name (for example ZZAUTOTEST-PL-GRANT-ROLE). This role is {Role-B}.

3. In the Part Library and Inventory group tick View and Create & Edit and leave Delete unticked, also tick See Financial Data so costs and prices show, and click Create (the toast reads "Role created successfully.").

4. Go to Settings → Staff and add a staff member: First name ZZAUTOTEST, a Last name (for example PL-GRANT), an email inbox you can open (for example your own address with +plgrant added before the @), Role {Role-B} and location {Location-A}; click Save. This staff member is {User-B}.

5. Open the invitation email in that inbox, accept it and set a password.

6. Open a second browser window (for example a private window) and sign in there as {User-B}, so the Admin stays signed in in the first window.

7. In the Admin window open Parts → Inventory.

8. Click New Inventory Part and note the bin the Inventory section fills in (for example General Storage); this is {Bin-A}, the location's default bin. Click Cancel.

9. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL GRANT DELETE) and a Part Number (for example ZZAUTOTEST-PL-GRANT-01), pick any Category (for example Uncategorized) and type Cost 5.00. This part is {Part-A}.

10. Leave Track quantities and cost of goods on and leave Min and Max empty.

11. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 2.

12. Click Save. The dialog closes.

13. Check the setup worked: in {User-B}'s window, {User-B} finds {Part-A} on the Active tab and the ⋮ menu offers Cycle count and Export only.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
