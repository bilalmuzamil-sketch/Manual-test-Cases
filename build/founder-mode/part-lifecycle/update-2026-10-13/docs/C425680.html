Setup: Saving a part with its number unchanged is never refused as a duplicate

Test case: C425680, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• You can switch to a second location, {Location-B} (for example Staging Lethbridge - 4310), in the location switcher in the top bar.

• Two active parts, {Part-A} (for example ZZAUTOTEST-PL-UNCH-01) and {Part-B} (for example ZZAUTOTESTPLUNCH01), are stocked at {Location-A} on two different Part Library entries, and their numbers match once upper and lower case, hyphens, asterisks, periods and spaces are ignored.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Open the location switcher in the top bar. If it lists no second location, go to Settings → Locations, add a location (for example ZZAUTOTEST PL Loc 2) and Save, then go to Settings → Staff, open your Admin user, give it access to the new location and Save. The second location is {Location-B} (for example Staging Lethbridge - 4310).

3. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Unchanged Active) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-UNCH-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save.

4. Pick {Location-B} in the location switcher in the top bar.

5. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Unchanged Second) and the Part Number {Part-B} (for example ZZAUTOTESTPLUNCH01). This part is {Part-B}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save.

6. Pick {Location-A} in the location switcher in the top bar.

7. Go to Settings → Data Import → Inventory and download the template the screen offers. Fill one row: Part Number {Part-B}, Description ZZAUTOTEST PL Unchanged Import, and the other columns the template requires (for example Category Uncategorized, Cost 10.00, Quantity 1). Upload the file and run the import. This is meant to place {Part-B} at {Location-A} on {Part-B}'s own Part Library entry.

8. Check the setup worked: at {Location-A}, the Active tab lists both {Part-A} and {Part-B}. If it does not, mark the case Blocked with the comment "could not place two matching numbers at one location".

Part 2. Setup for Claude session

• Switch location in the top bar, or with POST /api/iam/change-location (workplace_id and workplace_timezone, taken from GET /api/staff/my-workplaces).

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• The parts CSV import is Settings → Data Import → Inventory (needs the Data Import setting). Download the template the screen offers rather than writing columns from memory; the import's Grid Location column is the screen's Bin Location.

• UNVERIFIED: placing two parts whose numbers match (ignoring case and punctuation) at one location relies on the parts CSV import adding a part on an entry that is not yet stocked here without running the duplicate check of S7-N3. The PRD does not say whether the import runs that check. Record exactly what the import screen reports. If it refuses the row or updates {Part-A}, use two parts that already matched at one location before the release instead, or mark the case Blocked.

• Steps 4 and 8: record any message shown after Save; read the saved Sell Price back from GET /api/inventory/parts?search=<number>.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
