Setup: The part window offers no way to move a part to another library entry

Test case: C425719, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• Part {Part-A} (for example ZZAUTOTEST-PL-REPOINT-01) is stocked at {Location-A}.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Repoint) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-REPOINT-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save.

3. Check the setup worked: Parts → Inventory, search {Part-A}: one row.

Part 2. Setup for Claude session

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• Find each part and its id with GET /api/inventory/parts?search=<part number> from the signed-in session, and record {Part-A id} (and {Part-B id} where there is a second part) before step 1.

• For the second Step 3 result (a Claude session may check it; a manual tester cannot): UNVERIFIED, from the tech plan of 7 Oct 2026, the change request no longer accepts catalogPartId; send POST /api/inventory/parts/change for {Part-A id} with another entry's catalogPartId and expect the refusal "A part can't be moved to a different Part Library entry." and no change. Record request and answer.

• Trap: do not report the API answer as the manual tester's result.

Access
