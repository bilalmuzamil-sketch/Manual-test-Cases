Setup: A new part imported with no description takes its part number

Test case: C573681, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete', See Financial Data and the Data Import setting.

• {Bin-A} (for example General Storage) is a bin location of {Location-A}.

• No part or Part Library entry has the number {Part-A} (for example ZZAUTOTEST-PL-NODESCNEW-01) in any upper and lower case or punctuation.

• Import file {File-A} (for example ZZ-PL-NODESCNEW.csv) holds one row: part number {Part-A}, an empty description, quantity 2 and Bin Location {Bin-A}.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Open New Inventory Part and look at the Bin Location of the default bin row (for example General Storage). This bin is {Bin-A}. Close the window with Cancel.

3. Go to Settings → Data Import → Inventory and download the template the screen offers. Make {File-A}: one row with part number {Part-A} (for example ZZAUTOTEST-PL-NODESCNEW-01), the description cell left empty, quantity 2, Bin Location (grid_location) {Bin-A} and category Uncategorized; fill any other column the template requires (for example a cost of 10.00). Save it (for example as ZZ-PL-NODESCNEW.csv).

4. Check the setup worked: Parts → Inventory (both tabs) and Parts → Part Library, search the part of the number after ZZAUTOTEST-PL- (for example NODESCNEW): no row. If one exists, use the next suffix and make the file again.

Part 2. Setup for Claude session

• The parts CSV import is Settings → Data Import → Inventory (needs the Data Import setting). Download the template the screen offers and use its column headers. The QA lead's 9 Oct example import file has the columns name, part_number, uom, quantity, min_qty, max_qty, grid_location, purchase_price, core_price, vendor, manufacturer, category and tags, and no sell price column; its grid_location is the screen's Bin Location. UNVERIFIED: that the name column is the description; record the template's real headers.

• Step 3: Record the import screen's whole result (rows added, updated, skipped or refused, and any message) with a screenshot, and read the parts afterwards with GET /api/inventory/parts?search=<number>. The new part's description must equal {Part-A} exactly.

• Trap: the row names the bin {Bin-A}, so the "Unassigned" bin rule (S7-N10, its own case) stays out of this case.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
