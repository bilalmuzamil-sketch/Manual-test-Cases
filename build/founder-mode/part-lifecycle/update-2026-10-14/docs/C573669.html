Setup: Export follows the Category filter and the Supply filter

Test case: C573669, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919). The Admin role has 'Part Library & Inventory → View / Create & Edit / Delete'.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-EXPFLT-01) is active and tracked at {Location-A}, in category {Category-A} (for example the first category offered), with Min 5, Max 10 and quantity 1.

• Inventory part {Part-B} (for example ZZAUTOTEST-PL-EXPFLT-02) is active and tracked, in category {Category-B} (for example the second category offered), with Min 5, Max 10 and quantity 1.

• Inventory part {Part-C} (for example ZZAUTOTEST-PL-EXPFLT-03) is active and untracked, in {Category-A}, with quantity 1 in its bin.

• All three part numbers start with {Prefix-A} (for example ZZAUTOTEST-PL-EXPFLT).

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location selector in the top bar.

2. {Category-A} and {Category-B} are two different categories from the Category list in New Inventory Part (for example the first and the second offered).

3. Go to Parts → Inventory at {Location-A}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL export filter A") and a Part Number (for example ZZAUTOTEST-PL-EXPFLT-01), pick {Category-A}, type a Cost (for example 10.00) and a Sell Price (for example 20.00), type Min 5 and Max 10, leave "Track quantities and cost of goods" on, set the default bin's Quantity to 1 and click Save. The part number you typed is {Part-A}.

4. Go to Parts → Inventory at {Location-A}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL export filter B") and a Part Number (for example ZZAUTOTEST-PL-EXPFLT-02), pick {Category-B}, type a Cost (for example 10.00) and a Sell Price (for example 20.00), type Min 5 and Max 10, leave "Track quantities and cost of goods" on, set the default bin's Quantity to 1 and click Save. The part number you typed is {Part-B}.

5. Go to Parts → Inventory at {Location-A}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL export filter C") and a Part Number (for example ZZAUTOTEST-PL-EXPFLT-03), pick {Category-A}, type a Cost (for example 10.00) and a Sell Price (for example 20.00), switch "Track quantities and cost of goods" off (Min and Max disappear), set the default bin's Quantity to 1 and click Save. The part number you typed is {Part-C}.

6. {Prefix-A} is the text the three part numbers start with (for example ZZAUTOTEST-PL-EXPFLT).

7. Check the setup worked: searched for {Prefix-A}, the Active tab lists the three parts, and {Part-C} shows "Not Tracked" in Total Qty. With the Supply filter on Under-supplied, {Part-A} and {Part-B} should be listed; if one is not, raise its Min until it is. Set the Supply filter back to All.

Part 2. Setup for Claude session

• Categories: GET /api/inventory/categories returns value and label pairs; record two as {Category-A} and {Category-B}.

• Create {Part-A}, {Part-B} and {Part-C} (tracking off, isTracked false, for {Part-C}) with the New Inventory Part dialog in Playwright exactly as Part 1 says (the most reliable route), or with POST /api/inventory/parts/create. UNVERIFIED: on a Part Lifecycle build the tech plan says that request takes partNumber, description and isTracked in place of catalogPartId; record the body the dialog really sends before scripting it.

• Trap: creating a part with tracking off needs the Delete permission; the Admin role has it.

• Downloads: wait for the download event after each Export, save both files in the verification folder and list their part numbers with a CSV reader. Compare the second file with the rows the list showed in Step 9 (record them from the visible rows). UNVERIFIED: the export request carries the search, the Category filter and the supply value (tech plan §5).

• Run every step in the same Playwright browser and take a screenshot right after each step that has an expected result. Read on-screen words from the visible text, not from accessible names, and save the screenshots in the case's verification folder.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
