Setup: A rename carries over to vendor returns that are not completed

Test case: C425699, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• Part {Part-A} (for example ZZAUTOTEST-PL-CORET-01) is stocked at {Location-A} with 5 on hand.

• Vendor {Vendor-A} (for example ZZAUTOTEST PL CORET Vendor) exists.

• Vendor return {Return-A} for {Part-A} and {Vendor-A} is saved and not completed.

• Vendor return {Return-B} for {Part-A} and {Vendor-A} is completed (accepted by the vendor).

• The new number, {Number-A} (for example ZZAUTOTEST-PL-CORETNEW-02), is unused and does not contain {Part-A}.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL CO RET) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-CORET-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with Quantity 5 and click Save.

3. Go to Parts → Vendors and add a vendor (for example ZZAUTOTEST PL CORET Vendor), then Save. This vendor is {Vendor-A}.

4. Go to Parts → Returns → Create Return. Pick Vendor {Vendor-A}, pick {Part-A} in Part Number, set Qty To Return 1 and Price Per Unit 10.00, and click Save Return. This return is {Return-A}.

5. Create a second return the same way and click Save Return. Open it and set it to accepted by the vendor with the return's status control. This return is {Return-B}.

6. Write down {Number-A} (for example ZZAUTOTEST-PL-CORETNEW-02).

7. Check the setup worked: Parts → Returns lists {Return-A} as open and {Return-B} as completed, both reading {Part-A}. If the build offers no way to complete a return, write that in the result comment and mark the {Return-B} result Blocked.

Part 2. Setup for Claude session

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• Returns: Parts → Returns → Create Return (the Create Return page). UNVERIFIED: how a vendor return is set to accepted by the vendor on screen; the tech plan treats accepted_by_vendor and declined_by_vendor as completed. Record the control used.

• Record each return's part number before step 3 and after step 4 (GET /api/work-orders/part/list-return-requests lists return requests).

• Trap: a return cannot be deleted while its work order is complete; these returns have no work order.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
