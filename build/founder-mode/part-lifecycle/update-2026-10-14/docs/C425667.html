Test case: C425667, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919); the Admin role has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and 'Part Library & Inventory → Delete' and can see costs and prices.

• Bin {Bin-A} is the default bin of {Location-A} (for example General Storage), the bin New Inventory Part fills in, and bin {Bin-B} is a second bin at {Location-A} (for example ZZAUTOTEST-PL-BIN-B).

• Every part in this case is tracked and costs $10.00 per unit.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-IVNET-EXP-01) is active at {Location-A}, with 5 in {Bin-A} and -2 in {Bin-B}.

• Inventory part {Part-B} (for example ZZAUTOTEST-PL-IVNET-EXP-02) is active at {Location-A}, with -2 in its only bin {Bin-A}.

• Both part numbers start with {Prefix-A} (for example ZZAUTOTEST-PL-IVNET-EXP-).

• Line {Line-1} (for example "ZZAUTOTEST PL IV NET EXPORT MIXED") of work order {Work-order-1} (for example S2-15440) took 2 of {Part-A} from {Bin-B} while {Bin-B} held 0, which put {Bin-B} at -2.

• Line {Line-2} (for example "ZZAUTOTEST PL IV NET EXPORT NEGATIVE") of work order {Work-order-2} (for example S2-15440) took 2 of {Part-B} from {Bin-A} while {Bin-A} held 0, which put {Bin-A} at -2.

• A spreadsheet program or text editor is available to open a CSV file.

Part 1. Setup for manual QA tester

1. Sign in as an Admin, pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar, and open Parts → Inventory on the Active tab.

2. Click New Inventory Part and note the bin the Inventory section fills in (for example General Storage); this is {Bin-A}, the location's default bin. Click Cancel.

3. Open Settings → Bin Locations and check that {Location-A} has a bin other than {Bin-A}; if it has none, add one (for example ZZAUTOTEST-PL-BIN-B). That second bin is {Bin-B}. Go back to Parts → Inventory.

4. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL IV NET EXPORT MIXED) and a Part Number (for example ZZAUTOTEST-PL-IVNET-EXP-01), pick any Category (for example Uncategorized) and type Cost 10.00. This part is {Part-A}.

5. Leave Track quantities and cost of goods on and leave Min and Max empty.

6. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 5.

7. Click Add Bin Location, pick {Bin-B} and set its Quantity to 0.

8. Click Save. The dialog closes.

9. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL IV NET EXPORT NEGATIVE) and a Part Number (for example ZZAUTOTEST-PL-IVNET-EXP-02), pick any Category (for example Uncategorized) and type Cost 10.00. This part is {Part-B}.

10. Leave Track quantities and cost of goods on and leave Min and Max empty.

11. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 0.

12. Click Save. The dialog closes.

13. The shared start of the two part numbers (for example ZZAUTOTEST-PL-IVNET-EXP-) is {Prefix-A}.

14. Go to Work Orders and click New Work Order; pick any customer and one of its assets (for example a ZZAUTOTEST customer) and click Create. The new work order's number (for example S2-15440) is {Work-order-1}.

15. On the Lines tab click New Line, type a Title (for example ZZAUTOTEST PL IV NET EXPORT MIXED) and click Save & Close. This line is {Line-1}.

16. On {Line-1} open the line's ⋮ menu and choose Request part.

17. In New Part Request type the part number of {Part-A} and pick its inventory result (it shows Inventory Qty).

18. Take 2 from {Bin-B}, which holds 0, and nothing from any other bin; click Save & Close.

19. Back in Parts → Inventory, search {Part-A} and check that {Bin-B} now reads -2 (QA lead, 9 Oct 2026: using an inventory part on a work order line while its bin holds 0 takes the bin below zero).

20. Go to Work Orders and click New Work Order; pick any customer and one of its assets (for example a ZZAUTOTEST customer) and click Create. The new work order's number (for example S2-15440) is {Work-order-2}.

21. On the Lines tab click New Line, type a Title (for example ZZAUTOTEST PL IV NET EXPORT NEGATIVE) and click Save & Close. This line is {Line-2}.

22. On {Line-2} open the line's ⋮ menu and choose Request part.

23. In New Part Request type the part number of {Part-B} and pick its inventory result (it shows Inventory Qty).

24. Take 2 from {Bin-A}, which holds 0, and nothing from any other bin; click Save & Close.

25. Back in Parts → Inventory, search {Part-B} and check that {Bin-A} now reads -2 (QA lead, 9 Oct 2026: using an inventory part on a work order line while its bin holds 0 takes the bin below zero).

26. Check the setup worked: {Part-A} shows "{Bin-A} | 5" and "{Bin-B} | -2"; {Part-B} shows "{Bin-A} | -2".

• Record {Part-A id} and {Part-B id}.

Playbook §E: create the work order fresh (existing work orders bounce off their detail page), add the part with POST /api/work-orders/part/make-request (part_source_type inventory, part_category_id required) or through the line's ⋮ → Request part dialog, where the per-bin quantity inputs are input_bin_quantity_<bin id>. Record {Work-order-1 id} and {Work-order-2 id} from the create response (data.work_order_id) and {Line-1 id} and {Line-2 id} from GET /api/work-orders/lines/<work order id>.

• Inventory Value data (playbook §N): GET /api/reporting/reports/inventory-value?range=custom&start_date=&end_date=&locations=<location id>&search=<prefix> returns rows (qty, unit_cost, total_cost) and totals; money is integer cents. Use it only to cross-check what the screen shows; the result is the screen.

• Export file shape (playbook §N): a UTF-8 BOM, then "As of: YYYY-MM-DD", then "Locations: …", then the header row; find the header line rather than hard-coding it. Negative money is written -$20.00.

• Trap: keep the work order until the case is finished; deleting it (POST /api/work-orders/delete with the work_order_id) or removing the part request returns the stock and the bin is no longer below zero. Delete it only during cleanup.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
