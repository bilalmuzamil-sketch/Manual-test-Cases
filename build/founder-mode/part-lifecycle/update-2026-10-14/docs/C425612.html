Setup: The Part Library page refuses a number that another entry already has

Test case: C425612, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin who can pick two locations in the location selector, {Location-A} (for example Staging Heavy Duty - 9919) and {Location-B} (for example Staging Lethbridge - 4310). The Admin role has 'Part Library & Inventory → View / Create & Edit / Delete'.

• Part Library entry {Part-A} (for example ZZAUTOTEST-PL-LIBDUP-01) is stocked at {Location-A} only.

• Part Library entry {Part-B} (for example ZZAUTOTEST-PL-LIBDUP-02, all capitals, description "ZZAUTOTEST PL lib dup B") is a separate entry, stocked at {Location-B} only.

• {Number-A} is {Part-B} typed in lower case (for example zzautotest-pl-libdup-02).

Part 1. Setup for manual QA tester

1. Make sure the location selector lists two locations, {Location-A} (for example Staging Heavy Duty - 9919) and {Location-B} (for example Staging Lethbridge - 4310). If it lists only one, go to Settings → Locations, add a location (for example "ZZAUTOTEST PL Loc B") and save; then go to Settings → Staff, open your own staff record, give it access to the new location and save, and sign in again (saving a staff record signs that user out).

2. Pick {Location-A}. Go to Parts → Inventory at {Location-A}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL lib dup A") and a Part Number (for example ZZAUTOTEST-PL-LIBDUP-01), pick any Category (for example the first one offered), type a Cost (for example 10.00) and a Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 5 and click Save. The part number you typed is {Part-A}.

3. Pick {Location-B}. Go to Parts → Inventory at {Location-B}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL lib dup B") and a Part Number (for example ZZAUTOTEST-PL-LIBDUP-02), pick any Category (for example the first one offered), type a Cost (for example 10.00) and a Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 5 and click Save. The part number you typed is {Part-B}.

4. Pick {Location-A} again. {Number-A} is {Part-B} in lower case (for example zzautotest-pl-libdup-02).

5. Check the setup worked: Parts → Part Library lists {Part-A} and {Part-B} as two entries, each with "Total parts" 1.

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
