Setup: A core's own Part History page shows its name and its history

Test case: C573677, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919); the Admin role has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and 'Part Library & Inventory → Delete' and can see costs and prices.

• Bin {Bin-A} is the default bin of {Location-A} (for example General Storage), the bin New Inventory Part fills in.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-CORE-HIST-01) is active and tracked at {Location-A}, with 2 in {Bin-A} and a Core Charge of $25.00, so it has a core, {Core-A}.

• {Part-A}'s description was changed in its Edit Inventory Part dialog from {Description-A} (for example ZZAUTOTEST PL CORE HISTORY OLD) to {Description-B} (for example ZZAUTOTEST PL CORE HISTORY NEW) after the core existed.

• The way to open {Core-A}'s own Part History page was found and written down during setup.

Part 1. Setup for manual QA tester

1. Sign in as an Admin, pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar, and open Parts → Inventory on the Active tab.

2. Click New Inventory Part and note the bin the Inventory section fills in (for example General Storage); this is {Bin-A}, the location's default bin. Click Cancel.

3. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL CORE HISTORY OLD), which is {Description-A}, and a Part Number (for example ZZAUTOTEST-PL-CORE-HIST-01), pick any Category (for example Uncategorized) and type Cost 40.00. This part is {Part-A}.

4. Leave Track quantities and cost of goods on and leave Min and Max empty; keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 2.

5. Type Core Charge 25.00 and click Save. The dialog closes. The core this creates is {Core-A}.

6. Search {Part-A}, click its row, replace the Description with a new one (for example ZZAUTOTEST PL CORE HISTORY NEW), which is {Description-B}, and click Save.

7. Find how to open {Core-A}'s own Part History page from the screens: try the $25.00 in the Core column of the {Part-A} row, and try Search in the top bar for Core for {Description-B}. The page you want is a Part History page whose Part details panel names "Core for {Description-B}". Write down exactly how you reached it.

8. Check the setup worked: the {Part-A} row shows {Description-B} and $25.00 in its Core column, and you have written down how to open {Core-A}'s Part History page. If no screen opens it, mark the case Blocked with the comment "no screen link to the core's Part History page" and tell the QA lead.

Part 2. Setup for Claude session

• Create the parts through New Inventory Part with Playwright, exactly as Part 1 says. UNVERIFIED: the tech plan says the dialog now sends POST /api/inventory/parts/create with partNumber, description and isTracked (no catalogPartId); capture the body the dialog really sends once and reuse it for the other parts, recording the real field names.

• Record {Part-A id}. Record {Core-A id} = the core's part id. UNVERIFIED: the playbook says a core is a separate part record linked from its part (core_part_id) that appears in no row of GET /api/inventory/parts; read it from GET /api/inventory/parts/<Part-A id>.

• Part History pages open at /parts/history/<part id> (tech plan Phase 8); /parts/history/<Core-A id> shows the core's page for observation. UNVERIFIED: which screen links to it; record the screen path if one exists, because the tester needs one, and say in the result if only the address works.

• Make the description change in the part dialog (PRD S13-R15 renames the core with it, S10-R26 writes the core's own entry).

• Read the Part details title and the Event text on screen. Trap: the Part details title is cut short with two dots when long (design board 2.4); compare its start, and read the full text from the element.

• Trap (tech plan D22): a core gets no tracking entries of its own; only number, description and status entries are expected on it.
