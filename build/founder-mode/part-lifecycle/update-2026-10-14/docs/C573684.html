Setup: Canned job warning lists inactive parts A to Z, separated by commas

Test case: C573684, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), a role that has 'Part Library & Inventory → View', 'Create & Edit' and 'Delete'.

• Inventory parts {Part-A} (for example ZZAUTOTEST-PL-CANSORT-AB100), {Part-B} (for example ZZAUTOTEST-PL-CANSORT-FF5507) and {Part-C} (for example ZZAUTOTEST-PL-CANSORT-MM20) are tracked at {Location-A} with 4 in their default bins and are inactive.

• In A to Z order by part number the three come {Part-A}, then {Part-B}, then {Part-C}.

• Inventory part {Part-D} (for example ZZAUTOTEST-PL-CANSORT-ZZ900) is tracked at {Location-A} with 4 in its default bin and is active.

• Canned job {Canned-job-A} (for example "ZZAUTOTEST PL CANSORTSRC line") holds, in this order, {Part-C}, {Part-B}, {Part-A} and {Part-D}, one of each, saved while all four were active.

• Work order {Work-order-1} (for example S2-15440) at {Location-A} is open and has no lines.

Part 1. Setup for manual QA tester

1. Sign in as an Admin (or Owner) and pick the location in the top-bar location switcher (for example Staging Heavy Duty - 9919). This location is {Location-A}; every step runs there unless it names another location.

2. Go to Parts → Inventory and click "New Inventory Part". Type Description (for example ZZAUTOTEST PL CANSORT A) and Part Number (for example ZZAUTOTEST-PL-CANSORT-AB100). The part number you typed is {Part-A}.

3. Pick Category (for example Uncategorized), type Cost (for example 10.00) and Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 4 and click Save.

4. Go to Parts → Inventory and click "New Inventory Part". Type Description (for example ZZAUTOTEST PL CANSORT B) and Part Number (for example ZZAUTOTEST-PL-CANSORT-FF5507). The part number you typed is {Part-B}.

5. Pick Category (for example Uncategorized), type Cost (for example 10.00) and Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 4 and click Save.

6. Go to Parts → Inventory and click "New Inventory Part". Type Description (for example ZZAUTOTEST PL CANSORT C) and Part Number (for example ZZAUTOTEST-PL-CANSORT-MM20). The part number you typed is {Part-C}.

7. Pick Category (for example Uncategorized), type Cost (for example 10.00) and Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 4 and click Save.

8. Go to Parts → Inventory and click "New Inventory Part". Type Description (for example ZZAUTOTEST PL CANSORT D) and Part Number (for example ZZAUTOTEST-PL-CANSORT-ZZ900). The part number you typed is {Part-D}.

9. Pick Category (for example Uncategorized), type Cost (for example 10.00) and Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 4 and click Save.

10. Go to Work Orders and click "New Work Order". In Customer click Add and create a customer (for example "ZZAUTOTEST PL CANSORTSRC Customer"); in Asset click Add and create a unit (for example "ZZAUTOTEST-PL-CANSORTSRC-UNIT"); click Create. The number shown at the top left (for example S2-15440) is {Work-order-2}.

11. On {Work-order-2} click "New Line", type Title (for example "ZZAUTOTEST PL CANSORTSRC line") and click "Save & Close". This line is {Line-2}. Click "Approve" on {Line-2}.

12. Add the parts to {Line-2} in this order, one request each: first {Part-C}, then {Part-B}, then {Part-A}, then {Part-D}.

13. On {Line-2} open the line's ⋮ menu, click "Request part", type {Part-C} in Part Number, pick the row that shows "Inventory Qty", set Quantity to 1 and click "Save Part".

14. On {Line-2} open the line's ⋮ menu, click "Request part", type {Part-B} in Part Number, pick the row that shows "Inventory Qty", set Quantity to 1 and click "Save Part".

15. On {Line-2} open the line's ⋮ menu, click "Request part", type {Part-A} in Part Number, pick the row that shows "Inventory Qty", set Quantity to 1 and click "Save Part".

16. On {Line-2} open the line's ⋮ menu, click "Request part", type {Part-D} in Part Number, pick the row that shows "Inventory Qty", set Quantity to 1 and click "Save Part".

17. On {Line-2} open the line's ⋮ menu, click "Save as canned line" and save it under the line's title. That canned job is {Canned-job-A}.

18. Go to Work Orders and click "New Work Order". In Customer click Add and create a customer (for example "ZZAUTOTEST PL CANSORT Customer"); in Asset click Add and create a unit (for example "ZZAUTOTEST-PL-CANSORT-UNIT"); click Create. The number shown at the top left (for example S2-15440) is {Work-order-1}.

19. Set {Part-A} inactive: on Parts → Inventory, Active tab, search {Part-A}, click its row, pick Part Status "Inactive", click Save, leave "Note (Optional)" empty and click "Deactivate" in the "Deactivate part?" confirmation.

20. Set {Part-B} inactive: on Parts → Inventory, Active tab, search {Part-B}, click its row, pick Part Status "Inactive", click Save, leave "Note (Optional)" empty and click "Deactivate" in the "Deactivate part?" confirmation.

21. Set {Part-C} inactive: on Parts → Inventory, Active tab, search {Part-C}, click its row, pick Part Status "Inactive", click Save, leave "Note (Optional)" empty and click "Deactivate" in the "Deactivate part?" confirmation.

22. Check the setup worked: Settings → Canned Lines → {Canned-job-A} lists {Part-C}, {Part-B}, {Part-A} and {Part-D} (note the order it shows); on {Work-order-1} the New Line suggestion for {Canned-job-A} shows "Total Parts: 4" (close the dialog without saving); {Part-A}, {Part-B} and {Part-C} are on the Inactive tab and {Part-D} on the Active tab. If the canned job lists the parts A to Z already, write that in the comment: the case then cannot tell the two orders apart.

Part 2. Setup for Claude session

• Fastest reliable route: drive Part 1 in the browser with Playwright, using the labels in Part 1; no request shape below has been observed on a Part Lifecycle build.

• UNVERIFIED: after release a new part is created with POST /api/inventory/parts/create carrying partNumber, description and isTracked instead of catalogPartId (tech plan §5). Record the request the dialog sends and reuse it for further parts.

• Part requests: POST /api/work-orders/part/make-request with line, work_order, quantity, part_source_type 'inventory', part_number, sell_price, cost and part_category_id (playbook §E); part_category_id is required. The UI route is the line's ⋮ → "Request part" dialog.

• UNVERIFIED: a status change is sent as PATCH /api/inventory/parts/status with partIds, status ("active" or "inactive") and note (tech plan §5), for the dialog and the bulk bar alike. Record what the confirmation sends.

• Work orders: the playbook (§D, Navigation Map) says a freshly created work order reliably opens its detail page while an existing one can bounce to /workorders, so create the work order fresh and stay on it; lines are made with the New Line dialog (POST /api/work-orders/lines/create needs a canned line).

• Canned lines are listed under Settings → Canned Lines (/canned-lines, playbook Navigation Map). UNVERIFIED: after release the apply response carries one warning with partNumbers and a message (tech plan §5); judge from the toast on screen.

• Why this order: the tech plan (§6 Phase 7, CannedLineApplicationWarnings) joins the numbers with ", " in canned-job order, while the PRD (v29, S9-R10c) lists them A to Z by part number. The canned job holds the parts Z to A, so the two rules give different toasts. Record the exact toast text and compare it character by character.

• Trap: the second work order {Work-order-2} is only the source of the canned job; run the steps on {Work-order-1}.

• Evidence: screenshot the toast at step 6, the canned job's part list from Part 1, and record the build marker before you start.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
