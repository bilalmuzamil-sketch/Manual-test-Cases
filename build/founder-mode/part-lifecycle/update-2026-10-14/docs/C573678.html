Setup: A parts import row with a number already stocked here updates that part

Test case: C573678, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete', See Financial Data and the Data Import setting.

• Part {Part-A} (for example ZZAUTOTEST-PL-IMPDUP-01), with the description {Description-A} (for example ZZAUTOTEST PL Import Dup), is stocked at {Location-A} with Min 1 and Max 5, and 3 in its bin {Bin-A} (for example General Storage).

• {Number-A} (for example zzautotest.pl.impdup.01) matches {Part-A} once upper and lower case, hyphens, asterisks, periods and spaces are ignored.

• No other Part Library entry has a number that matches {Part-A} in that way.

• {Word-A} (for example IMPDUP) is a part of the number that both {Part-A} and {Number-A} contain.

• Import file {File-A} (for example ZZ-PL-IMPDUP-1.csv) holds one row: part number {Part-A}, description {Description-A}, Min 2, Max 6, quantity 3 and Bin Location {Bin-A}.

• Import file {File-B} (for example ZZ-PL-IMPDUP-2.csv) holds the same row with part number {Number-A}, Min 3 and Max 7.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Go to Parts → Inventory and click New Inventory Part. Type the Description {Description-A} (for example ZZAUTOTEST PL Import Dup) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-IMPDUP-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), type Min 1 and Max 5, keep the default bin row with Quantity 3 (its bin, for example General Storage, is {Bin-A}) and click Save.

3. Write down {Number-A} (for example zzautotest.pl.impdup.01) and {Word-A} (for example IMPDUP).

4. Go to Settings → Data Import → Inventory and download the template the screen offers. Make {File-A}: one row with part number {Part-A}, description {Description-A}, Min 2, Max 6, quantity 3, Bin Location (grid_location) {Bin-A} and category Uncategorized; fill any other column the template requires with the part's current values. Save it (for example as ZZ-PL-IMPDUP-1.csv).

5. Make {File-B}: a copy of {File-A} with part number {Number-A}, Min 3 and Max 7 (for example ZZ-PL-IMPDUP-2.csv).

6. Check the setup worked: Parts → Inventory, search {Word-A}: one row, {Part-A}, with Min 1 and Max 5. Parts → Part Library, search {Word-A}: one entry. If anything else matches, take the next suffix and make the files again.

Part 2. Setup for Claude session

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

The QA lead's 9 Oct example import file has the columns name, part_number, uom, quantity, min_qty, max_qty, grid_location, purchase_price, core_price, vendor, manufacturer, category and tags, and no sell price column; its grid_location is the screen's Bin Location. UNVERIFIED: that the name column is the description; record the template's real headers.

• Find each part and its id with GET /api/inventory/parts?search=<part number> from the signed-in session, and record {Part-A id} (and {Part-B id} where there is a second part) before step 1.

• Steps 3 and 7: Record the import screen's whole result (rows added, updated, skipped or refused, and any message) with a screenshot, and read the parts afterwards with GET /api/inventory/parts?search=<number>. Both times exactly one part must match {Word-A}, with the same id {Part-A id} and the part number {Part-A} unchanged.

• Trap: if another Part Library entry matched {Number-A} ignoring only upper and lower case, the import would match that entry first (PRD §2 and the context note under S7-N7) and could add a second part; the setup check rules this out.

• Part History will gain "Min/Max updated | … | Source: Import" entries (S10-R22a); they are not checked here.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
