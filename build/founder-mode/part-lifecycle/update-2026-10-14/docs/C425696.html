Setup: A rename carries over to open purchase order lines at every location

Test case: C425696, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• You can switch to a second location, {Location-B} (for example Staging Lethbridge - 4310), in the location switcher in the top bar.

• Part {Part-A} (for example ZZAUTOTEST-PL-COPO-01) is stocked at {Location-A} with 4 on hand, and also at {Location-B}.

• Vendor {Vendor-A} (for example ZZAUTOTEST PL COPO Vendor) exists.

• Purchase order {Purchase-order-A} (for example PO-1001) at {Location-A} has a line for {Part-A}, picked from the lookup, with 2 ordered and none received.

• Purchase order {Purchase-order-B} (for example PO-1002) at {Location-A} has a line for {Part-A}, picked from the lookup, with 1 ordered and fully received on vendor invoice {Invoice-A} (for example ZZ-COPO-INV-2).

• Purchase order {Purchase-order-C} (for example PO-1003) at {Location-A} has a line where {Part-A} was typed by hand and added as typed, with no link to the part, 1 ordered and none received.

• Purchase order {Purchase-order-D} (for example PO-1004) at {Location-B} has a line for {Part-A}, picked from the lookup, with 4 ordered and none received.

• The new number, {Number-A} (for example ZZAUTOTEST-PL-COPONEW-02), is unused and does not contain {Part-A}.

• The invoice number you will type when receiving is {Invoice-B} (for example ZZ-COPO-INV-1).

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Open the location switcher in the top bar. If it lists no second location, go to Settings → Locations, add a location (for example ZZAUTOTEST PL Loc 2) and Save, then go to Settings → Staff, open your Admin user, give it access to the new location and Save. The second location is {Location-B} (for example Staging Lethbridge - 4310).

3. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL CO PO) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-COPO-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with Quantity 3 and click Save.

4. Pick {Location-B}, create {Part-A} there the same way (typing the number exactly), then pick {Location-A} again.

5. Go to Parts → Vendors and add a vendor (for example ZZAUTOTEST PL COPO Vendor), then Save. This vendor is {Vendor-A}.

6. Go to Parts → Purchase Orders → New Purchase Order and pick {Vendor-A}. Add a line: type {Part-A} in Part Number and pick the result that shows an Inventory Qty, set Quantity 2 and save the order. The purchase order number shown is {Purchase-order-A} (for example PO-1001).

7. Go to Parts → Purchase Orders → New Purchase Order and pick {Vendor-A}. Add a line: type {Part-A} in Part Number and pick the result that shows an Inventory Qty, set Quantity 1 and save the order. The purchase order number shown is {Purchase-order-B} (for example PO-1002). Click Receive on it, fill the invoice number {Invoice-A} (for example ZZ-COPO-INV-2), cost 10.00, sell price 20.00 and received 1, and click Receive.

8. Go to Parts → Purchase Orders → New Purchase Order and pick {Vendor-A}. Add a line: type {Part-A} in full and choose the row that adds the number as typed (not the result with an Inventory Qty), set Quantity 1 and save the order. The purchase order number shown is {Purchase-order-C} (for example PO-1003).

9. Pick {Location-B}. Go to Parts → Purchase Orders → New Purchase Order and pick {Vendor-A}. Add a line: type {Part-A} in Part Number and pick the result that shows an Inventory Qty, set Quantity 4 and save the order. The purchase order number shown is {Purchase-order-D} (for example PO-1004). Then pick {Location-A} again.

10. Write down {Number-A} (for example ZZAUTOTEST-PL-COPONEW-02) and {Invoice-B} (for example ZZ-COPO-INV-1).

11. Check the setup worked: at {Location-A}, Purchase Orders lists {Purchase-order-A} and {Purchase-order-C} as not received and {Purchase-order-B} as received; at {Location-B}, {Purchase-order-D} is not received. Every line reads {Part-A}. Inventory at {Location-A} shows {Part-A} with 3 + 1 = 4 on hand.

Part 2. Setup for Claude session

• Switch location in the top bar, or with POST /api/iam/change-location (workplace_id and workplace_timezone, taken from GET /api/staff/my-workplaces).

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• Purchase orders: create them on screen and record each id from its address; GET /api/inventory/orders/<id> lists each item's part_number. Receiving goes through the Receive screen (Receive on the purchase order), which sends POST /api/inventory/orders/accept; the Receive button stays disabled until vendor, invoice number, part number, cost and a sell price above 0 are filled. Cost and invoice edits there are not kept if the screen is reloaded.

• Record each line's part_number before step 3 and after step 4 (GET /api/inventory/orders/<id>), so the four lines are compared by id, not by eye.

• Vendor invoices: a delivery is the vendor invoice (GET /api/inventory/deliveries); there is no /api/vendor-invoices.

• Trap: {Purchase-order-C} must hold the number typed by hand with no link; if the lookup's inventory result was picked, the line is linked and takes the new number, which is not this case.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
