Setup: Deleting a Part Library entry that a part uses is refused

Test case: C425620, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919). The Admin role has 'Part Library & Inventory → View / Create & Edit / Delete'.

• Part Library entry {Part-A} (for example ZZAUTOTEST-PL-INUSE-01) has the description {Description-A} (for example "ZZAUTOTEST PL in use") and no part behind it ("Total parts" 0) when the test starts.

• You can open a second browser tab on the same ShopView address, signed in as the same user.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location selector in the top bar.

2. Go to Parts → Inventory at {Location-A}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL in use") and a Part Number (for example ZZAUTOTEST-PL-INUSE-01), pick any Category (for example the first one offered), type a Cost (for example 10.00) and a Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 5 and click Save. The part number you typed is {Part-A}.

3. Open {Part-A} from the Active tab and click Delete Part (the part is on no work order, so it is deleted at once).

4. Go to Parts → Part Library and type {Part-A} in the Search box: the entry is still listed, because deleting an inventory part keeps its Part Library entry. Open it; its detail page shows "Total parts" 0. Its description is {Description-A} (for example "ZZAUTOTEST PL in use").

5. Check the setup worked: {Part-A}'s Part Library detail page shows "Total parts" 0, and Parts → Inventory does not list {Part-A}. If the entry is gone, repeat the setup with another part number.

Part 2. Setup for Claude session

• Create {Part-A} with the New Inventory Part dialog in Playwright exactly as Part 1 says (the most reliable route), or with POST /api/inventory/parts/create. • Deleting the inventory part keeps its Part Library entry (QA lead, 9 Oct 2026, set-up answer 4). UNVERIFIED: the delete request is POST /api/inventory/parts/delete (playbook, Inventory section). Record the entry's detail-page address and its id as {Library-entry-A id}.

• Use two pages in one Playwright browser context (same sign-in). Steps 7 to 14 create a part with exactly the entry's number in tab 2, which links it to the entry (an exact number links).

• Step 17: record whether the Delete button in tab 1 is still enabled before clicking (PRD v29 disables it while a part uses the entry; whether an open window updates without a reload is not stated). If it turned disabled, record that, then send POST /api/parts-catalogue/remove-catalogue-part?id={Library-entry-A id} (UNVERIFIED on this build) and record the refusal text word for word as Claude-only evidence.

• Run every step in the same Playwright browser and take a screenshot right after each step that has an expected result. Read on-screen words from the visible text, not from accessible names, and save the screenshots in the case's verification folder.

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
