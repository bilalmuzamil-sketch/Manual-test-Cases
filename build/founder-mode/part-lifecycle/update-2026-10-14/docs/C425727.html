Setup: Purchase order line lookup does not offer an inactive part

Test case: C425727, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), a role that has 'Part Library & Inventory → View', 'Create & Edit' and 'Delete'.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-POLOOK-01), with description {Description-A} (for example ZZAUTOTEST PL POLOOK PART A), is tracked at {Location-A} with 4 in its default bin and is inactive.

• Vendor {Vendor-A} (for example ZZAUTOTEST PL POLOOK Vendor) exists.

• Purchase order {Purchase-order-A} (for example PO-1234) for {Vendor-A} is open, not yet received, and holds one line for vendor part {Number-A} (for example ZZAUTOTEST-PL-POLOOK-VEND-01).

Part 1. Setup for manual QA tester

1. Sign in as an Admin (or Owner) and pick the location in the top-bar location switcher (for example Staging Heavy Duty - 9919). This location is {Location-A}; every step runs there unless it names another location.

2. Go to Parts → Vendors, click "New Vendor", type Name (for example "ZZAUTOTEST PL POLOOK Vendor") and click "Save & Close". This vendor is {Vendor-A}.

3. Go to Parts → Inventory and click "New Inventory Part". Type Description (for example ZZAUTOTEST PL POLOOK PART A) and Part Number (for example ZZAUTOTEST-PL-POLOOK-01). The part number you typed is {Part-A} and the description is {Description-A}.

4. Pick Category (for example Uncategorized), type Cost (for example 10.00) and Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 4 and click Save.

5. Go to Work Orders and click "New Work Order". In Customer click Add and create a customer (for example "ZZAUTOTEST PL POLOOK Customer"); in Asset click Add and create a unit (for example "ZZAUTOTEST-PL-POLOOK-UNIT"); click Create. The number shown at the top left (for example S2-15440) is {Work-order-1}.

6. On {Work-order-1} click "New Line", type Title (for example "ZZAUTOTEST PL POLOOK line") and click "Save & Close". This line is {Line-1}. Click "Approve" on {Line-1}.

7. On {Line-1} open the line's ⋮ menu, click "Request part", type a new number in Part Number (for example ZZAUTOTEST-PL-POLOOK-VEND-01) and press Tab, pick Source "Vendor", Category (for example Uncategorized), Vendor {Vendor-A}, Cost (for example 8.00) and Sell Price (for example 16.00), and click "Save Part". This number is {Number-A}.

8. On {Work-order-1} open the Parts tab and order {Number-A} with its "Order" action. Go to Parts → Purchase Orders: the new purchase order for {Vendor-A} holds {Number-A}. Its number is {Purchase-order-A}.

9. Set {Part-A} inactive: on Parts → Inventory, Active tab, search {Part-A}, click its row, pick Part Status "Inactive", click Save, leave "Note (Optional)" empty and click "Deactivate" in the "Deactivate part?" confirmation.

10. Check the setup worked: Parts → Purchase Orders lists {Purchase-order-A}, not yet received, with the {Number-A} line, and {Part-A} is on the Inactive tab only.

Part 2. Setup for Claude session

• Fastest reliable route: drive Part 1 in the browser with Playwright, using the labels in Part 1; no request shape below has been observed on a Part Lifecycle build.

• UNVERIFIED: after release a new part is created with POST /api/inventory/parts/create carrying partNumber, description and isTracked instead of catalogPartId (tech plan §5). Record the request the dialog sends and reuse it for further parts.

• UNVERIFIED: a status change is sent as PATCH /api/inventory/parts/status with partIds, status ("active" or "inactive") and note (tech plan §5), for the dialog and the bulk bar alike. Record what the confirmation sends.

• Part requests: POST /api/work-orders/part/make-request with line, work_order, quantity, part_source_type 'inventory', part_number, sell_price, cost and part_category_id (playbook §E); part_category_id is required. The UI route is the line's ⋮ → "Request part" dialog.

• UNVERIFIED: purchase order lines are added with POST /api/inventory/orders/add-item (tech plan §5); the PO screen's always-on offer row is suppressed only for the inactive match (tech plan §6 Phase 7). Observe the lookup text on screen.

• UNVERIFIED: the exact name of the purchase order's add-part control on this build; record the label you click.

• Evidence: take a screenshot at every step that has an expected result, and record the build marker before you start.

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
