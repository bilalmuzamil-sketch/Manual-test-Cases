Setup: A special order received at another location is not offered with its vendor

Test case: C573673, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin who can pick two locations in the location selector, {Location-A} (for example Staging Heavy Duty - 9919) and {Location-B} (for example Staging Lethbridge - 4310). The Admin role has 'Part Library & Inventory → View / Create & Edit / Delete'.

• Vendor {Vendor-A} (for example the first vendor in Parts → Vendors) exists.

• Within the last 12 months, {Location-B} received part number {Part-A} (for example ZZAUTOTEST-PL-SOOTHER-01) from {Vendor-A} on a special-order line of work order {Work-order-1} (for example S2-15440).

• {Location-A} never received {Part-A} and does not stock it.

• Work order {Work-order-2} (for example S2-15441) at {Location-A} is open, for a ZZAUTOTEST customer, with a line {Line-1} (for example "ZZAUTOTEST PL other location line").

Part 1. Setup for manual QA tester

1. Make sure the location selector lists two locations, {Location-A} (for example Staging Heavy Duty - 9919) and {Location-B} (for example Staging Lethbridge - 4310). If it lists only one, go to Settings → Locations, add a location (for example "ZZAUTOTEST PL Loc B") and save; then go to Settings → Staff, open your own staff record, give it access to the new location and save, and sign in again (saving a staff record signs that user out).

2. {Vendor-A} is any vendor listed under Parts → Vendors (for example the first one).

3. Pick {Location-B}. In the top bar click Work Orders, click New, and create a work order for a new customer (for example "ZZAUTOTEST PL other location customer") with an asset (for example unit "ZZAUTOTEST PL other location customer-UNIT"). The work order number shown (for example S2-15440) is {Work-order-1}. Add a line (for example "ZZAUTOTEST PL other location order line"), tick Line Approved, and click Save & Close.

4. On that line click + Add Part, type {Part-A} (for example ZZAUTOTEST-PL-SOOTHER-01; it must not exist anywhere yet) and pick the offer to add it as a new part, set Source to Vendor, pick any Category, pick {Vendor-A}, type Cost 10.00 and Sell Price 20.00 and click Save Part.

5. On the Parts tab of {Work-order-1} click Order on {Part-A}; then in Parts → Purchase Orders (still at {Location-B}) open that purchase order, click Receive, type an invoice number (for example ZZAUTOTEST-PL-INV-6) and quantity 1, and save the receipt.

6. Pick {Location-A}. Create a work order there the same way for a new customer (for example "ZZAUTOTEST PL other location customer A"), with one line (for example "ZZAUTOTEST PL other location line"). This is {Work-order-2} and its line is {Line-1}.

7. Check the setup worked: at {Location-B} the purchase order shows {Part-A} received; at {Location-A} Parts → Inventory does not list {Part-A}; Parts → Part Library lists {Part-A}; {Work-order-2} is open at {Location-A} with {Line-1}.

Part 2. Setup for Claude session

• Location ids come from GET /api/staff/my-workplaces (on staging Heavy Duty 9919 is b3c8c820-f815-4cf1-8938-10956c5ee71a and Lethbridge 4310 is f8a8b802-7780-4b16-bf10-343caeb616b2); switch with the top bar or POST /api/iam/change-location.

• Work orders: create them through the screens as Part 1 says, {Work-order-1} at {Location-B} and {Work-order-2} at {Location-A}; record each number and each id from the address bar ({Work-order-1 id}, {Work-order-2 id}).

• Order: the Order button on the work order's Parts tab sends POST /api/work-orders/part/perform-request-status-action with action "order" (playbook, Order / pick a part); UNVERIFIED that it shows only once the line is approved. Record it as {Purchase-order-A id}.

• Receive: the Receive Parts screen is /order/<purchase order id>?receive=1; the submit button stays disabled until vendor, invoice number, part number, cost and sell price are filled (playbook, Receive Parts screen driving).

• The lookup counts only numbers this location received (PRD v29, Product's 13 Oct answer 2). Run the steps with {Location-A} active. UNVERIFIED: the lookup reads GET /api/work-orders/part/request/inventory-parts-as-options-with-remaining-catalogue-parts (tech plan §5); record its rows for {Part-A} next to the screenshot of the result list.

• Run every step in the same Playwright browser and take a screenshot right after each step that has an expected result. Read on-screen words from the visible text, not from accessible names, and save the screenshots in the case's verification folder.

• Afterwards delete the work orders you created (playbook: uncomplete one first if it was completed); leave the ZZAUTOTEST parts.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
