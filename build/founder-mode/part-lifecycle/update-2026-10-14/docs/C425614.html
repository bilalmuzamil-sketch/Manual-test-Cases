Setup: A Part Library number over 50 characters is refused while on an open request

Test case: C425614, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919). The Admin role has 'Part Library & Inventory → View / Create & Edit / Delete'.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-LIBLEN-01) is active at {Location-A}.

• Work order {Work-order-1} (for example S2-15440) is open, for a ZZAUTOTEST customer.

• Its line {Line-1} (for example "ZZAUTOTEST PL lib length line") holds a part request for {Part-A}, not yet received.

• {Number-A} is a new number exactly 51 characters long (for example ZZAUTOTEST-PL-LIBLEN-01-XXXXXXXXXXXXXXXXXXXXXXXXXXX).

• {Number-B} is a new number exactly 50 characters long (for example ZZAUTOTEST-PL-LIBLEN-01-XXXXXXXXXXXXXXXXXXXXXXXXXX).

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location selector in the top bar.

2. Go to Parts → Inventory at {Location-A}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL lib length") and a Part Number (for example ZZAUTOTEST-PL-LIBLEN-01), pick any Category (for example the first one offered), type a Cost (for example 10.00) and a Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 5 and click Save. The part number you typed is {Part-A}.

3. In the top bar click Work Orders, click New, and in the New Work Order dialog use the Add button beside Customer to create a customer (for example "ZZAUTOTEST PL lib length customer") and the Add button beside Asset to create an asset for it (for example unit "ZZAUTOTEST PL lib length customer-UNIT"); click Save, and click Create if a confirmation appears. The work order number shown (for example S2-15440) is {Work-order-1}.

4. On {Work-order-1} click New Line, type a Title (for example "ZZAUTOTEST PL lib length line") and click Save & Close. This line is {Line-1}.

5. On {Work-order-1}, in the Parts row of {Line-1} click + Add Part; in New Part Request type {Part-A} in Part Number, pick the result that shows "Inventory Qty", set the quantity to 1 and click Save Part.

6. {Number-A} is ZZAUTOTEST-PL-LIBLEN-01-XXXXXXXXXXXXXXXXXXXXXXXXXXX (51 characters) and {Number-B} is ZZAUTOTEST-PL-LIBLEN-01-XXXXXXXXXXXXXXXXXXXXXXXXXX (50 characters); paste them into any text editor that shows a character count to make sure.

7. Check the setup worked: {Line-1} lists {Part-A}, not received, and the two numbers count 51 and 50 characters.

Part 2. Setup for Claude session

• Create {Part-A} with the New Inventory Part dialog in Playwright exactly as Part 1 says (the most reliable route), or with POST /api/inventory/parts/create. UNVERIFIED: on a Part Lifecycle build the tech plan says that request takes partNumber, description and isTracked in place of catalogPartId; record the body the dialog really sends before scripting it.

• Record each part's id, from the create response or from GET /api/inventory/parts?search=<part number>: {Part-A id} id for {Part-A}.

• Work order: create it through the screens as Part 1 says; record the number shown as {Work-order-1} and the work order id from the address bar as {Work-order-1 id}. A part request can also be added with POST /api/work-orders/part/make-request (playbook §E; part_category_id is required).

• Assert the two numbers' lengths in the script before typing them (len 51 and 50).

• Run every step in the same Playwright browser and take a screenshot right after each step that has an expected result. Read on-screen words from the visible text, not from accessible names, and save the screenshots in the case's verification folder.

• Afterwards delete the work order you created (playbook: uncomplete it first if it was completed); leave the ZZAUTOTEST parts.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
