Setup: An imported part with no bin location goes to the Unassigned bin

Test case: C573682, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example ZZAUTOTEST PL Loc Bins), with 'Part Library & Inventory → View / Create & Edit / Delete', See Financial Data, the Data Import setting and the Parts settings.

• {Location-A} has no bin location named "Unassigned" in Settings → Bin Locations.

• No part or Part Library entry has the number {Part-A} (for example ZZAUTOTEST-PL-UNASSIGNED-01) or {Part-B} (for example ZZAUTOTEST-PL-UNASSIGNED-02) in any upper and lower case or punctuation.

• Import file {File-A} (for example ZZ-PL-UNASSIGNED.csv) holds two rows that add {Part-A} and {Part-B}, each with quantity 0 and an empty Bin Location.

Part 1. Setup for manual QA tester

1. Sign in as an Admin.

2. Pick a location in the location switcher in the top bar and go to Settings → Bin Locations. If no bin location named "Unassigned" is listed, this location is {Location-A}. If one is listed, do not delete it: go to Settings → Locations, add a location (for example ZZAUTOTEST PL Loc Bins) and Save, go to Settings → Staff, open your Admin user, give it access to the new location and Save, pick the new location and check Settings → Bin Locations there. That location is {Location-A}.

3. Write down {Part-A} (for example ZZAUTOTEST-PL-UNASSIGNED-01) and {Part-B} (for example ZZAUTOTEST-PL-UNASSIGNED-02).

4. Go to Settings → Data Import → Inventory and download the template the screen offers. Make {File-A} with two rows: part number {Part-A} with description ZZAUTOTEST PL Unassigned A, and part number {Part-B} with description ZZAUTOTEST PL Unassigned B. Give both quantity 0 and category Uncategorized, and leave the Bin Location column (grid_location) empty in both. Fill any other column the template requires (for example a cost of 10.00). Save it (for example as ZZ-PL-UNASSIGNED.csv).

5. Check the setup worked: at {Location-A}, Settings → Bin Locations lists no "Unassigned" bin, and Parts → Inventory and Parts → Part Library show no row for {Part-A} or {Part-B}.

Part 2. Setup for Claude session

• Switch location in the top bar, or with POST /api/iam/change-location (workplace_id and workplace_timezone, taken from GET /api/staff/my-workplaces).

• The parts CSV import is Settings → Data Import → Inventory (needs the Data Import setting). Download the template the screen offers and use its column headers. The QA lead's 9 Oct example import file has the columns name, part_number, uom, quantity, min_qty, max_qty, grid_location, purchase_price, core_price, vendor, manufacturer, category and tags, and no sell price column; its grid_location is the screen's Bin Location. UNVERIFIED: that the name column is the description; record the template's real headers.

• Bin locations: Settings → Bin Locations (address /administration/bins; the PRD calls it Administration → Bin Locations). Record the list before step 1 and after step 3.

• Step 3: Record the import screen's whole result (rows added, updated, skipped or refused, and any message) with a screenshot, and read the parts afterwards with GET /api/inventory/parts?search=<number>.

• Steps 6 and 9: screenshot the Inventory section and record the switch "Track quantities and cost of goods". S7-N10 speaks of a tracked part; the tech plan of 7 Oct 2026 says the import never writes the tracking state, so a new imported part stays tracked (UNVERIFIED). If the switch is off, write it in the result comment.

• This matches the QA lead's 9 Oct set-up fact: a part imported with an empty Grid Location shows Bin Location "Unassigned", Quantity 0, "Default" in Edit Inventory Part.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
