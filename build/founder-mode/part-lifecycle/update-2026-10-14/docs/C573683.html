Setup: A linked entry whose manufacturer no longer exists takes the one picked

Test case: C573683, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• Part Library entry {Part-A} (for example a number found in data saved before the release), with the description {Description-A} (for example the description shown on its row), still points to a manufacturer that no longer exists in this organization.

• No other Part Library entry has exactly the number {Part-A}, with the same upper and lower case.

• {Location-A} stocks no part whose number matches {Part-A} once upper and lower case, hyphens, asterisks, periods and spaces are ignored.

• {Manufacturer-A} (for example the first name in the Manufacturer list) is a manufacturer offered in the Manufacturer list.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. This entry cannot be made on screen: manufacturers cannot be deleted in ShopView, so an entry that points to a missing manufacturer exists only in data saved before the release, and the cleanup that runs before the release may have removed them all. A Claude session finds one with Part 2 of this document and writes down its number as {Part-A} and its description as {Description-A}.

3. Go to Parts → Part Library, search {Part-A} and write down what its Manufacturer cell shows (for example empty).

4. Go to Parts → Inventory at {Location-A} and search {Part-A}, and the same number without hyphens, periods and spaces, on the Active and the Inactive tab. No row may show. If one does, pick another location that stocks none and use it as {Location-A}.

5. Open New Inventory Part, open the Manufacturer list, write down its first name as {Manufacturer-A}, and close the window with Cancel.

6. Check the setup worked: {Part-A} has been found and {Location-A} does not stock it. If no such entry exists on this build, mark the case Blocked with the comment "no Part Library entry points to a manufacturer that no longer exists on this build".

Part 2. Setup for Claude session

• Finding the entry (read only): page through the request the Part Library page sends and the organization's manufacturer list (the request behind the Manufacturer list of New Inventory Part). An entry qualifies when it carries a manufacturer id that matches no manufacturer in that list. UNVERIFIED: the field names; record them. The tech plan of 7 Oct 2026 says the link treats an id with no manufacturer row in the organization as missing.

• Prefer an entry whose exact number belongs to that entry only and that no location you use stocks; record {Part-A}, {Description-A}, the dangling manufacturer id and the workplaces its entry page lists.

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• Type the entry's own description at step 2, so no "Part created. Linked to …" message distracts from the manufacturer check.

• This case changes a pre-release entry on a test environment only (the entry gains a manufacturer) and never runs on production. After the run, delete the new part with Delete Part; the entry keeps its new manufacturer, so it cannot be reused for this case.

• Trap: if the Part Library list shows a name in the Manufacturer cell before the run even though that manufacturer no longer exists, record it; the expected result is still that the entry takes {Manufacturer-A}.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
