Setup: Each tab lists only the parts with that status at the current location

Test case: C425585, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin who can pick two locations in the location selector, {Location-A} (for example Staging Heavy Duty - 9919) and {Location-B} (for example Staging Lethbridge - 4310). The Admin role has 'Part Library & Inventory → View / Create & Edit / Delete'.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-LOCTAB-01) is active at {Location-A} and is not stocked at {Location-B}.

• Inventory part {Part-B} (for example ZZAUTOTEST-PL-LOCTAB-02) is stocked at both locations with the same part number: inactive at {Location-A} and active at {Location-B}.

• Both part numbers start with the same text, {Prefix-A} (for example ZZAUTOTEST-PL-LOCTAB).

Part 1. Setup for manual QA tester

1. Make sure the location selector lists two locations, {Location-A} (for example Staging Heavy Duty - 9919) and {Location-B} (for example Staging Lethbridge - 4310). If it lists only one, go to Settings → Locations, add a location (for example "ZZAUTOTEST PL Loc B") and save; then go to Settings → Staff, open your own staff record, give it access to the new location and save, and sign in again (saving a staff record signs that user out).

2. Pick {Location-A} in the location selector.

3. Go to Parts → Inventory at {Location-A}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL loc tab part A") and a Part Number (for example ZZAUTOTEST-PL-LOCTAB-01), pick any Category (for example the first one offered), type a Cost (for example 10.00) and a Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 5 and click Save. The part number you typed is {Part-A}.

4. Go to Parts → Inventory at {Location-A}, click New Inventory Part, type a Description (for example "ZZAUTOTEST PL loc tab part B") and a Part Number (for example ZZAUTOTEST-PL-LOCTAB-02), pick any Category (for example the first one offered), type a Cost (for example 10.00) and a Sell Price (for example 20.00), leave "Track quantities and cost of goods" on, set the default bin's Quantity to 5 and click Save. The part number you typed is {Part-B}.

5. Pick {Location-B} and create the same part there: New Inventory Part, the same Description and exactly the same Part Number {Part-B} (same upper and lower case), any Category, Cost (for example 10.00), Sell Price (for example 20.00), tracking on, default bin Quantity (for example 3), Save.

6. Pick {Location-A} again. Make {Part-B} inactive: on the Active tab type {Part-B} in the Search box, click its row, pick Part Status → Inactive, click Save, then click Deactivate in the "Deactivate part?" confirmation (leave Note (Optional) empty).

7. {Prefix-A} is the text both part numbers start with (for example ZZAUTOTEST-PL-LOCTAB).

8. Check the setup worked: at {Location-A} the Inactive tab searched for {Prefix-A} lists only {Part-B}; at {Location-B} the Active tab searched for {Prefix-A} lists only {Part-B}. If not, redo the last two steps.

Part 2. Setup for Claude session

• Create {Part-A} and {Part-B} at {Location-A}, and {Part-B} again at {Location-B} with the New Inventory Part dialog in Playwright exactly as Part 1 says (the most reliable route), or with POST /api/inventory/parts/create. UNVERIFIED: on a Part Lifecycle build the tech plan says that request takes partNumber, description and isTracked in place of catalogPartId; record the body the dialog really sends before scripting it.

• Location ids come from GET /api/staff/my-workplaces (on staging Heavy Duty 9919 is b3c8c820-f815-4cf1-8938-10956c5ee71a and Lethbridge 4310 is f8a8b802-7780-4b16-bf10-343caeb616b2); switch with the top bar or POST /api/iam/change-location.

• Record {Part-A id}, {Part-B id} for {Part-A} and {Part-B} at {Location-A}, and the id of {Part-B} at {Location-B} as {Part-C id} (one inventory part per location).

• Set {Part-B} inactive with PATCH /api/inventory/parts/status, body partIds [{Part-B id}], status "inactive", no note (UNVERIFIED: planned in the tech plan §5; then check the part shows on the Inactive tab), or through the part dialog as in Part 1. Run it while {Location-A} is the active location.

• Check: with {Location-A} active, GET /api/inventory/parts?search={Prefix-A}&status=inactive lists only {Part-B}; with {Location-B} active, status=active lists only {Part-B} (UNVERIFIED: status parameter from the tech plan §5).

• Run every step in the same Playwright browser and take a screenshot right after each step that has an expected result. Read on-screen words from the visible text, not from accessible names, and save the screenshots in the case's verification folder.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
