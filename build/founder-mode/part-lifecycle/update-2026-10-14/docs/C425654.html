Setup: A tracking change is refused for a user who has just lost the right to delete

Test case: C425654, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919); the Admin role has 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit' and 'Part Library & Inventory → Delete' and can see costs and prices.

• Staff member {User-D} (for example ZZAUTOTEST PL-REVOKE-TRACK) works at {Location-A} with the custom role {Role-D} (for example ZZAUTOTEST-PL-REVOKE-TRACK-ROLE), which starts with 'Part Library & Inventory → View', 'Part Library & Inventory → Create & Edit', 'Part Library & Inventory → Delete' and See Financial Data.

• {User-D} is signed in in a second browser window (for example a private window), and the Admin stays signed in in the first window.

• The Admin can cut {Role-D} down during the steps to 'Part Library & Inventory → View' only, with See Financial Data and every Settings permission unticked, so {User-D} becomes a user who cannot delete inventory parts while a screen is still open.

• Bin {Bin-A} is the default bin of {Location-A} (for example General Storage), the bin New Inventory Part fills in.

• Inventory part {Part-A} (for example ZZAUTOTEST-PL-REVOKE-TRK-01) is active and tracked at {Location-A}, with 2 in {Bin-A}.

• Parts → Inventory is open on the Active tab in {User-D}'s window.

Part 1. Setup for manual QA tester

1. Sign in as an Admin, pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar, and open Parts → Inventory on the Active tab.

2. Go to Settings → Roles & Permissions, click Create custom role, choose Skip (blank role) and type a Role name (for example ZZAUTOTEST-PL-REVOKE-TRACK-ROLE). This role is {Role-D}.

3. In the Part Library and Inventory group tick View, Create & Edit and Delete, also tick See Financial Data so costs and prices show, and click Create (the toast reads "Role created successfully.").

4. Go to Settings → Staff and add a staff member: First name ZZAUTOTEST, a Last name (for example PL-REVOKE-TRACK), an email inbox you can open (for example your own address with +plrevoketrk added before the @), Role {Role-D} and location {Location-A}; click Save. This staff member is {User-D}.

5. Open the invitation email in that inbox, accept it and set a password.

6. Open a second browser window (for example a private window) and sign in there as {User-D}, so the Admin stays signed in in the first window.

7. In the Admin window open Parts → Inventory.

8. Click New Inventory Part and note the bin the Inventory section fills in (for example General Storage); this is {Bin-A}, the location's default bin. Click Cancel.

9. Click New Inventory Part, type a Description (for example ZZAUTOTEST PL REVOKE TRACKING) and a Part Number (for example ZZAUTOTEST-PL-REVOKE-TRK-01), pick any Category (for example Uncategorized) and type Cost 5.00. This part is {Part-A}.

10. Leave Track quantities and cost of goods on and leave Min and Max empty.

11. In the Inventory section keep the bin row the dialog fills in ({Bin-A}) and set its Quantity to 2.

12. Click Save. The dialog closes.

13. Check the setup worked: in {User-D}'s window, {User-D} opens {Part-A} and the Track quantities and cost of goods switch can be clicked. Click Cancel.

Part 2. Setup for Claude session

• Why the cut removes See Financial Data and the Settings permissions too: the tech plan (D14, §9) says the server's delete right is also carried by Create & Edit, See Financial Data and Settings → Parts, so only a View-only role is a user who cannot delete inventory parts today.

• Create the parts through New Inventory Part with Playwright, exactly as Part 1 says. UNVERIFIED: the tech plan says the dialog now sends POST /api/inventory/parts/create with partNumber, description and isTracked (no catalogPartId); capture the body the dialog really sends once and reuse it for the other parts, recording the real field names. Create the part as the Admin.

• Record {Part-A id} and {Role-D id}.

• UNVERIFIED: Step 5 sends POST /api/inventory/parts/change with isTracked false; expect 403; record status and message.

• Trap: a 409 "Session has expired." means the session ended, not a permission refusal; record it as "not checked by hand".

• Trap: changing a role ends that user's session (409 "Session has expired."); sign in again and wait until GET /api/auth/me/fe-permissions shows the new set before you act.

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
