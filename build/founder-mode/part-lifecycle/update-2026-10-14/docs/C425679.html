Setup: With active and inactive matches, the active part's number is named

Test case: C425679, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin at {Location-A} (for example Staging Heavy Duty - 9919), with 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.

• You can switch to a second location, {Location-B} (for example Staging Lethbridge - 4310), in the location switcher in the top bar.

• Active part {Part-A} (for example ZZAUTOTEST-PL-BOTH-01) is stocked at {Location-A}.

• Inactive part {Part-B} (for example ZZAUTOTESTPLBOTH01) is also stocked at {Location-A}, on its own Part Library entry, and its number matches {Part-A} once upper and lower case, hyphens, asterisks, periods and spaces are ignored.

• The number you will type, {Number-A} (for example zz autotest pl both 01), matches both once upper and lower case, hyphens, asterisks, periods and spaces are ignored.

Part 1. Setup for manual QA tester

1. Sign in as an Admin and pick {Location-A} (for example Staging Heavy Duty - 9919) in the location switcher in the top bar.

2. Open the location switcher in the top bar. If it lists no second location, go to Settings → Locations, add a location (for example ZZAUTOTEST PL Loc 2) and Save, then go to Settings → Staff, open your Admin user, give it access to the new location and Save. The second location is {Location-B} (for example Staging Lethbridge - 4310).

3. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Both Active) and the Part Number {Part-A} (for example ZZAUTOTEST-PL-BOTH-01). This part is {Part-A}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with Quantity 3 and click Save.

4. Pick {Location-B} in the location switcher in the top bar.

5. Go to Parts → Inventory and click New Inventory Part. Type the Description (for example ZZAUTOTEST PL Both Second) and the Part Number {Part-B} (for example ZZAUTOTESTPLBOTH01). This part is {Part-B}. Pick any Category (for example Uncategorized), type a Cost (for example 10.00) and a Sell Price (for example 20.00), keep the default bin row with a Quantity (for example 3) and click Save. It gets its own Part Library entry, because its number is not an exact match of {Part-A}.

6. Pick {Location-A} in the location switcher in the top bar.

7. Go to Settings → Data Import → Inventory and download the template the screen offers. Fill one row: part number {Part-B}, typed exactly as you created it; description ZZAUTOTEST PL Both Second (the same description {Part-B} already has); quantity 1; category Uncategorized; leave the Bin Location column (grid_location) empty. Fill any other column the template requires (for example a cost of 10.00). Upload the file and run the import.

8. Why this works: the import first looks for a Part Library entry with the same number, ignoring only upper and lower case. It finds {Part-B}'s own entry, which {Location-A} does not stock yet, so it adds {Part-B} at {Location-A}. The specification names this as the one rare case where the import adds a second part whose number differs from a stocked part only by punctuation; the import does not refuse it. The new part goes into a bin named "Unassigned" because its Bin Location was left empty.

9. At {Location-A}, set {Part-B} inactive: on the Active tab type {Part-B} in the search, click its row, pick Inactive under Part Status, click Save, then click Deactivate in the "Deactivate part?" window. Then write down {Number-A} (for example zz autotest pl both 01).

10. Check the setup worked: at {Location-A}, type BOTH in the search. The Active tab lists {Part-A} (still with quantity 3) and not {Part-B}, and the Inactive tab lists {Part-B}. If the import refused the row, or updated {Part-A} instead (for example {Part-A}'s quantity changed and no {Part-B} row appeared), mark the case Blocked with the comment "the parts import did not add {Part-B} at {Location-A}, so two matching numbers could not be placed at one location".

Part 2. Setup for Claude session

• Switch location in the top bar, or with POST /api/iam/change-location (workplace_id and workplace_timezone, taken from GET /api/staff/my-workplaces).

• Create each part in the New Inventory Part window exactly as Part 1 says. UNVERIFIED: the tech plan of 7 Oct 2026 says POST /api/inventory/parts/create now takes partNumber, description and isTracked instead of a Part Library id; record the request the window really sends before scripting it, and use only that.

• The parts CSV import is Settings → Data Import → Inventory (needs the Data Import setting). Download the template the screen offers and use its column headers. The QA lead's 9 Oct example import file has the columns name, part_number, uom, quantity, min_qty, max_qty, grid_location, purchase_price, core_price, vendor, manufacturer, category and tags, and no sell price column; its grid_location is the screen's Bin Location. UNVERIFIED: that the name column is the description; record the template's real headers.

• Why the setup works (PRD v29): S7-N7 says the duplicate check of S7-N3 to S7-N6 does not apply to the parts import; §2 says the import matches a number ignoring upper and lower case first, and only when nothing matches does it also ignore hyphens, asterisks, periods and spaces; the context note under S7-N7 says the import can still add a second part whose number differs from a stocked part only by punctuation when the Part Library entry it matches is not the one stocked here (Product's answer of 13 Oct, question 3). So {Part-B}'s entry must exist (created at {Location-B}) before the import, and the row must carry {Part-B} exactly.

• UNVERIFIED on a build: Record the import screen's whole result (rows added, updated, skipped or refused, and any message) with a screenshot, and read the parts afterwards with GET /api/inventory/parts?search=<number>. If the import refuses the row, or updates {Part-A} instead of adding {Part-B}, that contradicts S7-N7 and its context note: record it as a possible deviation with the exact screen text, then use two parts that already matched at one location before the release if the environment has them, or mark the case Blocked.

• To set a part inactive quickly: UNVERIFIED, from the tech plan of 7 Oct 2026, PATCH /api/inventory/parts/status with partIds set to the part's id and status set to inactive; otherwise use the part window as Part 1 says.

• Messages: take a screenshot while each message shows and copy its text exactly, including any second, smaller line. Error messages that fade go away after about 3 seconds, so capture them at once.

• Step 6: the PRD (S7-N5a) requires the message to name the active part's number, {Part-A}; record the exact text and whether it names {Part-A} or {Part-B}.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
