
# SV-10380 — Inventory Value report ignores negative bins and overstates net inventory value (Ready to Fix, updated 2026-10-07)

## Summary

The Inventory Value report uses positive-bin availability rather than net recorded stock to calculate inventory value. It ignores negative bins when positive bins exist and omits parts with only negative quantities. This overstates the report relative to the recorded stock valuation and hides deficits that need correction.

## Reproduction

Code-derived scenarios to validate in QA; this investigation did not reproduce the issue in a running customer environment.

1. Use a non-core part at one location, costing $10 per unit.
2. Set its recorded bin quantities to +5 and -2. Verify the part's net recorded quantity is 3.
3. Open Inventory Value for the same location/current cutoff without restrictive category, vendor or search filters.
4. Observe quantity 5 and cost value $50 instead of net quantity 3 and $30.
5. Repeat with a part whose only bin quantity is -2. The report omits it instead of showing -2 and -$20.

| Recorded bin quantities | Current report quantity / cost | Expected report quantity / cost |
| --- | --- | --- |
| +5 and +3 | 8 / $80 | 8 / $80 |
| +5 and -2 | 5 / $50 | 3 / $30 |
| -2 only | Omitted / $0 contribution | -2 / -$20 |
| +5 and -5 | 5 / $50 | Net 0 / $0 contribution |

Accounting opening inventory uses the part's net recorded quantity, including negatives. The same stored stock can therefore produce different opening and report values even before category account mapping is introduced. These examples isolate quantity treatment; they assume the same unit cost, location and cutoff, with no other accounting activity.

## Expected behavior

Use the net sum of all bin quantities, including negatives, for Inventory Value report quantities and valuation. Include negative-quantity parts with their signed values. A net-zero part contributes zero; this bug does not mandate displaying a zero-quantity row.

Keep the shop-floor availability calculation unchanged. Availability for picking and financial valuation serve different purposes and must not share a positive-only rule merely for consistency.

Showing a negative balance does not certify that the stock records are physically correct. It exposes an unresolved deficit for correction instead of hiding it. Do not force accounting to match by discarding negatives or posting balancing journals.

## Acceptance criteria

- [ ] At $10 unit cost, +5 and -2 bins produce quantity 3 and cost value $30.
- [ ] A -2-only part appears with quantity -2 and cost value -$20 and reduces report totals accordingly.
- [ ] +5 and -5 bins contribute zero value, not $50.
- [ ] All-positive quantities retain existing results.
- [ ] Fractional quantities retain supported precision and existing monetary rounding rules.
- [ ] Report rows, aggregate totals, exports and newly captured snapshots use the same net quantity basis for the same scope and cutoff. Quantity-dependent displayed values use that same basis.
- [ ] Existing historical snapshots captured with positive-only quantities are explicitly addressed; changing the live calculation must not be described as repairing old captured values automatically.
- [ ] Existing location access, organization isolation and report filters remain enforced.
- [ ] The parts list's available-to-pick quantity and supply filters retain their existing behavior.
- [ ] Regression coverage verifies mixed-sign bins, negative-only stock, net-zero bins, all-positive stock and fractional quantities; replace report tests that encode positive-only valuation.

## Code evidence

Inspected core-MAIN and accounting-MAIN. Source findings and existing test expectations were reviewed; runtime verification remains for implementation.

**core-MAIN**

* `api/src/Reporting/Reports/Infrastructure/Persistence/Query/Dbal/InventoryValueBinsExpression.php:47`: sums only positive bins whenever any positive bin exists.
* `api/src/Reporting/Reports/Infrastructure/Persistence/Query/Dbal/DbalInventoryValueFetcher.php:695`: requires `bins.qty > 0`, excluding negative-only parts.
* Same report fetcher, line 370: quantity × purchase cost supplies the cost total.
* `api/src/Reporting/Reports/Infrastructure/Persistence/Repository/Doctrine/DbalInventoryValueSnapshotRepository.php`: snapshot capture uses the shared bin expression and the positive-quantity filter.
* `api/src/Inventory/Parts/Infrastructure/Persistence/Repository/Doctrine/DoctrinePartBinLocationRepository.php:202`: recorded quantity uses the sum of all bins.
* `api/src/Inventory/Parts/Domain/Service/PartBinQuantityAdjuster.php`: updates the part quantity from the full bin sum without clamping negatives.
* `api/src/Accounting/Outbox/Infrastructure/Doctrine/AccountingOnboardingSourceFetcher.php:766`: opening valuation uses recorded part quantity and includes nonzero negative quantities.

# SV-10814 — Part Lifecycle - Story 1 - Active and Inactive tabs on the Inventory list (Open, updated 2026-10-08)

## Summary

Split the Inventory list into Active and Inactive tabs so a shop works from a clean active list and can still find its retired parts.

## Context

Active and inactive are set per location. Every part that exists on release day is active, so nothing changes for a shop until someone retires a part.

## Requirements

* S1-R1: The Inventory list shows two tabs, Active and Inactive.
* S1-R2: Active is the selected tab when the page opens.
* S1-R3: The Active tab lists only parts that are active at the current location.
* S1-R4: The Inactive tab lists only parts that are inactive at the current location.
* S1-R5: Every part that exists on the day of release is active.
* S1-R6: Switching tabs clears any rows the user had ticked.
* S1-R7: Search, filters and sort work the same way on both tabs.
* S1-R8: The Active and Inactive tabs sit on their own line under the page title, above the search and filter row.
* S1-R9: Export in the actions menu exports the parts on the tab that shows: active parts from the Active tab, inactive parts from the Inactive tab.
* S1-R10: Cycle count is offered on both tabs. It counts the parts on the tab that shows, and the printed count sheet lists those parts.
* S1-N1: If there are no inactive parts at the location and no search or filter is narrowing the list, the Inactive tab shows "No inactive parts at this location."
* S1-N2: If a search or filter leaves the Inactive tab empty, it shows the list's standard filtered empty state.

## Acceptance Criteria

- [ ] Given the Inventory page, when it opens, then the Active tab is selected and lists only parts active at this location.
- [ ] Given parts were retired at this location, when the user opens the Inactive tab, then only those parts are listed.
- [ ] Given a location with no inactive parts and nothing typed in search or filters, when the user opens the Inactive tab, then it reads "No inactive parts at this location."
- [ ] Given a search that matches nothing on the Inactive tab, when it runs, then the list shows its usual filtered empty state, not the message above.
- [ ] Given rows ticked in bulk mode, when the user switches tabs, then the ticks clear.
- [ ] Given the Inactive tab is showing, when the user picks Export, then the file holds only inactive parts; from the Active tab it holds only active parts.
- [ ] Given the Inactive tab is showing, when the user starts a Cycle count, then it counts the parts on that tab and the printed count sheet lists them.

## UI/UX

Tabs sit on their own line under the page title, above the search and filter row. Empty Inactive tab message: "No inactive parts at this location."

Design: page 3, board 3.5; page 4, boards 4.2, 4.6 and 4.10

# SV-10815 — Part Lifecycle - Story 2 - Deactivate parts in bulk (Open, updated 2026-10-08)

## Summary

Let a parts manager retire many parts at once from the Inventory list, without deleting them.

## Context

Bulk status is a mode, the same pattern as Cycle count: the row keeps one click, and the mode changes what that click means. Failures stay ticked so the user can retry them.

## Requirements

* S2-R1: Bulk deactivation is a mode. The user turns it on from the Inventory actions menu, the three-dot button in the toolbar that holds Cycle count and Export.
* S2-R2: The menu entry reads "Deactivate parts" while the Active tab shows and "Activate parts" while the Inactive tab shows. Only one of the two shows at a time. It sits between Cycle count and Export.
* S2-R3: Outside the mode the Inventory list has no checkbox column, and a row click opens the part.
* S2-R4: Turning the mode on adds a checkbox column, 44px wide, at the left of the table, and scrolls the table back to its left edge so the column is in view.
* S2-R5: While the mode is on, a click anywhere on a row ticks or unticks that row instead of opening the part.
* S2-R6: The checkbox in the header ticks or clears every row loaded in the list. The list loads 30 parts at a time as the user scrolls, so it ticks only the rows loaded so far. The count in the bar shows exactly how many parts will change.
* S2-R7: While the mode is on, the bulk bar spans the full width of the list directly under the Active and Inactive tabs, and the search and filter row moves down under it.
* S2-R7a: In the light theme the bulk bar is near-black (#121926), the count is white, and the word "selected" is light grey. In the dark theme the bar is white and its text is dark. Its corners are rounded 8px.
* S2-R7b: From left to right the bar shows: the number of ticked rows in a round badge followed by the word "selected", a thin divider, and a blue button reading "Deactivate". The number updates as the user ticks.
* S2-R8: The Deactivate button is disabled while no row is ticked. Hovering it then shows "Tick the parts to deactivate".
* S2-R8a: One change takes at most 200 parts. With more than 200 rows ticked, the Deactivate button is disabled, and hovering it shows "Select 200 parts or fewer."
* S2-R9: An X button sits at the right end of the bar. Hovering it shows "Clear selection", which is also its screen reader label.
* S2-R9a: The X leaves the mode, clears the selection and puts the toolbar back to its normal state.
* S2-R10: Search, the filter bar, sorting and paging keep working while the mode is on, as they do in Cycle count.
* S2-R10a: Changing the search term or a filter clears the ticks, so the user only ever changes parts they can see. Sorting keeps them.
* S2-R10b: While the mode is on, the actions menu offers only Export. Cycle count and the bulk entry come back when the mode ends.
* S2-R11: When the user confirms (Story 10), every ticked part becomes inactive.
* S2-R12: The deactivated parts leave the Active tab without a page reload.
* S2-R13: The deactivated parts appear on the Inactive tab.
* S2-R14: When every ticked part changes, the mode ends and the selection clears.
* S2-R15: When some parts fail, the mode stays on and the selection keeps only the parts that failed.
* S2-R16: Switching between the Active and Inactive tabs ends the mode and clears the selection.
* S2-R17: A part's core becomes inactive together with the part, in the same change.
* S2-N1: With nothing ticked, the Deactivate button is visible but disabled, so the confirmation cannot open.
* S2-N2: Outside the mode there is no checkbox column, so no part can be ticked from the default list.
* S2-N3: A core cannot be set active or inactive on its own. Asked to, the system refuses it with "A core follows its part. Activate or deactivate the part instead."
* S2-E1: If a part being set inactive sits on an open work order, the change still goes through.
* S2-E2: That part stays on the open work order.
* S2-E3: The part's work order and invoice history does not change. The status change is recorded in the part's own history (Story 10).
* S2-E4: Cycle count and bulk status mode cannot both be on. While Cycle count runs, the actions menu is replaced by the count controls, so the bulk status entry cannot be reached until the count is saved or discarded. While bulk status mode is on, the menu does not offer Cycle count (S2-R10b).

## Acceptance Criteria

- [ ] Given a user with the Delete permission on the Active tab, when they open the actions menu, then "Deactivate parts" sits between Cycle count and Export.
- [ ] Given the mode is on, when the user clicks anywhere on a row, then the row ticks instead of opening the part, and clicking again unticks it.
- [ ] Given nothing is ticked, when the user hovers Deactivate, then it is disabled and shows "Tick the parts to deactivate".
- [ ] Given more than 200 rows ticked, when the user hovers Deactivate, then it is disabled and shows "Select 200 parts or fewer."
- [ ] Given rows are ticked, when the user changes the search term or a filter, then the ticks clear; when they change the sort, the ticks stay.
- [ ] Given the mode is on, when the user opens the actions menu, then only Export is offered.
- [ ] Given two parts ticked, when the user confirms, then "2 parts updated." shows, both parts leave the Active tab without a reload, appear on the Inactive tab, and the mode ends.
- [ ] Given one of the ticked parts cannot change, when the user confirms, then the toast names it with its reason and stays, the mode stays on, and only that part stays ticked.
- [ ] Given a part with a core is deactivated, when the change is applied, then its core becomes inactive too.
- [ ] Given the user clicks the X on the bar, when the mode ends, then the ticks clear and the toolbar is back to normal.

## UI/UX

Bulk bar under the tabs: count badge, "selected", divider, blue Deactivate button, X at the right. Near-black (#121926) in the light theme, 8px corners.

# SV-10819 — Part Lifecycle - Story 6 - Search and sort the Inventory list by tracking state (Open, updated 2026-10-08)

## Summary

Let a parts manager find untracked parts with search and sort, without scrolling the whole list.

## Context

Only the words "not", "tracked" and "not tracked" search on tracking state, so short fragments never pull in every untracked part.

* S6-R3: The Total Quantity column can be sorted.
* S6-R4: When that column is sorted, untracked parts sit below every tracked part, in both sort directions.

# SV-10826 — Part Lifecycle - Story 13 - The part dialog (Open, updated 2026-10-08)

## Summary

One dialog to set up a part, correct its number or description, and set its status, so every change to a part happens in one place and keeps its history.

## Context

The number and description live on the shared Part Library entry, so editing them at one location changes them everywhere the part is stocked; the dialog says so before the save. A rename keeps the part, its history and every line that holds it.

## Requirements

* S13-R1: The dialog is titled "New Inventory Part" when creating a part and "Edit Inventory Part" when editing one.
* S13-R2: The title row has a thin line under it, and the close X at its right end.
* S13-R3: When editing, the title row shows the part's saved status as a pill beside the close X: "Active" in green, or "Inactive" in grey.
* S13-R4: The fields appear in this order: Description, Part Number, Part Status (editing only), Vendor, Category, Manufacturer, Average Cost (editing) or Cost (creating), Sell Price, Core Charge, Inventory Tracking (the switch, then Min and Max), Tags, and Inventory (bin locations, then "Add Bin Location").
* S13-R4a: Vendor is hidden where the screen that opens the dialog hides it. Cost, Average Cost, Sell Price and Core Charge show only to a user who can see financial data. Min and Max show only while tracking is on (S4-R5).
* S13-R5: "Add Bin Location" has a plus icon before its label.
* S13-R6: The footer has a thin line above it. "Delete Part" sits at its left; Cancel and Save sit at its right.
* S13-R7: "Delete Part" is the design system's danger button: red, with a white trash icon and white label.
* S13-R8: Cancel is the design system's secondary button: white, with a grey outline and dark label. It closes the dialog without saving.
* S13-R9: Save is the design system's primary button: blue, with a white label.
* S13-R10: Delete Part is shown only when editing, to a user with the 'Part Library & Inventory → Delete' permission.
* S13-R11: When editing, Description and Part Number are plain text fields holding the part's current values.
* S13-R12: When the user changes the description and at least one other location stocks the same Part Library entry, the dialog shows, under the field, "This also changes the description at {n} other locations.", or "This also changes the description at 1 other location." for one.
* S13-R13: That message shows only while the typed description differs from the saved one, ignoring spaces before and after it.
* S13-R14: Saving a changed description changes the part's Part Library entry, so every location that stocks the part shows the new description.
* S13-R15: A changed description also renames the part's core, which reads "Core for {description}".
* S13-R16: When the user changes the part number and at least one other location stocks the same Part Library entry, the dialog shows, under the field, "This also changes the part number at {n} other locations.", or "This also changes the part number at 1 other location." for one.
* S13-R17: That message shows only while the typed number differs from the saved one, ignoring spaces before and after it. Parts at other locations count whether they are active or inactive.
* S13-R18: Saving a changed number renames the part in place. The part keeps its identity, its history, and every line that holds it. Its Part Library entry is renamed with it, and its core takes the same number. No new Part Library entry is created.
* S13-R19: A rename carries over to open work that holds this part, at every location: purchase order lines not yet fully received, part requests not yet received or returned, canned jobs, and returns that are not completed take the new number. Receiving, ordering, applying a canned job and returning then find the renamed part.
* S13-R19a: A line that only shares the old number, typed in by hand with no link to this part, keeps its number.
* S13-R20: When editing, a "Part Status" choice offers two options, Active and Inactive, set to the part's saved status. A user without the 'Part Library & Inventory → Delete' permission sees the choice disabled.
* S13-R21: Picking a different status changes nothing until Save. When Save is pressed with a different status picked, the confirmation of Story 10 opens first.
* S13-R22: Confirming saves every change in the dialog, then applies the status, and closes the dialog with "Part deactivated." or "Part activated.".
* S13-R23: Cancelling the confirmation saves nothing and returns to the dialog with the picked status kept.
* S13-R24: Saving with the saved status picked saves the part with no confirmation.
* S13-R25: The title row pill shows the saved status, not the picked one.
* S13-R26: Delete Part deletes the part and closes the dialog. It asks for no confirmation.
* S13-R27: When the part sits on a work order, Delete Part does nothing and hovering it shows "Please delete related work order parts first."
* S13-R28: When the part has a return or credit that is not completed, Delete Part does nothing and hovering it shows "Please complete or cancel the related return or credit first."
* S13-N1: If another Part Library entry already answers to the typed number, the save is refused, the dialog stays open, and the system shows "Part number {number} already belongs to another part in the Part Library." The match ignores upper and lower case, hyphens, asterisks, periods and spaces.
* S13-N2: An empty Description shows "Description is a required field" and an empty Part Number shows "Part number is a required field". The part is not saved.
* S13-N3: Saving with the number unchanged changes nothing about the number, the Part Library entry or open work.
* S13-N4: If the status change is refused after the save, the confirmation stays open and the system shows "This part could not be deactivated" or "This part could not be activated", with the reason.
* S13-N5: If saving the form is refused while the confirmation is open, the confirmation closes, the dialog shows the refusal, and nothing is saved.
* S13-N6: If Delete Part reaches the system while the part sits on a work order, or has a return or credit that is not completed, the delete is refused with "Inventory part that has a work order part cannot be deleted." or "Inventory part with an open return or a pending credit cannot be deleted." Only that message is shown.
* S13-E1: Re-importing a part through the parts CSV import with its old number creates a separate part under the old number. Re-pointing a part onto a different Part Library entry is not possible from the dialog. Both are handled by the merge and duplicate tool (Out of scope).

## Acceptance Criteria

- [ ] Given a part stocked at two locations, when the user changes its description, then "This also changes the description at 1 other location." shows under the field, and goes away if the original text is typed back.
- [ ] Given the same part, when the user changes its number and saves, then the part is renamed in place at both locations, keeps its history, and no new Part Library entry is created.
- [ ] Given an open purchase order line linked to the part, when the part is renamed, then the line shows the new number; a hand-typed line with the old number and no link keeps its number.
- [ ] Given another entry already answers to the typed number, when the user saves, then it is refused with "Part number {number} already belongs to another part in the Part Library." and the dialog stays open.
- [ ] Given Inactive picked and the form edited, when the user confirms, then the edits save, the part is retired, and "Part deactivated." shows.
- [ ] Given the save of the form is refused while the confirmation is open, when that happens, then the confirmation closes, the dialog shows the refusal, and nothing is saved.
- [ ] Given the part sits on a work order, when the user hovers Delete Part, then it shows "Please delete related work order parts first." and does nothing; if a delete still reaches the system, only the system's refusal message shows.
- [ ] Given the title row, when the dialog opens, then the pill shows the saved status, not the one picked in the form.

## UI/UX

Built from the design system's Modal and Button: danger Delete Part with a trash icon, secondary Cancel, primary Save; status pill in the title row.
