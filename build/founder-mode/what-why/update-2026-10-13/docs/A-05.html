Setup: A ShopCoach line reads Title - Description in the Customer Invoice report

Test case: (new case), Founder Mode / What/Why. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Admin (all permissions) at {Location-A} (for example Staging Heavy Duty - 9919) on the What/Why QA build.

• Require Tech Story (Settings, Work Orders tab) is off.

• Customer {Customer-A} (for example ZZAUTOTEST-WW-A05 Fleet) has a contact person and an asset, {Asset-A} (for example ZZAUTOTEST-WW-A05 Truck).

• Work order {Work-order-1} (for example S2-15440) is open for {Customer-A} and {Asset-A} at {Location-A}, not invoiced.

• {Work-order-1} has a line {Line-1} added from the ShopCoach line builder, with no tech story, whose title {Title-A} (for example Inspect brakes) and description {Description-A} (for example Customer reports grinding) were written down when it was added.

• {Work-order-1} has been completed and invoiced as invoice {Invoice-A} (for example 10234), dated {Invoice-date-A} (for example 13 Oct 2026).

Part 1. Setup for manual QA tester

1. Sign in to the What/Why QA build as an Admin and pick the location you will use in the top bar (for example Staging Heavy Duty - 9919). This is {Location-A}.

2. Open Settings, go to the Work Orders tab, write down whether Require Tech Story is on or off, then turn Require Tech Story off and click Save Settings.

3. Open Customers and create a customer named (for example) ZZAUTOTEST-WW-A05 Fleet, with one contact person (for example Pat Tester). This is {Customer-A}.

4. On {Customer-A}, add an asset (for example a truck named ZZAUTOTEST-WW-A05 Truck, 2018 Freightliner Cascadia). This is {Asset-A}.

5. Open Work Orders and click New Work Order. Choose {Customer-A} and {Asset-A} and click Create.

6. Write down the work order number the app shows (for example S2-15440). This is {Work-order-1}.

7. If the work order has no contact, set it to {Customer-A}'s contact person and answer YES when asked to keep that contact for the asset. If it asks for mileage, enter any number (for example 123456).

8. Make sure {Asset-A} has a year, make and model (for example 2018 Freightliner Cascadia).

9. On {Work-order-1}'s Lines tab click New Line, then AI SHOPCOACH LINE BUILDER. Describe a job (for example brakes grinding) and click Build Lines.

10. Add the first suggested line to the work order. This is {Line-1}. Open it in Edit Line and write down its Title as {Title-A} and its Description as {Description-A}; close without saving.

11. If {Line-1} shows an Approve button, click Approve.

12. Complete {Line-1} (for example from the line's status menu). No tech story is asked for and none is written. If the app insists on one, Require Tech Story is still on: go back and turn it off.

13. Set {Work-order-1}'s status to Complete (do the Review step first if the app asks for it).

14. Open the Finance tab and click Create Invoice. Close the New Customer Payment window without taking a payment.

15. Write down the invoice number (for example 10234) and its date (for example 13 Oct 2026). These are {Invoice-A} and {Invoice-date-A}.

16. Check the setup worked: {Work-order-1} shows the status Invoiced, the Finance tab shows {Invoice-A}, and {Line-1}'s Title and Description read exactly as typed and no tech story was written. If Create Invoice does nothing or fails, the usual reason is a missing contact person or an unreceived part; fix it and invoice again. Change nothing on the line after invoicing: the report uses the values the invoice was created with.

Part 2. Setup for Claude session

• Build: the What/Why QA build, app https://sv10130.qa.shopview.com; its API host follows the playbook pattern https://sv10130api.qa.shopview.com (UNVERIFIED for this branch: record that the API root answers). QuickBooks steps run on https://qb1.qa.shopview.com, which runs the same code against the sv10130 backend (SV-10130 developer comment, 8 Oct 2026). Sign in as admin unless the case says otherwise.

• Require Tech Story is organisation-wide: read its value first (Settings, Work Orders tab), set it for this case and restore it at the end, because other cases on the same build depend on it. The UI Save Settings click sends POST /api/organizations/settings/change (body UNVERIFIED: capture it from the click and record it).

• Create {Customer-A} in the UI (Customers, New Customer) with one contact person; read {Customer-A id} and {Contact-A id} from GET /api/customers/view/{Customer-A id} (data.company.contacts). A work order with no contact person cannot be invoiced (invoices/create answers 500).

• Create {Asset-A} on {Customer-A} in the UI and record {Asset-A id}; record {Location-A id} from GET /api/staff/my-workplaces.

• Fastest work order: POST /api/work-orders/create with company_id {Customer-A id}, customer_id {Contact-A id}, vehicle_id {Asset-A id}, workplace_id {Location-A id}, start_date today and is_vehicle_here true. The response key is work_order_id: record it as {Work-order-1 id}. Only a freshly created work order reliably opens on its Lines tab.

• ShopCoach is an AI service: suggestions differ run to run, so record the suggested title and description you used. UNVERIFIED: the exact name of the input box and of the button that adds suggested lines to the work order; record them.

• Trap (Jira SV-10131 developer comment): the editors open when you click a suggested line's title or description cell.

• Mileage, if needed: POST /api/work-orders/change-mileage with work_order_id and mileage as a STRING (a number answers 500).

• Tech story: POST /api/work-orders/lines/change-story with line_id {Line-1 id}, tech_story and work_order_id {Work-order-1 id}. Complete the line with POST /api/work-orders/lines/change-status (status complete), then POST /api/work-orders/change-status with id {Work-order-1 id} (the key is id, not work_order_id) and status complete; walk approved, in_progress, ready_for_review first if a jump is refused.

• Invoice: POST /api/invoices/create with work_order_id {Work-order-1 id}; record invoice_id as {Invoice-A id}, and the number and date the Finance tab shows as {Invoice-A} and {Invoice-date-A}.

• Trap: the invoice copies the line values when it is created (tech plan section 2: the report reads the frozen invoice copy), so set Title, Description and tech story before Create Invoice.

• Report: GET /api/reporting/export/customer_invoice (needs Invoicing & payments - View). Its query parameters are UNVERIFIED: capture them from the browser download and record them. UNVERIFIED: whether Export Reports sits on the Reports page (SV-10132 developer comment) or under Administration (tech plan Phase 1); record which.

• Read the CSV with Python (csv module, encoding utf-8). The labor line's text is in the ItemDescription column (tech plan section 5 and the SV-10132 developer comment). UNVERIFIED: which column identifies the invoice; record it. Compare with == against the expected string and record len(text) and len(text.encode('utf-8')).

• Evidence: keep the downloaded CSV, a screenshot of the row, and the comparison output in the case's verification folder.

• Expected string: {Title-A} + ' - ' + {Description-A}. Trap: if the AI title starts with =, +, - or @, a spreadsheet may open it as a formula (SV-10132 developer known gap); read the raw CSV with Python in that case.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
