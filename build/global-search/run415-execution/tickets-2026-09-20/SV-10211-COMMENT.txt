h3. The example this ticket was raised on

!REG2-final.png|width=760,height=513!

*Actual Result:* both names are scored *1.00* — identical to the last digit — so the stronger kind of match earns no advantage at all. That is the exact fault this ticket described.
*Expected Result:* the name that begins with the typed text scores higher than the one that merely contains it.

h3. What changed between then and now

* *18 September*, build {{v26.36.7-069b8c2}} — the two were separated and the correct one ranked first. Checked twice and recorded as passed, which is why this ticket was closed.
* *20 September*, build {{v26.36.8-d146c39}} — both score 1.00 and the advantage is gone.

The change for SV-10161 was deployed between those two dates. It raised the credit given to a match on a record's own name so far that such a match now reaches the maximum score on its own, which leaves no room for the difference between these two kinds of match to show. The wider effect is written up in SV-10277.
