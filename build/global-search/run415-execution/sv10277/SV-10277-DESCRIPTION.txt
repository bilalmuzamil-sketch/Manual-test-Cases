*Split from SV-10161.*

----

h3. Description

After the fix for SV-10161, direct name matches are correctly ranked above matches found through secondary fields.

However, results with a direct name match now frequently receive the *same maximum score*, which prevents the other ranking signals defined in the PRD from affecting their order.

Global Search is no longer distinguishing between:

* parts that are in stock and parts that are out of stock
* a name that *begins* with the search text and one that merely *contains* it
* results that should receive different importance and recency signals

h3. Steps to Reproduce

h4. Example 1 — stock is not affecting ranking

# Open Global Search ({{Ctrl}}+{{K}})
# Search {{shoe}}
# Open the *Parts* tab

!SIMPLE1-parts-v4.png|width=760,height=785!

*Actual:* all 20 parts receive the same score, including the 7 that show *0 Available*.
*Expected:* an in-stock part receives a ranking signal the out-of-stock ones do not, so stock availability is able to affect the order.

{quote}Parts. In stock (>0) → +0.20; bin location present → +0.05; sold/used in last 30 days (frequency, log-scaled) → up to +0.15; viewed recently → +0.10.{quote}

h4. Example 2 — match strength is not affecting ranking

# Open Global Search ({{Ctrl}}+{{K}})
# Search {{mobile}}
# Open the *Customers* tab

!SIMPLE2-companies-v4.png|width=760,height=850!

*Actual:* {{Mobile Truck & Trailer Repair Island Lake}} and {{Henderson Mobile Truck Repair}} receive the same score.
*Expected:* the PRD separates these two kinds of match, so they should not receive identical scores.

{quote}Prefix match on primary name field → +0.70.{quote}
{quote}Whole-word match anywhere in indexed fields → +0.50.{quote}

h4. Example 3 — multiple result types reach identical scores

# Open Global Search ({{Ctrl}}+{{K}})
# Search {{truck repair}}
# Review the result tabs

!SIMPLE3-everything-v4.png|width=760,height=849!

*Actual:* all 20 rows receive an identical score in *Work orders*, *Customers*, *Vendors*, *Part sales*, *Purchase orders* and *Vendor invoices*, and all 20 in *Assets* receive an identical score to each other. Their displayed order is then determined by the recency tie-break.
*Expected:* ranking combines match quality with the entity's own recency and importance signals, and the recency tie-break decides the order only where the final scores genuinely tie.

{quote}Each candidate gets a numeric score combining match quality and entity-specific recency/importance signals.{quote}
{quote}The score is clamped to a sane range; ties are broken by recency (most recently updated wins).{quote}

h3. Technical Finding

QA observed that the maximum score is *1.00*, and that it is a real maximum rather than the highest score of the day: across 230 results nothing exceeded it, and other searches finish well below it — the customers returned for {{brake}} reach only 0.32.

Direct-name scoring appears able to reach 1.00 from match scoring alone, which leaves no room for the further PRD signals to change the final score. This explains the behaviour above; it is offered as a QA observation, not as the prescribed implementation.

h3. Documentation Gap

PRD 6.1 still gives the bonus for a match on the primary display name as *+0.10*. QA measured the bonus applied by the product as *at least +0.50*, on a pair of customers identical apart from whether the search text sits in the name or in the address. Whichever value is intended, the PRD and the product currently disagree.

h3. Regression Context

This ranking behaviour appeared after the SV-10161 fix. *The SV-10161 behaviour itself is correct and should remain:* a customer's own name should rank above a match found only through contact information. That was re-checked across 20 person-name searches and 230 customer rows and was correct every time.
