# Every tab checked — and the earlier comment on SV-10211 was wrong

The QA lead: *"SV-10211 was for a behavior for the Customer tab … SV-10211 is still FIXED for the
customer's tab … you need to check with all tabs and have to create 1 ticket for all the tabs showing
the same behavior."*

## My mistake, and why it was a mistake
I commented on SV-10211 claiming it had regressed, using a **Vendors** example taken from ordinary
data where the two companies differ in how busy they are. §6.1 counts those signals, so a name that
merely contains the word can legitimately outrank one that begins with it when it is the busier
record — **my example proved nothing.** The comment was replaced with a correction and its two
pictures deleted. **SV-10211 is fixed; its own controlled trio still returns the right order.**

Worse, my first sweep classified pairs by the API's own `match.kind` labels rather than by whether the
name literally begins with the query — which is why `Continental Fleet Services` was counted as a
"begins with" row for the query `service`. It does not begin with it.

## The fair test, and how it was built
A name-strength comparison is only valid when **every other signal is equal**, so nothing reaches the
score ceiling for an unrelated reason. Two parts were created for it:

| Part | Name | Part number | Stock | Bin | Sold | Viewed |
|---|---|---|---|---|---|---|
| A | `ZZTABQ Wheel Seal` — **begins** with the query | `PQ-7001` | 0 | shared | never | never |
| B | `Cooper ZZTABQ Cartridge` — query **inside** the name | `PQ-7002` | 0 | same | never | never |

The part numbers deliberately carry **no** trace of the query — a first attempt used `ZZTABP-3001`
and both rows matched on the part **number** as an identifier, which measured nothing.
(`ZZTABP-3001`/`3002` remain on the branch as the discarded first attempt.)

## Result — one tab only

| Tab | Name that BEGINS with the typed text recognised as the stronger match? | Evidence |
|---|---|---|
| Customers | **yes** — `prefix on name` | controlled trio `ZZPREFIX`, and real data `fleetwise` |
| Vendors | **yes** — `prefix on name` | `ZZTOGVEN`, and real data `stillwater` |
| Assets | **yes** — `prefix on make` | real data `mobile` → `Mobile Wagon` |
| **Parts** | **NO** — recorded as `word on description` | **controlled pair `ZZTABQ`**, and real data `brake` |
| Work orders · Part sales · Purchase orders · Vendor invoices | not applicable — found by number, matched exactly | 40 / 12 / 36 / 15 lists swept, no wrong ordering |

**So it is one tab, not all of them.** Raised as **SV-10279** (parent **SV-9164**, *Matching pipeline*,
read live as **TESTING QA**), with the controlled pair, the Customers comparison alongside it, the
tab-by-tab table, both §6.1 sentences and §4's definition of a part's displayed name quoted verbatim,
and C55707 / C55724 with their run link.

## The lesson
**A ranking comparison is only evidence when every other signal is held equal.** Real data almost never
holds them equal, and the score ceiling hides the difference anyway. Seed the pair, or say nothing.
Learning **L0174**.
