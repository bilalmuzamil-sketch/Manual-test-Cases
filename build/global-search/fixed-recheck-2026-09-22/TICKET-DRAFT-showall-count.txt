h3. Description

The *Show all* control on a search group heading is required to carry the number of results behind it, so the person can see how many more there are before clicking. It carries no number at all - it reads only {{Show all}}.

The control itself is correct in every other respect. It appears on a group with more than five results, it stays away from a group with five or fewer, and it is there for every kind of record. Only the count is absent.

For example, on one search:

* {{Work orders (20)}} - heading shows 20, the control beside it reads *Show all*
* {{Assets (17)}} - heading shows 17, the control beside it reads *Show all*
* {{Parts (6)}} - heading shows 6, the control beside it reads *Show all*

The requirement's own worked example is a search matching thirty-four work orders: the tab reads {{Work Orders (20)}} and the control reads *{{Show all 20}}*.

h3. Steps to Reproduce

# Open global search and type a word that several kinds of record share, so that at least one group comes back with more than five results.
# Look at the heading of a group with more than five results.
#* the heading carries its own count, for example {{Work orders (20)}}
#* the control on the right of it reads {{Show all}}, with no number
# Look at a group whose count is not twenty - for example a group of six - so the missing number cannot be confused with the twenty on the tab.
#* the same: {{Show all}}, no number

*Actual Result*

The control reads {{Show all}}. No group's control carries a number - checked on four groups in one search, counting twenty, twenty, seventeen and six.

*Expected Result*

The control reads {{Show all N}}, where N is that group's count and never reads higher than twenty - {{Show all 20}}, {{Show all 17}}, {{Show all 6}}.

h3. Sources

*Global Search - Product Requirements*, Confluence page 576978945, version 17 (v1.5 in the body), read live on 22 September 2026.

Section 5.2, Typing / results:

{quote}Below the tab strip, results are grouped by entity type with a count: Work orders (12), Customers (2), etc. Each group shows up to 5 results (raised from today's 3). When a group has more, a Show all N link appears to the right of the group header.{quote}

Section 5.2, counts:

{quote}Counts are capped at 20. No count in the modal reads higher than 20 - not a tab, not a group header, not the Show all N link. A query matching 34 work orders shows Work Orders (20) and Show all 20. Twenty is both what search returns per entity type and what it reports.{quote}

Section 8, what the system must do:

{quote}expose the Show all N link, which switches the modal to that entity's scope tab, and cap the scoped list at 20 rows scrolled inside the modal with no further loading{quote}

h3. Two things this will be challenged on, answered in advance

*"The number is there, it just did not render in your reading."* It is not. The control is a {{button}} and its own text was read directly, twice, on a settled panel, and both readings were identical. The group heading immediately beside it renders its own count correctly in the same reading - which is what shows the number is absent rather than unread.

*"You were looking at the tab's twenty."* No. Two of the four groups checked counted seventeen and six, so a number in their controls could not have come from the tab.
