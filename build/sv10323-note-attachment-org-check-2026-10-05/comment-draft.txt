I tested this on the QA branch [sv9667.qa.shopview.com|https://sv9667.qa.shopview.com] (build v26.40.7-7ffda69) on 5 October 2026, against the ticket, Nemanja's QA checklist and spec rule S10-R5b, and compared it with production (build v26.40.7-e1021b1). 9 of the 10 checks below passed; 1 is open.

The For Customer box on a note's file now follows the note's own shop. A shop can no longer change another shop's files, and a file added by someone who has since left the shop can be shared with the customer again.

*Why this is partially passed and not fully passed:* one point is still open, and it is posted as a question to Nemanja in the [next comment|https://shopview.atlassian.net/browse/SV-10323?focusedCommentId=77937]. A user with the Technician role sees no For Customer box at all, while the spec says a user who can only view the record should see it greyed out. Production does the same, so this change did not cause it, but it sits inside the rule this ticket implements, so we need to know whether it was left out on purpose or belongs to this fix. Once that question is answered (and fixed, if it needs fixing), this ticket will be marked fully passed.

h3. How to see it yourself
# Open [sv9667.qa.shopview.com|https://sv9667.qa.shopview.com] as Admin and open work order *S2-17414*, *Notes* tab.
# The note *"ZZAUTOTEST SV-10323 note by a staff member who then leaves"* was added by a staff member who has since been removed. Its file *zz10323_leaver.png* is already ticked *For Customer*. Click the box to clear it, then click it again to tick it. Both work with no error. Reload: it is still ticked.
# As Admin, go to *Administration > Staff*, open *Tech ShopView* and change the role to *Sales Representative* (Work Orders View, no Work Orders Edit). Sign out, sign back in with the *Tech* quick-login and open the same Notes tab. The *For Customer* boxes are greyed out and clicking them does nothing.
