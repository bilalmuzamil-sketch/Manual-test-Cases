Setup: Drops are refused on an inactive technician and one removed from this location

Test case: C96970, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Technician {Technician-B} (for example Ralph Edwards) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Customer {Customer-A} (for example "ZZAUTOTEST C96970 Refused Drops") is used by this case only.

• Approved work order {Work-order-1} (for example S10043-17631) for {Customer-A} is led by technician {Technician-A} (for example ZZAUTOTEST Ina Inactive).

• Approved work order {Work-order-2} (for example S10043-17632) for {Customer-A} is led by {Technician-B}.

• Approved work order {Work-order-3} (for example S10043-17633) for {Customer-A} is led by technician {Technician-C} (for example ZZAUTOTEST Mona Moved).

• After the work orders were given their leads, {Technician-A}'s staff account was deactivated.

• You pinned {Technician-C} in Board View, and after that {Location-A} was removed from {Technician-C}'s Location field. {Technician-C} is still active.

• On the Work Orders page nothing is ticked in Status, Asset on Site shows no choice (if its chip shows Yes or No, click the x on the chip), Assigned to me is off and Search is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Settings > Staff. Create a new staff member for this case only (do not reuse a shared one, because this case changes the record): click New Staff Member and enter First Name and Last Name (for example ZZAUTOTEST Ina Inactive), an Email, Role Technician, Departments Service, Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}.

5. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Ralph Edwards), an Email, Role Technician, Departments Service, Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-B}.

6. Your initials > Settings > Staff. Create a new staff member for this case only (do not reuse a shared one, because this case changes the record): click New Staff Member and enter First Name and Last Name (for example ZZAUTOTEST Mona Moved), an Email, Role Technician, Departments Service, Location {Location-A} and one other location {Location-B} (for example Staging Light Duty), so her Location field is never empty, turn Time Clock on, then Save & Close. This is {Technician-C}.

7. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST C96970 Refused Drops") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

8. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17631). Repeat this twice more. Number them {Work-order-1}, {Work-order-2} and {Work-order-3} in the order you create them.

9. On the work order page pick the technician in the Lead Technician dropdown; it saves at once. Give {Work-order-1} the lead {Technician-A}, {Work-order-2} the lead {Technician-B} and {Work-order-3} the lead {Technician-C}.

10. Work Orders > All tab > Board View. If three technicians are already pinned, unpin one (click the filled pin in its column header), because only three pins are allowed. Click the pin icon in {Technician-C}'s column header. Her column moves right after Unassigned with a filled pin.

11. Deactivate {Technician-A}: your initials > Settings > Staff > {Technician-A}'s edit icon > click Deactivate Account and confirm.

12. Remove {Location-A} from {Technician-C}: your initials > Settings > Staff > {Technician-C}'s edit icon > remove {Location-A} from her Location field (keep {Location-B}) > Save. She stays active.

13. Check the setup worked: Work Orders > All tab > Search with the name of {Customer-A} shows {Work-order-1} led by {Technician-A}, {Work-order-2} led by {Technician-B} and {Work-order-3} led by {Technician-C}. Settings > Staff shows {Technician-A} deactivated and {Technician-C} active without {Location-A}. If anything differs, fix it before you start, then clear the search.

Part 2. Setup for Claude session

• Goal: one deactivated technician {Technician-A} and one active technician {Technician-C} removed from {Location-A} (pinned before the removal), each still leading one work order at {Location-A}; then drops of {Work-order-2} onto both in Board View and in Tech View.

• GET /api/staff lists staff; each row has both id and staff_id, and the Schedule's staffId and the working-hours calls use staff_id.

• Create {Technician-A} and {Technician-C} new for this case (never deactivate or move a shared technician). Create {Customer-A}, its contact and asset, and {Work-order-1} to {Work-order-3} on screen as in Part 1. Record {Work-order-1 id} to {Work-order-3 id}.

• Pin {Technician-C} on screen (Board View column header pin icon) before removing {Location-A}; pins are per user and at most three.

• UNVERIFIED on the Work Orders QA site: whether the Location field can be left empty, which is why {Technician-C} is given {Location-B} as well.

• Steps 4 to 7: Playwright drag-and-drop from {Work-order-2}'s card to each column. Read the message text after the second drop exactly and compare it character for character with "This technician can't be assigned work orders." Record where the card ends up after each drop.

• Steps 3 and 9: record each header's text and whether it shows an inactive marker or a pin. UNVERIFIED: how the build shows the inactive marker (a label or a badge); record what you see.

• Steps 10 to 13: the same drags in Tech View on the rows; then open {Work-order-2} and read its Lead Technician. Confirm with GET on the work order that the lead did not change.

• Context: this case follows PRD version 49 (14 Oct 2026). Nothing about how the build behaves today is assumed; judge only what you see.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.
