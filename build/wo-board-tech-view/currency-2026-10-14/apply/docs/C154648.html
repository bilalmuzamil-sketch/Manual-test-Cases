Setup: Tech View and Board View are unavailable while Imported is selected

Test case: C154648, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Imported work order {Work-order-1} (for example ZZIMP-154648-1) exists at {Location-A} for customer {Customer-A} (for example "ZZAUTOTEST C154648 Imported"); it came from an invoice import, so it is listed only when Imported is ticked in Status.

• Ordinary work order {Work-order-2} (for example S10043-17581) for {Customer-A} exists at {Location-A}.

• On the Work Orders page nothing is ticked in the Status filter.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST C154648 Imported") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

5. Create the Imported work order from an invoice import: your initials > Settings > Invoices (in the IMPORTS group; on some builds Settings > Data Import > Invoices) > Download Template. Fill one row and keep the heading row (the columns marked * are required): Shop Location = the name of {Location-A}, Customer = the name of {Customer-A}, Invoice Number (for example ZZIMP-154648-1), Invoice Date as month/day/year (for example 10/14/2026), Item Labor, a Line Title (for example ZZAUTOTEST labor), Qty 1, Rate 100, Total 100, Tax Amount 5.

6. Save the file as .csv, click Select CSV File, pick the file and click Import Invoices. The message reads "All invoices have been imported successfully." The imported work order's number is the Invoice Number you typed. This is {Work-order-1}.

7. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Add Line. In the next New Line form type "clutch", pick "Service - Adjust clutch", turn Line Approved on and click Save & Close. Write down the number shown at the top left (for example S10043-17581). This is {Work-order-2}.

8. Go to Work Orders > All > List, click Status and, if anything is ticked, click "Clear selection".

9. Check the setup worked: Work Orders > All > List: with Status > "Imported" ticked, {Work-order-1} is listed. With the selection cleared, {Work-order-2} is listed and {Work-order-1} is not. Leave nothing ticked in Status. If no Imported work order can be made, the case cannot start: mark it Blocked and write why.

Part 2. Setup for Claude session

• Goal: an Imported work order {Work-order-1} and an ordinary work order {Work-order-2} at {Location-A}, then the case's steps on screen.

• Create {Customer-A}, then the import file as in Part 1. UNVERIFIED on the Work Orders QA site: whether the import also creates a customer that does not exist yet; create {Customer-A} first so it does not matter.

• Record {Work-order-1} (the Invoice Number) and {Work-order-2} (the number on its page). Check in List with Status > Imported ticked that {Work-order-1} is listed, then clear the selection.

• Steps 4 and 6: hover each display button with Playwright and read the tooltip text exactly; compare it character for character with "Not available while Imported is selected." Steps 5 and 7: click each button and confirm the address and the table did not change.

• Steps 11 and 15: open Status, hover the Imported option and read its tooltip exactly ("Imported work orders open in List."); steps 12 and 16: click it and confirm it did not become ticked.

• UNVERIFIED: the design export of 14 Oct shows Imported work orders inside Tech View and Board View's Unassigned with a lock and no greyed switcher; the PRD (version 48) wins. A build that still behaves like the design fails this case.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Work Orders QA site for this feature (epic SV-10043): app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com. Use the site named in the test run if it differs.
  • Staging (after the feature is merged there): app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, window at least 1024 px wide. Do not run "playwright install".

Access

  • On a QA site, sign in with the sign-in page's Admin quick-login button (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Elsewhere, ask the QA lead for the environment's cookies.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.

Cleanup
