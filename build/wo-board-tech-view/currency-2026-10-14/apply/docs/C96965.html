Setup: Clear shifts removes only the old lead's whole-work-order shifts

Test case: C96965, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

Part 2. Setup for Claude session

• Goal: the three work orders and six shifts of the Preconditions, then two drags on Board View and a read of the Schedule.

• GET /api/staff lists staff; each row has both id and staff_id, and the Schedule's staffId and the working-hours calls use staff_id.

• Create {Customer-A}, its contact and asset, then {Work-order-1} to {Work-order-3} on screen as in Part 1 (two approved lines each). Record {Work-order-1 id}, {Work-order-2 id}, {Work-order-3 id}, {Line-1 id} and {Line-3 id} from the Lines tab requests.

• Faster route for shifts, UNVERIFIED on the Work Orders QA site (proven only on the Schedule QA site sv8685, build v3.5-7ec992f): POST /api/schedule/shifts with workOrderId, lineIds (every line id for an entire-work-order shift, the chosen line ids otherwise), staffId, startDate, startTime, spreadMode "single", totalMinutes, perDayMinutes and isAllDay false; 201 means created. If it is refused, use the Schedule screen as in Part 1 and record what the screen sent.

• Read shifts back with GET /api/schedule/board?from=<ISO instant>&to=<ISO instant> (full instants such as 2026-10-15T00:00:00Z; a bare date or a range over 62 days is refused). Compare each shift's start and end with the location's time zone before deciding a shift is wrong (SV-11229, a shift saved six hours off, was closed Obsolete on 12 Oct 2026).

• Trap: on the Schedule a work order with only one line is booked at once as a whole, with no Entire work order / Choose lines window (recorded in C368178). That is why every work order in this case has two lines.

• Steps 3 to 7: Playwright drag-and-drop from the card to {Technician-B}'s column; read the question's title exactly, then click Clear shifts (first drag) or Keep shifts (second drag).

• Steps 8 to 12: read the Schedule on screen, and confirm with the board read above that exactly the shifts in the expected results remain (record each shift's technician, work order, lines and times).

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.
