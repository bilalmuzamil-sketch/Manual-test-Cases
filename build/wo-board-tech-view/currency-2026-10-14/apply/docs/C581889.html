Setup: Board View and Tech View show the filter message when no work order matches

Test case: C581889, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Approved work order {Work-order-1} (for example S10043-17590) for customer {Customer-A} (for example "ZZAUTOTEST NT1 Filtered Empty") exists at {Location-A}, and it is {Customer-A}'s only work order.

• No work order at {Location-A} is in status {Status-A} (for example Paid). Pick a status other than Imported and Approved.

• On the Work Orders page nothing is ticked in Status, Assigned to me is off and Search is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST NT1 Filtered Empty") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

5. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Add Line. In the next New Line form type "clutch", pick "Service - Adjust clutch", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17590). This is {Work-order-1}.

6. Choose {Status-A}: Work Orders > All > List > Status, tick one status (for example Paid; not Imported and not Approved) and nothing else. If the List shows no work order, that status is {Status-A}. Otherwise try another status (for example Declined, Review). Then click Clear selection.

7. Turn Assigned to me off and empty Search.

8. Check the setup worked: Searching {Customer-A}'s name with no status ticked shows only {Work-order-1}; with only {Status-A} ticked and no search, the List shows no work order. Leave nothing ticked and Search empty.

Part 2. Setup for Claude session

• Goal: one work order {Work-order-1} for {Customer-A}, and a status {Status-A} that no work order at {Location-A} has.

• Find {Status-A} on screen as in Part 1 (List, one status ticked, no rows). Record the status and the time you checked it: on a shared QA site another session can create a work order in that status later, so re-check just before step 3 of the test.

• Read the empty-state texts with Playwright as exact strings: "No work orders match these filters" and "Try removing a filter to widen your results.", and look for a button labelled exactly "Clear all filters" in each display.

• UNVERIFIED: the design export of 14 Oct shows the two lines with no button in Tech View and Board View, and shows the search message ("No results for …") when a filter and a search are both on. The PRD wins; a build that follows the design fails this case.

• Older builds of the List read "No work orders match your filters" (playbook section on Work Orders labels); that wording is out of date since PRD version 43.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work
