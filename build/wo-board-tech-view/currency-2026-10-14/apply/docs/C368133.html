Your role also needs Schedule access (Settings > Roles & Permissions > Admin > Schedule: View and Create & Edit).

4. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, the Service department, {Location-A} in Location and a Role other than Office User or Time Clock User. Part 2. Setup for Claude session

• Goal: the seven work orders and five shifts of the Preconditions, then drags on Board View with the outcome of each drag recorded.

• GET /api/staff lists staff; each row has both id and staff_id, and the Schedule's staffId and the working-hours calls use staff_id.

• Create {Customer-A}, its contact and asset, then {Work-order-1} to {Work-order-7} on screen as in Part 1 (two approved lines each). Record each work order's number and id ({Work-order-1 id} … {Work-order-7 id}) and, on {Work-order-3}, {Line-1 id} and {Line-2 id} from the Lines tab requests.

• Faster route for shifts, UNVERIFIED on the Work Orders QA site (proven only on the Schedule QA site sv8685, build v3.5-7ec992f): POST /api/schedule/shifts with workOrderId, lineIds (every line id for an entire-work-order shift, the chosen line ids otherwise), staffId, startDate, startTime, spreadMode "single", totalMinutes, perDayMinutes and isAllDay false; 201 means created. If it is refused, use the Schedule screen as in Part 1 and record what the screen sent.

• Read shifts back with GET /api/schedule/board?from=<ISO instant>&to=<ISO instant> (full instants such as 2026-10-15T00:00:00Z; a bare date or a range over 62 days is refused). Compare each shift's start and end with the location's time zone before deciding a shift is wrong (SV-11229, a shift saved six hours off, was closed Obsolete on 12 Oct 2026).

• Trap: on the Schedule a work order with only one line is booked at once as a whole, with no Entire work order / Choose lines window (recorded in C368178). That is why every work order in this case has two lines.

• Run the steps on Board View with Playwright drag-and-drop from the card to the target column. After each drop, wait for either the question (title text starting "Clear ") or the "Lead technician updated" message, and record which appeared; on a question click Keep shifts.

• Context: the developer reported on 12 Oct 2026 (SV-11126, build e84b3d1) that the question now opens for an Entire work order shift and not for a shift on only some lines. That is not evidence about the build you test; judge only what you see.
