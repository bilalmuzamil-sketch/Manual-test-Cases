Setup: A search alone that matches nothing shows the search message with no button

Test case: C581890, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• No work order at {Location-A} matches the search text {Search-A} (for example ZZAUTOTEST-NOMATCH-A02).

• On the Work Orders page nothing is ticked in Status, Assigned to me is off and Search is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Pick the search text {Search-A} (for example ZZAUTOTEST-NOMATCH-A02). Check it matches nothing: Work Orders > All > List with nothing ticked in Status, type {Search-A} in Search; no work order is listed. Then empty Search.

5. Turn Assigned to me off and make sure nothing is ticked in Status.

6. Check the setup worked: With nothing ticked in Status, Assigned to me off and {Search-A} in Search, the List shows no work order. Empty Search before you start.

Part 2. Setup for Claude session

• Goal: no records are needed; only a search text {Search-A} that matches nothing at {Location-A}, with every filter off.

• Read the message with Playwright as an exact string and compare it with "No work orders match the search "{Search-A}"." filled with the real text; confirm that no button sits in the empty state of each display.

• UNVERIFIED: whether the All tab itself counts as an active filter on the build. The PRD calls the tabs filter views (predefined status sets); this case treats All with nothing ticked as no filter. If the build shows the filter message here, record it as a question, not a pass.

• UNVERIFIED: the design export of 14 Oct shows "No results for …" and "Check the spelling, or search by work order number, customer, unit or VIN." The PRD wins; a build that follows the design fails this case.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.
