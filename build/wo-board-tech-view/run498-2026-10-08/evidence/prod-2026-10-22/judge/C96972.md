# C96972 — A reassign is refused if the work order was just invoiced elsewhere
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481916

## Preconditions
Preconditions
- Needs: 2 users · 2 browsers · about 25 minutes.
- Build: the Work Orders QA build (sv10043, v26.40.8-7a95011).
- [User-A] = you: an Owner/Admin user (on a QA branch the Admin quick-login user, shown as "Admin ShopView"). The Admin role holds Work orders > View and Work orders > Create & Edit.
- [User-B]: a second user with create and edit and invoicing permission (e.g. "Sam Second", Admin role) in a second browser.
- Desktop browser window at least 1024 px wide. Narrower windows show only the List, without the display switcher.
- One location for the whole case, shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); everything below is created in this location.
- Two eligible technicians at this location: [Tech-A] "Esther Howard" and [Tech-B] (e.g. "Ralph Edwards"). A person only counts as a technician here when the staff member is active (not deactivated), Time Clock is on, the Role is neither Office User nor Time Clock User, and this location is picked in their Location field.
- Customer "ZZAUTOTEST F1 Invoiced Elsewhere" (used by this case only), with a contact person, and one Complete work order [WO-1] led by [Tech-A], so it can be invoiced.
- Esther Howard is named in the expected results and stays as written; the other names and the number are examples.

## Steps
- In browser 1 open Work Orders, click the All tab, pick Board View and search for "ZZAUTOTEST F1 Invoiced Elsewhere". The card shows Complete.
- In browser 2 open [WO-1] and invoice it (Finance tab > Create Invoice). Its status is now Invoiced.
- In browser 1, without reloading, drag [WO-1] from [Tech-A]'s column into [Tech-B]'s column.
- Read where the card ends up and the alert, then close the alert.
- Reload browser 1 and read the card's column.

## Expected (source quote — judge against this, never change it)
Expected results
- The drop is refused: the card goes back to Esther Howard's column and the lead stays Esther Howard.
- An alert reads "Failed to update lead technician, please try again." and also explains the status (e.g. that the work order is now Invoiced). Write down the explanation. The status cannot be changed in the middle of a single drag by hand; a board that still shows the old status is the same situation for the user.
Source — where this behaviour comes from
Epic SV-10043; story SV-10047 (Story 4, Reassign or unassign the lead technician); PRD Confluence 845185030, edited 7 Oct 2026 (status line "PRD v33"), S4-E3, S4-N3, S4-N8, read 8 Oct 2026. Source-verified 8 October 2026.
Exact quotes from the source (for reproducibility)
- S4-E3: “If status becomes prohibited during a drag, reject the drop using S4-N3 and S4-N8, with a status explanation.”
- S4-N3: “If reassignment fails, return the card or row to its original column or group.”
- S4-N8: “Failed reassignment shows a user-dismissible alert: “Failed to update lead technician, please try again.””
