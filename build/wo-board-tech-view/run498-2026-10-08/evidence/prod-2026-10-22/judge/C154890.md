# C154890 — If shifts can't be cleared, the lead does not change either
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481983

## Preconditions
Preconditions
- Needs: 1 user · 1 browser · Schedule access · about 20 minutes.
- Build: the Work Orders QA build (sv10043, v26.40.8-7a95011).
- [User-A] = you: an Owner/Admin user (on a QA branch the Admin quick-login user, shown as "Admin ShopView"). The Admin role holds Work orders > View and Work orders > Create & Edit.
- Desktop browser window at least 1024 px wide. Narrower windows show only the List, without the display switcher.
- One location for the whole case, shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); everything below is created in this location.
- Two eligible technicians at this location: [Tech-A] "Esther Howard" and [Tech-B] (e.g. "Ralph Edwards"). A person only counts as a technician here when the staff member is active (not deactivated), Time Clock is on, the Role is neither Office User nor Time Clock User, and this location is picked in their Location field.
- Customer "ZZAUTOTEST F1 Clear Fails" (used by this case only) with one Approved work order [WO-1] led by [Tech-A].
- A shift for [Tech-A] on [WO-1] tomorrow 8:00–12:00 (entire work order).
- You can turn this computer's network connection off and on (e.g. Wi-Fi off).
- Esther Howard is named in the expected results and stays as written; the other name and the number are examples.
Setup
- Sign in as an Owner/Admin user (on a QA branch: the Admin quick-login button on the sign-in page; you appear as "Admin ShopView"). The Admin role holds Work orders > View and Work orders > Create & Edit (to check: your initials at the top right > Settings > Roles & Permissions > Admin > Work orders).
- Use one location for the whole case: it is shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); to change it click your initials at the top right > Change Location.
- Settings (your initials at the top right > Settings) > Staff: reuse a technician only after checking it is active, has Time Clock on, a Role other than Office User or Time Clock User and this location in Location; otherwise add one: New Staff Member > First Name and Last Name, an Email, Role "Technician", at least one Department (required), Location = this location, Time Clock on > Save & Close. Record them as [Tech-A] = "Esther Howard" (use exactly this name: the expected results name it), [Tech-B] (e.g. Ralph Edwards).
- Create the customer used only by this case: top menu Customers > New Customer > Name "ZZAUTOTEST F1 Clear Fails" > Save. On the customer page click the Contacts tab > New Contact > First Name and Last Name > Save (a new asset needs a contact). Then click the Assets tab > New Asset > pick the Contact, then Year, Make, Model and Unit (e.g. 2022, Freightliner, M2, unit "TRK-118") > Save. Make is required; Unit can be left empty.
- Create these work orders for "ZZAUTOTEST F1 Clear Fails": Work Orders > Create Work Order > in the New Work Order window pick the Customer and its Asset > Save. The new work order opens with the New Line form (otherwise click New Line

## Steps
- Open Work Orders, click the All tab and pick Board View in the display switcher (right side of the toolbar; tooltip "Board View").
- Type "ZZAUTOTEST F1 Clear Fails" in Search.
- Drag the card from [Tech-A]'s column into [Tech-B]'s column; the prompt opens.
- Turn off this computer's network connection (e.g. Wi-Fi off).
- Click Clear shifts.
- Read the card's position and the alert, then close the alert.
- Turn the network back on, reload, open the work order and read Lead Technician, then open the Schedule for tomorrow.

## Expected (source quote — judge against this, never change it)
Expected results
- Nothing is half done: the card goes back to Esther Howard's column, Lead Technician still reads Esther Howard, and her 8:00–12:00 shift is still on the Schedule.
- The alert reads "Failed to update lead technician, please try again.". A failure of only the shift clearing (with the lead change itself able to save) cannot be caused by hand; write 'clearing-only failure not checked by hand' in the result comment and pass or fail on what you can see.
Source — where this behaviour comes from
Epic SV-10043; story SV-10047 (Story 4, Reassign or unassign the lead technician); PRD Confluence 845185030, edited 7 Oct 2026 (status line "PRD v33"), S4-R27, read 8 Oct 2026. Review Decisions DR-46; tech plan §12.1 (clearing failure rolls back the lead change). Source-verified 8 October 2026.
Exact quotes from the source (for reproducibility)
- S4-R27: “The lead change and the shift clearing succeed or fail together. If clearing fails, the lead technician is not changed and S4-N8 shows.”
- S4-N8: “Failed reassignment shows a user-dismissible alert: “Failed to update lead technician, please try again.””
