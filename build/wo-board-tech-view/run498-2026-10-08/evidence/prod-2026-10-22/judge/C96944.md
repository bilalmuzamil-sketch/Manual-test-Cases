# C96944 — A card's status badge always sits in the same spot
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481888

## Preconditions
Preconditions
- Needs: 1 user · 1 browser · about 20 minutes
- Build: the Work Orders QA build (sv10043, v26.40.8-7a95011). A desktop browser with the window at least 1024 pixels wide (full screen on an ordinary laptop or monitor). Below that width the page shows only List.
- [User-A]: an Owner/Admin user (on a QA branch: the Admin quick-login button on the sign-in page; you appear as "Admin ShopView"). The Admin role holds Work orders > View and Work orders > Create & Edit (to check: your initials at the top right > Settings > Roles & Permissions > Admin > Work orders).
- One location for the whole case, shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); everything below is created in this location.
- One technician at this location: [Tech-A] (e.g. "Esther Howard"). A person only counts as a technician here when the staff member is active (not deactivated), Time Clock is on, the Role is neither Office User nor Time Clock User, and this location is picked in their Location field.
- Two customers used by this case only: a short name "ZZAUTOTEST F2 Badge Spot" and a long name "ZZAUTOTEST F2 Badge Spot Commercial Transport Services" (stands in for the case's example "Fibridge Commercial Transport Services"). "ZZAUTOTEST F2 Badge Spot" has two assets, one with no Unit.
- Three work orders, all led by [Tech-A]: [WO-1] Approved for the long-named customer; [WO-2] an Estimate for "ZZAUTOTEST F2 Badge Spot"; [WO-3] Approved for "ZZAUTOTEST F2 Badge Spot" on the asset with no unit.
- What must hold: the three cards differ in customer-name length, status and unit.
Setup
- Sign in with the Admin quick-login button on the sign-in page (you appear as "Admin ShopView"). Check the location in the top bar next to the bell; to change it click your initials at the top right > Change Location.
- Settings (your initials at the top right > Settings) > Staff: confirm each technician below is active at this location with Time Clock on, or add it: New Staff Member > First Name and Last Name, an Email, Role "Technician", at least one Department (required), Location = this location, Time Clock on > Save & Close. Record them as [Tech-A] (e.g. Esther Howard).
- Top menu Customers > New Customer > Name "ZZAUTOTEST F2 Badge Spot Commercial Transport Services" > Save (if it already exists, open it instead). On the customer page click the Contacts tab > New Contact > First Name and Last Name > Save (a new asset needs a contact). Then click the Assets tab > New Asset > pick the Contact, then Year, Make, Model and Unit (e.g. 2022, Freightliner, M2, TRK-118) > Save. Make is required; Unit can be left empty. Do the same for "ZZAUTOTEST F2 Badge Spot", and give "ZZAUTOTEST F2 Badge Spot" a second asset with Unit left empty.
- Work Orders > Create Work Order > in the New Work Order window pick Customer "ZZAUTOTEST F2 Badge Spot" and its asset > Save. The work order opens on its Lines tab with the New Line form open: in "What Are You Doing?" pick a ready-made li

## Steps
- Open Work Orders.
- Click the All tab on the left of the toolbar.
- Click Search and type ZZAUTOTEST F2 Badge Spot so only this test's work orders show.
- In the display switcher at the right of the toolbar, click Board View (tooltip "Board View").
- Look at where the status badge sits on each of the three cards.
- Hover each card.

## Expected (source quote — judge against this, never change it)
Expected results
- On every card the status badge is in the same place (in the design: top-right of the card, next to the number), whatever the customer name length or missing unit.
- It stays in that place while the card is hovered (the more-actions button appears as an overlay, it does not push the badge aside).
Source — where this behaviour comes from
Epic SV-10043; story SV-10046 (Story 3, Board View — board by lead technician); PRD Confluence 845185030, edited 7 Oct 2026 (status line "PRD v33"), S3-R5, Key Decisions, read 8 Oct 2026. Design: Claude Design export of 8 Oct 2026 (Work Orders.dc.html), Board card header; on-screen labels only.
PRD “Work Orders — Board View & Tech View Display Options”, Confluence 845185030, version 73 (21 Oct 2026, Chris Ward), S3-R11, read 22 Oct 2026: “Board View shows no Density control in this release (SV-11580).” QA lead, 22 Oct 2026: the density step and “at every density” were removed from this test.
Exact quotes from the source (for reproducibility)
- S3-R5: “Keep each card’s status badge in a fixed position.”
- Key Decisions: “More-actions appears as a hover overlay on the card so the status badge sits in a fixed spot instead of floating.”

## Newest PASSED result in run 498 (staging judgement)
Tested on staging, build v26.40.19-1493c63, on 17 October 2026.
- Result: Passed on staging, following the test's steps.
- Customer ZZAUTOTEST F2 Badge Spot: three cards (S2-35373, S2-35374, S2-35375) with different customer name lengths.
- On every card the status badge sits at the top-right, level with the work order number, at the same spot on all three cards.
- The badge stays in that same spot on all three cards at Compact, Regular and Comfortable, and hovering a card did not move it.
