# C368167 — A refused lead change on the work order page shows an error, keeps the old lead
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3792488

## Preconditions
Setup file (for Claude sessions; a tester does not need it)
Preconditions
- You are signed in as an Admin user (Work orders > View and Create & Edit) at {Location-A}, in a desktop browser window at least 1024 px wide.
For example: {Location-A} is Staging Heavy Duty - 9919.
- Two active technicians work at {Location-A}: "Esther Howard" (the expected results name her) and {Technician-B}, who is offered in the work order page's "Lead Technician" list.
For example: {Technician-B} is Jenny Wilson.
- Customer {Customer-A}, used by this case only, has work order {Work-order-1}, led by "Esther Howard", with status Complete (all lines complete and reviewed, not invoiced).
For example: {Customer-A} is ZZAUTOTEST Refused Lead Change and {Work-order-1} is S2-37327.
- Two tabs of the same browser window are open, tab 1 and tab 2, both signed in as you. Do not sign in again in a private window: a second sign-in can end the first tab's session.
- If any record above is missing, mark this test Blocked: "setup not done".

## Steps
- In tab 1, open {Work-order-1} and leave the page open.
- In tab 2, open {Work-order-1}, click the "Finance" tab and click "Create Invoice". Wait until the invoice shows on the Finance tab (its number starts with "INV-"). If a "New Customer Payment" window opens, leave it open: do not pay and do not close it, because closing it with its X takes the invoice back off. If no such window opens (the current build does not open one), simply go on to the next step.
- In tab 1, without reloading, click "Lead Technician" on the status card.
- Pick {Technician-B}.
- Read the message that appears and the "Lead Technician" field.
- Reload tab 1 and read "Lead Technician".

## Expected (source quote — judge against this, never change it)
Expected results
- Step 5: an error message appears (write down its words, e.g. "The lead technician can't be changed once a work order is Invoiced or Paid.") and the Lead Technician field goes back to "Esther Howard".
- Step 6: after the reload Lead Technician still reads "Esther Howard". The change was not saved.
- If browser 1 already shows the field disabled at step 3 because the page refreshed itself, write 'page refreshed itself' in the result comment and pass on the disabled field.
Source — where this behaviour comes from
Regression for epic SV-10043 (PR #3548); developer's regression list, received 8 Oct 2026, High 1; QA handoff test plan (generated 2026-10-08), §7; PRD Confluence 845185030, version 68 (19 Oct 2026, Chris Ward), read 19 Oct 2026, where quoted (§4 Key Decisions). Source-verified 8 October 2026.
Exact quotes from the source (for reproducibility)
- Dev reply High 1: “A refused change now shows an error and puts the old value back.”
- QA handoff §7: “A refused change shows an error and puts the old value back.”
- QA handoff §7: “changing the lead from the dialog, by a board drag or from the detail card is refused with "The lead technician can't be changed once a work order is Invoiced or Paid."”
- PRD §4 Key Decisions (lead lock): “Lead technician cannot be changed once a work order is Invoiced or Paid. This is a product rule, not only a screen rule, so it must hold on every path that changes the lead technician — board drag, the lead technician dialog, Unassign, Undo, and the work order detail page.”
Last checked against build v26.40.8-7a95011 on 10/8/2026.
