# C590112 — Design: Tech View table fills the full width and Status fits its labels
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3995721

## Preconditions
Setup file (for Claude sessions; a tester does not need it)
Preconditions
- You are signed in as an Admin user (the "Admin" role, which has Work orders > View and Create & Edit) at {Location-A}.
For example: {Location-A} is Staging Heavy Duty - 9919.
- The browser window is 1440 px wide with the zoom at 100%, and the design pictures "DC-03-tech-view-regular-light-1440.png" and "DC-03-tech-view-regular-light-1536.png" attached to this case are open beside it at 100% (actual size). Names, numbers and rank numbers in the pictures are sample data. Your screen lets you widen the window to 1536 px.
- Customer {Customer-A} has an Approved work order {Work-order-1}, led by technician {Technician-A}, and an Estimate {Work-order-2} with no lead technician. Customer {Customer-B} has a work order {Work-order-3} in "Ready For Review", led by {Technician-A}.
For example: {Customer-A} is ZZAUTOTEST C590112 Short, {Customer-B} is ZZAUTOTEST C590112 Review, {Technician-A} is ZZAUTOTEST C590112 Ana, and {Work-order-1} to {Work-order-3} are S10043-17807 to S10043-17809.
- Starting screen: "Work Orders" > "All" tab, "Tech View" shown, "Search" empty, no filter chosen, "Assigned to me" off, density "Regular".
- If any record above is missing, mark this test Blocked: "setup not done".

## Steps
- Look at the left and right edges of the table, from the column header row down to the last row on screen.
- Look at the line between the "Unassigned" group and the next group.
- Scroll the table down a few screens.
- Scroll the table sideways to its far right.
- Widen the window to 1536 px.
- Type the name of {Customer-A} in "Search".
- Replace the search text with the name of {Customer-B}.
- Click "List" in the display switcher.

## Expected (source quote — judge against this, never change it)
Expected results
- Step 1: the table is white and runs from the page's left edge to its right edge, with no grey strip, margin, card, panel, rounded corner or shadow around it, as in the 1440 px picture.
- Step 2: the groups are separated by a double grey line above each group header, as in the picture.
- Step 3: the column header row stays at the top while the rows move up under it.
- Step 4: the table scrolls sideways inside the page, each header label stays above its own column, and no column is squeezed or cut off.
- Step 5: at 1536 px the table still runs edge to edge on white, as in the 1536 px picture.
- Step 6: the "Status" column is only as wide as its widest pill ("Approved" or "Estimate"), with no wide empty space after the pills.
- Step 7: the "Status" column is wider, just wide enough for the "Ready For Review" pill (about 132 px, as in the design).
- Step 8: List's table looks as it does in production today.
Source — where this behaviour comes from
Epic SV-10043; story SV-10045 (Story 2, Tech View); PRD "Work Orders — Board View & Tech View Display Options", Confluence 845185030, version 61 (16 Oct 2026, Chris Ward), S2-R22, S2-R1 and Goals, read 16 Oct 2026. Claude Design project "Work Orders" (Branko Cicovic), export of 14 Oct 2026, board "Work Orders.dc.html" (the design pictures named in the preconditions were rendered from it), read 14 Oct 2026. Related tickets: SV-11324. Product owner answers: Chris Ward, WO Board and Tech View question sheet (https://docs.google.com/spreadsheets/d/1gBGmNB4B1bRrD2ZJvBn1tuvbfxFPjcsKddz_I5H3CvU), answer 13, read 15 Oct 2026. Source-verified 16 October 2026. Last checked against build v26.40.19-1493c63 (staging) on 10/16/2026.
With the design's default columns the table is about 1,790 px wide, so it scrolls sideways at 1440 and 1536 px in the design too. Chris Ward answered on 15 Oct 2026 (answer 13) that sideways scrolling is fine, as in the design, and columns keep the design's minimum widths and are never squeezed or clipped; PRD version 61 still says so, and this case follows it.
PRD version 57 (S2-R22; Chris Ward accepted Slavcho Mitrov's resolution, Slack, 15 Oct 2026) adds that the Status column has no minimum width and sizes to its widest pill, because the pills keep List's widths; steps 6 and 7 check it.
Exact quotes from the source (for reproducibility)
- S2-R22: “Tech View’s table runs edge to edge on white, with no side gutter and no card or panel around it, as in the design. When the columns are wider than the screen, the table scrolls sideways, as in the design; columns keep the design’s minimum widths and are never squeezed or clipped. The Status column is the one exception: it has no minimum width and sizes to its widest pill on the page, because its pills keep the List’s production widths (S6-R2a). With Ready for Review on the page that is about the design’s 132px; with only short statuses it is narrower.”
- S2-R1: “Group work orders by lead technician with visible separators.”
- Goals: “List remains the default and is unchanged from production. The only changes to the Work Orders page are the display switcher and the icons on the filter chips and Search, which follow the design file in every display option, List included (S1-R9a). Today’s tabs, toolbar layout and Create Work Order button stay as they are.”
- Design — README.md (design library), list screens: “runs edge to edge on white (never inside a card on grey)”
- Design — SKILL.md (design library), list screens: “A list screen is white and the table runs edge to edge.”
- Design — Work Orders.dc.html, Tech View column header row: “position: sticky; top: 0; z-index: 2; background: var(--sv-surface); border-bottom: 1px solid var(--sv-border-default);”
- Design — Work Orders.dc.html, Tech View group header: “border-top: 3px double var(--sv-border-default);”
- Design — Work Orders.dc.html, Tech View table: “min-width: {{ rowsMinWidth }}; flex: 1; padding-bottom: 20px; background: var(--sv-surface);”
