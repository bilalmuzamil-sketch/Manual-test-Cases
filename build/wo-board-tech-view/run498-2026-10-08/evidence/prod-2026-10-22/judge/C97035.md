# C97035 — Analytics event totals for one session match the rules exactly
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481973

## Preconditions
Preconditions
- Needs: 1 user · 1 browser (private window) · Google Analytics DebugView access · about 15 minutes
- Build: the Work Orders QA build (sv10043). Desktop browser window at least 1024 px wide (narrower windows show only the List, without the display switcher).
- Role: Owner/Admin. On a QA branch sign in with the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". The Admin role holds Work orders > View and Work orders > Create & Edit (to check: your initials at the top right > Settings > Roles & Permissions > Admin > Work orders). This user is the dispatcher.
- Location: one location for the whole case, shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); to change it click your initials at the top right > Change Location. Every technician and work order below belongs to this location.
- Analytics access: you can open Google Analytics for the property the QA build reports to, at Admin > DebugView. The QA build runs analytics in debug mode, so each event appears in DebugView within a few seconds under your user. If you cannot open DebugView, the event checks in this case cannot be done by hand: write "not checked by hand" in the result comment and pass or fail on what you can see on the Work Orders page.
- Event names to look for in DebugView: work_orders_display_view (a display was shown), work_orders_field_load and work_orders_density_load (the fields and density you have, once per display per session), work_orders_field_toggle and work_orders_density_change (a saved change).
- Your saved display is List and your density has never been changed.
- Board View fields Service advisor, Line count and Created date start off.
- There are enough work orders at this location for a Board View column to load more cards when scrolled.
Setup
- Click List in the display switcher once, so your saved display is List. If your density has ever been changed, use a user who has never changed it.
- Start a fresh analytics session: close every browser window, open a new private window and sign in.
- Check the setup worked: Google Analytics > Admin > DebugView shows your device within a few seconds of opening any ShopView page. If it does not, carry on but write "not checked by hand" for the event checks, as the Preconditions say.

## Steps
- Open Work Orders (List).
- Click Tech View in the display switcher at the right of the toolbar (tooltip "Tech View").
- Click Board View in the display switcher (tooltip "Board View").
- Click Tech View in the display switcher at the right of the toolbar (tooltip "Tech View"), then pick Compact density from its density button.
- In Board View's Fields to display (switch to Board View first), turn on Service advisor, Line count and Created date quickly, one after another.
- Leave the density as it is (Compact was picked in Tech View at step 4).
- Scroll a long column so more cards load.
- In DebugView, count each event name for this session.

## Expected (source quote — judge against this, never change it)
Expected results
- work_orders_display_view = 5 (load 1 + Tech View 1 + Board View 1 + Tech View 1 + Board View again in step 5, 1).
- work_orders_field_load = 13 + 17 = 30 (Board View and Tech View once each, never again in the session).
- work_orders_density_load = 1 (Tech View only; Board View has no density in this release).
- work_orders_field_toggle = 3 (one per changed field, even when changed quickly together).
- work_orders_density_change = 1. Step 7 adds nothing.
- Grand total = 5 + 30 + 1 + 3 + 1 = 40 events. Use these counts as the sample for the report check in the field selection rate case.
QA lead decision, 19 Oct 2026: Tech View's count is 17, not 15. PRD version 64, S2-R4: “Tech View offers the same columns as List, plus the Assigned Techs column (Story 7), through its own column chooser (Story 5).” List offers 16 columns, plus Assigned Techs makes 17. The earlier 15 came from a developer's comment of 6 Oct 2026.
