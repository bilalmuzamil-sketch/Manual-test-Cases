# C96910 — A user who never chose a display sees List
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481855

## Preconditions
Preconditions
- Needs: 2 users · 1 browser · about 15 minutes.
- Build: the Work Orders QA build (sv10043, v26.40.8-7a95011).
- [User-A] = you: an Owner/Admin user (on a QA branch the Admin quick-login user, shown as "Admin ShopView"). The Admin role holds Work orders > View and Work orders > Create & Edit.
- [User-B]: a brand-new user who has never opened Work Orders, with a role that has Work Orders view (e.g. Service Advisor) and this location picked in Location, and an email you can open.
- Desktop browser with the window at least 1024 pixels wide (full screen on an ordinary laptop or monitor). Below that width the page shows only List.
- One location for the whole case, shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); everything below is created in this location.
- [Tech-A]: one eligible technician at this location. A person only counts as a technician here when the staff member is active (not deactivated), Time Clock is on, the Role is neither Office User nor Time Clock User, and this location is picked in their Location field.
- Customer "ZZAUTOTEST F1 Default List" (used by this case only) with one Approved work order [WO-1] led by [Tech-A].
- Names are examples; what must hold: [User-B] has never opened Work Orders (so has never chosen a display).

## Steps
- Sign out.
- Sign in as [User-B].
- Open Work Orders from the top navigation.
- Look at the work orders area and the display switcher.
- Refresh the page.
- Look at the display again.

## Expected (source quote — judge against this, never change it)
Expected results
- The page opens in List: the ordinary work order table, not grouped by technician and not shown as columns of cards.
- In the display switcher the List option is the highlighted one.
- After the refresh the page is still in List.
Source — where this behaviour comes from
Epic SV-10043; story SV-10044 (Story 1, Switch between display options); PRD Confluence 845185030, edited 7 Oct 2026 (status line "PRD v33"), S1-R2, Key Decisions, read 8 Oct 2026.
Exact quotes from the source (for reproducibility)
- S1-R2: “List is the default display option for every user until they choose another.”
- Key Decisions: “Default display option remains List. Existing users see no change until they choose otherwise.”
