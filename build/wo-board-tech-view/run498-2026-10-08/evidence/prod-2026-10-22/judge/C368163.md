# C368163 — Searching in the Reassign lead technician dialog narrows the technician list
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3763434

## Preconditions
Setup (manual QA tester and Claude session)
Preconditions
- You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).
- Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.
- Technicians {Technician-A} (for example Esther Howard), {Technician-B} (for example Ralph Edwards) and {Technician-C} (for example Dana Ortiz) are active staff members at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.
- No other eligible technician at {Location-A} has the first three letters of {Technician-B}'s first name (for example "ral") anywhere in its name, in any letter case, and none matches "zzqx".
- Staff member {User-B} (for example Owen Office) is active at {Location-A} with the Office User role.
- Customer {Customer-A} (for example "ZZAUTOTEST F1 Dialog Search") has one Approved work order, {Work-order-1} (for example S10043-17671), led by {Technician-A}.
- On the Work Orders page nothing is ticked in Status, Asset on Site shows no choice (if its chip shows Yes or No, click the x on the chip), Assigned to me is off and Search is empty.

## Steps
- Open Work Orders, click the All tab and click Board View in the display switcher.
- Type the name of {Customer-A} in Search.
- Hover {Work-order-1}'s card in {Technician-A}'s column and click its More actions (…) button.
- Click Reassign lead technician.
- Read the top of the dialog and the list of choices.
- Click the dialog's search box (it reads Search technicians) and type the first three letters of {Technician-B}'s first name with a capital first letter (for example Ral).
- Clear the search box and type the same three letters in lower case (for example ral).
- Clear the search box and type the first name of {User-B} (for example Owen).
- Clear the search box and type zzqx.
- Clear the search box.
- Click Cancel.
- Open the same card's More actions (…) menu again and click Reassign lead technician.
- Read the search box.
- Click Cancel.
- Click Tech View in the display switcher.
- Hover {Work-order-1}'s row, click its More actions (…) button and click Reassign lead technician.
- Type the same three letters as at step 6 in the search box, read the list, then click Cancel.

## Expected (source quote — judge against this, never change it)
Expected results
- Step 5: the dialog names the work order it changes, by number and customer (for example "S10043-17671 · ZZAUTOTEST F1 Dialog Search"), and marks {Technician-A} as the current lead. Its first row is Unassigned, followed by the eligible technicians of {Location-A}, {Technician-A}, {Technician-B} and {Technician-C}, with no grouping.
- Step 6: only technicians whose name contains the typed letters stay in the list: {Technician-B}. {Technician-A} and {Technician-C} disappear from it.
- Step 7: lower-case letters give the same list, {Technician-B} only. Upper or lower case does not matter.
- Step 8: no technician is listed for {User-B}'s name. {User-B} has the Office User role and is never offered, not even by searching.
- Steps 8 and 9: when nothing matches, the dialog says so and repeats what you typed (in the design: No technicians match “zzqx”). Write down the words you see; a different wording alone is not a fail.
- Step 10: clearing the search box brings back the whole list from step 5.
- Step 11: nothing changes. The card stays in {Technician-A}'s column and no message appears.
- Step 13: the search box is empty when the dialog opens again.
- Step 17: Tech View's dialog narrows the list the same way, to {Technician-B}, and after Cancel the row stays in {Technician-A}'s group.
Source — where this behaviour comes from
Epic SV-10043; story SV-10047 (Story 4, Reassign or unassign the lead technician); PRD "Work Orders — Board View & Tech View Display Options", Confluence 845185030, version 54 (15 Oct 2026, Chris Ward), S4-R12 and S4-R14, read 15 Oct 2026. Eligibility from PRD section 5 Terminology (Technician). Design export of 8 Oct 2026 (Branko Cicovic, Claude Design project 787fef1a, Work Orders.dc.html): subtitle "work order number · customer", search box "Search technicians" keeping the technicians whose name contains the typed text in any letter case, current lead highlighted with a check mark, no-match text "No technicians match “the typed text”", search emptied each time the dialog opens; these design-only details are cited to the design, and the PRD fixes the list content (S4-R12). Product owner answers: Chris Ward, WO Board and Tech View question sheet (https://docs.google.com/spreadsheets/d/1gBGmNB4B1bRrD2ZJvBn1tuvbfxFPjcsKddz_I5H3CvU), answer 19, read 15 Oct 2026. Source-verified 15 October 2026. Last checked against build v26.40.19-72f4f3b (staging) on 10/16/2026.
The PRD (version 52) listed the dialog's content, search, grouping, avatars and N open count as design work still owed. Chris Ward answered on 15 Oct 2026 (answer 19) that the dialog is final as drawn, with Unassigned as its first row; PRD version 54 removes that line and says so in S4-R12.
Exact quotes from the source (for reproducibility)
- S4-R12: “The dialog offers eligible active technicians in the current location and Unassigned. It follows the design: a Search technicians box, each technician with their avatar and N open count, no grouping. Unassigned is the first row.”
- S4-R14: “Canceling the dialog leaves the lead unchanged.”
