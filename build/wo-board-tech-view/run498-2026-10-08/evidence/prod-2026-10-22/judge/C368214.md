# C368214 — After Back and Forward the List keeps its tab, search and filters
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3792535

## Preconditions
Setup file (for Claude sessions; a tester does not need it)
Preconditions
- You are signed in with the "Admin" role at {Location-A}.
For example: {Location-A} is Staging Heavy Duty - 9919.
- Customer {Customer-A} has one Approved work order, {Work-order-1}.
For example: {Customer-A} is ZZAUTOTEST C368214 Back Forward and {Work-order-1} is S10043-17751.
- Starting screen: "Work Orders" > "All" tab (the "Status" filter is on this tab), "List" shown, "Search" empty, no filter chosen, "Assigned to me" off, in a browser window at least 1024 px wide.
- If any record above is missing, mark this test Blocked: "setup not done".

## Steps
- Click "Status" and tick "Approved".
- Type the name of {Customer-A} in "Search".
- Click {Work-order-1}'s row.
- Press the browser Back button.
- Press the browser Forward button.
- Press the browser Back button.

## Expected (source quote — judge against this, never change it)
Expected results
- Step 1: the "Status" chip shows "Approved".
- Step 2: {Work-order-1}'s row shows.
- Step 3: the work order page for {Work-order-1} opens.
- Step 4: List comes back on the "All" tab with "Status" "Approved" and the same rows, as it does in production today.
- Step 5: the work order page for {Work-order-1} opens again.
- Step 6: List shows the same tab, filter and rows as at step 4.
Source — where this behaviour comes from
Regression for epic SV-10043 (PR #3548); developer's regression list, received 8 Oct 2026; QA handoff test plan (generated 2026-10-08), hotspot 3; PRD "Work Orders — Board View & Tech View Display Options", Confluence 845185030, version 61 (16 Oct 2026, Chris Ward), S1-R8 and section 1 Business Case where quoted, read 16 Oct 2026. In versions 54 and 61 S1-R8 gained sentences about Tech View and Board View; its List sentences are unchanged, so the expected results are unchanged. Source-verified 16 October 2026. Last checked against build v26.40.19-e435950 (staging) on 10/19/2026.
QA lead decision, 19 Oct 2026: the "Status" filter is offered on the "All" tab only (production does the same), so this case uses the "All" tab.
Exact quotes from the source (for reproducibility)
- QA handoff hotspot 3: “The rebuilt Work Orders List. Check saved preferences against URL links, Back and Forward, location switch, stale rows after an edit, and sorting and paging.”
- S1-R8: “In Tech View and Board View, browser Back restores both vertical and horizontal scroll position. Horizontal position comes back exactly, and so do the filter view (tab) and filters that were on screen, in Tech View and Board View. List’s Back behavior is unchanged in this release. Vertically, the row or card that was at the top of the view comes back at the top, fully shown; it may sit up to one row or card from the exact pixel position. List behaves as it does today.”
- PRD section 1 Business Case: “List remains the default and stays exactly as it is in production today; the only addition to the Work Orders page is the switcher that offers the two new displays.”
