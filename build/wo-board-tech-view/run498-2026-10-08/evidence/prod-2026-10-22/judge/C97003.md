# C97003 — A view-only user can reorder technician columns and Unassigned stays first
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481947

## Preconditions
Preconditions
- Needs: 2 users · 2 browsers · about 25 minutes
- Build: staging (https://app.staging.shopview.com), v26.40.19-e435950. Desktop browser window at least 1024 px wide (narrower windows show only the List, without the display switcher).
- [User-A]: the dispatcher, Owner/Admin. On a QA branch sign in with the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". The Admin role holds Work orders > View and Work orders > Create & Edit. [User-A] also does the setup.
- [User-B]: a view-only user (e.g. "ZZAUTOTEST Viewer") whose role (e.g. "ZZAUTOTEST WO View Only") has under Work orders only View ticked, at the test location; signed in later in a second browser or a private window. No technician is pinned for [User-B], and [User-B] has not reordered the technicians yet.
- Location: one location for the whole case, shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); to change it click your initials at the top right > Change Location. Every technician and work order below belongs to this location.
- Technicians (examples, the expected results call them by first name or full name): "ZZAUTOTEST Ana Alpha", "ZZAUTOTEST Ben Bravo", "ZZAUTOTEST Cal Charlie". A staff member counts as a technician when, in Settings > Staff > the staff member's edit icon > Edit Staff Member, they are Active, Time Clock is on, the Role is neither Office User nor Time Clock User, and this location is picked in their Location field.
- Customers (used by this case only, each with one contact and one asset): "ZZAUTOTEST F3 Viewer Column Order Alpha Co", "ZZAUTOTEST F3 Viewer Column Order Golf Co". The steps and expected results call them by the end of the name ("Alpha Co", "Golf Co").
- Work orders (both Approved): lead Ana — Alpha Co; no lead — Golf Co.
- Starting technician order: Unassigned first, then technicians by first name (Ana, Ben, Cal) for both users.
Setup
- Settings (your initials at the top right > Settings) > Staff: confirm "ZZAUTOTEST Ana Alpha", "ZZAUTOTEST Ben Bravo", "ZZAUTOTEST Cal Charlie" exist and count as technicians at this location (edit icon > Edit Staff Member). To add one: New Staff Member with those settings (at least one Department is required) (e.g. first name "ZZAUTOTEST Ana", last name "Alpha") > Save & Close.
- Create a view-only user (skip if one exists): Settings > Roles & Permissions > Create Custom Role > Skip > Role Name (e.g. "ZZAUTOTEST WO View Only") > under Work orders tick only View > Create. Then Settings (your initials at the top right > Settings) > Staff > New Staff Member (e.g. "ZZAUTOTEST Viewer", an email inbox you can open) with that role at the test location, and finish the invite so the user can sign in. Record this user as [User-B].
- Create this case's customers: "ZZAUTOTEST F3 Viewer Column Order Alpha Co", "ZZAUTOTEST F3 Viewer Column Order Golf Co". For each: top menu Customers > New Customer, Name > Save; on the customer page click the Contacts tab > New Contact > Fi

## Steps
- Sign in as the view-only user [User-B] (e.g. ZZAUTOTEST Viewer).
- Open Work Orders from the top menu and click the All tab.
- Type "ZZAUTOTEST F3 Viewer Column Order" in Search so only this case's work orders show.
- Click Board View in the display switcher (tooltip "Board View").
- Write down the column order (initially Unassigned first, then technicians by first name: Ana, Ben, Cal).
- Press on the drag handle at the left of Cal's column header (the six-dot handle) and drag Cal's column before Ana's, then release.
- Try to drag Ben's column to the left of the Unassigned column and release there.
- Try to press on the Unassigned column header and drag it to the right of Cal. Then write down the column order.
- Click Tech View in the display switcher at the right of the toolbar (tooltip "Tech View").
- Try to drag Ben's group header above the Unassigned group and release there.
- Refresh the page (F5) and read the technician order in Tech View and in Board View.
- In another browser, sign in as the dispatcher [User-A] (create and edit user), open Work Orders > All > Board View and read the technician order.

## Expected (source quote — judge against this, never change it)
Expected results
- Step 6: the view-only user can drag a technician column. The order becomes Unassigned, Cal, Ana, Ben.
- Step 7: Ben cannot be placed before Unassigned. Unassigned stays the first column.
- Step 8: the Unassigned column cannot be dragged.
- Step 10: in Tech View, Unassigned stays the first group and Ben cannot be dropped above it.
- Step 11: after the refresh the view-only user still sees, in both views, the column order written down at step 8, with Unassigned first (for example: Unassigned, Ben, Cal, Ana).
- Step 12: the dispatcher's own technician order is unchanged (Unassigned, Ana, Ben, Cal) because the order is saved per user.
Source — where this behaviour comes from
Epic SV-10043; story SV-10052 (Story 9, Drag to reorder work and technician groups/columns); PRD Confluence 845185030, edited 7 Oct 2026 (status line "PRD v33"), S9-R2, S9-R8, read 8 Oct 2026. Story 9 prerequisite and Key Decisions (Permissions), same PRD. Tech plan (revised 24 Sep 2026) Phase 9 drop rules.
Exact quotes from the source (for reproducibility)
- S9-R2: “Users with Work Orders view permission can reorder technician groups and columns. The order is saved per user.”
- S9-R8: “Keep Unassigned fixed during technician reordering.”
- Story 9 prerequisite: “View permission permits technician-only group/column reordering.”
- Key decision: permissions: “Permissions. Work Orders view permits viewing all four filter tabs and reordering technician groups/columns.”
- Tech plan Phase 9 drop rules: “technician-group drags stay inside their area — pinned technicians reorder only among pins, and Unassigned is never a technician drop target (S9-R8, S9-R9)”
Last checked against build v26.40.19-e435950 (staging) on 10/19/2026.
QA lead decision, 19 Oct 2026: step 11 compares with the order written down at step 8, because the step 7 try moves Ben to just after Unassigned; Unassigned stays first, as S9-R8 requires.

## Newest PASSED result in run 498 (staging judgement)
Tested on staging, build v26.40.19-e435950, on 19 October 2026.
- Result: Passed on staging, signed in as a user who can only view work orders.
- The view-only user could drag Cal's column; Unassigned stayed the first column.
- Trying to drop Ben before Unassigned put Ben just after Unassigned instead; Unassigned could not be dragged at all; in Tech View Ben could not be dropped above Unassigned.
- After refreshing, both views kept the order left at step 8: Unassigned, Ben, Cal, Ana. Step 11 now compares with that written-down order (QA lead's decision, 19 Oct 2026).
- The dispatcher's own order was unchanged: Unassigned, Ana, Ben, Cal, because the order is saved per user.
