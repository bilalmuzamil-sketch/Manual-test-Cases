# C368130 — A location with no technicians shows only Unassigned in Tech View and Board View
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3761651

## Preconditions
Setup (manual QA tester and Claude session)
Preconditions
- You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit.
- Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.
- Location {Location-A} (for example "ZZAUTOTEST F2 Empty Shop") is used by this case only and has no technicians: no staff member has {Location-A} in their Location field. You are working at {Location-A}.
- Customer {Customer-A} (for example "ZZAUTOTEST F2 No Tech Location") has two Approved work orders at {Location-A}, {Work-order-1} and {Work-order-2} (for example S10043-17831 and S10043-17832), with no lead technician.
- On the Work Orders page nothing is ticked in Status, Asset on Site shows no choice (if its chip shows Yes or No, click the x on the chip), Assigned to me is off and Search is empty.

## Steps
- Open Work Orders and click the All tab.
- Click Tech View in the display switcher.
- Read what the page shows.
- Click Board View in the display switcher.
- Read what the page shows.

## Expected (source quote — judge against this, never change it)
Expected results
- Step 3: Tech View shows the Unassigned group holding {Work-order-1} and {Work-order-2}, and no technician groups.
- Step 5: Board View shows the Unassigned column holding {Work-order-1} and {Work-order-2}, and no technician columns.
- Steps 3 and 5: both displays explain that there are no technicians. The PRD does not fix the wording: write down what you see (the design reads "No technicians yet" and "Add technicians to assign work orders. Until then, every work order stays in Unassigned."). A different wording alone is not a fail.
Source — where this behaviour comes from
Epic SV-10043; story SV-10045 (Story 2, Tech View — table grouped by lead technician); PRD "Work Orders — Board View & Tech View Display Options", Confluence 845185030, version 54 (15 Oct 2026, Chris Ward), Design updates required from Branko, S2-R2 and S3-R1, read 15 Oct 2026. The Design updates line was reworded in version 43 (8 Oct 2026); the no-technicians state is still listed as design work, so the expected results are unchanged. Claude Design export of 14 Oct 2026 (Work Orders.dc.html), no-technicians empty state. PRD footer comment Slavcho Mitrov 1 Oct 2026 item 3 (the panel explains work stays in Unassigned, no Add Technician button). Source-verified 15 October 2026. Last checked against build v26.40.19-72f4f3b (staging) on 10/16/2026.
Exact quotes from the source (for reproducibility)
- Design updates required from Branko: “Filtered-empty results (the List's empty state, S1-N1), and an organization with no technicians, in both new views.”
- S2-R2: “Keep Unassigned, containing work orders without a lead technician, fixed before all technician groups.”
- S3-R1: “Show one Board View column per eligible technician under S2-R7, plus Unassigned.”
- Design — Work Orders.dc.html, no-technicians empty state: “Add technicians to assign work orders. Until then, every work order stays in Unassigned.”
