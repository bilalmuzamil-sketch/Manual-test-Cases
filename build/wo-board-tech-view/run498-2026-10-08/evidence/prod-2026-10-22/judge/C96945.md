# C96945 — A card's More actions menu appears on hover or focus and offers Reassign
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481889

## Preconditions
Setup file (for Claude sessions; a tester does not need it)
Preconditions
- You are signed in as an Admin user (the "Admin" role, which has Work orders > View and Create & Edit) at {Location-A}.
For example: {Location-A} is Staging Heavy Duty - 9919.
- Technician {Technician-A} is active at {Location-A} with the "Technician" role and is pinned in your Board View.
For example: {Technician-A} is ZZAUTOTEST C96945 Ana.
- Customer {Customer-A} has one Approved work order, {Work-order-1}, led by {Technician-A}.
For example: {Customer-A} is ZZAUTOTEST C96945 Card Menu and {Work-order-1} is S10043-17731.
- Starting screen: "Work Orders" > "All" tab, "Board View" shown, the name of {Customer-A} in "Search", no filter chosen, "Assigned to me" off, in a browser window at least 1024 px wide.
- If any record above is missing, mark this test Blocked: "setup not done".

## Steps
- Hover the card for {Work-order-1}.
- Click the "More actions" (…) button that appears.
- Read the menu items.
- Press Escape.
- Move the mouse off the card and click once on an empty part of the page. (After Escape the keyboard focus stays on the "More actions" button, which keeps it showing until the focus leaves the card.)
- Click once in the "Search" box.
- Press Tab until a card shows a focus ring.
- Use the arrow keys to move the focus ring to the card for {Work-order-1}.

## Expected (source quote — judge against this, never change it)
Expected results
- Step 1: the "More actions" (…) button appears on the card.
- Step 2: the card's menu opens.
- Step 3: the menu includes "Reassign lead technician".
- Step 4: the menu closes.
- Step 5: the "More actions" button is hidden again.
- Step 6: the cursor is in the "Search" box.
- Step 7: a card shows the focus ring.
- Step 8: the card for {Work-order-1} shows the focus ring and its "More actions" (…) button shows without hovering.
Source — where this behaviour comes from
Epic SV-10043; story SV-10046 (Story 3, Board View — board by lead technician); PRD "Work Orders — Board View & Tech View Display Options", Confluence 845185030, version 61 (16 Oct 2026, Chris Ward), S3-R13, S3-R14, S11-R1 and S11-R3, read 16 Oct 2026. Design: Claude Design export of 8 Oct 2026 (Work Orders.dc.html), Board card more-actions menu; on-screen labels only. Source-verified 16 October 2026. Last checked against build v26.40.19-1493c63 (staging) on 10/16/2026.
Until 16 Oct 2026 this case reached the card by pressing Tab repeatedly. PRD version 54 said Tab reaches every row, card and header in on-screen order. PRD versions 55, 60 and 61 (15 and 16 Oct 2026, Chris Ward rulings on Slavcho Mitrov's questions and the QA triage of SV-11395, SV-11397, SV-11422 and SV-11421) changed this: each view is one Tab stop that lands on a work order, and the arrow keys move between cards, rows, headers and columns. This case follows version 61, the latest.
Exact quotes from the source (for reproducibility)
- S3-R13: “Reveal the card’s more-actions overlay on hover or keyboard focus.”
- S3-R14: “Include Reassign lead technician in the card’s more-actions menu.”
- S11-R1: “Each view is a single Tab stop. Tab lands on one work order row (Tech View) or card (Board View), the one last focused, or the first one when none has been (never a group or column header while a work order is shown; when every group is collapsed, Tab lands on the first group header; after the user arrows onto a header and tabs out and back in, Tab returns to a work order row while any row is shown; on Board View, if the last-focused card has scrolled out of view in its column, Tab lands on the first card in view); the focused row or card shows a visible focus ring.”
- S11-R3: “Inside a view the arrow keys move focus: Up and Down move between rows and group headers in Tech View, and between cards and the column header within a Board View column; Left and Right move between Board View columns. Tab from a focused row, card or header reaches its own controls (more actions, pin, collapse) in order, then leaves the view. Tab never stops on every row.”
