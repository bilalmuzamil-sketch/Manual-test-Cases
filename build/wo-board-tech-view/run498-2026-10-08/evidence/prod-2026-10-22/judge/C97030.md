# C97030 — Header counts match the rows and cards listed, in every display
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481968

## Preconditions
Preconditions
- Needs: 1 user · 1 browser · about 30 minutes
- Build: the Work Orders QA build (sv10043). Desktop browser window at least 1024 px wide (narrower windows show only the List, without the display switcher).
- Role: Owner/Admin. On a QA branch sign in with the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". The Admin role holds Work orders > View and Work orders > Create & Edit (to check: your initials at the top right > Settings > Roles & Permissions > Admin > Work orders). This user is the dispatcher.
- Location: one location for the whole case, shown in the top bar next to the bell (e.g. "Staging Heavy Duty - 9919"); to change it click your initials at the top right > Change Location. Every technician and work order below belongs to this location.
- Technicians (examples, the expected results call them by first name or full name): "ZZAUTOTEST Ana Alpha", "ZZAUTOTEST Ben Bravo", "ZZAUTOTEST Cal Charlie". A staff member counts as a technician when, in Settings > Staff > the staff member's edit icon > Edit Staff Member, they are Active, Time Clock is on, the Role is neither Office User nor Time Clock User, and this location is picked in their Location field.
- Customers (used by this case only, each with one contact and one asset): "ZZAUTOTEST F3 Header Counts Alpha Co", "ZZAUTOTEST F3 Header Counts Bravo Co", "ZZAUTOTEST F3 Header Counts Charlie Co", "ZZAUTOTEST F3 Header Counts Delta Co", "ZZAUTOTEST F3 Header Counts Echo Co", "ZZAUTOTEST F3 Header Counts Golf Co", "ZZAUTOTEST F3 Header Counts Hotel Co". The steps and expected results call them by the end of the name ("Alpha Co", "Bravo Co", "Charlie Co", "Delta Co", "Echo Co", "Golf Co", "Hotel Co").
- Exactly these work orders for this case:- Lead Ana: Alpha Co Approved, Bravo Co Approved, Charlie Co Estimate (3).
- Lead Ben: Delta Co In Progress, Echo Co Invoiced (2).
- Lead Cal: none (0).
- No lead: Golf Co Approved, Hotel Co Estimate (2).
- Total: 3 + 2 + 0 + 2 = 7.
- The Status filter starts with nothing ticked.
- None of these technicians has a shift on the Schedule for these work orders (check the Schedule page). If a window titled "Clear … scheduled shifts?" still appears during a move, click "Keep shifts".
Setup
- Settings (your initials at the top right > Settings) > Staff: confirm "ZZAUTOTEST Ana Alpha", "ZZAUTOTEST Ben Bravo", "ZZAUTOTEST Cal Charlie" exist and count as technicians at this location (edit icon > Edit Staff Member). To add one: New Staff Member with those settings (at least one Department is required) (e.g. first name "ZZAUTOTEST Ana", last name "Alpha") > Save & Close.
- Create this case's customers: "ZZAUTOTEST F3 Header Counts Alpha Co", "ZZAUTOTEST F3 Header Counts Bravo Co", "ZZAUTOTEST F3 Header Counts Charlie Co", "ZZAUTOTEST F3 Header Counts Delta Co", "ZZAUTOTEST F3 Header Counts Echo Co", "ZZAUTOTEST F3 Header Counts Golf Co", "ZZAUTOTEST F3 Header Counts Hotel Co". For each: top menu Customers > New Customer, Name 

## Steps
- Open Work Orders from the top menu and click the All tab.
- Type "ZZAUTOTEST F3 Header Counts" in Search so only this case's work orders show.
- Click List in the display switcher (tooltip "List").
- Count the List rows.
- Click Tech View in the display switcher at the right of the toolbar (tooltip "Tech View").
- Read each group header count and count the rows under each group.
- Click Board View in the display switcher (tooltip "Board View").
- Read each column header count and count the cards in each column.
- Click Status and tick "Approved" only. Read the counts in Board View, then in Tech View, and count the List rows.
- Clear the Status filter and click the Estimates tab. Read the counts in Board View and in Tech View.

## Expected (source quote — judge against this, never change it)
Expected results
- Step 4: List shows 7 rows.
- Step 6: Tech View headers read Unassigned 2, Ana 3, Ben 2, Cal 0. Each count equals the rows under it, and 2 + 3 + 2 + 0 = 7 = the List rows.
- Step 8: Board View columns read Unassigned 2, Ana 3, Ben 2, Cal 0. Each count equals the cards in the column, with the same total 7.
- Step 9: Unassigned 1 (Golf Co), Ana 2 (Alpha Co, Bravo Co), Ben 0, Cal 0, total 3, in both views and the same as the 3 List rows.
- Step 10: Unassigned 1 (Hotel Co), Ana 1 (Charlie Co), Ben 0, Cal 0 in both views. Each count always equals what is listed under it.
Source — where this behaviour comes from
Epic SV-10043; story SV-10045 (Story 2, Tech View); SV-10046 (Story 3, Board View); PRD Confluence 845185030, edited 7 Oct 2026 (status line "PRD v33"), S2-R12, S3-R12, read 8 Oct 2026. Inline PRD comment answer by Chris Ward, 25 Sep 2026 (count = work orders shown after filters).
Exact quotes from the source (for reproducibility)
- S2-R12: “Each group header shows the technician’s name, avatar, and a count of the work orders currently shown in that group, after the filter view and filters are applied, so the count always matches the rows listed.”
- S3-R12: “Each column header shows the technician’s name, avatar, and a count of the work orders currently shown in that column, after the filter view and filters are applied, so the count always matches the cards listed.”
