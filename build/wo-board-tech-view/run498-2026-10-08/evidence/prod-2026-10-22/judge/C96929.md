# C96929 — A group's work orders are in the order their leads were given, not List's sort
Test in run 498: https://shopview.testrail.io/index.php?/tests/view/3481873

## Preconditions
Setup (manual QA tester and Claude session)
Preconditions
- You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).
- Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.
- User {User-B} (for example ZZAUTOTEST Sort Viewer) is a new staff member with the Admin role at {Location-A}, can sign in, and has never changed or saved a sort in List.
- Technician {Technician-A} (for example Kristin Watson) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User. {Technician-A} leads no other work order.
- Customers {Customer-A} (for example "ZZAUTOTEST F2 Sort Alpha Freight"), {Customer-B} (for example "ZZAUTOTEST F2 Sort Mid Trucking") and {Customer-C} (for example "ZZAUTOTEST F2 Sort Zeta Hauling") start with the same words (for example ZZAUTOTEST F2 Sort) and are used by this case only.
- Four Approved work orders, all led by {Technician-A}, were created in this order: {Work-order-1} (for example S10043-17621) for {Customer-C}, {Work-order-2} (for example S10043-17622) for {Customer-A}, {Work-order-3} (for example S10043-17623) for {Customer-B} and {Work-order-4} (for example S10043-17624) for {Customer-B}.
- Each of the four got {Technician-A} as its lead after it was created (on the work order page, with Lead Technician on the status card), one after another, in a known order. Write down that order. For example: {Work-order-1}, then {Work-order-3}, then {Work-order-4}, then {Work-order-2}.
- Nobody has reordered {Technician-A}'s work orders at {Location-A}.
- On the Work Orders page nothing is ticked in Status, Asset on Site shows no choice (if its chip shows Yes or No, click the x on the chip), Assigned to me is off and Search is empty.

## Steps
- Sign in as {User-B}.
- Open Work Orders, click the All tab and click List in the display switcher.
- Type the shared start of the three customer names (for example ZZAUTOTEST F2 Sort) in Search.
- Write down the order of the four work orders in List.
- Click Tech View in the display switcher.
- Write down the order of the rows in {Technician-A}'s group.
- Click Board View in the display switcher.
- Write down the order of the cards in {Technician-A}'s column.

## Expected (source quote — judge against this, never change it)
Expected results
- Step 4: List shows the four work orders in its usual default order: by customer name from A to Z (with the example names: {Customer-A}, then {Customer-B}’s two work orders, then {Customer-C}). The List itself does not change (S2-R6).
- Step 6: Tech View’s rows in {Technician-A}’s group are in the order the leads were given: each work order that got its lead after it was created went to the bottom of {Technician-A}’s work (S2-R6, S9-R14). With the example order: {Work-order-1}, {Work-order-3}, {Work-order-4}, {Work-order-2}. This is not List’s order.
- Step 8: Board View’s cards in {Technician-A}’s column are in the same order as Tech View’s rows (S9-R14: “in both views”).
Source — where this behaviour comes from
- Epic SV-10043; stories SV-10045 (Story 2, Tech View — table grouped by lead technician) and SV-10052 (Story 9, Drag to reorder). PRD “Work Orders — Board View & Tech View Display Options”, Confluence 845185030, version 68 (19 Oct 2026, Chris Ward), S2-R6 and S9-R14, read 19 Oct 2026. Review Decisions 853901313 DR-45 (desktop List default sort is customer name A to Z).
- When it changed: PRD change log, version 53, 15 Oct 2026, Chris Ward: “S9-R14 confirmed as written: a lead given after creation puts the work order at the bottom of that technician’s work (SV-11312 works as specified).”
- Updated 19 Oct 2026 on the QA lead’s instruction, to PRD version 64 (was: Tech View and Board View follow List’s order).
Exact quotes from the source (for reproducibility)
- S2-R6: “Before a manual order is saved, use the List’s default work order sort, ties included, exactly as the List sorts today: work orders for the same customer go by start date, newest first. The List itself does not change. A work order that gets a new lead after it was created goes to the bottom of that technician’s work instead (S9-R14).”
- S9-R14: “A work order that gets a new lead from the lead technician dialog (Assign or Reassign lead technician) or from its detail page goes to the bottom of the new technician’s work, for everyone at the location, in both views. A work order dragged to a technician goes where it is dropped. Removing the lead with the menu’s Unassign action (S11-R9) or on the detail page puts the work order in Unassigned in the initial sort, not at the bottom, so it is not lost behind every other unassigned work order. Going to the bottom applies only to work moved onto a technician. A work order created or split off with a lead keeps the initial sort (S9-R3).”

## Newest PASSED result in run 498 (staging judgement)
Tested on staging, build v26.40.19-e435950, on 19 October 2026, signed in as Admin, window 1440 px wide.
- Result: Passed. The build does what the test now expects, which is what the spec says.
- Set-up: a new technician, Nora Sort QA1019 (leads no other work, nobody has reordered her work). Four work orders made in this order: S2-37437 (Zeta Hauling QA1019), S2-37438 (Alpha Freight QA1019), S2-37439 and S2-37440 (Mid Trucking QA1019). Her name was then given as lead one after another with Reassign lead technician: S2-37437, S2-37439, S2-37440, S2-37438.
- Step 4, List with no saved sort (Customer, A to Z): S2-37438 Alpha, S2-37440 Mid (newer first), S2-37439 Mid, S2-37437 Zeta. Picture 1.
- Step 6, Tech View, Nora Sort QA1019's group: S2-37437, S2-37439, S2-37440, S2-37438, the order the leads were given, not List's order. Picture 2, left.
- Step 8, Board View, her column: the same order. Picture 2, right.
- Source checked: the developer's closing note on SV-11101 (comment 78793) and SV-11312 (comment 78792) says a work order that gets its lead after it was created goes to the bottom of that technician's work. The spec "Work Orders - Board View & Tech View Display Options", version 64, says the same in S9-R14 ("A work order that gets a new lead from the Reassign lead technician dialog or from its detail page goes to the bottom of the new technician's work, for everyone at the location, in both views.") and S2-R6, and its change log records Chris Ward confirming it in version 53 (15 Oct 2026). So the developer's note is correct.
- Not covered by this test: a work order created with its lead already set (the spec says it keeps the List's order). The New Work Order screen has no lead field, so that only happens through a split or the Schedule.
