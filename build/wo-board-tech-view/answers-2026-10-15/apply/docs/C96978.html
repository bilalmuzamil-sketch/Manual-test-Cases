Setup: Fields to display offers the 13 optional fields with their usual values

Test case: C96978, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Technicians {Technician-A} (for example Esther Howard) and {Technician-B} (for example Ralph Edwards) are active staff members at {Location-A} with Time Clock on, a Role other than Office User or Time Clock User, and can sign in.

• Staff member {Advisor-A} (for example James Smith) can be picked as a Service Advisor.

• Customer {Customer-A} (for example "ZZAUTOTEST F2 Card Field Values") has an asset with a VIN (for example 1FUJGLDR5CSBM1234).

• Approved work order {Work-order-1} (for example S10043-17661) for {Customer-A} is led by {Technician-A}, has Service Advisor {Advisor-A}, Asset on site turned on and three approved lines with labor hours, {Line-1}, {Line-2} and {Line-3} (for example 2.0, 3.0 and 3.0 hours, 8.0 in all).

• {Line-2}'s technician is {Technician-B}, set through Edit Line.

• {Technician-A} is clocked in on {Line-1}'s Labor row and {Technician-B} on {Line-2}'s, so two people are clocked in.

• List's Column Selection shows Lead Technician, Asset, VIN/Serial #, Progress, Service Advisor, Clocked In, Lines, Total price, On Site and Created on.

• On the Work Orders page nothing is ticked in Status, Asset on Site shows no choice (if its chip shows Yes or No, click the x on the chip), Assigned to me is off and Search is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Esther Howard), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}. Give an email you can open, accept the invitation and set a password.

5. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Ralph Edwards), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-B}. Give an email you can open, accept the invitation and set a password.

6. Your initials > Settings > Staff: pick a staff member who can be chosen as Service Advisor on a work order (for example James Smith). This is {Advisor-A}.

7. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST F2 Card Field Values") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) and VIN/Serial # (for example 1FUJGLDR5CSBM1234) > Save. Contact and Make are required.

8. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17661). This is {Work-order-1}. On {Work-order-1}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

9. On {Work-order-1}'s Lines tab the first line is {Line-1}. Click New Line twice more and add two more ready-made lines with Line Approved on: {Line-2} and {Line-3}. Give the three lines labor hours (for example 2.0, 3.0 and 3.0, 8.0 in all).

10. On {Line-2} click Edit Line, pick {Technician-B} as its technician and save.

11. On the work order page pick {Advisor-A} as Service Advisor and turn Asset on site on.

12. In a second browser sign in as {Technician-A} and click Start on {Line-1}'s Labor row. Sign out, sign in as {Technician-B} and click Start on {Line-2}'s Labor row. Leave both clocked in until the test is over.

13. Work Orders > All > List > Column Selection: turn on Lead Technician, Asset, VIN/Serial #, Progress, Service Advisor, Clocked In, Lines, Total price, On Site and Created on.

14. Work Orders > All: clear any Status selection, click the x on the Asset on Site chip if it shows Yes or No, turn Assigned to me off and empty Search.

15. Check the setup worked: Work Orders > All > List > Search the name of {Customer-A}: {Work-order-1} shows Lead Technician {Technician-A}, 3 lines and a Clocked In value with two people. Then empty Search.

Part 2. Setup for Claude session

• Goal: one work order with every optional field filled and two people clocked in; compare the card with List.

• Clocking in: POST the time-clock start for each technician from that technician's session (playbook section on the time clock); record both clock-ins and stop them after the test.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Work Orders QA site for this feature (epic SV-10043): app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com. Use the site named in the test run if it differs.
  • Staging (after the feature is merged there): app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, window at least 1024 px wide. Do not run "playwright install".

Access

  • On a QA site, sign in with the sign-in page's Admin quick-login button (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Elsewhere, ask the QA lead for the environment's cookies.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.

Cleanup

Name everything you create with ZZAUTOTEST at the start. Leave ZZAUTOTEST records in place; they are marked as test data.
