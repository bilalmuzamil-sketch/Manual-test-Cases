Setup: Every control in Tech View and Board View works from the keyboard

Test case: C368151, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Technician {Technician-A} (for example ZZAUTOTEST Ana Alpha) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Technician {Technician-B} (for example ZZAUTOTEST Ben Bravo) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Customer {Customer-A} (for example "ZZAUTOTEST F3 Keyboard Controls") has four Approved work orders: {Work-order-1} (for example S10043-17701) and {Work-order-2} (for example S10043-17702) led by {Technician-A}, {Work-order-3} (for example S10043-17703) led by {Technician-B}, and {Work-order-4} (for example S10043-17704) with no lead technician.

• {Technician-A} is not pinned for you at the start.

• Tech View shows the Assigned Techs column (it is on by default).

• No technician has a shift on the Schedule for these work orders.

• On the Work Orders page nothing is ticked in Status, Asset on Site shows no choice (if its chip shows Yes or No, click the x on the chip), Assigned to me is off and Search is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example ZZAUTOTEST Ana Alpha), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}.

5. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example ZZAUTOTEST Ben Bravo), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-B}.

6. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST F3 Keyboard Controls") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

7. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17701). This is {Work-order-1}. On {Work-order-1}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

8. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17702). This is {Work-order-2}. On {Work-order-2}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

9. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17703). This is {Work-order-3}. 10. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17704). This is {Work-order-4}. Leave its Lead Technician empty, so it sits in Unassigned.

11. Open the Schedule page and check that {Technician-A} and {Technician-B} have no shift on this case's work orders. If a window titled "Clear … scheduled shifts?" still appears during a move, click Keep shifts.

12. Work Orders > All: clear any Status selection, click the x on the Asset on Site chip if it shows Yes or No, turn Assigned to me off and empty Search.

13. Work Orders > All > Board View: if {Technician-A}'s column header shows the pinned state, click the pin to unpin.

14. Check the setup worked: Work Orders > All > List > Search the name of {Customer-A} shows exactly four Approved work orders: {Work-order-1} and {Work-order-2} led by {Technician-A}, {Work-order-3} led by {Technician-B} and {Work-order-4} with no lead. Then empty Search.

Part 2. Setup for Claude session

• Goal: reach and use with the keyboard the More actions button, pin, collapse arrow, an avatar, Column Selection, a filter chip's x and the display switcher.

• Drive the keyboard with Playwright's keyboard.press only (no mouse) from the step named in the case; after each press record document.activeElement (its role, label and the work order number it belongs to) and whether a focus ring is drawn (outline or box-shadow).

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Work Orders QA site for this feature (epic SV-10043): app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com. Use the site named in the test run if it differs.
  • Staging (after the feature is merged there): app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, window at least 1024 px wide. Do not run "playwright install".

Access

  • On a QA site, sign in with the sign-in page's Admin quick-login button (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Elsewhere, ask the QA lead for the environment's cookies.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.

Cleanup

Name everything you create with ZZAUTOTEST at the start. Leave ZZAUTOTEST records in place; they are marked as test data.
