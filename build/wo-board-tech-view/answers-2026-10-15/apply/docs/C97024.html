Setup: Fields on and off are recorded once per display per session

Test case: C97024, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• You can open Google Analytics for the property the QA build reports to, at Admin > DebugView, and your device shows there within a few seconds of opening any ShopView page. If you cannot open DebugView, the event checks cannot be done by hand: write "not checked by hand" in the result comment and pass or fail on what you can see on the Work Orders page.

• The event names to look for in DebugView are work_orders_display_view, work_orders_field_load, work_orders_density_load, work_orders_field_toggle and work_orders_density_change.

• Your role has See financial data.

• In Board View's Fields to display, VIN/Serial is on as a saved choice and every other optional field is at its default.

• You start in a fresh browser session: every browser window was closed, a new private window opened and you signed in.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Check your role has See financial data: your initials > Settings > Roles & Permissions > your role.

5. Work Orders > Board View > Fields to display: turn VIN/Serial on, so one optional field is a saved choice; leave every other field at its default.

6. Close every browser window, open a new private window and sign in, so a fresh analytics session starts.

7. Check the setup worked: Google Analytics > Admin > DebugView opens and shows your device within a few seconds of opening any ShopView page. If it does not, carry on and write "not checked by hand" for the event checks.

Part 2. Setup for Claude session

• Goal: count the field-load events per display in one analytics session.

• Read the GA4 events from the page's dataLayer (window.dataLayer) after each step instead of DebugView, and record each work_orders_field_load event's field, value and source.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Access
