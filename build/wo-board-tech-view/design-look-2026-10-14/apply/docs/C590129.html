Setup: Reassign lead technician dialog looks as in the design

Test case: C590129, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as {User-A} (for example Admin ShopView), an Owner or Admin user whose role has Work orders > View, Work orders > Create & Edit and See financial data, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is 1440 px wide, with the browser zoom at 100%.

• The design picture DC-20-reassign-dialog-light-1440.png is open beside the app at 100% zoom (actual size); it is attached to this case.

• In the design pictures the names, numbers, dates and amounts are sample data, and the rank numbers (1, 2, 3 …) beside rows and cards are left out of this release, so do not compare those.

• The design's dialog title reads "Reassign Lead Tech" and it has no Unassigned row; the PRD names the action Reassign lead technician and offers Unassigned, so compare the layout and look only.

• Technician {Technician-A} (for example ZZAUTOTEST DC20 Bea Dialog) is an active technician at {Location-A} who has a profile photo.

• Technician {Technician-B} (for example ZZAUTOTEST DC20 Cal Dialog) is an active technician at {Location-A} who has no profile photo.

• Customer {Customer-A} (for example "ZZAUTOTEST DC20 Reassign Dialog") is used by this case only.

• Approved work order {Work-order-1} (for example S10043-17854) for {Customer-A} is led by {Technician-A}.

• On the Work Orders page nothing is chosen in any filter, Assigned to me is off, Search is empty and density is Regular (the default).

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". This is {User-A}. To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on (the Admin role has full access, See financial data included).

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a screen at least 1440 px wide (1536 px or wider if the case names 1536 px). Set the browser zoom to 100% (Ctrl+0, or Cmd+0 on a Mac). To give the window an exact width without developer tools, use a window-size browser extension (for example Window Resizer for Chrome) and choose 1440 × 900; it shows the size it set.

4. Open this case in TestRail and download the design picture named in the Preconditions from the case's attachments. Open each in an image viewer at 100% (actual size) and place it beside the browser window.

5. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User, and already have a profile photo. Otherwise click New Staff Member and enter First Name and Last Name (for example ZZAUTOTEST DC20 Bea Dialog), an Email you can open with ZZAUTOTEST in it, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}. To give {Technician-A} a profile photo: accept the invitation email sent to {Technician-A}'s email and set a password, sign in as {Technician-A} in a private browser window, click your initials (top right) > Edit Profile > click "Click to upload a profile photo" and pick any photo (for example a photo of a face), then close that window.

6. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User, and have no profile photo (a newly added staff member has none). Otherwise click New Staff Member and enter First Name and Last Name (for example ZZAUTOTEST DC20 Cal Dialog), an Email with ZZAUTOTEST in it, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-B}.

7. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST DC20 Reassign Dialog") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

8. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17854). This is {Work-order-1}. On {Work-order-1}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

9. Work Orders > All: open each filter in the filter bar and clear any selection, turn Assigned to me off, empty Search, and set density to Regular with the density button (the icon button with lines and an up-and-down arrow, to the left of the display switcher).

10. Check the setup worked: Tech View shows {Work-order-1} in {Technician-A}'s group.

• Evidence: the build marker before and after, a screenshot after each step that has an expected result, the matching design picture, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Work Orders QA site for this feature (epic SV-10043): app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com. Use the site named in the test run if it differs.
  • Staging (after the feature is merged there): app https://app.staging.shopview.com, API https://api.staging.shopview.com.

Access

  • On a QA site, sign in with the sign-in page's Admin quick-login button (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Elsewhere, ask the QA lead for the environment's cookies.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.

Cleanup
