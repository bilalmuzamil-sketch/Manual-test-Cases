Setup: Tech View's Assigned Techs column sits right after Lines

Test case: C368141, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Technician {Technician-A} (for example Esther Howard) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Approved work order {Work-order-1} (for example S10043-17611) for customer {Customer-A} (for example "ZZAUTOTEST F3 Assigned Techs Column") is led by {Technician-A} and has one approved line, {Line-1} (for example "Service - Full grease service").

• Brand-new staff user {User-B} (for example Tess Default) has the Admin role at {Location-A}, has never changed Tech View's columns, and is signed in in a second browser.

• Developer note kept from the automation engineer (nothing for the tester to do): Dev-layer test — fe-unit. Existing coverage: techViewColumns.spec.ts:36,65

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Esther Howard), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}.

5. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST F3 Assigned Techs Column") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

6. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17611). This is {Work-order-1}. Its line is {Line-1}.

7. On {Work-order-1}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

8. Your initials > Settings > Staff > New Staff Member: First Name and Last Name (for example Tess Default), an Email you can open, Role Admin, at least one Department (required), Location {Location-A} > Save & Close. Accept the invitation from that email and set a password. This is {User-B}. Do not open or change any Work Orders columns as {User-B} before the test. Sign in as {User-B} in a second browser.

9. Check the setup worked: Work Orders > All > List > Search the name of {Customer-A}: exactly {Work-order-1} shows, Approved, Lead Technician {Technician-A}; {User-B} can sign in and has not changed any column.

Part 2. Setup for Claude session

• Goal: a user who has never changed Tech View's columns, then read the column order around Lines, and turn Assigned Techs off and on.

• Read the header row left to right with Playwright as exact strings; the column right after Lines must read Assigned Techs both at the start and after turning it back on.

• Developer coverage (from the automation engineer's note on the earlier version): techViewColumns.spec.ts:36,65 (front-end unit).

• List's saved state (columns, filters, tab, sort) is the user preference GET/PUT /api/users/me/preferences/work-orders-list (playbook, Work Orders filters section); filter state persists on the server across browser contexts. The preference keys for Tech View's columns and Board View's fields are UNVERIFIED: record them from the network requests when you change a column.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.
