Setup: Tech View keeps its own column choice, separate from List, for each user

Test case: C96975, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• You can also work at a second location, {Location-B} (for example Staging Lethbridge - 4310): it is listed under your initials > Change Location.

• Technician {Technician-A} (for example Esther Howard) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Approved work order {Work-order-1} (for example S10043-17604) for customer {Customer-A} (for example "ZZAUTOTEST F2 Tech Own Columns") at {Location-A} is led by {Technician-A} and has one approved line, {Line-1} (for example "Service - Full grease service").

• In List's Column Selection, Service Advisor and Progress are on.

• In Tech View's Column Selection, Service Advisor, Progress and Assigned Techs are on.

• A second browser or computer is available.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Change Location: a second location must be listed, {Location-B} (for example Staging Lethbridge - 4310). If none is, add it to your own staff record (Settings > Staff > your own row's edit icon > Location).

5. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Esther Howard), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}.

6. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST F2 Tech Own Columns") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

7. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17604). This is {Work-order-1}. Its line is {Line-1}.

8. On {Work-order-1}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

9. Work Orders > All > List > Column Selection: turn Service Advisor and Progress on. Then Tech View > Column Selection: turn Service Advisor, Progress and Assigned Techs on.

10. Check the setup worked: Work Orders > All > Search the name of {Customer-A} shows {Work-order-1}, Approved, led by {Technician-A}; List shows Service Advisor and Progress; Tech View shows Service Advisor, Progress and Assigned Techs; your initials > Change Location lists {Location-B}.

Part 2. Setup for Claude session

• Goal: List and Tech View column choices set to a known start, then one change in each display, then re-read after re-login, in a second browser context and at {Location-B}.

• A second Playwright browser context counts as the second browser. Sign in there with the same login; quick login signs out other sessions on the same login, so on a QA site use the case's own login path and confirm the first context is still signed in (if it was signed out, record it and sign in again).

• List's saved state (columns, filters, tab, sort) is the user preference GET/PUT /api/users/me/preferences/work-orders-list (playbook, Work Orders filters section); filter state persists on the server across browser contexts. The preference keys for Tech View's columns and Board View's fields are UNVERIFIED: record them from the network requests when you change a column.

• Cleanup: turn Service Advisor and Assigned Techs back on in Tech View and Progress back on in List, so the shared user is back where it started.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Work Orders QA site for this feature (epic SV-10043): app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com. Use the site named in the test run if it differs.
  • Staging (after the feature is merged there): app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, window at least 1024 px wide. Do not run "playwright install".

Access

  • On a QA site, sign in with the sign-in page's Admin quick-login button (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Elsewhere, ask the QA lead for the environment's cookies.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.

Cleanup

Name everything you create with ZZAUTOTEST at the start. Leave ZZAUTOTEST records in place; they are marked as test data.
