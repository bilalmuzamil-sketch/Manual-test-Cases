Setup: Cards and Tech View's Assigned Techs show the lead and line technicians

Test case: C96993, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit and Schedule access, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Technician {Technician-A} (for example Esther Howard) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Technician {Technician-B} (for example Ralph Edwards) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Technician {Technician-C} (for example Dana Ortiz) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Technician {Technician-D} (for example Jenny Wilson) is an active staff member at {Location-A} with Time Clock on, the Service department and a Role other than Office User or Time Clock User, so they have a row on the Schedule.

• Approved work order {Work-order-1} (for example S10043-17605) for customer {Customer-A} (for example "ZZAUTOTEST F3 Avatar Group") is led by {Technician-A} and has three approved lines: {Line-1} (for example "Service - Full grease service") given to {Technician-B}, {Line-2} (for example "Service - Adjust clutch") given to {Technician-C}, and {Line-3} (for example "Replace - Brake pot") with no labor technician.

• {Technician-D} has a Schedule shift on {Line-3} of {Work-order-1} tomorrow 8:00–10:00, so four different people are on {Work-order-1}: one lead, two line technicians and one scheduled technician.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on. Your role also needs Schedule access (Settings > Roles & Permissions > Admin > Schedule: View and Create & Edit).

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Esther Howard), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}.

5. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Ralph Edwards), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-B}.

6. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Dana Ortiz), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-C}.

7. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, the Service department, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Jenny Wilson), an Email, Role Technician, Departments Service (only Service technicians get a row on the Schedule), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-D}.

8. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST F3 Avatar Group") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

9. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Add Line. In What Are You Doing? type "clutch" and pick the ready-made line "Service - Adjust clutch", turn Line Approved on and click Save & Add Line. In What Are You Doing? type "brake pot" and pick the ready-made line "Replace - Brake pot", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17605). This is {Work-order-1}. Its lines are {Line-1}, {Line-2} and {Line-3}, in that order.

10. On {Work-order-1}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

11. On {Work-order-1}'s Lines tab open {Line-1} (Edit Line) > Technicians > pick {Technician-B} > save the line. On {Work-order-1}'s Lines tab open {Line-2} (Edit Line) > Technicians > pick {Technician-C} > save the line. Leave {Line-3} with no labor technician.

12. Schedule > go to tomorrow > drag {Work-order-1} from the work order list onto {Technician-D}'s row at 8:00 > in the picker choose Choose lines and tick {Line-3} > set the end time to 10:00 > save.

13. Check the setup worked: Work Orders > All > List > Search the name of {Customer-A}: exactly {Work-order-1} shows, Approved, Lead Technician {Technician-A}. On its Lines tab {Line-1} shows {Technician-B}, {Line-2} shows {Technician-C} and {Line-3} no labor technician. On the Schedule {Technician-D}'s shift on {Work-order-1} is there tomorrow 8:00–10:00.

Part 2. Setup for Claude session

• Goal: one work order with four different people on it (lead, two line technicians, one scheduled technician), then read the avatar group in Board View and Tech View.

• Faster route for the shift, UNVERIFIED on the Work Orders QA site (proven only on the Schedule QA site sv8685): POST /api/schedule/shifts with workOrderId, lineIds [{Line-3 id}], staffId (the staff_id of {Technician-D} from GET /api/staff), startDate, startTime, spreadMode "single", totalMinutes, perDayMinutes and isAllDay false; 201 means created. If refused, use the Schedule screen as in Part 1.

• Read the avatar names from each avatar's hover tooltip with Playwright; record the order.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Work Orders QA site for this feature (epic SV-10043): app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com. Use the site named in the test run if it differs.
  • Staging (after the feature is merged there): app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, window at least 1024 px wide. Do not run "playwright install".

Access

  • On a QA site, sign in with the sign-in page's Admin quick-login button (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Elsewhere, ask the QA lead for the environment's cookies.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.
