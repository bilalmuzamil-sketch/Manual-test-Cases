Setup: Tech View and Board View offer a Technician filter that List does not

Test case: C581915, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Technician {Technician-A} (for example Ana Carter) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Technician {Technician-B} (for example Ana Brooks) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User, was added after {Technician-A}, has the same first name as {Technician-A} and a last name that comes before {Technician-A}'s in the alphabet.

• Technician {Technician-C} (for example Ben Adams) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User, was added after {Technician-B}, has a first name that comes after theirs and a last name that comes before both of theirs.

• Approved work order {Work-order-1} (for example S10043-17621) for customer {Customer-A} (for example "ZZAUTOTEST NT1 Technician Filter List") is led by {Technician-A}.

• On the Work Orders page nothing is chosen in any filter, Assigned to me is off and Search is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Ana Carter), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}. Use an email with ZZAUTOTEST in it (for example zzautotest.ana.carter@example.com).

5. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Ana Brooks), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-B}. Add {Technician-B} after {Technician-A}. Use an email with ZZAUTOTEST in it.

6. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Ben Adams), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-C}. Add {Technician-C} after {Technician-B}. Use an email with ZZAUTOTEST in it.

7. If staff with these exact names already exist at {Location-A}, reuse them only if they meet the conditions above; otherwise pick other names that keep the same pattern (two with the same first name where the one added later has the earlier last name, and a third with a later first name and the earliest last name).

8. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST NT1 Technician Filter List") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

9. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17621). This is {Work-order-1}.

10. On {Work-order-1}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

11. Work Orders > All: open each filter in the filter bar and clear any selection (Clear selection), turn Assigned to me off and empty Search.

12. Check the setup worked: Work Orders > All > Tech View shows a group for each of {Technician-A}, {Technician-B} and {Technician-C}, and {Work-order-1} sits in {Technician-A}'s group. Nothing is chosen in any filter.

Part 2. Setup for Claude session

• Goal: three technicians whose names prove the sort (first name, then last name; not the order they were added), then read the Technician filter in Tech View, Board View and List.

• UNVERIFIED: the filter's on-screen label is taken from the PRD ("Technician filter"); record the label and the chip's data-test-id the build uses. The List chips once had data-test-ids filter_chip_status, filter_chip_company_id, filter_chip_tech_assigned_id, filter_chip_service_advisor_id and filter_chip_vehicleHere (playbook, August 2026); the PRD now says Customer and Service Advisor stay retired.

• Trap (playbook): a filter list closes the moment one option is ticked (SV-8824); reopen it before ticking the next option.

• Read the option list and the group headers as exact strings and compare them as sets; check the order of {Technician-B}, {Technician-A} and {Technician-C} within the list.

• Cleanup: clear the Technician filter at the end.

• UNVERIFIED: the design export shows a Department filter; the PRD (version 52, Out of Scope) leaves it out. A build that shows it fails this case.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only.
