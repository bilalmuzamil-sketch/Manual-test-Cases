Setup: The Technician filter combines with other filters and Clear all filters

Test case: C581917, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919).

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Technician {Technician-A} (for example Esther Howard) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Technician {Technician-B} (for example Ralph Edwards) is an active staff member at {Location-A} with Time Clock on and a Role other than Office User or Time Clock User.

• Customer {Customer-A} (for example "ZZAUTOTEST NT3 Technician Filter Mix") is used by this case only.

• Customer {Customer-B} (for example "ZZAUTOTEST NT3 Other Customer") is used by this case only, and its name does not contain {Customer-A}'s name.

• Approved work order {Work-order-1} (for example S10043-17627) for {Customer-A} is led by {Technician-A}.

• Approved work order {Work-order-2} (for example S10043-17628) for {Customer-A} is led by {Technician-B}.

• Approved work order {Work-order-3} (for example S10043-17629) for {Customer-B} is led by {Technician-A}.

• None of these work orders is assigned to you: you are not their lead technician, not their Service Advisor and not on any of their lines.

• Status {Status-A} (for example Paid) is a status none of {Customer-A}'s work orders has.

• On the Work Orders page nothing is chosen in any filter, Assigned to me is off and Search is empty.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Esther Howard), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-A}.

5. Your initials > Settings > Staff. Reuse a staff member only if they are active, have Time Clock on, {Location-A} in Location and a Role other than Office User or Time Clock User. Otherwise click New Staff Member and enter First Name and Last Name (for example Ralph Edwards), an Email, Role Technician, at least one Department (required), Location {Location-A}, turn Time Clock on, then Save & Close. This is {Technician-B}.

6. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST NT3 Technician Filter Mix") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

7. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST NT3 Other Customer") > Save. This is {Customer-B}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRL-903) > Save. Contact and Make are required.

8. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17627). This is {Work-order-1}.

9. On {Work-order-1}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

10. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17628). This is {Work-order-2}.

11. On {Work-order-2}'s page pick {Technician-B} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

12. Work Orders > Create Work Order > in the New Work Order window pick {Customer-B} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17629). This is {Work-order-3}.

13. On {Work-order-3}'s page pick {Technician-A} in the Lead Technician dropdown; it saves at once (the dropdown shows once the work order is Approved).

14. On each of {Work-order-1}, {Work-order-2} and {Work-order-3}: if the Service Advisor is you, change it to another staff member (or leave it empty), and do not give yourself any line.

15. Choose {Status-A}: Work Orders > All > List > Search the name of {Customer-A} > Status, tick one status (for example Paid; not Approved and not Imported). If the List shows no work order, that status is {Status-A}. Then clear the Status selection and the search.

16. Work Orders > All: open each filter in the filter bar and clear any selection (Clear selection), turn Assigned to me off and empty Search.

17. Check the setup worked: Work Orders > All > List > Search the name of {Customer-A} shows {Work-order-1} (lead {Technician-A}) and {Work-order-2} (lead {Technician-B}) and not {Work-order-3}; with Assigned to me on, the same search shows no work order. Turn Assigned to me off and empty Search again.

Part 2. Setup for Claude session

• Goal: two work orders of {Customer-A} with different leads, a decoy of {Customer-B} with the same lead as {Work-order-1}, none assigned to the signed-in user; then combine the Technician filter with Search, Assigned to me and Status.

• Read the empty-state texts with Playwright as exact strings: "No work orders match these filters" and "Try removing a filter to widen your results.", and a button labelled exactly "Clear all filters" (older builds of the List read "Clear Filters", playbook; the PRD label is followed).

• UNVERIFIED: the Technician filter's on-screen label and data-test-id; record them. Whether Clear all filters also empties Search is not stated by the PRD; record what happens.

• Re-check {Status-A} just before step 11: on a shared QA site another session can create a work order in that status.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Work Orders QA site for this feature (epic SV-10043): app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com. Use the site named in the test run if it differs.
  • Staging (after the feature is merged there): app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, window at least 1024 px wide. Do not run "playwright install".

Access

  • On a QA site, sign in with the sign-in page's Admin quick-login button (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Elsewhere, ask the QA lead for the environment's cookies.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.

Cleanup

Name everything you create with ZZAUTOTEST at the start. Leave ZZAUTOTEST records in place; they are marked as test data.
