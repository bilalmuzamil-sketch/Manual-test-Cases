Setup: A new user's Tech View opens on the design's 13 columns

Test case: C96979, WO Board and Tech View. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in braces, such as {Part-A} or {Line-1}, stands for a record you create or pick. Every brace name is defined before it is used. Wherever a value is given "for example", you may use any other value: the example is not a record that already exists in the app. Write down the real value you used for each brace name, because the test steps refer to it.

What the setup creates (the test case's Preconditions)

• You are signed in as an Owner or Admin user whose role has Work orders > View and Work orders > Create & Edit, at {Location-A} (for example Staging Heavy Duty - 9919). You are {User-A}.

• Your browser window is at least 1024 px wide, so the display switcher (List, Tech View, Board View) shows at the right of the Work Orders toolbar.

• Brand-new staff user {User-B} (for example Nora New) has the Admin role at {Location-A}, has never changed any Work Orders columns, and is signed in in a second browser.

• Custom role {Role-A} (for example "ZZAUTOTEST F2 No Financial") has Work Orders view on and See Financial Data off.

• Brand-new staff user {User-C} (for example Nate Nofinance) has role {Role-A} at {Location-A}, has never changed any Work Orders columns, and is signed in in a third browser (or a private window).

• Approved work order {Work-order-1} (for example S10043-17602) for customer {Customer-A} (for example "ZZAUTOTEST F2 Tech Default Columns") has one approved line, {Line-1} (for example "Service - Full grease service"), and no lead technician.

• Your own List columns may be anything at the start; the steps set them.

Part 1. Setup for manual QA tester

1. Sign in as an Owner or Admin user. On a QA site click the Admin quick-login button on the sign-in page; you appear as "Admin ShopView". To check the permissions: your initials (top right) > Settings > Roles & Permissions > Admin > Work orders: View and Create & Edit are on. This is {User-A}.

2. Pick one location for the whole case; it is shown in the top bar next to the bell (to change it: your initials > Change Location). This is {Location-A} (for example Staging Heavy Duty - 9919). Create everything below at {Location-A}.

3. Use a desktop browser window at least 1024 px wide (narrower windows show only the List, with no display switcher).

4. Your initials > Settings > Staff > New Staff Member: First Name and Last Name (for example Nora New), an Email you can open, Role Admin, at least one Department (required), Location {Location-A} > Save & Close. Accept the invitation from that email and set a password. This is {User-B}. Do not open or change any Work Orders columns as {User-B} before the test. Sign in as {User-B} in a second browser.

5. Your initials > Settings > Roles & Permissions > Create Custom Role (for example "ZZAUTOTEST F2 No Financial") > turn on Work Orders view, leave See Financial Data off > Save. This is {Role-A}.

6. Your initials > Settings > Staff > New Staff Member: First Name and Last Name (for example Nate Nofinance), an Email you can open, Role {Role-A}, at least one Department (required), Location {Location-A} > Save & Close. Accept the invitation from that email and set a password. This is {User-C}. Do not open or change any Work Orders columns as {User-C} before the test. Sign in as {User-C} in a third browser or a private window.

7. Top menu Customers > New Customer > Name (for example "ZZAUTOTEST F2 Tech Default Columns") > Save. This is {Customer-A}; use it for this case only. On the customer page click Contacts > New Contact > First Name and Last Name (for example ZZAUTOTEST Contact) > Save. Then Assets > New Asset > pick the contact, Year (for example 2022), Make (type "Freight" and pick Freightliner), Model (for example M2), Unit (for example TRK-118) > Save. Contact and Make are required.

8. Work Orders > Create Work Order > in the New Work Order window pick {Customer-A} and its asset > Save (if a Confirmation about the credit limit appears, click Create). The work order opens on its Lines tab with the New Line form. In What Are You Doing? type "grease" and pick the ready-made line "Service - Full grease service", turn Line Approved on and click Save & Close. The status reads Approved. Write down the number shown at the top left (for example S10043-17602). This is {Work-order-1}. Its line is {Line-1}. Leave Lead Technician empty.

9. Check the setup worked: {User-B} and {User-C} can each sign in and open Work Orders, and neither has changed any column. Work Orders > All > Search the name of {Customer-A} shows {Work-order-1}, Approved, with no lead. If {User-B} or {User-C} already existed and changed columns, create a fresh user instead.

Part 2. Setup for Claude session

• Goal: two brand-new users (one with financial access, one without) who have never saved Tech View columns, then read their Tech View columns, then change and reload your own List columns.

• A new user needs a real invitation email to set a password. If no mailbox is available, ask the QA lead for a test mailbox; never reuse a user who has changed columns, because the case reads the starting columns.

• Read the column headers in order with Playwright as exact strings and compare them with: Status, Waiting On Parts, Number, Customer, Unit, Asset, Progress, Service Advisor, Clocked In, Lines, Assigned Techs, Created on, Total price (Total price only for {User-B}).

• List's saved state (columns, filters, tab, sort) is the user preference GET/PUT /api/users/me/preferences/work-orders-list (playbook, Work Orders filters section); filter state persists on the server across browser contexts. The preference keys for Tech View's columns and Board View's fields are UNVERIFIED: record them from the network requests when you change a column.

• UNVERIFIED: the build checked on 8 Oct (v26.40.8-7a95011) started Tech View on the List defaults with Assigned Techs off; PRD version 51/52 changed that. A build that still does that fails this case.

• Evidence: a screenshot after each step that has an expected result, the build marker, and the real value of every brace name.

How to work

Prepare the same starting state by carrying out Part 1 in a browser with Playwright (or the faster route above, where one is given), then run the test case's steps in the same browser. Record the real value of every brace name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Work Orders QA site for this feature (epic SV-10043): app https://sv10043.qa.shopview.com, API https://sv10043api.qa.shopview.com. Use the site named in the test run if it differs.
  • Staging (after the feature is merged there): app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • Record the build marker (app-version on the app page) before you start and again at the end; the QA site redeploys without notice.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright, window at least 1024 px wide. Do not run "playwright install".

Access

  • On a QA site, sign in with the sign-in page's Admin quick-login button (scripted: node build/testing-tools/qa-branch-boot.mjs, see build/APP-ACTIONS-PLAYBOOK.md section A). Quick login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first. Elsewhere, ask the QA lead for the environment's cookies.
  • Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. GET /api/staff/my-workplaces lists the locations and their ids; switch location with your initials (top right) > Change Location.
