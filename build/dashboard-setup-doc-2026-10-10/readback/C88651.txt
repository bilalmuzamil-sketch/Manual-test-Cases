# **Setup: Every tile shows only the selected location's figures**

Test case: [C88651](https://shopview.testrail.io/index.php?/cases/view/88651), Dashboard. Part 1 is for the manual QA tester. Part 2 is for a Claude session that prepares the case on its own. Both create the starting state listed in the test case's Preconditions; the numbers below match that list.

## **What must be true before you start**

1.  User: you are signed in as an Admin (the Admin role has every permission, including Reports).
2.  Location: you are in a fresh test location made for this run, so nothing else is invoiced, credited or clocked there; on the Dashboard, the Revenue tile on This Week reads $0.00 with 0 Invoices. This is location A.
3.  Timing: you run the whole case on one day, and not on the last evening of the week, so every record you create stays inside This Week.
4.  Data: a second location B you can switch to (any other location in the list).
5.  Data: a test customer with one contact and one asset that uses that contact (for example ZZAUTOTEST Dash Customer 1, contact Dana Test, unit ZZ-101).
6.  Data (In location A): one invoiced work order (not sent, not paid) for the test customer, one labor line of 3.00 hours at $100.00 an hour (Tech Time 3.00). You have written down its Subtotal (e.g. $300.00).

# **Part 1. Setup for manual QA tester**

Each line says which precondition it sets up. Where a precondition is not listed, it needs no setup.

  - **For precondition 1:**

<!-- end list -->

1.  On the QA site's sign-in page, in the DEV MODE — QUICK LOGIN panel, click Admin (this signs you in as Admin ShopView).
2.  To use another role, check it has Reports: profile icon \> Settings \> Roles & Permissions \> edit icon on the role \> Reports is switched on.

<!-- end list -->

  - **For precondition 2:**

<!-- end list -->

1.  Create a fresh location for every run (use a new name each time, for example ZZAUTOTEST Quiet plus today's date and a letter): profile icon \> Settings \> Locations \> New Location: Name, Address 1, City, State/Province, ZIP/Postal Code, Timezone, Telephone, Shop Supplies Charge 0 \> Save & Close.
2.  Switch to it: click your profile icon (your initials, top right, beside the current location name) \> under Change Location: click the orange button showing the current location \> pick the location from the list.
3.  While you are in it, add the labor rate this test uses (rates belong to each location): profile icon \> Settings \> Labor Rates \> New Labor Rate: Name (for example ZZAUTOTEST Rate 100, Rate 100) \> Save & Close.
4.  Check: Dashboard \> Revenue tile \> range pill \> This Week: it reads $0.00 with 0 Invoices.

<!-- end list -->

  - **For precondition 4:**

<!-- end list -->

1.  The same Change Location list
2.  Any other location.

<!-- end list -->

  - **For precondition 5:**

<!-- end list -->

1.  Customers \> New Customer \> Name \> Save
2.  On its Contacts tab: New Contact
3.  Add an asset (Add beside Asset in the New Work Order window, or the customer's Assets tab) and pick that contact in the asset's Contact field.

<!-- end list -->

  - **For precondition 6:**

<!-- end list -->

1.  In location A: Work Orders \> Create Work Order \> in the New Work Order window pick the Customer and an Asset (Add beside either if needed) \> Save (if a Confirmation says the customer is over their credit limit, click Create)
2.  Set Service Advisor to any name in the list in the left panel
3.  In the New Line window (\> New Line on the Lines tab for each further line): What Are You Doing? (any text), Add Technician (yourself), Labor Rate the $100 rate you added in this location (for example ZZAUTOTEST Rate 100), Estimated Time 3 and Tech Time 3, tick Line Approved \> Save & Close
4.  On the line click Story (Add tech story for this line) \> type a short story \> Update
5.  Click Complete (if a Missing Details window asks for Mileage, enter one \> Complete All Lines)
6.  Click Mark Reviewed
7.  Finance tab \> Create Invoice
8.  Close the New Customer Payment window without paying (do not send or pay the invoice).

# **Part 2. Setup for Claude session**

Prepare the same starting state by carrying out Part 1 in a browser with Playwright. Record the real values you used, the build marker and screenshots in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only.

## **Environment**

  - Dashboard QA site: app https://sv490.qa.shopview.com, API https://sv490api.qa.shopview.com.
  - Record the build marker (app-version on the app page) before you start.
  - Browser: Chromium at /opt/pw-browsers/chromium through Playwright. Do not run "playwright install".

## **Access**

  - Sign in with the QA site's quick login: node build/testing-tools/qa-branch-boot.mjs (see build/APP-ACTIONS-PLAYBOOK.md section A). Carry the sv\_sso\_session cookie only, scoped to the host.
  - Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  - Change location through the profile icon (your initials, top right) \> Change Location.

## **Test data**

Name anything you create with ZZAUTOTEST at the start. Leave all test data in place; nothing is deleted afterwards.
