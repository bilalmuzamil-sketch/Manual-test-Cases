# **Setup: Each tile shows the same figure as its matching report**

Test case: [C88601](https://shopview.testrail.io/index.php?/cases/view/88601), Dashboard. Part 1 is for the manual QA tester. Part 2 is for a Claude session that prepares the case on its own. Both create the starting state listed in the test case's Preconditions; the numbers below match that list.

## **What must be true before you start**

1.  User: you are signed in as a user whose role has the Reports permission (for example Admin).
2.  Browser: you use a desktop browser window at least 1024 pixels wide (a maximised laptop or desktop window).
3.  Location: you are in a location (workplace) that has invoices and technician clocked time this month (one day is enough) and over the last twelve months.
4.  User: your role can create a work order and an invoice in that location (Admin can).

# **Part 1. Setup for manual QA tester**

Each line says which precondition it sets up. Where a precondition is not listed, it needs no setup.

  - **For precondition 1:**

1.  On the QA site's sign-in page, in the DEV MODE — QUICK LOGIN panel, click Admin (this signs you in as Admin ShopView).
2.  To use another role, check it has Reports: profile icon \> Settings \> Roles & Permissions \> edit icon on the role \> Reports is switched on.

  - **For precondition 3:**

<!-- end list -->

1.  To change location, click your profile icon (your initials, top right, beside the current location name) \> under Change Location: click the orange button showing the current location \> pick the location from the list.
2.  On the QA site try Staging Heavy Duty - 9919.
3.  Check: on the Dashboard, Revenue on This Month is above $0.00 and Technician Efficiency on This Month shows a percentage (not -).
4.  If not, create today's data first: Customers \> New Customer \> Name \> Save
5.  Work Orders \> Create Work Order \> in the New Work Order window pick the Customer and an Asset (Add beside either if needed) \> Save (if a Confirmation says the customer is over their credit limit, click Create)
6.  The New Line window opens: What Are You Doing? (any text), Add Technician = Tech ShopView, Labor Rate = EVR Travel to EVO ($100 an hour), Estimated Time 1 and Tech Time 1, tick Line Approved \> Save & Close
7.  Clock time as the technician: in a second browser or a private window, on the QA site's sign-in page, in the DEV MODE — QUICK LOGIN panel, click Tech (this signs you in as Tech ShopView, a technician at Staging Heavy Duty - 9919 with Time Clock on)
8.  Open the work order \> on the line's Labor row click Start
9.  When done click Stop \> Clock Out
10. To make the time exact, as Admin: the three dots at the top right of the Lines tab \> Timesheets (n) \> edit the record's start and end (if it cannot be edited there or in Reports \> Timesheet Activities, keep the real time and use the hours Timesheet Activities shows)
11. On the line click Story (Add tech story for this line) \> type a short story \> Update
12. Click Complete (if a Missing Details window asks for Mileage, enter one \> Complete All Lines)
13. Click Mark Reviewed
14. Finance tab \> Create Invoice
15. Close the New Customer Payment window without paying (do not send or pay the invoice).
16. Then check again.
17. If not, try the other locations in the list.
18. If no location in the list passes this check, mark the case Blocked and write in the result comment that no location has this data.

# **Part 2. Setup for Claude session**

Prepare the same starting state by carrying out Part 1 in a browser with Playwright. Record the real values you used, the build marker and screenshots in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only.

## **Environment**

  - Dashboard QA site: app https://sv490.qa.shopview.com, API https://sv490api.qa.shopview.com.
  - Record the build marker (app-version on the app page) before you start.
  - Browser: Chromium at /opt/pw-browsers/chromium through Playwright. Do not run "playwright install".

## **Access**

  - Sign in with the QA site's quick login: node build/testing-tools/qa-branch-boot.mjs (see build/APP-ACTIONS-PLAYBOOK.md section A). Carry the sv\_sso\_session cookie only, scoped to the host.
  - Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  - Change location through the profile icon (your initials, top right) \> Change Location.

## **Test data**

Name anything you create with ZZAUTOTEST at the start. Leave all test data in place; nothing is deleted afterwards.
