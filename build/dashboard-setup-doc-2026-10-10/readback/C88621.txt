# **Setup: One very high value caps the percentage axis at 200%**

Test case: [C88621](https://shopview.testrail.io/index.php?/cases/view/88621), Dashboard. Part 1 is for the manual QA tester. Part 2 is for a Claude session that prepares the case on its own. Both create the starting state listed in the test case's Preconditions; the numbers below match that list.

## **What must be true before you start**

1.  User: you are signed in as an Admin (the Admin role has every permission, including Reports).
2.  Location: you are in one location (workplace) with the data below.
3.  Browser: you use a desktop browser at 100% zoom on a screen at least 1024 pixels wide (any ordinary laptop or desktop monitor).
4.  Data: a one-off very high Billing Efficiency month for one advisor exists: one invoiced work order today whose Service Advisor has nothing else invoiced this month, with one labor line of 1.00 hour assigned to a technician who clocked exactly 0.25 hours on it (1.00 / 0.25 x 100 = 400%).
5.  Location: the location also has other advisors with ordinary monthly figures under 200% over the last twelve months, so most plotted points are at or below 200%.

# **Part 1. Setup for manual QA tester**

Each line says which precondition it sets up. Where a precondition is not listed, it needs no setup.

  - **For precondition 1:**

<!-- end list -->

1.  On the QA site's sign-in page, in the DEV MODE — QUICK LOGIN panel, click Admin (this signs you in as Admin ShopView).
2.  To use another role, check it has Reports: profile icon \> Settings \> Roles & Permissions \> edit icon on the role \> Reports is switched on.

<!-- end list -->

  - **For precondition 2:**

<!-- end list -->

1.  To change location, click your profile icon (your initials, top right, beside the current location name) \> under Change Location: click the orange button showing the current location \> pick the location from the list.
2.  On the QA site use Staging Heavy Duty - 9919 unless a later line says otherwise.

<!-- end list -->

  - **For precondition 4:**

<!-- end list -->

1.  Pick the advisor: Reports \> Advisor Analysis, Date: This month: choose an advisor with no row there (your own name, Admin ShopView, if it has none).
2.  Then Customers \> New Customer \> Name \> Save (for example ZZAUTOTEST Dash Customer)
3.  Work Orders \> Create Work Order \> in the New Work Order window pick the Customer and an Asset (Add beside either if needed) \> Save (if a Confirmation says the customer is over their credit limit, click Create)
4.  The New Line window opens: What Are You Doing? (any text), Add Technician = Tech ShopView, Labor Rate = EVR Travel to EVO ($100 an hour), Estimated Time 1 and Tech Time 1, tick Line Approved \> Save & Close
5.  Then set Service Advisor in the work order's left panel to that advisor
6.  Clock time as the technician: in a second browser or a private window, on the QA site's sign-in page, in the DEV MODE — QUICK LOGIN panel, click Tech (this signs you in as Tech ShopView, a technician at Staging Heavy Duty - 9919 with Time Clock on)
7.  Open the work order \> on the line's Labor row click Start
8.  When done click Stop \> Clock Out
9.  Make the clocked time exactly 0.25 hours (15 minutes), as Admin: the three dots at the top right of the Lines tab \> Timesheets (n) \> edit the record's start and end (if it cannot be edited there or in Reports \> Timesheet Activities, keep the real time and use the hours Timesheet Activities shows)
10. On the line click Story (Add tech story for this line) \> type a short story \> Update
11. Click Complete (if a Missing Details window asks for Mileage, enter one \> Complete All Lines)
12. Click Mark Reviewed
13. Finance tab \> Create Invoice
14. Close the New Customer Payment window without paying (do not send or pay the invoice).

<!-- end list -->

  - **For precondition 5:**

<!-- end list -->

1.  Check: Billing Efficiency set to Last 12 Months \> View details shows several advisors' points
2.  Then set the pill back to This Month (the dashboard remembers your choices).

# **Part 2. Setup for Claude session**

Prepare the same starting state by carrying out Part 1 in a browser with Playwright. Record the real values you used, the build marker and screenshots in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only.

## **Environment**

  - Dashboard QA site: app https://sv490.qa.shopview.com, API https://sv490api.qa.shopview.com.
  - Record the build marker (app-version on the app page) before you start.
  - Browser: Chromium at /opt/pw-browsers/chromium through Playwright. Do not run "playwright install".

## **Access**

  - Sign in with the QA site's quick login: node build/testing-tools/qa-branch-boot.mjs (see build/APP-ACTIONS-PLAYBOOK.md section A). Carry the sv\_sso\_session cookie only, scoped to the host.
  - Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  - Change location through the profile icon (your initials, top right) \> Change Location.

## **Test data**

Name anything you create with ZZAUTOTEST at the start. Leave all test data in place; nothing is deleted afterwards.
