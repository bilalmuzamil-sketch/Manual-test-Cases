# **Setup: This Month's figure and trend line both include today's sales**

Test case: [C351716](https://shopview.testrail.io/index.php?/cases/view/351716), Dashboard. Part 1 is for the manual QA tester. Part 2 is for a Claude session that prepares the case on its own. Both create the starting state listed in the test case's Preconditions; the numbers below match that list.

## **What must be true before you start**

1.  User: you are signed in as an Admin (the Admin role has every permission, including Reports).
2.  Location: you are in a location (workplace) where nobody else creates an invoice or a credit memo while you run the case, and where no shop supplies are added (for example ZZAUTOTEST Dashboard Quiet).
3.  Browser: you use a desktop browser at 100% zoom on a screen at least 1024 pixels wide (any ordinary laptop or desktop monitor).
4.  Before you start: you have written down the Revenue headline on This Month (e.g. $2,422.00) before the invoice below is created.
5.  Data: Then one invoice dated today is created in that location, with no discount, with clocked time, for example 2.50 hours at $100.00 an hour = $250.00.

# **Part 1. Setup for manual QA tester**

Each line says which precondition it sets up. Where a precondition is not listed, it needs no setup.

  - **For precondition 1:**

  - **For precondition 2:**

2.  Pick ZZAUTOTEST Dashboard Quiet (it charges 0 % shop supplies).
3.  If you cannot be sure nobody else invoices there while you run the case, write that in the result comment.

<!-- end list -->

  - **For precondition 4:** Dashboard \> Revenue tile on This Month.
  - **For precondition 5:**

<!-- end list -->

1.  Customers \> New Customer \> Name \> Save (for example ZZAUTOTEST Dash Customer)
2.  Work Orders \> Create Work Order \> in the New Work Order window pick the Customer and an Asset (Add beside either if needed) \> Save (if a Confirmation says the customer is over their credit limit, click Create)
3.  The New Line window opens: What Are You Doing? (any text), Add Technician = Tech ShopView, Labor Rate = EVR Travel to EVO ($100 an hour), Estimated Time 2.5 and Tech Time 2.5, tick Line Approved \> Save & Close
4.  Then the Service Advisor is filled in with your name (Admin ShopView)
5.  To use another advisor change Service Advisor in the work order's left panel
6.  Clock time as the technician: in a second browser or a private window, on the QA site's sign-in page, in the DEV MODE — QUICK LOGIN panel, click Tech (this signs you in as Tech ShopView, a technician at Staging Heavy Duty - 9919 with Time Clock on)
7.  Open the work order \> on the line's Labor row click Start
8.  When done click Stop \> Clock Out
9.  To make the time exact, as Admin: the three dots at the top right of the Lines tab \> Timesheets (n) \> edit the record's start and end (if it cannot be edited there or in Reports \> Timesheet Activities, keep the real time and use the hours Timesheet Activities shows)
10. On the line click Story (Add tech story for this line) \> type a short story \> Update
11. Click Complete (if a Missing Details window asks for Mileage, enter one \> Complete All Lines)
12. Click Mark Reviewed
13. Finance tab \> Create Invoice
14. Close the New Customer Payment window without paying (do not send or pay the invoice).

# **Part 2. Setup for Claude session**

Prepare the same starting state by carrying out Part 1 in a browser with Playwright. Record the real values you used, the build marker and screenshots in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only.

## **Environment**

  - Dashboard QA site: app https://sv490.qa.shopview.com, API https://sv490api.qa.shopview.com.
  - Record the build marker (app-version on the app page) before you start.
  - Browser: Chromium at /opt/pw-browsers/chromium through Playwright. Do not run "playwright install".

## **Access**

  - Sign in with the QA site's quick login: node build/testing-tools/qa-branch-boot.mjs (see build/APP-ACTIONS-PLAYBOOK.md section A). Carry the sv\_sso\_session cookie only, scoped to the host.
  - Keep cookies in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  - Change location through the profile icon (your initials, top right) \> Change Location.

## **Test data**

Name anything you create with ZZAUTOTEST at the start. Leave all test data in place; nothing is deleted afterwards.
