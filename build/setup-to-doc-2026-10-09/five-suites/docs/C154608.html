Setup: Edit tax rate locks once invoiced, unlocks on reversal, needs permission

Test case: C154608, FM - Part Sale. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

Values given as examples ("e.g." or "for example") can be anything: they are not records that already exist in the app. Write down the real values you used, because the test steps refer to them.

What the setup creates

  • You are signed in as an Owner/Admin user (that role holds every permission, including Part sales - Create & Edit and Invoicing & payments - Create & Edit).
  • A test customer exists.
  • A test vendor exists to order parts from.
  • The invoiced sale: a new part sale started today for the test customer (a sale started before this release handles cores the old way), with the part "Brake Pads" (Quantity 1, Vendor = the test vendor, Sell Price $290.91).
  • The part is ordered and received, so the sale is Complete.
  • The sale has been invoiced and paid in full, and that payment then reversed: the sale stays Invoiced, with no payment applied.
  • Two tax rates exist (for example a second one, "ZZAUTOTEST 6%" at 6.00%).
  • The user without the permission: a spare test user with the role "ZZAUTOTEST No part sale edit" (built from a template, for example "Parts Manager"): Part sales - Create & Edit unticked, Part sales View left ticked.

Part 1. Setup for manual QA tester

The case's full original preconditions, with every step for setting them up:

  1. Sign in as an Owner/Admin user. That role holds every permission, including Part sales -> Create & Edit and Invoicing & payments -> Create & Edit.
  2. A test customer exists. If not: top menu Customers -> New Customer, enter a Name (e.g. "4 Star Truck Repair") and click Save.
  3. A test vendor exists to order parts from. If not: top menu Parts -> Vendors (left sidebar) -> New Vendor, enter a Name (e.g. "ZZAUTOTEST Parts Supply"), pick a value in Taxes (required, e.g. "GST"), then click Save & Close.
  4. Start a new part sale today (a sale started before this release handles cores the old way): top menu Parts -> Part Sales -> New Part Sale; in the New part sale dialog pick the Customer and click Save. The sale opens with the status Estimate.
  5. On the Parts tab click Add Part (on a sale with no parts the Add Part dialog opens by itself). In the Add Part dialog enter Description "Brake Pads", Quantity 1 (required), Vendor = the test vendor and Sell Price $290.91, then click Save & Close.
  6. Order and Receive that part: click Authorize (green button above the parts list), then in the row's Actions column click Order, then Receive; in the Receive parts dialog tick the row, type a part number in the red Part number box (e.g. "ZZ-BP-1", then press Enter), enter a Cost (e.g. $150.00) and click Receive Parts. Receiving every part takes the sale to Complete.
  7. On the Finance tab click Create Invoice. In the New Customer Payment dialog pick a Payment Method (e.g. "Cash") and click Make Payment for the full balance. (The payment dialog lists every open invoice for this customer and fills in an amount on each one: set the Payment amount of every other invoice to 0 so only this sale is paid.) Do not just close the dialog: closing it without paying cancels the invoice.
  8. Then reverse that payment: top menu Customers -> open the customer -> Payments tab -> on the payment's row click the trash icon (tooltip "Remove") -> in the Confirmation dialog click Reverse. The sale stays Invoiced, with no payment applied.
  9. Two tax rates exist: Settings (click your initials at the top right -> Settings) -> Taxes. If needed click New Tax and add one, e.g. "ZZAUTOTEST 6%" at 6.00%.
  10. Create the test role: Settings (click your initials at the top right -> Settings) -> Roles & Permissions -> Create Custom Role -> in Choose a template pick e.g. "Parts Manager" -> Apply; untick Part sales -> Create & Edit (leave Part sales View ticked); enter the Role name "ZZAUTOTEST No part sale edit" and click Create. Assign it: Settings -> Staff -> on a spare test user's row click the edit icon -> in Edit Staff Member set Role to "ZZAUTOTEST No part sale edit" -> Save & Close. That user must log out and back in before testing (a role change ends their session).

Part 2. Setup for Claude session

Prepare the same starting state by carrying out Part 1 in a browser with Playwright, then run the test case's steps in the same browser. Record the real value of every named record, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
