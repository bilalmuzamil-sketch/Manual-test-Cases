Setup: Adding a note needs View permission on that kind of record

Test case: C154704, FM - Notifications. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

Values given as examples ("e.g." or "for example") can be anything: they are not records that already exist in the app. Write down the real values you used, because the test steps refer to them.

What the setup creates

  • Sign in as an Owner/Admin user (the standard Admin role). This is User A.
  • User B: a teammate at the same location who can sign in, with the role "ZZAUTOTEST Part sales only" (built from the "Service Advisor" template; Work orders - View unticked, Part sales - View ticked).
  • A work order at this location (customer for example "4 Star Truck Repair").
  • A part sale at this location.
  • User C: a second teammate, with the role "ZZAUTOTEST Work orders only" (built from the "Service Advisor" template; Work orders - View ticked, Part sales - View unticked).

Part 1. Setup for manual QA tester

The case's full original preconditions, with every step for setting them up:

  1. Sign in as an Owner/Admin user (the standard Admin role). This is User A.
  2. A teammate at the same location to tag, User B, who can sign in: on a QA branch the second user is the Tech quick-login user (sign in from a private browser window with the Tech button; appears as "Tech ShopView"). They are listed under Settings -> Staff.
  3. A work order at this location: top menu Work Orders -> Create Work Order, select a customer (e.g. "4 Star Truck Repair"), save.
  4. A part sale at this location: top menu Parts -> Part Sales -> New Part Sale, pick the Customer and click Save.
  5. Create the test role: Settings (click your initials at the top right -> Settings) -> Roles & Permissions -> Create Custom Role -> in Choose a template pick "Service Advisor" -> Apply; untick Work orders -> View and leave Part sales -> View ticked; enter the Role name "ZZAUTOTEST Part sales only" and click Create. Assign it: Settings -> Staff -> on User B's row click the edit icon -> in Edit Staff Member set Role to "ZZAUTOTEST Part sales only" -> Save & Close. User B must log out and back in before testing (a role change ends their session).
  6. A second teammate, User C. On a QA branch only two users can sign in (Admin and Tech): when a step says "Sign in as User C", first give Tech ShopView User C's role (Settings -> Staff -> on Tech ShopView's row click the edit icon -> Role -> Save & Close; Tech signs out and back in) and run that step as Tech ShopView. For tagging or group membership only, any staff member (e.g. "Ashlee Thomas") can be User C. Part 2. Setup for Claude session

Prepare the same starting state by carrying out Part 1 in a browser with Playwright, then run the test case's steps in the same browser. Record the real value of every named record, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
