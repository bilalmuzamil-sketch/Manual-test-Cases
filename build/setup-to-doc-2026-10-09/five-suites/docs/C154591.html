Setup: Core actions are hidden without the shared core permission

Test case: C154591, FM - Part Sale. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

Values given as examples ("e.g." or "for example") can be anything: they are not records that already exist in the app. Write down the real values you used, because the test steps refer to them.

What the setup creates

  • A test customer exists.
  • A test vendor exists to order parts from.
  • The part sale: a new part sale started today for the test customer (a sale started before this release handles cores the old way).
  • The part sale has the part "Water Pump" (Quantity 1; Vendor = the test vendor; Sell Price $517.55; Core Charge $79.99) and, beneath it, a row "Core for Water Pump".
  • The part has been authorized, ordered and received: the part row reads Received and its core row offers Return Core in the Actions column.
  • The service work order: a service work order for the same customer with a received core (a part with Vendor = the test vendor and a Core Charge of $79.99).
  • User X is a spare test user with the role "ZZAUTOTEST Parts no core" (built from a template, for example "Parts Manager"): Part sales - Create & Edit ticked; every box under Vendor and order management (vendors, purchase orders, deliveries and part returns) unticked; Work order lines - Create & Edit and Work orders - Create & Edit unticked.
  • User Y is a spare test user with the role "ZZAUTOTEST No financial data" (built from a template, for example "Parts Manager"): See Financial Data (under Cross-Cutting) unticked.
  • The sale and the work order are built while signed in as an Owner/Admin user.

Part 1. Setup for manual QA tester

The case's full original preconditions, with every step for setting them up:

  1. A test customer exists. If not: top menu Customers -> New Customer, enter a Name (e.g. "4 Star Truck Repair") and click Save.
  2. A test vendor exists to order parts from. If not: top menu Parts -> Vendors (left sidebar) -> New Vendor, enter a Name (e.g. "ZZAUTOTEST Parts Supply"), pick a value in Taxes (required, e.g. "GST"), then click Save & Close.
  3. Start a new part sale today (a sale started before this release handles cores the old way): top menu Parts -> Part Sales -> New Part Sale; in the New part sale dialog pick the Customer and click Save. The sale opens with the status Estimate.
  4. On the Parts tab click Add Part (on a sale with no parts the Add Part dialog opens by itself). In the Add Part dialog enter Description "Water Pump", Quantity 1 (required), Vendor = the test vendor, Sell Price $517.55 and Core Charge $79.99, then click Save & Close. The grid shows the part and, beneath it, a row "Core for Water Pump".
  5. Click Authorize (green button above the parts list); the sale becomes Approved and the part row shows Auth To Order. In that row's Actions column click Order. The row now shows Awaiting.
  6. Click Receive on the row. In the Receive parts dialog tick both rows (Select All), type a part number in each red Part number box (e.g. "ZZ-WP-1", then press Enter), enter the part row's Cost (e.g. $400.00), keep Qty Received at the full quantity and click Receive Parts. The message "Parts received." appears; the part row reads Received and its core row offers Return Core in the Actions column.
  7. A service work order for the same customer with a received core: top menu Work Orders -> Create Work Order, select the customer, add a line, add a part to it with Vendor = the test vendor and a Core Charge of $79.99, then Order and Receive the part (in the Receive parts dialog type a part number and Cost, then click Receive Parts).
  8. Create the test role: Settings (click your initials at the top right -> Settings) -> Roles & Permissions -> Create Custom Role -> in Choose a template pick e.g. "Parts Manager" -> Apply; tick Part sales -> Create & Edit, and untick every box under Vendor and order management (vendors, purchase orders, deliveries and part returns), Work order lines -> Create & Edit and Work orders -> Create & Edit (this build has no permission named "Vendors" or "Work Order Parts"; these are the nearest); enter the Role name "ZZAUTOTEST Parts no core" and click Create. Assign it: Settings -> Staff -> on a spare test user's row click the edit icon -> in Edit Staff Member set Role to "ZZAUTOTEST Parts no core" -> Save & Close. That user must log out and back in before testing (a role change ends their session). This user is User X.
  9. Create the test role: Settings (click your initials at the top right -> Settings) -> Roles & Permissions -> Create Custom Role -> in Choose a template pick e.g. "Parts Manager" -> Apply; untick See Financial Data (under Cross-Cutting); enter the Role name "ZZAUTOTEST No financial data" and click Create. Assign it: Settings -> Staff -> on a spare test user's row click the edit icon -> in Edit Staff Member set Role to "ZZAUTOTEST No financial data" -> Save & Close. That user must log out and back in before testing (a role change ends their session). This user is User Y.
  10. Build the sale and the work order while signed in as an Owner/Admin user, then switch to User X and User Y for the steps.

Part 2. Setup for Claude session

Prepare the same starting state by carrying out Part 1 in a browser with Playwright, then run the test case's steps in the same browser. Record the real value of every named record, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
