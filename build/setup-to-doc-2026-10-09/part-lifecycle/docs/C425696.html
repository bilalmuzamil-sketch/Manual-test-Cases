Setup: A rename carries over to open purchase order lines at every location

Test case: C425696, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in square brackets, such as [Part-A], stands for a record you create or pick; it is defined in the list below and used the same way in the test case. Values given as examples can be anything: they are not records that already exist in the app. Write down the real value you used for each name, because the test steps refer to it.

What the setup creates

  • User: an Admin, who has 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.
  • [Loc-1] = the location you work in (pick it in the location switcher in the top bar).
  • [Loc-2] = a second location the Admin can pick in the location switcher. If there is none: Settings → Locations → add a location (e.g. 'ZZAUTOTEST PL Loc 2') → Save, then Settings → Staff → open the Admin → give access to the new location → Save.
  • Data: part [Part-A] (3 on hand) at [Loc-1], also stocked at [Loc-2]; a vendor [Vendor-A].
  • Purchase orders: [PO-1] at [Loc-1], [Part-A] picked from the lookup, 2 ordered, not received; [PO-2] at [Loc-1], [Part-A] picked, 1 ordered, fully received on vendor invoice [Inv-2]; [PO-3] at [Loc-1], [Part-A] typed by hand and added as typed (no link to the part), not received; [PO-4] at [Loc-2], [Part-A] picked, 4 ordered, not received.
  • Must hold: [Part-A-new] is unused and does not contain [Part-A].

Part 1. Setup for manual QA tester

  1. Write down: [Part-A] = ZZAUTOTEST-PL-COPO-01, [Part-A-new] = ZZAUTOTEST-PL-COPONEW-02, [Vendor-A] = ZZAUTOTEST PL COPO Vendor, [Inv-2] = ZZ-COPO-INV-2 (examples).
  2. Sign in as the Admin and pick [Loc-1] in the location switcher in the top bar.
  3. At [Loc-1]: Parts → Inventory → New Inventory Part → Description: ZZAUTOTEST PL CO PO → Part Number: [Part-A] → Category: any (e.g. Uncategorized) → Cost: 10.00 → Sell Price: 20.00 → keep the default bin row (Quantity e.g. 3) → Save.
  4. Pick [Loc-2]: create [Part-A] there the same way, then pick [Loc-1] again.
  5. Parts → Vendors → add a vendor named [Vendor-A] → Save.
  6. Parts → Purchase Orders → New Purchase Order → Vendor [Vendor-A] → add a line: type [Part-A] and pick the result with an Inventory Qty → Quantity 2 → save. [PO-1] = its number.
  7. New Purchase Order → [Vendor-A] → line: pick [Part-A] the same way → Quantity 1 → save → Receive it: invoice number [Inv-2], cost 10.00, sell 20.00, received 1 → Receive. [PO-2] = its number.
  8. New Purchase Order → [Vendor-A] → line: type [Part-A] in full and choose the row that adds the number as typed (not the result with an Inventory Qty) → Quantity 1 → save. [PO-3] = its number.
  9. Pick [Loc-2]: New Purchase Order → [Vendor-A] → line: pick [Part-A] → Quantity 4 → save. [PO-4] = its number. Pick [Loc-1] again.
  10. Check the setup worked: the Purchase Orders lists show [PO-1], [PO-3] not received and [PO-2] received at [Loc-1], and [PO-4] not received at [Loc-2]; every line reads [Part-A]. Inventory at [Loc-1] shows [Part-A] with 3 + 1 = 4 on hand.

Part 2. Setup for Claude session

Prepare the same starting state by carrying out Part 1 in a browser with Playwright, then run the test case's steps in the same browser. Record the real value of every bracketed name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
