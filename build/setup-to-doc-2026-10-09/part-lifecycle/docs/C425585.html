Setup: Each tab lists only the parts with that status at the current location

Test case: C425585, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in square brackets, such as [Part-A], stands for a record you create or pick; it is defined in the list below and used the same way in the test case. Values given as examples can be anything: they are not records that already exist in the app. Write down the real value you used for each name, because the test steps refer to it.

What the setup creates

  • User: [User-A], signed in with the Admin role. Admin holds the 'Part Library & Inventory' permissions View, Create & Edit and Delete by default (Settings → Roles & Permissions); Delete is what allows Deactivate parts and Activate parts.
  • Locations: [Loc-1] and [Loc-2], two locations [User-A] can pick in the location selector in the top bar (Setup creates [Loc-2] if only one exists).
  • Browser: a desktop browser window at least 1280 pixels wide (parts management is desktop and tablet only).
  • Data: [Part-A] (e.g. ZZAUTOTEST-PL-LOCTAB-01) active at [Loc-1] and not stocked at [Loc-2]. [Part-B] (e.g. ZZAUTOTEST-PL-LOCTAB-02) stocked at both locations with the same part number: inactive at [Loc-1], active at [Loc-2]. Numbers and descriptions are examples; the statuses and locations must hold.

Part 1. Setup for manual QA tester

  1. If the location selector in the top bar lists only one location, create a second one: Settings → Locations → New Location, type a name (e.g. ZZAUTOTEST-PL-LOC-B) and the other required fields, and save. [Loc-2] = the second location; [Loc-1] = the one you work in first.
  2. Pick [Loc-1] in the location selector.
  3. Create [Part-A]: go to Parts → Inventory, click New Inventory Part, type Description "ZZAUTOTEST PL loc tab part A" and Part Number ZZAUTOTEST-PL-LOCTAB-01 (examples), pick any Category (e.g. the first one offered), type Cost (e.g. 10.00) and Sell Price (e.g. 20.00), leave "Track quantities and cost of goods" on, keep the default bin with Quantity 5, and click Save. [Part-A] = the part number you typed.
  4. Create [Part-B]: go to Parts → Inventory, click New Inventory Part, type Description "ZZAUTOTEST PL loc tab part B" and Part Number ZZAUTOTEST-PL-LOCTAB-02 (examples), pick any Category (e.g. the first one offered), type Cost (e.g. 10.00) and Sell Price (e.g. 20.00), leave "Track quantities and cost of goods" on, keep the default bin with Quantity 5, and click Save. [Part-B] = the part number you typed.
  5. Pick [Loc-2] in the location selector and create the same part there: New Inventory Part, the same Description "ZZAUTOTEST PL loc tab part B" and exactly the same Part Number [Part-B] (same upper and lower case), any Category, Cost (e.g. 10.00), Sell Price (e.g. 20.00), tracking on, default bin Quantity (e.g. 3), Save.
  6. Pick [Loc-1] again. Make [Part-B] inactive: on the Active tab type [Part-B] in the Search box, click its row, pick Part Status → Inactive in Edit Inventory Part, click Save, then click Deactivate in the "Deactivate part?" confirmation (leave Note (Optional) empty).
  7. Check the setup worked: at [Loc-1] the Inactive tab searched for ZZAUTOTEST-PL-LOCTAB lists only [Part-B]; at [Loc-2] the Active tab searched for ZZAUTOTEST-PL-LOCTAB lists [Part-B]. If not, redo steps 5 and 6.

Part 2. Setup for Claude session

Prepare the same starting state by carrying out Part 1 in a browser with Playwright, then run the test case's steps in the same browser. Record the real value of every bracketed name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).

Cleanup

Leave records whose names start with ZZAUTOTEST; they are marked as test data. Delete work orders you created when the case is finished.
