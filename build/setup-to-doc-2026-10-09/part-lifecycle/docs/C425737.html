Setup: Library entry stocked only elsewhere is hidden when it matches an inactive part

Test case: C425737, Founder Mode / Part Lifecycle. Part 1 is for a manual QA tester. Part 2 is for a Claude session that prepares and runs the case on its own. Both create the starting state listed in the test case's Preconditions.

How to read this document: a name in square brackets, such as [Part-A], stands for a record you create or pick; it is defined in the list below and used the same way in the test case. Values given as examples can be anything: they are not records that already exist in the app. Write down the real value you used for each name, because the test steps refer to it.

What the setup creates

  • User: [Admin] = you, signed in with the Admin role, which by default has 'Part Library & Inventory → View / Create & Edit / Delete' and See Financial Data.
  • Location: [Loc-1] = the location picked in the top-bar location switcher at the start; every step runs at [Loc-1] unless it names another location.
  • Location: [Loc-2] = a second location [Admin] can switch to.
  • Data: [Part-A] = a tracked part at [Loc-1], set inactive in Setup. [Num-2] = a part number stocked only at [Loc-2] that equals [Part-A] once case, hyphens and periods are ignored. [Num-3] = a part number stocked only at [Loc-2] that matches nothing at [Loc-1]. All three have the description [Desc-A].
  • Data: [WO-1] = an open work order at [Loc-1] with one approved line [Line-1].
  • Names and numbers marked (e.g. …) are examples only. What must hold is the status (active or inactive), tracking, quantity and link described above.

Part 1. Setup for manual QA tester

  1. Go to Settings → Locations, add a location (e.g. "ZZAUTOTEST PL LIBMATCH Loc") and save. [Loc-2] = that location.
  2. Go to Settings → Staff, open [Admin] and make sure [Loc-2] is one of the locations [Admin] can use; save. [Loc-2] now shows in the top-bar location switcher.
  3. Switch to [Loc-2]. Create two parts with New Inventory Part, both with Description (e.g. ZZAUTOTEST PL LIBMATCH), Category, Cost and Sell Price: Part Number (e.g.) "ZZAUTOTEST.PL.LIBMATCH.01" and Part Number (e.g.) "ZZAUTOTEST-PL-LIBOTHER-01". [Num-2] = the first number, [Num-3] = the second.
  4. Switch to [Loc-1]. Create [Part-A] with New Inventory Part: Part Number (e.g.) "ZZAUTOTEST-PL-LIBMATCH-01" and the same Description. [Part-A] = that number, [Desc-A] = that description.
  5. Go to Work Orders, click "New Work Order"; in Customer click Add and create a customer (e.g. "ZZAUTOTEST PL LIBMATCH Customer"); in Asset click Add and create a unit (e.g. "ZZAUTOTEST-PL-LIBMATCH-UNIT"); click Create.
  6. [WO-1] = the work order number shown at the top left (e.g. S2-1234).
  7. On [WO-1] click "New Line", type Title (e.g. "ZZAUTOTEST PL LIBMATCH line"), click "Save & Close". [Line-1] = that line. Click "Approve" on [Line-1].
  8. While [Part-A] is still active, on [Line-1] click ⋮ → "Request part" and type [Desc-A] in Part Number: [Part-A] (with "Inventory Qty"), [Num-2] and [Num-3] (both marked "Part Library") are offered. Close with ×.
  9. Set [Part-A] inactive: on the Active tab search [Part-A], click its row, pick Part Status "Inactive", click Save, leave the note empty and click "Deactivate" in the "Deactivate part?" confirmation.
  10. Check the setup worked: at [Loc-1] [Part-A] is on the Inactive tab; at [Loc-2] both [Num-2] and [Num-3] are on the Active tab.

Part 2. Setup for Claude session

Prepare the same starting state by carrying out Part 1 in a browser with Playwright, then run the test case's steps in the same browser. Record the real value of every bracketed name, the build marker and screenshots in the case's verification folder in the Manual-test-Cases repository, and judge pass or fail against the test case's Expected results only. Facts below come from the team's recorded playbook (build/APP-ACTIONS-PLAYBOOK.md).

Environment

  • Staging: app https://app.staging.shopview.com, API https://api.staging.shopview.com.
  • A QA branch named in the test run: the app is https://sv followed by the branch number and .qa.shopview.com, and the API host adds "api" after the branch number with no dot (for example https://sv10043.qa.shopview.com and https://sv10043api.qa.shopview.com).
  • Record the build marker (app-version on the app page) before you start.
  • Browser: Chromium at /opt/pw-browsers/chromium-1194/chrome-linux/chrome through Playwright. Do not run "playwright install".

Access

  • Ask the QA lead for the environment's cookies (sv_sso_session, cf_clearance and PHPSESSID). Keep them in /tmp only, with file mode 600. Never write a cookie into a document, a commit or a log.
  • Check access: GET /api/auth/me/fe-permissions answers 200. On a QA branch the sign-in page has quick-login buttons; quick-login signs out other sessions using the same login, so confirm with the QA lead that no other session is live first.
  • GET /api/staff/my-workplaces lists the locations and their ids; switch location in the top bar, or with POST /api/iam/change-location (workplace_id and its workplace_timezone).
