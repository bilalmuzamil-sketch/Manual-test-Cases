Found while testing SV-11249

This can only be reproduced through the API. The New Location screen always sends a colour, so a user on screen cannot cause it.

When a location is created through the API without a colour, the whole organization breaks:

  • New work orders can no longer be created in any location.

  • Settings → Locations shows an empty list with two red "Ooooops! An error occurred" messages.

Giving that location a colour fixes it straight away.

Steps to reproduce

Open the QA branch to reproduce the issue: https://sv11249.qa.shopview.com (log in as an admin).

  1. Open Chrome's developer tools (F12) and go to the Console tab. The requests below run from the logged-in page.

  2. Create a work order to confirm the starting state is fine. Use POST https://sv11249api.qa.shopview.com/api/work-orders/create with the body {"company_id":"<customer company id>","vehicle_id":"<asset id>","workplace_id":"b3c8c820-f815-4cf1-8938-10956c5ee71a","start_date":"2026-11-06","is_vehicle_here":true}. It returns 201 with a work order id.

  3. Create a location with no color: POST https://sv11249api.qa.shopview.com/api/workplaces/create with the body {"name":"ZZAUTOTEST NoColour 81408","shop_id":"NC1408","address_1":"1 Test St","city":"Calgary","state_or_province":"AB","postal_code":"T2P1J9","telephone":"4035550100","timezone":"America/Edmonton","country_code":"CA"}. It returns 201, {"data":{"workplace_id":"908a63f3-1453-4744-a8d7-89873b739c40"}}, and the location is saved with color: null.

  4. Send the same work-order request as in step 2 again. It now returns 500: "An error occurred. We're sorry for this inconvenience, please try again a bit later." (requestId 37776e77-c59a-4d13-b3f9-2844ecaf75f6).

  5. Send GET https://sv11249api.qa.shopview.com/api/workplaces. It returns 500 too (requestId 9037e5a3-bb38-4fc2-8888-3828dedfe258).

  6. In the app, click the gear (Settings) and then Locations in the left menu. The list is empty and two red error messages appear.

Fastest way to see it: the branch has been left in the broken state. Open https://sv11249.qa.shopview.com/administration/locations and you will see the empty list and the two red errors straight away.

Picture 1: Settings → Locations on sv11249. Top: before, all 4 locations are listed. Bottom: after one location is created through the API with no colour, the list is empty and two red errors appear.

Expected behaviour

One of these should happen:

  • The API refuses a location without a colour with a clear message (for example 400 "Color is required").

  • Or the location is saved with a default colour.

Either way, one location's data must never stop the rest of the organization from creating work orders or listing its locations.

Current behaviour

The API accepts the location and saves it with no colour. After that, every work order create and the locations list return 500 for the whole organization.
