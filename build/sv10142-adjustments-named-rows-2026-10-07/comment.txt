*OVERALL QA STATUS: PARTIALLY PASSED*

Everything that could be tested on this branch passed. The ticket is waiting only on the customer portal check. Stefan is asked in a separate comment to enable the portal on this branch.

The fix is working:
* Each line-level fee and discount now prints its own name, as {{Labor · <name>}} or {{Parts · <name>}}.
* Identical rows combine into one row carrying the total.
* Fees and discounts are no longer netted against each other.
* Inside Labor and inside Parts, fees come before discounts, each A to Z by name, whatever order they were entered in.
* The Legacy layout is unchanged.

h3. Why this is still Partially Passed

The customer portal could not be checked. In the profile menu (top right), {{Customer Portal}} does not open from this branch, because the shared portal server does not accept sign-ins from it.
Stefan's PR lists the customer-portal document as using the same invoice template, so it still needs to be looked at.

h3. Where the expected behaviour comes from

The invoice spec still describes the old behaviour. *Invoice UI Refresh*, version 70, S7-R5 states:
{quote}Under the Adjustments heading, in this order: a rollup row labeled exactly "Labor" totaling all line-level labor fees and discounts, a rollup row labeled exactly "Parts" totaling all line-level parts fees and discounts, then each work-order-wide fee or discount as its own named row{quote}

Chris ruled on this ticket afterwards, in [comment 77792|https://shopview.atlassian.net/browse/SV-10142?focusedCommentId=77792] (2 October), [comment 77997|https://shopview.atlassian.net/browse/SV-10142?focusedCommentId=77997] (6 October) and [comment 78126|https://shopview.atlassian.net/browse/SV-10142?focusedCommentId=78126] (7 October).
His comments are the latest information, so this test follows them. I have asked him to update the spec in the separate comment.
